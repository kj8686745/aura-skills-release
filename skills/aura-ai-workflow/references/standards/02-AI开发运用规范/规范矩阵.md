# AI 开发运用规范矩阵

**适用版本**：`0.1.0-draft`  
**状态**：建设中  
**用途**：按 AI 研发任务定位规则；必要性、适用条件和示例以对应正文为准。

先按任务定位文档，再搜索规则编号。矩阵只转录规则编号、标题和必要性，不增加第二套要求。“必须”和“禁止”也只在相应规则的适用场景内生效；不要求每次任务加载全部文件。

## 规则速查

### [01-AI辅助开发基本规则](./01-AI辅助开发基本规则.md)

| 规则编号 | 必要性 | 规则名称 |
| --- | --- | --- |
| `AURA-AI-USE-001` | 禁止 | AI 可以辅助但不得替代开发者决策 |
| `AURA-AI-USE-002` | 禁止 | AI 不得绕过基础规范、能力包契约和项目事实 |
| `AURA-AI-USE-003` | 必须 | 开发者必须对 AI 输出结果负责 |
| `AURA-AI-USE-004` | 必须 | AI 任务必须能确定目标和执行边界 |
| `AURA-AI-USE-005` | 必须 | AI 越界或关键事实不清时必须暂停受影响动作 |

### [02-AI工作入口初始化规范](./02-AI工作入口初始化规范.md)

| 规则编号 | 必要性 | 规则名称 |
| --- | --- | --- |
| `AURA-AI-INIT-001` | 应当 | 持续使用 AI 的项目应建立可复用工作入口 |
| `AURA-AI-INIT-002` | 应当 | 工作入口应由一个文件提供稳定导航 |
| `AURA-AI-INIT-003` | 必须 | AI 工作入口必须按任务路由且不复制规范 |
| `AURA-AI-INIT-004` | 应当 | 每次 AI 任务启动应执行轻量初始化 |
| `AURA-AI-INIT-005` | 必须 | 能力包由任务内容触发，不由通用入口硬编码执行 |
| `AURA-AI-INIT-006` | 必须 | 工作入口必须区分自主执行与人工确认 |
| `AURA-AI-INIT-007` | 必须 | AI 完成任务后必须输出可审查结果 |

### [03-AI会话运用机制规范](./03-AI会话运用机制规范.md)

| 规则编号 | 必要性 | 规则名称 |
| --- | --- | --- |
| `AURA-AI-SESSION-001` | 建议 | 建议按任务目标组织 AI 会话 |
| `AURA-AI-SESSION-002` | 必须 | 新会话必须依据当前任务和可核实事实启动 |
| `AURA-AI-SESSION-003` | 应当 | 一个会话应保持一个主目标 |
| `AURA-AI-SESSION-004` | 必须 | 跨会话续接必须核对可追溯状态，不凭记忆猜测 |
| `AURA-AI-SESSION-005` | 必须 | 出现实际上下文失真时必须收束 |
| `AURA-AI-SESSION-006` | 禁止 | 需要复用的重要结论不得只留在聊天中 |
| `AURA-AI-SESSION-007` | 建议 | 目标或上下文确需分离时可新开会话 |
| `AURA-AI-SESSION-008` | 应当 | Codex 编码会话应由项目入口和当前任务驱动 |

### [04-AI上下文管理通用规范](./04-AI上下文管理通用规范.md)

| 规则编号 | 必要性 | 规则名称 |
| --- | --- | --- |
| `AURA-AI-CTX-GEN-001` | 必须 | 上下文管理是所有 AI 研发任务的基础要求 |
| `AURA-AI-CTX-GEN-002` | 应当 | 上下文应按任务、事实和证据分层提供 |
| `AURA-AI-CTX-GEN-003` | 必须 | AI 任务必须从最小必要上下文开始 |
| `AURA-AI-CTX-GEN-004` | 禁止 | 不得用无关材料污染 AI 上下文 |
| `AURA-AI-CTX-GEN-005` | 应当 | 源码任务应先定位结构再读取文件 |
| `AURA-AI-CTX-GEN-006` | 必须 | 上下文过载时必须收束任务 |
| `AURA-AI-CTX-GEN-007` | 应当 | 跨会话长任务应依据可追溯状态续接 |
| `AURA-AI-CTX-GEN-008` | 必须 | AI 输出必须说明依据和未验证项 |

### [05-AI输出审查与人工确认](./05-AI输出审查与人工确认.md)

| 规则编号 | 必要性 | 规则名称 |
| --- | --- | --- |
| `AURA-AI-REVIEW-001` | 禁止 | AI 输出默认不得直接视为交付结果 |
| `AURA-AI-REVIEW-002` | 必须 | AI 输出必须经过业务、规范和验证审查 |
| `AURA-AI-CONFIRM-001` | 必须 | 未获授权或仍有关键选择的高影响变更必须人工确认 |
| `AURA-AI-CONFIRM-002` | 必须 | 能力包相关关键决策必须人工确认 |
| `AURA-AI-REVIEW-003` | 必须 | AI 生成或修改结果必须完成相称验证 |
| `AURA-AI-REVIEW-004` | 禁止 | 缺少依据、事实或验证的输出不得直接采纳 |
| `AURA-AI-REVIEW-005` | 必须 | 审查结果必须明确采纳状态 |

### [06-常见任务使用流程](./06-常见任务使用流程.md)

| 规则编号 | 必要性 | 规则名称 |
| --- | --- | --- |
| `AURA-AI-FLOW-001` | 必须 | AI 开发任务必须先分析再修改 |
| `AURA-AI-FLOW-002` | 应当 | 新增后端功能应按最小改动路径执行 |
| `AURA-AI-FLOW-003` | 应当 | 新增前端页面应先读取相邻页面和接口封装 |
| `AURA-AI-FLOW-004` | 必须 | 能力包接入必须使用公开入口和最小验证路径 |
| `AURA-AI-FLOW-005` | 必须 | 修改已有功能必须先定位原因和影响范围 |
| `AURA-AI-FLOW-006` | 应当 | 代码审查默认只输出问题和建议 |
| `AURA-AI-FLOW-007` | 必须 | 问题定位必须先基于证据排查 |
| `AURA-AI-FLOW-008` | 必须 | 文档和汇报必须区分事实、计划和待确认事项 |
