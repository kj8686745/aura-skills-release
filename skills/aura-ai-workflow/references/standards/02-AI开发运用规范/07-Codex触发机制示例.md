# 07-Codex 触发机制示例

**状态**：候选规范  
**适用对象**：使用 Codex 参与研发、审查、问题定位和文档整理的人员  
**定位**：说明 Codex 项目指令、任务选路和 Skills 如何配合应用 AI 开发运用规范；其他工具需按自身机制适配。

## 一、核心结论

AI 不会因为项目里存在规范文件就自动稳定遵守规范。

Codex 的项目指令、当前任务和可用 Skills 共同决定本轮该读取什么；下图是判断关系，不是每次必须逐项执行的流水线：

```text
运行开始时发现项目指令
  + 当前用户任务和项目事实
  → 按任务选读规范或调用适用 Skill
  → 在授权范围内实施并相称验证
  → 结果与未验证项
```

规范文件定义要求和边界，Skill 负责把命中部分组织为可执行协作；有项目指令或 Skill，并不单独证明规范已被正确应用。

## 二、Codex 中的触发来源

### AURA-AI-CODEX-001：项目级 AGENTS.md 应声明 AI 工作入口

**必要性**：应当

在持续使用 Codex、需要复用项目规则的仓库中，宜通过项目级 `AGENTS.md` 提供简洁入口；已有有效入口直接复用。Codex 按项目根到当前工作目录发现指令，每个目录可能由 `AGENTS.override.md` 覆盖普通文件；发现发生在运行开始时，不要求每轮重新读取同一文件。入口只需说明对项目有用的导航，例如：

- AI 任务应先读取哪些入口文件；
- 当前项目适用哪些基础规范；
- 实际接入能力时如何找到能力索引；
- 哪些决定超出当前任务授权；
- 哪些任务可在现有授权内继续；
- 与任务有关的资料从哪里定位。

示例：

```md
## AI 工作入口

当任务涉及 AI 协作方式时，先从 AURA 的 AI 开发运用规范矩阵定位命中文档；不要默认读取整个目录。

当任务实际接入具体能力时，再通过能力包索引读取对应公开说明。

先按任务定位目标；需要追查调用链时再扩大读取范围。
当前任务未命中具体能力时，不预读能力包正文。
```

**正例**：项目入口只告诉 Codex 如何按任务找到规范矩阵、目标模块和验证命令。

**反例**：入口要求每次修改都读取 AI 规范全部文件和全部能力包；或明明已有项目规则，又为一次性任务创建重复入口。

**检查方式**：核对入口是否位于 Codex 可发现的路径、目标链接有效；分别以普通页面修改和能力接入任务检查实际选读范围。项目指令发现机制以 [OpenAI 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)为准。

## 三、按任务选路

### AURA-AI-CODEX-002：不同任务应触发不同规范

**必要性**：应当

Codex 应结合用户实际目标、项目事实和已加载的项目指令选读规范，不能只匹配字面“触发词”。下表是定位示例；存在专用开发 Skill 时可由它加载命中的技术规范，不要求普通编码任务另把所有 AI 运用文件读一遍。

| 用户任务 | 优先定位 | 默认动作 |
| --- | --- | --- |
| “继续这个项目” | 项目入口；涉及跨会话续接时再读 `03-AI会话运用机制规范` | 先核对当前目标和实际文件，不扫描全项目 |
| “帮我开发一个接口” | 后端及接口规范，或适用的开发 Skill | 定位相邻实现；授权明确时继续修改与验证 |
| “接入某个能力包” | 公开能力包索引和命中的使用说明或 Skill | 已指定能力时核对适用性与公开入口，不重复选型确认 |
| “审查这段代码” | 当前 diff 和命中的规范；审查与确认规则按需补充 | 默认只输出问题、证据、影响和建议 |
| “定位问题” | `06-常见任务使用流程` | 先整理证据和排查路径 |
| “生成文档/汇报” | `06-常见任务使用流程` | 区分事实、计划和待确认 |
| “不要扫描全项目” | `04-AI上下文管理通用规范` | 收束上下文 |

**正例**：接口开发读取后端和接口契约相关文件，只有实际接入设备能力时才进入该能力的公开说明。

**反例**：看到“接口”二字就同时加载全部 AI 规范、全部基础规范与全部能力包，或把“继续”一律解释成必须读取状态文件。

**检查方式**：能说明所选规范与当前任务的关系；没有仅凭词面命中而加载无关资料。

## 四、编码过程中的标准触发流程

### AURA-AI-CODEX-003：编码任务必须先进入上下文管理流程

**必要性**：必须

以“新增后端接口”为例，Codex 应先完成必要的任务与事实核对，再在授权范围内实施。下列步骤可按实际任务合并，不要求先提交方案等待批准：

```text
1. 识别任务：后端接口开发
2. 使用已加载的项目规则；需要核对时定位 AGENTS.md
3. 按当前任务定位命中的后端、接口或 AI 协作规则；可由适用 Skill 选读
4. 读取目标模块和相邻实现
5. 判断修改范围；存在实质性方案选择且当前授权不足时再询问
6. 没有决策缺口时在授权范围内继续
7. 修改代码
8. 运行相称验证
9. 输出变更、验证和未处理项
```

如果目标模块无法定位且会影响实现结果，Codex 应先说明缺失事实；没有相邻实现并不自动阻止新功能开发。

**正例**：已授权的接口开发先核对同模块实现和当前契约，然后完成修改、相关验证及结果说明。

**反例**：因为用户没填写固定提示词字段就拒绝查看代码；或把列出“最小方案”当成必须等待的审批环节。

**检查方式**：改动与当前目标、项目证据和命中规范对应；没有无关规范加载或重复请示。

## 五、暂停条件触发

### AURA-AI-CODEX-004：出现越界信号时 Codex 必须暂停受影响动作

**必要性**：必须

以下情况应暂停受影响动作、核实事实或收束读取范围；能独立完成的授权部分可继续：

| 越界信号 | Codex 应做什么 |
| --- | --- |
| 任务只授权“审查”，AI 准备自行修改 | 不实施修改，只输出审查结果 |
| 需要删除、迁移、覆盖难以恢复的数据且未获授权 | 暂停该动作，列出目标和影响，等待决定 |
| 权限、租户或认证的信任边界将改变，但任务未授权或方案不明 | 暂停受影响修改，说明具体选择 |
| 上下文开始过载 | 停止扩大读取，回到目标文件和直接证据 |
| 候选资料被当成已发布依据 | 不作已发布结论，核对当前状态 |
| 关键判断缺少证据 | 先读取可取得的事实；仍无依据则标注未验证 |

**正例**：只读审查中发现需要修改权限判断，先报告问题；若用户随后授权整改，再实施并验证。

**反例**：审查任务里直接改代码；或发现一处证据不足便终止全部任务，连可独立核对的事实也不查。

**检查方式**：被暂停的是未授权或依据不足的具体动作；可继续的部分没有被机械阻断。

## 六、人工确认触发

### AURA-AI-CODEX-005：未获授权或仍有关键选择的高影响动作必须人工确认

**必要性**：必须

Codex 应按[人工确认规则](./05-AI输出审查与人工确认.md)判断授权和影响；普通的接口、迁移文件、依赖和配置修改不因文件类型自动停下。下列事项在当前任务未明确授权或存在实质性决策缺口时，不能自行决定：

- 改变已有消费者使用的公开契约或权限信任边界；
- 使用未发布能力、申请能力包或规范例外；
- 删除、覆盖难以恢复的数据，或执行生产环境操作；
- 裁定候选规范已确认或已发布；
- 执行正式发布、回滚或其他超出当前任务授权的对外动作。

存在真实决策缺口时，可简要说明：

```text
已确认事实：
需要决定的事项：
受影响动作与影响：
建议选择：
```

**正例**：已授权修改接口实现时直接编码和验证；发现需要破坏现有公开响应字段时，只暂停该契约决定。

**反例**：因要改 `pom.xml` 就停止全部工作并等待再次批准，或未经授权执行生产发布。

**检查方式**：核对确认点是否对应当前授权之外的真实决定，而不是机械匹配文件名。

## 七、Codex Skills 的触发方式

### AURA-AI-CODEX-006：使用 Skill 时必须以命中的规范正文为依据

**必要性**：必须

在 Codex 中，使用 Skill 时必须以当前任务命中的规范正文为依据，由 Skill 将相关规则组织为可执行流程；不得把 Skill 的摘要当成独立规则源。可以显式指定可用 Skill；Codex 也可能依据 Skill 的名称、描述和当前任务选择它。隐式选择不是“出现某个词就必然调用”的保证，任务实际用到的规则必须可追溯。

关系是：

```text
规范文件
  → 定义规则和边界

Skill
  → 按任务加载规则、案例和检查方式

Codex
  → 按当前任务选择适用 Skill 或直接选读相关规范
```

后端开发、前端开发和具体能力接入分别使用其适用的开发或能力使用 Skill；普通上下文整理不因此默认加载所有开发 Skill。Skill 的名称与可用状态应以实际安装的版本为准，不在这里维护一份易过期的技能清单。参见 [OpenAI 官方 Skills 说明](https://learn.chatgpt.com/docs/build-skills)。

**正例**：用户显式调用已安装的能力使用 Skill，Skill 只选读该能力公开说明；没有专用 Skill 时按任务直接定位相关规范。

**反例**：假定文档中出现某个 Skill 名称就代表本机已安装、已执行，或把 Skill 的摘要文字当成独立于规范的第二套规则。

**检查方式**：实际调用的 Skill 可发现、适用当前任务；引用的规则与同版正文一致，没有全量资料预加载。

## 八、一次真实编码任务示例

用户输入：

```text
帮我在当前项目里新增设备告警查询接口。
```

Codex 应执行：

```text
1. 识别为后端接口开发；
2. 使用已加载的项目指令，必要时核对 AGENTS.md；
3. 按当前任务定位后端和接口相关规范；有专用 Skill 时由其选读；
4. 从工作区定位目标模块和相邻接口，关键事实仍缺失时再询问；
5. 检查是否涉及权限、租户、数据范围；
6. 确定最小改动路径；
7. 当前任务已授权且没有实质性决策缺口时修改代码；
8. 编译或执行接口最小验证；
9. 输出改动文件、验证结果、未确认项。
```

Codex 不应直接：

```text
全项目搜索所有 alarm 代码
→ 大范围生成 Controller / Service / Mapper
→ 默认新增表结构
→ 跳过权限和数据范围
→ 声称完成
```

## 九、可选的 Codex 任务表达

以下表达可按需要删减；不是每次任务的必填模板。

### 1. 开发任务

```text
这是一个需要 AI 辅助编码的项目开发任务。
请使用已加载的项目入口，并按任务从 AI 开发运用规范矩阵定位相关规则。
只有实际接入具体能力时，再读取对应公开能力包使用说明。
本次任务是：
目标模块是：
允许修改：
不允许修改：
请定位最小改动路径；如无实质性决策缺口，在授权范围内继续实现并验证。
```

### 2. 审查任务

```text
这是一个 AI 辅助代码审查任务。
请依据当前 diff 和命中的规范审查；实际涉及具体能力时再读其公开使用说明。
只输出问题、证据、影响和建议。
不要直接修改文件。
```

### 3. 收束上下文

```text
停止扩大上下文。
优先核对当前目标文件和直接证据；如调用链指向相邻模块，可以说明关联后继续查证。
旧会话结论与当前事实冲突时，以核实后的当前事实为准。
请纠正偏差并继续本轮任务。
```

## 十、落地建议

持续使用 Codex 的项目宜维护简短、可发现的项目入口，指向已有的项目资料、按任务定位的规范和验证方式。一次性任务或现有资料足以支持当前任务时，不为满足示例另建 `AGENTS.md`、状态文件或技能目录。
