# 08-使用示例

**状态**：候选规范  
**适用对象**：使用 AI 辅助研发、审查、问题定位和能力包接入的研发人员

以下示例展示自然语言任务如何触发相应处理，不要求照抄。能从项目入口和工作区定位的信息无需用户重复提供；任务已授权且没有关键决策缺口时，AI 应继续实施和验证。

## 一、后端接口开发

```text
请在当前项目的设备模块增加告警查询接口，沿用现有权限、分页和响应方式。
先核对相邻实现及接口规范，然后完成代码和相称验证。只有需求或现有契约存在会改变结果的缺口时再问我。
```

## 二、前端页面开发

```text
请在当前项目的设备模块增加告警列表页，沿用同模块页面的路由、请求封装和权限模式。
从现有页面与接口定位需要的字段，完成实现并验证；若关键交互在现有资料中无法确定，再问我。
```

## 三、能力包接入判断

```text
当前业务需要在设备详情页展示在线状态。请先核对项目已有实现，再从公开能力包索引判断是否有适用能力。
如果适合，说明公开入口、适用版本和最小接入路径；如果不适合，说明缺口，不要猜测未公开的 SDK 方法。
```

## 四、代码审查

```text
请只读审查当前设备模块的接口变更及相关测试。核对分层、权限和数据范围、请求响应契约，以及实际命中的能力包使用要求。
只输出有文件和规则依据的问题、影响及建议，不要修改文件。
```

## 五、问题定位

```text
当前项目的设备列表在切换分页后重复显示上一页数据。请结合现有页面、请求和可取得的日志定位原因，区分已证实结论与待验证假设。
本次只做诊断，不修改代码。
```

## 六、低上下文续接

```text
继续处理设备告警查询接口。请先核对当前代码变更和已有验证记录，确认哪些部分已完成、哪些尚未验证，再继续本次已授权的工作。
不要把旧会话摘要当成当前代码事实；若现有资料缺少会改变实现结果的决定，再提出具体问题。
```

## 七、要求 AI 停止扩大范围

```text
本轮只处理设备告警查询接口。请停止无目标地扩大读取范围，回到接口、相邻服务和直接证据；调用链确实指向其他模块时再继续查证。
不要处理历史草稿或修改无关文件，核实后继续完成已授权部分。
```

## 八、不推荐的提示词

以下提示词容易导致 AI 越界、上下文过载或输出不可验证，不建议使用。

### 1. 范围过大

```text
帮我把整个项目优化一下。
```

问题：没有目标模块、问题范围和验证方式，容易导致无关扫描和大范围修改。

建议改为：

```text
请只审查 device 模块的查询接口性能问题，先输出问题和证据，不要修改代码。
```

### 2. 跳过分析

```text
不用分析，直接生成完整功能。
```

问题：AI 容易忽略项目结构、相邻实现、权限和数据范围。

建议改为：

```text
请先核对相邻实现并确定最小改动路径；本次授权已覆盖的部分可继续实现并验证，存在实质性选择缺口时再问我。
```

### 3. 跳过验证

```text
不用测试，写完就行。
```

问题：AI 输出无法作为交付结果。

建议改为：

```text
请说明本次改动需要哪些最低验证；如果当前环境无法验证，请明确标注未验证项。
```

### 4. 绕过权限

```text
权限先不用管，先跑起来。
```

问题：权限、租户和数据范围属于项目基础边界，不能为了临时可运行而绕过。

建议改为：

```text
请按现有权限和数据范围实现；如果缺少权限信息，先列出需要确认的内容。
```

### 5. 全量扫描

```text
扫描所有文件，看看哪里有问题。
```

问题：上下文过大，容易产生无关结论。

建议改为：

```text
请只审查本次 diff 涉及的文件，并按项目适用的后端基础规范输出问题。
```
