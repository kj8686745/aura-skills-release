# 02-AI 工作入口初始化规范

**状态**：候选规范  
**适用对象**：使用 Codex 或类似 AI 编码助手参与研发、审查、问题定位和文档整理的人员  
**定位**：定义项目如何建立通用 AI 工作入口，使 AI 在日常研发过程中能够稳定触发上下文管理、任务路由、规范加载、停止条件和人工确认机制。

## 一、核心定位

AI 工作入口不是 AURA 项目专属文件。项目持续使用 AI 辅助研发时，应提供一个稳定的项目规则入口；一次性、范围明确的任务不要求先创建文件。已有入口能满足要求时直接复用。

它解决的问题是：

- AI 进入项目后先读什么；
- AI 如何判断当前任务类型；
- AI 什么时候加载基础规范；
- AI 什么时候加载能力包规范；
- AI 什么时候暂停受影响动作；
- AI 什么时候必须要求人工确认；
- AI 如何避免依赖旧会话和无限扩大上下文。

通用初始化只建立基础工作机制，不替代具体能力包规范。

```text
通用 AI 工作入口
  → 负责上下文、任务路由、停止条件、交付格式

能力包规范
  → 负责具体框架、组件、接口、示例和能力接入要求
```

## 二、适合建立入口的场景

### AURA-AI-INIT-001：持续使用 AI 的项目应建立可复用工作入口

**必要性**：应当

以下场景适合建立或补齐 AI 工作入口：

- AI 将持续参与项目开发、审查或问题定位；
- 多人或多会话需要稳定复用项目规则；
- 项目有专属构建、验证、文档或能力接入入口，无法只靠当前任务说明表达。

入口初始化只建立项目级导航，不要求改业务代码，也不为一次普通任务先生成空文档。已有入口覆盖这些信息时无需重复创建。

**正例**：团队长期用 Codex 维护同一仓库，复用已有项目规则，并补上实际构建命令和模块文档入口。

**反例**：只为修复一处明确的文案，就先创建一整套 AI 目录和状态文件。

**检查方式**：核对入口是否服务持续复用，且未与现有项目规则重复。

## 三、初始化产物

### AURA-AI-INIT-002：工作入口应由一个文件提供稳定导航

**必要性**：应当

使用 Codex 时，推荐把仓库共同规则放在项目根目录的 `AGENTS.md`；其他工具应采用其实际支持的项目指令入口。不能假定任意名称的文件都会被自动加载。

最小结构是一个入口文件，其他文档按项目已有布局引用：

```text
项目根目录/
├─ AGENTS.md          # 使用 Codex 时的项目入口
└─ docs/              # 项目已有文档，按任务引用；无需为入口补建空文件
```

入口文件应能定位当前任务真正需要的信息：

- 当前项目的研发边界是什么；
- 任务相关代码和文档从哪里查找；
- 构建或验证方式在哪里；
- 项目实际使用能力包时，如何定位对应索引；
- 哪些决策超出当前任务授权。

状态文件只在跨会话任务需要持久续接、且现有项目文档不足以表达状态时创建。文档路径遵守项目原有组织方式。

**正例**：`AGENTS.md` 指向现有项目总览、各模块 `docs` 和验证命令；没有状态文件时按当前代码与 Git 状态判断。

**反例**：入口写着不存在的 `docs/当前状态.md`，或重复创建与项目 README 内容相同的说明文件。

**检查方式**：核对入口链接和命令实际存在；使用 Codex 时确认文件位于其可发现的项目路径。

## 四、AGENTS.md 必须包含的内容

### AURA-AI-INIT-003：AI 工作入口必须按任务路由且不复制规范

**必要性**：必须

入口应简洁地给出：

```text
1. 项目定位及事实来源
2. 按任务选择代码、文档与适用规范的方式
3. 当前授权内可继续执行的动作，以及需停止确认的边界
4. 构建、验证与结果说明入口
5. 实际使用能力包时的能力索引或对应入口
```

没有使用某项能力的项目不需预填该能力的占位入口。通用入口不能复制整套规范，也不能要求每次任务加载全部资料。

**正例**：入口说明“前端页面任务查前端规范；实际接入设备能力时再查能力索引和物联中枢云使用说明”。

**反例**：在 `AGENTS.md` 粘贴全部能力包正文，要求每次修改都先阅读。

**检查方式**：抽取一个普通编码任务和一个能力接入任务，确认两者只命中各自所需入口。

## 五、任务启动流程

### AURA-AI-INIT-004：每次 AI 任务启动应执行轻量初始化

**必要性**：应当

项目入口建立后，任务启动时按当前目标做轻量定位；不重复初始化文件，不预读全套规范：

```text
1. 使用工具已加载或可定位的项目入口，确认当前任务与授权范围；
2. 定位目标文件、相邻实现及必要的当前事实；
3. 只加载命中的规范；使用具体能力时再进入能力索引；
4. 判断关键事实或决策是否缺失；若无缺口，在授权范围内继续并做相称验证。
```

不要求每次任务都输出方案并等待确认。仅当目标或关键选择不清会改变结果时才询问。

**正例**：修改某页面字段时，读取项目入口、该页面及其 API 封装，按已授权目标修改并验证。

**反例**：每次任务都重读所有规范、创建状态文件，并要求用户再次确认已明确的改动。

**检查方式**：核对读取文件与任务的关系；没有额外决策缺口时不产生重复确认。

## 六、能力包触发方式

### AURA-AI-INIT-005：能力包由任务内容触发，不由通用入口硬编码执行

**必要性**：必须

能力包触发应来自当前任务和项目实际接入事实；先通过能力索引判断，再读取命中的使用说明。项目已有某能力，不表示每个任务都要加载它。

示例：

| 用户任务 | 通用入口判断 | 后续触发 |
| --- | --- | --- |
| “在设备详情页展示运行状态” | 页面开发 + 设备能力 | 先查能力索引，再定位命中的物联中枢云公开说明 |
| “新增文件下载功能” | 接口开发 + 文件能力 | 先查能力索引，再定位命中的文件任务与实时交互公开说明 |
| “新增设备告警接口” | 后端接口开发 | 后端基础规范，必要时再触发对应业务能力包 |
| “审查这次 AI 生成的接口” | 只读审查任务 | 当前 diff 与命中的接口规范，按需补 AI 输出审查规则 |
| “整理当前项目状态” | 文档整理任务 | 上下文管理规范，不默认触发能力包 |

能力包未命中时，AI 不应自行猜测能力包。

**正例**：用户要求展示设备状态，先查能力索引确认物联中枢云的公开入口，再读取命中的能力使用说明。

**反例**：修改普通表单时，因项目已接入设备能力就加载物联能力包并改动相关配置。

**检查方式**：核对能力包与任务场景是否直接相关，且接入依据来自公开索引而不是猜测。

## 七、停止条件

### AURA-AI-INIT-006：工作入口必须区分自主执行与人工确认

**必要性**：必须

工作入口应说明：当前任务已授权且范围明确的常规实现和相称验证，可以继续执行；以下情况在授权不足、关键事实缺失或仍需作出实质性选择时，只暂停**受影响的动作**，说明缺口并取得必要决定：

- 当前请求仅授权审查或分析，执行却需要修改、发布或对外发送；
- 需要改变公开契约、权限信任边界或持久数据，且当前任务未授权这一改变或存在会实质影响结果的方案选择；
- 需要删除、覆盖难以恢复的数据，或操作生产环境、正式发布，但当前任务没有明确授权该具体动作；
- 目标对象或关键项目事实无法核实，继续执行会明显改变结果；
- 需要判断候选规范是否获准发布，而没有对应的正式依据。

普通的接口实现、数据库迁移文件、依赖声明或构建配置调整，只要属于已明确授权的研发任务，仍应按对应规范实施和验证，不因文件类型本身重复请求确认。

需要确认时简要说明：

```text
已确认事实：
缺少的关键决定：
受影响的动作与影响：
建议选择：
```

**正例**：用户要求实现新接口，AI 按现有契约完成代码与测试；若发现必须更改已有消费者使用的字段且未授权，暂停这项契约变更并说明选择。

**反例**：只要看到 `pom.xml` 或数据库迁移文件，就要求用户对每一步重新批准；或在未授权时直接改生产数据。

**检查方式**：核对停止原因是否是授权、事实或重大不可恢复影响，而不是简单按文件类型设卡。

## 八、交付输出要求

### AURA-AI-INIT-007：AI 完成任务后必须输出可审查结果

**必要性**：必须

任务完成后，应先说明结果，再给出与任务相关的变更或发现、实际验证和未验证项；涉及规范或能力包时指出所依据的入口。没有待确认事项时无需机械列出空栏目。

如果只是审查任务，不应输出“已修复”或“已完成开发”。

如果只是候选规范整理，不应输出“已发布”。

**正例**：说明“已完成设备列表筛选，改动页面与 API 封装，构建通过；未做真实环境联调”。

**反例**：仅写“已完成”，或把未运行的测试写成已通过。

**检查方式**：结果能够回溯到实际文件或证据，完成、未验证和待决定事项没有混写。

## 九、AGENTS.md 示例

以下是已存在项目说明和模块文档时的精简示例。复制前应检查路径和命令，不存在的文件不要写入入口。Codex 会按项目路径发现 `AGENTS.md`；入口内不必要求它每轮重新读取已加载的同一文件。

```md
# 项目 AI 工作入口

## 项目事实

- 项目概况：`README.md`
- 模块设计：进入目标模块后查该模块的 `docs/`
- 当前任务以用户要求、目标文件和实际代码为准，不用旧会话代替现状。

## 按任务读取

- 开发或修复：先定位目标代码与相邻实现，再读取命中的开发规范。
- 审查：依据目标文件或 diff 输出问题和证据，不自行修改。
- 实际接入 AURA 能力时：先查能力包索引，再读取命中的公开使用说明；普通任务不预读全部能力包。

## 执行边界

- 授权范围内的常规修改和相称验证可直接推进。
- 超出当前授权、关键事实不足，或涉及难以恢复的数据与正式发布时，暂停受影响动作并说明需要的决定。

## 验证与交付

- 使用目标模块已有的构建和测试命令，说明实际运行结果。
- 先报告结果，再说明关键变更、未验证项和确有必要的待决策事项。
```

## 十、与 AURA 能力包体系的关系

本规范只定义通用 AI 工作入口。AURA 的基础编码规范处理共同研发要求；具体能力由能力包索引及对应公开说明提供。项目入口只保留按任务选路的方式，不复制能力包正文，也不预设未来能力分类。
