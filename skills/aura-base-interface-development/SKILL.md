# AURA 接口契约与联调

询问如何调用本技能时，阅读[使用说明](USAGE.md)。

本技能适配 `0.1.0-draft` 基础编码规范，当前为候选技能。接口规则、模板要求和示例以规范正文为准；按任务读取，不批量加载全部示例。

跨模块任务先在[规范矩阵](references/standards/01-基础编码规范/规范矩阵.md)查触发条件，再按规则编号或主题词定位正文；矩阵只作索引，必要性与执行要求以正文为准。只读取命中的规则与示例，不整篇加载矩阵后的所有规范。

先依据本次接口类型和交付物，在下表选资料；对较长的规范先定位目录、规则 ID 或章节标题，只读取命中条款至下一条标题及必要上下文。编写模块接口文档时优先读接口文档规范的核心规则与最小结构、模板中适用的章节；接口设计细节再查接口规范对应条款，身份或租户细节再查安全规范对应条款。不为一项任务整篇加载所有规范与模板。核对项目路径或网关前缀时，只查询相关配置键及相邻必要行，不整篇输出可能含凭据的配置文件；运行行为未验证时标明待核对。

## 执行与交付

先核对需求、现有接口实现、调用方和提供方约定，再确定本次是新契约设计、模块接口文档编制、实现联调，还是存量接口审查与兼容变更。已有系统已经运行一段时间、存在历史响应封装或需要统一 `R<T>`/`PageResult<T>` 时，先使用 `aura-base-interface-review` 输出现状、证据、差异和迁移顺序；本技能负责新契约和经审查后的模块文档，不把审查结论直接当作已完成改造。按一个业务模块组织相关接口，不把每个接口机械拆成一份文件；用真实契约填模板，示例中的业务对象和结果不能照搬。涉及页面或服务内部代码时，同时应用相应开发技能。

契约设计交付接口身份、请求响应、错误、权限和变更约定；联调交付实际请求及结果、问题归属和待解决差异。只核对本次适用的正常、参数错误、认证权限、重复请求或并发等场景，明确文档、代码和运行结果是否一致。未运行的联调不得写成通过。

本技能不重定义框架状态码、响应封装或公开 API；关键字段、调用权限或兼容影响无法从现行规范、代码及约定确认时，列出待确认点，不自行发明契约。专项 SDK 用法由能力包使用技能补充。
