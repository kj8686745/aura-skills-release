# AURA 接口契约与联调

版本读 `VERSION`，规范与资料来源见 [source.json](references/source.json)。询问调用方法时才读 [USAGE.md](USAGE.md)。先核对目标模块、现有文档及真实提供方/调用方，不默认扫描全项目。

## 选择任务

| 任务 | 直接读取与执行 |
| --- | --- |
| 设计或变更接口契约 | [接口规范](references/standards/01-基础编码规范/05-接口规范体系/01-接口规范.md)命中的条款；核对调用方与兼容影响，同步模块文档 |
| 新建或更新模块接口文档 | [文档规范](references/standards/01-基础编码规范/05-接口规范体系/02-接口文档规范.md)的核心规则、最小结构和[模板](references/standards/01-基础编码规范/05-接口规范体系/03-接口文档模板.md)适用章节；先盘点现状，再填真实契约 |
| 准备联调或处理契约差异 | [生命周期指南](references/standards/01-基础编码规范/05-接口规范体系/05-接口生命周期使用指南.md)命中的阶段；核对部署路径、版本、实际请求和结果，记录差异归属 |

身份、数据表达、OpenAPI、实时事件、外部调用或具体示例命中时，再从[专项资料与执行细节](references/任务路由.md)选择对应项。只读相关条款和必要上下文；完整规范矩阵用于人工全局核查，不作为普通任务前置。

## 脚本辅助

Java/Spring MVC 模块先运行随包 [inventory-api-contracts.ps1](scripts/inventory-api-contracts.ps1)，显式传项目和模块范围，输出盘点文件后读取摘要与命中项。它提取直接映射、方法、参数绑定、返回类型及平台注解，不解析 DTO 全部字段、继承、组合注解或网关运行改写；未解析项回到源码确认，不猜测。

文档完成后运行 [check-api-document.ps1](scripts/check-api-document.ps1)，与同范围盘点核对总览、接口卡片、参数表、成功/错误示例及 OpenAPI 登记。调用参数见[脚本说明](USAGE.md#脚本调用)。脚本源码只在排错或维护时读取，`0/1/2` 分别表示请求的静态检查无阻断项、确定错误、检查不完整；静态通过不证明业务字段充分或联调通过。

## 实施与交付

按一个业务模块维护一份连续文档，优先更新已有文件；新增或变更接口契约默认同步文档，只改内部实现且契约不变时不机械生成。文档归入模块 `docs/` 并接入项目文档总入口。实现代码由对应开发技能主导，双方维护同一份契约，不重复生成。

从 Controller、请求/响应 DTO、异常映射、认证及相关网关配置提取事实，继续沿模型追踪嵌套字段与调用链。逐字段填写类型、必填/必返、空值、约束、含义和成败示例；脚本盘点不能代替此步骤。示例只参考写法，不照搬业务或接口事实。涉及配置时只读取相关键及必要行。

内外 HTTP 使用同一 `R<T>`、`CommonConstants.SUCCESS=200` 和公共分页目标契约；框架类型尚未具备时保留实现缺口，不宣称已统一。对外 OpenAPI 按 `AURA-BASE-API-026` 核对 `/openapi`、`@PlatfomApi` 与真实路径；不把 Controller 静态映射当作最终网关访问地址。

普通存量文档维护按当前模块执行；明确要求独立审查时使用可用的 `aura-backend-compliance-review`，不把项目历史较长当作强制审查前置。遇到会改变兼容、权限或业务语义的缺口时列出证据并询问，其余已明确部分继续。

交付模块文档、必要代码差异、脚本结果、待核对字段和实际联调状态。没有运行的请求不能写成成功；本技能不携带前端实现规范，也不替代专项 SDK 能力说明。
