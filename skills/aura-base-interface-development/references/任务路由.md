## 执行与交付

先核对需求、现有接口实现、调用方和提供方约定，明确本次契约、文档或联调范围。存量文档可以直接依据当前模块更新；需要迁移响应/分页时识别调用方和兼容影响，明确独立审查任务才进入审查技能。用同一份模块文档贯穿变更，不把审查结果当作改造已完成。涉及页面或服务内部代码时，由相应开发技能主导实现。

契约设计交付接口身份、请求响应、错误、权限和变更约定；联调交付实际请求及结果、问题归属和待解决差异。只核对本次适用的正常、参数错误、认证权限、重复请求或并发等场景，明确文档、代码和运行结果是否一致。未运行的联调不得写成通过。

对外 API 不另定 `OpenApiResponse` 或 `OpenPage` 作为新契约；与内部 HTTP 接口统一使用 `R<T>`、`CommonConstants.SUCCESS=200` 和同一个公共分页对象目标契约。外部原始响应按其已确认契约适配，不改变 AURA 响应码；若项目尚未提供公共分页类型，文档标明目标与实现缺口，不宣称代码已具备该类型。

本技能不重定义框架状态码、响应封装或公开 API；关键字段、调用权限或兼容影响无法从现行规范、代码及约定确认时，列出待确认点，不自行发明契约。专项 SDK 用法由能力包使用技能补充。
