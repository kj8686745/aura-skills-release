# 接口文档示例：服务间行政区划调用

> 本文是业务服务调用行政区划能力的设计示例，路径、参数、超时和版本均为示例约定，不代表提供方已经发布该契约或完成联调。调用使用客户端凭证模式，不能把用户浏览器 Token 或客户端密钥传递给前端。

## 二、公开能力与边界

调用方只使用行政区划服务公开的 HTTP 入口和响应契约，不访问提供方数据库、内部类、缓存或内部消息主题。

| 接口编号 | 能力 | 方法 | 路径 |
| --- | --- | --- | --- |
| API-AREA-SERVICE-001 | 查询行政区划 | GET | `/admin/area/{code}` |
| API-AREA-SERVICE-002 | 查询下级区域 | GET | `/admin/area/{code}/children` |

具体路径、字段和版本以提供方登记的公开契约为准；调用方不得依据服务内部 Controller 或数据库结构自行拼接。

## 接口逐项契约

### API-AREA-SERVICE-001 查询行政区划

- **请求**：`GET /admin/area/{code}`，路径参数 `code` 为必填行政区划编码；请求头包含服务身份 `Authorization: Bearer <SERVICE_ACCESS_TOKEN>` 和已登记的请求标识。
- **成功**：HTTP `200`，`data` 为单个区域公开模型，至少包含 `code` 和 `name`；不得直接返回数据库实体或内部层级字段。
- **失败**：参数格式错误使用 `400/AREA_INVALID_PARAM`；令牌无效或缺失使用 `401/AREA_UNAUTHORIZED`；Scope 不足使用 `403/AREA_FORBIDDEN`；区域不存在使用 `404/AREA_NOT_FOUND`；依赖故障使用 `500/AREA_DEPENDENCY_FAILED`。
- **调用方处理**：只有幂等查询的明确临时失败可以按第五节策略重试；`404` 不伪造默认区域，`401/403` 不通过重试绕过授权。

### API-AREA-SERVICE-002 查询下级区域

- **请求**：`GET /admin/area/{code}/children`，路径参数 `code` 为必填父级区域编码；认证、请求标识和用户/租户上下文沿用 API-AREA-SERVICE-001。
- **成功**：HTTP `200`，`data` 为区域公开模型数组；没有下级区域返回 `[]`，不返回 `null`。每项至少包含 `code`、`name` 和提供方登记的层级字段。
- **失败**：参数、认证、权限、资源不存在和依赖故障分别使用 `AREA_INVALID_PARAM`、`AREA_UNAUTHORIZED`、`AREA_FORBIDDEN`、`AREA_NOT_FOUND` 和 `AREA_DEPENDENCY_FAILED`；调用方不得把权限失败当作空数组。
- **调用方处理**：只对同一请求的幂等临时失败执行有限重试；返回空数组表示“当前区域没有下级”，不是服务不可用。

## 三、服务认证

调用方使用 OAuth2 `client_credentials` 获取服务令牌：

1. 通过安全配置读取 `app-id`、`app-secret` 和 Token 入口；
2. 使用客户端认证调用 `/admin/oauth2/token`，提交 `grant_type=client_credentials`；
3. 将返回的 `token_type` 和 `access_token` 组合为 `Authorization: Bearer <token>`；
4. 在令牌未过期期间复用令牌，过期后重新获取；
5. `app-secret` 只保存在服务端安全配置，不进入前端、日志、异常信息或接口文档示例。

Token 请求示例（不填写真实密钥）：

```http
POST /admin/oauth2/token
Authorization: Basic <BASE64(client-id:client-secret)>
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
```

业务请求示例：

```http
GET /admin/area/350100
Authorization: Bearer <SERVICE_ACCESS_TOKEN>
```

服务间调用不使用浏览器用户 Token，也不把用户身份伪装成服务身份；如业务需要传递用户或租户上下文，必须使用已经登记的上下文传递方式。

## 四、请求和响应契约

请求参数：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| path | `code` | string | 是 | 行政区划编码，按提供方定义传递 |
| header | `Authorization` | string | 是 | 服务访问令牌 |
| header | 请求标识 | string | 按项目约定 | 用于调用链关联 |

统一 HTTP 响应使用 `R<T>`：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "code": "350100",
    "name": "福州市"
  },
  "ok": true
}
```

调用方必须先判断 `code`，再读取 `data`；`ok` 是只读兼容字段，不能替代错误处理。

API-AREA-SERVICE-002 的成功响应示例：

```json
{
  "code": 200,
  "msg": "success",
  "data": [
    { "code": "350102", "name": "鼓楼区" },
    { "code": "350103", "name": "台江区" }
  ],
  "ok": true
}
```

## 五、超时、重试、熔断与失败归属

| 项目 | 约定 |
| --- | --- |
| 连接超时 | 示例值 2 秒；实际项目须登记生效配置 |
| 读取超时 | 示例值 5 秒；实际项目须登记生效配置，不能无限等待 |
| 可重试错误 | 连接失败、明确的临时 5xx 或限流，且请求为幂等查询 |
| 不可重试错误 | 401/403、参数错误、资源不存在和业务拒绝 |
| 重试次数 | 示例为最多 2 次；实际项目须登记生效配置 |
| 退避方式 | 指数退避并设置最大次数和最大等待时间 |
| 熔断 | 连续依赖失败达到阈值后短暂失败，避免线程堆积 |
| 降级 | 返回明确的依赖不可用结果；不得伪造行政区划数据 |
| 最终失败归属 | 调用方负责业务兜底和用户反馈；提供方负责服务错误和契约稳定 |

查询接口为幂等读操作，允许在明确边界内重试；不能对未知是否已生效的写操作套用同一策略。

## 六、联调场景

| 场景 | 预期结果 |
| --- | --- |
| 有效客户端凭证 | 获取服务令牌并正常查询 |
| 客户端凭证错误 | Token 申请失败，不重试业务请求 |
| 令牌过期 | 获取新令牌后重新调用一次 |
| 无权限 Scope | 返回权限错误，记录调用方处理，不绕过授权 |
| 区划不存在 | 返回资源不存在，调用方不伪造默认区域 |
| 短暂 5xx | 幂等查询按统一重试策略处理 |
| 连续依赖失败 | 熔断并返回依赖不可用状态 |
| 超时 | 停止等待，按失败归属处理，不无限重试 |
| 恢复 | 熔断窗口结束后允许探测请求恢复 |
| 密钥检查 | 日志、异常和文档不出现客户端密钥或完整 Token |
