## 规则正文

### AURA-BASE-FE-009：异步提交必须区分受理与完成

**必要性**：必须

区分提交中、已受理、执行中和最终结果；任务编号不表示完成。超时或断连后无法确认副作用时保留“结果未知”，按业务接口的查询或同键幂等契约确认，不自动产生新请求标识。

**为什么需要**：异步执行可能在受理后失败，响应丢失也不代表操作未执行。

**正确写法**：

导入返回 taskId 后显示受理；查询任务状态后分别呈现完成、部分成功、失败或取消；状态查询失败保留上次已确认结果。

**错误写法**：返回任务编号立即提示导入成功；超时后换幂等键自动重建。

**判断要点 / 验证方式**：验证受理后失败、响应丢失、部分成功、刷新恢复和未知状态；确认业务任务接口、幂等键和恢复入口。

**例外与人工确认**：同步返回最终结果的接口不需要额外任务状态；不虚构框架固定 taskId 或幂等字段。

### AURA-BASE-FE-013：提交操作必须防止重复触发

**必要性**：必须

所有业务表单使用 `@fxft/aura-web-kit/hooks/form` 的 `useForm`，经 `validateForm` 成功后才设置提交中状态；提交期间禁用按钮，重复触发入口继续检查状态。重置用 `resetForm`，回填后用 `clearFormValidate`，不直接调用实例的对应方法。

**为什么需要**：公共表单生命周期统一处理挂载与历史校验，防重也需覆盖快速点击和校验等待。

**正确写法**：

```ts
import { useForm } from "@fxft/aura-web-kit/hooks/form";
const { validateForm, resetForm, clearFormValidate } = useForm();
const validating = ref(false);
const submitting = ref(false);
async function onSubmit() {
  if (validating.value || submitting.value) return;
  validating.value = true;
  try {
    if (!(await validateForm(dataFormRef))) return;
    submitting.value = true;
    await saveOrder({ ...form }); // 真实业务 API，同步完成后才关闭
    visible.value = false;
    emit("refresh");
  } finally { validating.value = false; submitting.value = false; }
}
```

失败反馈、结果未知与恢复按 FE-009、FE-016 和具体接口契约处理；完整 UI 见[弹窗表单](页面模式/弹窗表单.md)。

**错误写法**：`formRef.value.validate/resetFields/clearValidate`；只给按钮加 loading 而事件仍能重复发送。

**判断要点 / 验证方式**：空字段不发送请求；连续点击只发送一次；失败保留输入；已受理或未知结果不会盲目重建。

**例外与人工确认**：这里只核对前端防重行为，不推断接口幂等性；异步任务何时允许重新提交由业务契约决定。

### AURA-BASE-FE-014：并发请求必须处理竞态和过期响应

**必要性**：必须

快速筛选、切换记录和反复打开弹窗时，用取消、请求序号或目标校验约束响应归属；旧响应不能覆盖数据、错误或新请求的 loading。

**为什么需要**：发起顺序与完成顺序可能不同。

**正确写法**：

请求捕获当前目标和序号；只有当前序号可更新详情和结束 loading；关闭或换目标使旧序号失效。

**错误写法**：任何响应返回都写列表，旧请求 finally 关闭新请求的 loading。

**判断要点 / 验证方式**：延迟旧请求、快速切换 ID 和查询，确认只展示最新目标；卸载后不继续更新业务实例。

**例外与人工确认**：无。

### AURA-BASE-FE-015：列表和大数据展示必须有分页或虚拟化边界

**必要性**：必须

标准列表复用项目绑定的 `useTable` 与 `AuraPagination`，查询回第一页用 `getDataList()`，保留当前页刷新用 `getDataList(false)`；表格绑定 `tableStyle`，按列 prop 配置 `tableAlign`。不可预测的大数据使用分页、分段或虚拟化。

**为什么需要**：复用分页、排序和列样式可保持协议一致并控制浏览器负载。

**正确写法**：

```ts
import { useTable } from "/@/config/aura/index";
import type { BasicTableProps } from "@fxft/aura-web-kit/hooks/table";
const state = reactive<BasicTableProps>({ pageList: getOrderPage, queryForm: {}, tableAlign: { name: "left", amount: "right" } });
const { getDataList, currentChangeHandle, sizeChangeHandle, tableStyle } = useTable(state);
```

**错误写法**：标准列表重复手写分页；默认请求全表；每页重复实现表头颜色与对齐回调。

**判断要点 / 验证方式**：验证搜索、重置、分页、排序、删除刷新和大数据；selection 宽 40，index 宽 60（长标题可 80），数据列保留溢出提示。

**例外与人工确认**：规模明确且有上限的小数据可关闭分页；关联短表可直接请求，仍保持加载、错误和容量边界。

### AURA-BASE-FE-016：页面必须提供结果反馈与恢复入口

**必要性**：必须

区分空数据、加载失败、业务拒绝、无权限与会话失效。只读查询在所属区域提供重试；变更操作使用项目绑定消息服务。登录失效交给统一处理器；写操作结果未知按 FE-009 恢复。

**为什么需要**：用户需要从真实结果判断下一步操作。

**正确写法**：

请求失败显示局部 i18n 错误及重试；接口响应明确保存成功后才关闭弹窗和刷新父列表。

**错误写法**：失败后清空表单并显示成功；字典查询失败打断整页；顶部与空态重复同一主操作。

**判断要点 / 验证方式**：验证失败后保留输入、局部重试、403、认证失效和成功后刷新；不以 Toast 出现判断业务完成。

**例外与人工确认**：无。

### AURA-BASE-FE-017：文件上传下载必须受控并反馈进度

**必要性**：必须

文件操作使用 Aura 上传组件或项目绑定下载服务，限制类型、大小、数量与并发，处理取消、失败和进度。接口返回的相对文件地址通过项目文件工具补齐 API 前缀；完整 URL、blob/data 保持其协议语义。

**为什么需要**：文件服务依赖授权、请求和资源上下文，不能由页面随意拼接地址。

**正确写法**：

上传复用 `AuraUpload` 系列；下载复用 `/@/config/aura/download`；接口文件使用`/@/config/aura/browser` 的 `getFileFullUrl` 绑定入口。

**错误写法**：页面拼 `VITE_API_URL + record.path`，或把接口文件误当提供方 public 资源。

**判断要点 / 验证方式**：验证非法文件、超限、断网、取消、过期授权和 blob URL 释放；按安装版本核对文件工具导出。

**例外与人工确认**：无。

### AURA-BASE-FE-018：时间、金额和枚举展示必须使用公共转换

**必要性**：必须

日期时间使用公共工具及 Day.js，用户文案走 `t/$t`；枚举和 `@dictKey` 按字典语义展示。筛选/编辑控件配置 i18n placeholder，无占位语义时用 `data-placeholder-exempt` 和相邻原因注释。

**为什么需要**：公共转换保持时区、语言、金额和状态含义一致。

**正确写法**：

使用 `@fxft/aura-web-kit/utils/date`，字典展示使用 Aura 组件；已有 `common` 文案复用，中英文 key 同步。

**错误写法**：手工加八小时；硬编码枚举选项；在 `.vue/.ts` 直接写用户可见中文。

**判断要点 / 验证方式**：验证语言切换、空值、未知枚举和时间输入；构建前核对文案、placeholder、字典映射和中英文 key，并执行项目已有 ESLint 与构建入口。

**例外与人工确认**：注释、接口/字典返回值、接口错误、Mock 数据和 i18n 文件可含中文；真实名称字段无需转字典。
