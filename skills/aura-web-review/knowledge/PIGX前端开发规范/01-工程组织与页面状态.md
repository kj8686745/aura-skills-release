## 规则正文

### AURA-BASE-FE-001：按职责和领域组织

**必要性**：必须

当前框架使用模板既有目录：业务接口和接口类型放在 `src/api/<业务域>/`，路由在 `src/router/`，项目实例绑定在 `src/config/aura/`，页面在 `src/views/<业务域>/<页面>/index.vue`。不新增 `app/`、`services/` 替代这些入口。完整顶层目录统一见 BASE-01 的当前模板目录树。

**为什么需要**：目录必须与实际模板入口一致，才能复用代码生成、动态路由和框架绑定。

**正确写法**：

```text
src/api/order/index.ts
src/views/order/list/index.vue
src/views/order/list/components/order-form.vue
src/views/order/list/useOrderQuery.ts
src/config/aura/request.ts
```

**错误写法**：在当前框架页面目录另建请求内核，或为统一形式把既有路由移入 `app/router`。

**判断要点 / 验证方式**：核对模板目录、API 导入和路由解析位置；新增文件能从业务域定位，不要求批量迁移已有文件。

**例外与人工确认**：无。

所有手写 Vue、TS 和 CSS/SCSS 的保留、拆分、放置及复用按[文件组织与职责拆分](文件组织与职责拆分.md)判断；新增和功能改造按职责选择最小结构，纯注释不触发结构重构。

### AURA-BASE-FE-002：领域聚合优先

**必要性**：必须

领域通过 `api/<业务域>` 与 `views/<业务域>` 保持可发现的关联；少量页面私有 TS/SCSS 可同级就近放，多组职责才按需分目录；同模块共用提升到模块，项目跨模块共用才进入 `src/hooks/`、`src/utils/` 等公共层，公共层不反向依赖页面。跨项目 TS 能力先查 `aura-web-kit` 公开入口，通用 Aura UI 归属 `aura-ui`，项目保留实例绑定与业务规则。

**为什么需要**：领域关联不要求把接口搬进页面；公共实现单处维护可避免多个综合端产生差异。

**正确写法**：

`api/order/index.ts` 定义请求与类型，`views/order/list` 组合订单页面；通用表单校验从 `@fxft/aura-web-kit/hooks/form` 导入。

**错误写法**：按页面复制通用工具、请求内核、联邦算法或主题实现。

**判断要点 / 验证方式**：检查同领域文件命名和导入路径；抽公共能力前查[能力清单](aura-web-kit能力清单与接入规范.md)。

**例外与人工确认**：无。

### AURA-BASE-FE-003：页面负责组合，组件负责明确职责

**必要性**：必须

路由入口使用 `index.vue`，默认保留完整 SFC、简单本地状态、计算与页面编排。组件、Hook、普通 TS 与样式的保留、内部整理、提取及复用层级统一按[文件组织与职责拆分](文件组织与职责拆分.md)，正反例和审查依据也以该正文为准。Dialog/Drawer 与普通区域遵循同一原则，不因类型、数量或行数直接要求拆分。已提取的页面私有 Vue 放同路径 `components/`，少量私有 TS/SCSS 可同级。

**为什么需要**：通过清楚的职责和所有权降低维护成本，避免职责混杂，也避免仅为缩短文件产生额外协调。

**正确写法**：内聚且归属清楚的流程保留；独立职责混杂且提取有收益时，将模板、私有状态、行为和样式一起迁移，通过业务输入输出协调。组件 ref 在脚本具名方法中通过可选链访问。

```ts
function handleEdit(id: string) { orderFormRef.value?.openDialog(id); }
```

**错误写法**：仅凭弹窗数量要求提取；只搬模板、区域私有实现仍散落父页并传整页 state；模板直接绑定 `@click="orderFormRef.openDialog()"`。

**判断要点 / 验证方式**：沿状态和资源所有者、依赖与调用链核对实际收益；结构评估和完整结构任务同时检查入口内未提取职责及已有子组件，合理保留也计为完成。纯展示组件的维护与验证收益按统一正文判断，不以私有状态或请求为拆分前提。同时检查组件 ref 初次未挂载时的渲染与反复打开。实际提取后按影响验证首次挂载、打开/关闭、换目标及清理行为。

**例外与人工确认**：简单展示、轻量交互以及同一流程内拆分无收益的内容允许保留；不同合理组织方式只给建议，不阻断交付。未查清关系时记未证实，不凭外观判偏差。共用组件提升到最小共同范围，项目跨模块实际复用才进入 `src/components`。

### AURA-BASE-FE-004：状态来源单一

**必要性**：必须

查询、分页、选择、表单和共享状态各有一个真实来源与明确所有者，私有状态不因拆文件进入 Store；Hook 默认每次调用创建独立状态，共享实例须使用明确的既有 Store 或缓存机制，避免模块级可变变量无意共享。弹窗专属数据在实际打开时加载，不在页面或组件挂载阶段提前请求。已提取组件持有其私有状态，通过公开打开流程加载，父页面只传 ID、已选 ID 和操作约束；合理内联时由所属页面持有该交互状态并在具名打开处理中加载，不为公开方法而强制拆组件。

**为什么需要**：避免父子组件维护过期副本，也减少未打开弹窗的请求。

**正确写法**：

父页面调用 `formRef.value?.openDialog(id)`，弹窗按 ID 获取真实详情并初始化候选项，保存后通知父页面刷新。

**错误写法**：父页面在 `onMounted` 预加载所有弹窗数据，或把列表行快照当作完整详情。

**判断要点 / 验证方式**：首次进入页面无弹窗专属请求；打开、换目标和再次打开均读取正确数据；快速切换不被旧响应覆盖。

**例外与人工确认**：主页面自身使用的数据仍按其生命周期加载；保存后只刷新仍打开且需要刷新的关联弹窗。

### AURA-BASE-FE-005：页面状态真实表达

**必要性**：必须

页面按真实请求表达加载、成功、空、错误、无权限和提交中等适用状态。只读加载失败使用所属区域的错误态与重试，不弹全局错误消息；顶部已有主操作时，空态不重复同一按钮。

**为什么需要**：空数据与加载失败含义不同，局部状态也能防止一个区域打断整页。

**正确写法**：

字典加载失败只影响字典区域，展示本地化错误提示与重试；主列表保留自己的状态。

**错误写法**：catch 后把失败显示成“无数据”，或详情查询失败连续弹全局错误消息。

**判断要点 / 验证方式**：分别验证成功、空数据、慢请求、403、断网和局部重试；状态文案走 i18n。

**例外与人工确认**：无。
