## 规则正文

### AURA-BASE-FE-001：按职责和领域组织

**必要性**：必须

当前框架使用模板既有目录：业务接口和接口类型放在 `src/api/<业务域>/`，路由在 `src/router/`，项目实例绑定在 `src/config/aura/`，页面在 `src/views/<业务域>/<页面>/index.vue`。不新增 `app/`、`services/` 替代这些入口。完整顶层目录统一见 BASE-01 的当前模板目录树。

**为什么需要**：目录必须与实际模板入口一致，才能复用代码生成、动态路由和框架绑定。

**正确写法**：

```text
src/api/order/index.ts
src/views/order/list/index.vue
src/views/order/list/components/order-form.vue
src/hooks/order/useOrderQuery.ts
src/config/aura/request.ts
```

**错误写法**：在当前框架页面目录另建请求内核，或为统一形式把既有路由移入 `app/router`。

**判断要点 / 验证方式**：核对模板目录、API 导入和路由解析位置；新增文件能从业务域定位，不要求批量迁移已有文件。

**例外与人工确认**：无。

### AURA-BASE-FE-002：领域聚合优先

**必要性**：必须

领域通过 `api/<业务域>` 与 `views/<业务域>` 保持可发现的关联；页面私有逻辑留在页面目录。跨项目 TS 能力先查 `aura-web-kit` 公开入口，通用 Aura UI 归属 `aura-ui`，项目保留实例绑定与业务规则。

**为什么需要**：领域关联不要求把接口搬进页面；公共实现单处维护可避免多个综合端产生差异。

**正确写法**：

`api/order/index.ts` 定义请求与类型，`views/order/list` 组合订单页面；通用表单校验从 `@fxft/aura-web-kit/hooks/form` 导入。

**错误写法**：按页面复制通用工具、请求内核、联邦算法或主题实现。

**判断要点 / 验证方式**：检查同领域文件命名和导入路径；抽公共能力前查[能力清单](aura-web-kit能力清单与接入规范.md)。

**例外与人工确认**：无。

### AURA-BASE-FE-003：页面负责组合，组件负责明确职责

**必要性**：必须

路由入口仅保留 `index.vue`；私有表单、详情、抽屉、弹窗和嵌套业务视图放在同路径 `components/`。两个及以上业务 Dialog/Drawer，或单个弹窗具有独立列表、表单、请求与提交状态时，编码前拆成私有组件。组件 ref 在脚本具名方法中用可选链访问，模板不直接绑定 ref 成员。

**为什么需要**：页面编排与弹窗生命周期分开后，挂载时序和独立请求状态更容易控制。

**正确写法**：

```ts
const OrderForm = defineAsyncComponent(() => import("./components/order-form.vue"));
const orderFormRef = ref<InstanceType<typeof OrderForm>>();
function handleEdit(id: string) { orderFormRef.value?.openDialog(id); }
```

```vue
<order-form ref="orderFormRef" @refresh="getDataList" />
<el-button @click="handleEdit(scope.row.id)">{{ $t("common.editBtn") }}</el-button>
```

**错误写法**：`@click="orderFormRef.openDialog()"`；多个独立业务弹窗全部内联在路由页。

**判断要点 / 验证方式**：检查 ref 初次未挂载时的渲染、首次打开和反复打开；父页面只保留主查询与编排。

**例外与人工确认**：字段少、无独立请求的单一轻量弹窗可以内联；稳定跨业务复用后才进入 `src/components`。

### AURA-BASE-FE-004：状态来源单一

**必要性**：必须

查询、分页、选择、表单和共享状态各有一个真实来源。父页面向弹窗传 ID、已选 ID 和本次操作约束；弹窗专属详情、候选项和列表在公开 `openDialog/openDrawer` 中加载，不由父页面或挂载阶段提前请求。

**为什么需要**：避免父子组件维护过期副本，也减少未打开弹窗的请求。

**正确写法**：

父页面调用 `formRef.value?.openDialog(id)`，弹窗按 ID 获取真实详情并初始化候选项，保存后通知父页面刷新。

**错误写法**：父页面在 `onMounted` 预加载所有弹窗数据，或把列表行快照当作完整详情。

**判断要点 / 验证方式**：首次进入页面无弹窗专属请求；打开、换目标和再次打开均读取正确数据；快速切换不被旧响应覆盖。

**例外与人工确认**：主页面自身使用的数据仍按其生命周期加载；保存后只刷新仍打开且需要刷新的关联弹窗。

### AURA-BASE-FE-005：页面状态真实表达

**必要性**：必须

页面按真实请求表达加载、成功、空、错误、无权限和提交中等适用状态。只读加载失败使用所属区域的错误态与重试，不弹全局错误消息；顶部已有主操作时，空态不重复同一按钮。

**为什么需要**：空数据与加载失败含义不同，局部状态也能防止一个区域打断整页。

**正确写法**：

字典加载失败只影响字典区域，展示本地化错误提示与重试；主列表保留自己的状态。

**错误写法**：catch 后把失败显示成“无数据”，或详情查询失败连续弹全局错误消息。

**判断要点 / 验证方式**：分别验证成功、空数据、慢请求、403、断网和局部重试；状态文案走 i18n。

**例外与人工确认**：无。
