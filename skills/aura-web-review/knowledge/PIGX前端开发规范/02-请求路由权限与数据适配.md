## 规则正文

### AURA-BASE-FE-006：请求集中封装

**必要性**：必须

业务 API 在 `src/api/<业务域>/` 使用 `/@/config/aura/request` 默认导出；统一请求、认证异常、公共头、参数序列化和存储隔离属于框架保护区。页面不创建 Axios、不拼 Token/租户头、不自行退出登录。

**为什么需要**：复用项目懒加载入口与认证链路，防止远程页面出现第二套请求行为。

**正确写法**：

```ts
import request from "/@/config/aura/request";
export interface OrderPageQuery { current: number; size: number; keyword?: string }
export const getOrderPage = (params: OrderPageQuery) =>
  request({ url: "/order/page", method: "get", params });
```

**错误写法**：`axios.create(...)`；新增 `/@/utils/request` 兼容 alias；在组件内拼接内部服务地址。

**判断要点 / 验证方式**：搜索页面中的 axios、内部地址和认证处理；核对真实响应包装、错误和公共头。

**例外与人工确认**：无。

### AURA-BASE-FE-007：前端可见性与权限上下文边界

**必要性**：必须

模板中的受限按钮、入口与操作使用项目既有 `v-auth` 指令及其已注册的并集/交集变体，不直接调用 `permissions.has/any/all`。权限码统一定义为具名常量，同一业务的工具栏、行内按钮、空态等多个入口复用同一码；不为同一动作另造权限。

脚本在 `setup()` 中从公开入口 `@fxft/aura-web-kit/hooks/permissions` 取得宿主 `usePermissions()`；受限的打开、查询、保存和重置等具名入口在初始化、状态变更或请求前再次校验权限，防止绕过模板直接调用。无权限或权限未就绪时不执行相应动作，不自建空权限上下文。只恢复不受限本地展示的重置不因名称机械设限；若重置触发受限查询则沿查询权限兜底。

只含受限操作的列、footer、下拉触发器、批量区及专用选择列按全部子操作权限并集控制，避免空壳。普通 DOM 分组使用项目实际支持的权限指令；组件注册、插槽结构需条件控制时在脚本派生布尔值，模板使用该状态。不得把单权限 `v-auth` 当作接受权限数组的并集指令。包含查看、刷新等不受限操作的混合容器保留这些操作，只控制受限分组。

`v-auth` 只控制 DOM 呈现（实现可能隐藏或移除节点），不能阻止组件 `setup`、注册、挂载钩子或监听中的请求。Tab、Drawer 等需阻止无权初始化的容器，先在脚本筛选可挂载项、校正当前选中项或约束打开状态，模板再使用派生结构/状态和入口指令；不能把 `ElTabPane` 的 `v-if` 简单换成 `v-auth` 后仍注册无权页签或请求。权限撤回后受控状态与请求入口也须失效。

保留行状态、流程阶段等业务 `v-if` 条件；只维护本次授权范围，不全项目机械替换，也不要求所有不触发受限动作的展示都添加 `v-auth`。这里只检查前端可见性、初始化和权限上下文；接口实际授权不在本技能结论范围。

**为什么需要**：模板可见性、组件初始化与脚本动作是不同边界，单纯隐藏按钮不能阻止无权初始化和调用。

**正确写法**（订单编辑入口片段；具体请求与 ref 沿项目真实契约）：

```vue
<el-table-column v-if="canOperateOrder" :label="$t('common.action')">
  <template #default="scope">
    <el-button v-auth="ORDER_PERMISSION.EDIT" @click="handleEditOrder(scope.row.id)">
      {{ $t('common.editBtn') }}
    </el-button>
  </template>
</el-table-column>

<script setup lang="ts">
import { computed } from "vue";
import { usePermissions } from "@fxft/aura-web-kit/hooks/permissions";
const ORDER_PERMISSION = { EDIT: "order_edit" } as const;
const permissions = usePermissions();
const canOperateOrder = computed(() => permissions.has(ORDER_PERMISSION.EDIT));
function handleEditOrder(id: string) {
  if (!permissions.has(ORDER_PERMISSION.EDIT)) return;
  // 权限通过后调用项目已有的打开方法，并在实际保存入口再次校验。
}
</script>
```

**错误写法**：模板直接调用权限方法；按钮有指令但公开打开/查询入口无兜底；只隐藏 Tab DOM 却仍初始化请求；同一业务入口重复写散落权限码；删除业务条件；用 URL 参数模拟管理员权限。

**判断要点 / 验证方式**：覆盖无权限、仅一项权限、未就绪、权限恢复及撤回；核对可挂载列表、选中项、打开状态和具名方法。无权限时对应组件不初始化、不请求，直接调用受限方法不产生状态变更或请求；有权限时原业务条件及正常流程有效；接口实际授权不在本技能结论范围。

**例外与人工确认**：指令名称、并集/交集语义及组件指令适用性以当前项目注册实现为准；只读展示与非权限业务条件不机械改造。

### AURA-BASE-FE-008：路由来源明确

**必要性**：必须

`staticRoutes` 承载登录/OAuth/401/404；`dynamicRoutes` 承载本地补充页；正式业务入口由接口菜单控制。联邦菜单仍走接口菜单，组件串为 `/<remoteName>/<expose路径>?type=moduleFederation`，开启“带参”。不创建第二套路由器、守卫或主布局。

**为什么需要**：菜单、刷新和权限恢复需要使用同一条框架链路。

**正确写法**：

```text
remoteName: aura-order-web
expose: ./views/order/list/index.vue
componentPath: /aura-order-web/views/order/list/index.vue?type=moduleFederation
```

**错误写法**：菜单首段写 `remoteEntryName`；正式菜单接管后保留临时重复路由。

**判断要点 / 验证方式**：核对菜单返回字段、expose、首次访问、刷新和无权限访问；细节见[路由与菜单](路由与菜单规范.md)。

**例外与人工确认**：快速验证可临时加入既有 `dynamicRoutes`，正式前端运行验证后移除被菜单接管的条目。

### AURA-BASE-FE-010：接口数据必须经过领域适配

**必要性**：必须

业务 API 明确请求和响应类型，按契约处理包装、公开字段、空值、枚举和错误。页面只消费公开接口字段和响应，不依赖未公开内部模型；公共分页保持 `useTable` 的 `current/size` 请求与 `records/total` 响应契约。实际接口协议不同的，在项目已有 API 适配边界按真实契约明确转换，页面和公共 Hook 使用统一分页结构，不增加多字段兜底。

**为什么需要**：转换边界需要稳定业务语义，同时兼容公共 Hook 的真实协议。

**正确写法**：

`getOrderPage` 接收业务查询类型并返回已约定分页响应；仅在字段或语义不一致时在 `api/order` 内转换。

**错误写法**：每个页面自行猜测 `response.data.data`，或将标准分页改成 `items/pageSize` 后直接交给 `useTable`。

**判断要点 / 验证方式**：用真实响应核对分页、未知枚举、空值和错误语义；改动字段只影响适配入口。

**例外与人工确认**：公开接口类型与业务类型一致时可以直接复用，不强制增加一对一 Adapter 文件。

### AURA-BASE-FE-011：Mock 有明确边界

**必要性**：必须

Mock 只用于页面开发、演示或局部验证；沿用项目已有开发代理或 Mock 机制，不修改请求内核。真实前端运行验证与 Mock 结果分别记录，不把 Mock 作为契约、权限或生产证据。

**为什么需要**：模拟数据无法验证真实授权和接口行为。

**正确写法**：

业务 API 始终使用 `/@/config/aura/request`；开发代理切换模拟服务，在已授权的真实接口环境核对页面 Network。

**错误写法**：按 hostname 在页面返回假数据，或为 Mock 复制 `services/request` 内核。

**判断要点 / 验证方式**：确认数据来源、生产禁用条件、错误覆盖与真实接口结果；检查产物不意外包含模拟数据。

**例外与人工确认**：真实接口环境不可用时继续前端静态审查，但真实前端运行验证记录为未验证。

### AURA-BASE-FE-012：页面展示模型与领域模型分离

**必要性**：必须

展示转换保持在页面边界，不将格式化文案、选择状态和组件默认值写回领域数据。根据 API/OpenAPI、TypeScript 类型中的枚举、`@dictKey` 及真实业务契约确认字典关联，建立“原始 code → 字典 options → 筛选/表格/详情/表单”的映射；业务判断与请求提交保留原始 code。字典展示必须使用 Aura 字典组件，组件选型取决于业务语义，不能只按是否位于表格判断。

**为什么需要**：切换语言和展示方式不应改变业务判断或请求模型；接口名称快照不能替代当前字典语义，标签也不应破坏连续描述的阅读与排版。

**正确写法**：

- 状态、结果、严重级别等独立分类标识优先使用 `AuraDictTag`，传入原始 code 和相应字典 `options`。
- 连续描述、规则摘要、句内枚举与行内交互提示可使用 `AuraDictText`，即使位于表格内。例如触发规则摘要“离开区域 · 持续 · 时长”中的字典片段使用 Text，并保持原有行内排版；相邻独立状态列仍按分类标识使用 Tag。非表格纯文本详情也可使用 Text。
- 筛选和表单继续按真实选择契约使用 `AuraDictSelect` 或项目字典选项，不能套用展示组件的匹配规则。
- 开关内部的 `active/inactive` 交互文案可保留 `AuraDictText`，沿用所在控件的字号、颜色和行内排版，不强行嵌套 `AuraDictTag`；此例外不适用于旁边独立的状态展示列。

**错误写法**：直接绑定 `statusName/typeName` 等字典名称快照，或通过 `getLabel`、`map/find/switch`、三元映射、手写 `el-tag` 代替字典组件；用名称文本判断业务状态；仅因位于表格就把复合规则摘要的 Text 全部替换为 Tag；页面硬编码选项伪装字典。Mock 可提供契约对应的字典选项。

**判断要点 / 验证方式**：类型保留 `/** @dictKey <key> */`；沿“接口 code + 字典关联 → 表格列/私有组件/可配置或动态列 → 最终组件渲染”逐项核对原始值、options 来源与真实调用，覆盖主列表、嵌套/弹窗表格和历史记录；追踪列配置的 formatter、slot 或 render 分支，确认该位置是独立分类标识还是连续描述，再判断 Tag/Text 是否合适。不能只搜索组件名或以零扫描命中判通过。结合实际范围检查未知字典值、中英文切换和原值提交；静态检查无法确认的动态链路保留缺证，不宣称静态绝对识别。

**例外与人工确认**：没有字典关联的真实实体名称、物模型事件名称可直接展示，不凭 `*Name` 后缀机械替换。数字单位格式化、状态机/权限等非展示编码判断不受展示禁令影响；简单展示转换不要求独立 Presenter。组件 Props、选项字段和公开能力以实际依赖声明及实现为准，不虚构接口或为通过检查自行升级依赖。
