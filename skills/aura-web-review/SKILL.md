# AURA 前端代码审查

当前版本：`0.1.0`。

只读目标前端项目的源码、配置、依赖声明与已有产物，审查页面、组件及前端运行链路。先确认 Vue 3 + Vite 和 Aura 多文件证据，识别规则见[取证与报告](references/取证与报告.md#项目识别)。已有 Aura 专有线索的 IncompleteCandidate 在明确规范审查任务中使用 `-ReviewCandidate` 盘点并按最新规范报告缺项；普通 Vue/Vite 或只有单一联邦插件的项目不接管。接口仅核对前端调用与消费公开契约，不扩展到其他领域实现。随包示例仅供判断，不授权安装、修改配置或开发。

## 入口与依据

首次调用说明审查范围，已有项目位置和任务时直接推进。项目全部适用对象为默认范围；用户限定模块或变更时遵从限定，必要调用方和配置仅作判定上下文。用法问答才读 [USAGE.md](USAGE.md)。

先读[审查路由](references/审查路由.md)，按任务读取 `knowledge/PIGX前端开发规范/` 中命中的文件。沿用现有前端技能的知识库组织；规则以随包同版正文为准，证据以目标源码、依赖、声明、配置与运行结果为准。二者冲突时明确版本与适用条件，不能让项目已有写法代替规范。

27 条 FE 规则及必要性见[逐规则路由](references/rules.json)，来源与变更状态见[来源记录](references/source.json)。运行只读随包知识；Git 来源字段仅供维护追溯，不要求联网拉仓库。

`aura-ui` 本轮明确排除，单列范围说明，不计作未证实，也不拖累已纳入子项；`ui-plus` 正常纳入，单独核对实际依赖、公开导出、resolver、地图和视频调用及证据，未使用须有依据才判不适用。FE-025 保留原编号，在矩阵说明本轮纳入 ui-plus 子项。公共能力摘要必须分别列 aura-ui 与 ui-plus 两行，不能合并。能力包建设暂缓。

## 连续工作流

1. **冻结与盘点**：核对 Git 提交、未提交差异、审查范围和规范来源。运行 `scripts/Review-Frontend.ps1 -Action Collect -ProjectRoot <项目>`；Aura 候选明确审查时加 `-ReviewCandidate`，限定范围使用 `-Scope`。读取返回的 `reportDirectory` 写六报告。脚本仅提供摘要和候选，Agent 补充未涵盖的入口、配置和资产。
2. **确认框架与适用性**：核对 package.json、锁文件、实际安装声明、Vite 和 config/aura。统一按最新基线 MF Vite 1.23.5、enhanced 2.9.2、web-kit 1.9.0、TS 5.9.3、ESLint 8.57.1 / typescript-eslint 8.46.1 检查，不增加旧版适配。实际版本或配置缺项据规范和源码确认偏差；仅真正无法取得证据的部分保留未证实。
3. **逐规则取证**：按路由读取页面、组件、请求、Store、权限、配置和相邻调用方。每条规则分别填写纳入对象、已检查对象、未检查对象、排除依据及证据。候选无命中不能判通过；直接请求可能位于允许的适配层，原生表单方法可能处于公共封装内部，需要追踪调用链。
4. **归并与判定**：由 Agent 根据实际取证编写报告，为证据、候选和发现分配稳定 E/C/F 编号。候选判为确认偏差、排除或待补证，规则判为通过、偏差、未证实或不适用。确认偏差必须有原规范要求、实际行为、位置、影响、证据、整改建议及关闭条件；纯建议不计入偏差。不要求填写机器判定 JSON。
5. **必要补证**：只执行项目已有且符合授权范围的检查命令。先检查 scripts 副作用；不运行带 --fix/--write 的格式化或 lint，不安装依赖、不修改锁文件。构建产物使用约定目录或隔离副本。无浏览器、依赖、业务材料或命令失败时记缺口，继续其余审查，不修改项目以掩盖失败。
6. **交付与复核**：Agent 按原模板直接编写六份 Markdown，逐规则核对状态、范围、证据和统计；可运行 `scripts/Review-Frontend.ps1 -Action Check -ReportDirectory <结果包>` 辅助检查结构。交付前复核被审版本及资产增删改，必要时在新目录再次盘点并对比；变化影响的证据重新获取，旧证据保留原版本。执行状态与项目质量分别说明。

进度消息不作为逐阶段确认节点。项目不可定位或关键边界确需用户决定时集中询问；普通环境缺口不暂停其余工作。

正常审查应连续完成全部可静态核对项，不能以大量“尚未检查”作为最终交付。未证实只留真实的运行条件或必要材料缺口，明确补证办法；尚未完成的过程包只能标部分完成。用户限定抽查时如实说明范围。

## 原报告结构

必须遵循[原审查结果包模板](references/审查结果包模板.md)，保留六个文件名、报告卡片字段、状态及统计口径：

默认目录为 `<ProjectRoot>/审查结果包-项目名-提交短号-日期/`，已有目录追加序号不覆盖；无 Git 用可取得指纹/时间代替短号。脚本可省略 `-OutputDirectory` 自动创建该包的 `证据/`，返回 `reportDirectory`；用户显式指定输出优先。项目内仅允许专用结果包目录，全部结果包及其 JSON 自动排除出盘点。不得因此改源码、lock、env 或 gitignore。

`01` 第 5 节必须用中文对照表解释“规则中文名称 + ID、规范要求、实际检查情况、结论/缺证分类、证据位置及补法”；`02` 首列包含中文名称，编号不能代替解释。确认偏差卡片继续保留要求、实际、影响和证据。

```text
审查结果包-项目简称-提交短号-日期/
├─ 00-结果包说明.md
├─ 01-审查报告.md
├─ 02-规则核查矩阵.md
├─ 03-证据与执行记录.md
├─ 04-整改与复核清单.md
├─ 05-扫描候选与判定.md
└─ 证据/
```

脚本接口、逐规则取证、报告核对及复核方式见[取证与报告](references/取证与报告.md)。脚本沿用 `.ps1` 形式，支持 PowerShell 5.1/7；运行环境缺失时 Agent 直接完成可执行审查并记录辅助脚本未运行，不自动安装运行时。盘点试跑包只标部分完成。`Check` 通过只说明已检查的结构成立，不证明统计、证据链、脱敏或项目合规。

## 完成边界

不修改被审业务源码、配置、依赖、登录态或部署；整改由用户另行授权。原始日志与截图在落盘前脱敏，包内只保留必要证据，不保存密码、Token、私钥或敏感业务数据。

取证前排除 `.npmrc`、`.yarnrc*`、`.env*`、私钥与凭据文件；不批量打印全目录配置、认证值或环境变量。需要核对依赖源时使用已脱敏材料；缺少材料记录未证实。源码也可能含敏感值，工具查询限定文件、符号与必要上下文，保存前再脱敏。

交付前按[完整性清单](checklists/审查交付.md)实际核对。全部纳入规则均有状态、范围与依据且完成候选判定和六文件复核，才可称静态审查完成；范围受限用抽查完成，尚未执行取证用部分完成，关键目标不可访问用阻断。发布准入审查完成必须满足项目既定验收条件。运行缺口可以保留未证实，但不能把尚未读取的规则填写占位依据后称完成。
