# 取证与六文件报告

项目识别、规范适用性和调用链取证供三种模式共用；本页 Collect/Check、全 27 条矩阵、六文件模板/编号/统计、包内证据和六文件复核仅适用于 `formal-review`。限定变更按[变更审查](change-review.md)输出单报告，`development-self-check` 按[开发自检](development-self-check.md)保留轻量记录；两者不创建六文件或结果包、不调用 Collect/Check。

## Agent 与辅助脚本

Agent 负责规范适用性、调用链取证、候选归并、逐规则判定、报告及最终核对。正式审查使用 [原模板](审查结果包模板.md) 直接编写六份 Markdown；盘点 JSON 是证据材料，不是报告数据模型，不需要将判断填回 JSON。

取证只覆盖目标前端源码、配置、依赖和已有产物；页面→领域 API→前端请求封装是接口取证终点。公开接口材料用于判断前端消费方式，不扩展到接口内部实现或跨项目运行结论。随包模板保留公共六文件结构并裁剪为前端视图。

`scripts/Review-Frontend.ps1` 支持 PowerShell 5.1/7 和内置模块。脚本不执行项目 scripts、不读 Git 凭据或环境变量、不修改项目、不生成审查结论。没有 PowerShell 时使用现有只读工具，并记录脚本未运行。

## 项目识别

参考 `aura-web-project-router` 的四项证据联合识别方式，随包实现，不依赖另一个技能已安装。先确认 package.json 中 Vue 3 + Vite，再核对：

1. `src/config/moduleFederationBaseConfig.ts` 含 `currentRemoteConfig`。
2. `src/hooks/moduleFederation.ts` 含 `exposeModules`。
3. `src/config/aura/federation.ts` 含 `@fxft/aura-web-kit/federation` 当前公开绑定。
4. `vite.config.ts/js/mts/mjs/cts/cjs` 同文件同时包含 `@module-federation/vite` 与 `federation()`。

第三项采用当前 1.9.0 集成使用的绑定，依据现有模块联邦检查工具 `scripts/lib/project-type.ps1`；不沿用 router 旧版硬查 `src/utils/moduleFederationRegistry.ts` 的条件，不要求恢复旧副本。命中全部为 `Integrated`；零命中为 `NotAura`；部分命中为 `IncompleteCandidate`。NotAura 仅返回识别事实；IncompleteCandidate 若有 currentRemoteConfig/exposeModules/当前绑定任一 Aura 专有证据，在明确规范审查任务中加 -ReviewCandidate 即可盘点。只有联邦插件不放行。缺当前绑定等本身是最新规范审查对象，不自动归为未证实。Agent 还需排除注释/死代码等假命中，不能用项目名、目录名或单一依赖证明 Aura 身份。

若项目声明使用 workspace/catalog 等别名，先用已有公开依赖材料核对；脚本不猜版本、不安装依赖，不能据此把未知工程判为符合。统一按最新随包规范检查实际版本和布局，事实充分的缺项按规则报告偏差，不实现旧版适配、不升级或恢复文件。

### Collect

参数：`-Action Collect -ProjectRoot <项目> [-OutputDirectory <显式盘点目录>] [-Scope <相对路径数组>] [-ReviewCandidate]`。

入口必须有可解析的 package.json，dependencies/devDependencies 中明确声明 Vue 3 与 Vite；别名或 workspace/catalog 等无法直接确认版本的声明停止盘点，交由 Agent 核对已有前端事实。根目录 server/backend 实现目录不纳入扫描，显式指定这些范围也会拒绝。

默认在 <ProjectRoot>/审查结果包-项目名-提交短号-日期/证据/ 生成 inventory.json，返回 reportDirectory；无 Git 用时间标记，已有默认包追加序号。显式 OutputDirectory 优先，项目内只允许专用结果包及子目录，项目外也可；显式 inventory.json 已存在则拒绝覆盖。结果包及全部证据从扫描排除。内容为时间、范围、逐文件 SHA-256/字节数、语法扫描状态、候选位置、排除计数和读取失败。候选只有规则提示、位置和文件摘要，不携带源码原文，不分配报告 E/C/F 编号。多次盘点由 Agent 按原始对象和根因匹配已有编号，不能按新排序重编号。

脚本排除依赖/生成物/隐藏目录、链接/junction、环境与包管理认证配置及常见凭据文件。支持 Vue、JS/TS（含 mjs/cjs/mts/cts）、JSON、样式、HTML、YAML。大于 2 MB、锁文件及非 JS/TS/Vue 只取摘要，不做候选扫描。排除是工具边界，不是规则不适用依据；Agent 仍须盘点必要的被排除配置、资源和上下文，不能读取认证原值来补覆盖。

语法候选覆盖直接请求、web-kit 内部路径、旧扫描插件和原生表单方法，远非全部 FE 规则。注释、字符串、适配层和公共封装都可能命中。没有命中也必须逐规则取证；候选不能直接复制为违规。新增手工候选同样记录原始位置、依据和归并关系。

总指纹按排序后的 `相对路径 + Tab + SHA-256` 行以 LF 连接后计算。它只覆盖 assets，不包括排除项；失败单独记录。交付前如发生变更，在新目录再次盘点，对比文件集合及逐文件摘要，不能只对旧清单里的文件检查 hash。摘要一致也不能证明运行行为正确。

### Check

参数：`-Action Check -ReportDirectory <结果包>`。只读检查六文件存在且非空、矩阵每条原 ID 一行及状态单元格、普通行内 Markdown 本地链接存在且不越界。链接路径不得通过符号链接/junction 跳出结果包；外部 HTTP(S) 链接不联网检查。锚点、引用式链接、复杂 Markdown 和文档字段语义由 Agent 核对。

通过仅输出“结构检查通过”，不校验统计闭合、规范理解、证据覆盖、E/C/F 关联语义、复核正确性或脱敏。不能把 Check 作为整个审查的完成依据。报告中的源码位置写项目相对路径及版本；本地可点击证据链接指向包内材料。

## 逐规则取证与判定

按 [规则路由](审查路由.md) 选择规则并保留原 ID、必要性及规范位置；仅正式审查要求全部 27 条和完整矩阵。每条纳入规则记录适用条件、纳入对象、已检查对象、未检查对象、排除依据与判定依据；正式审查另按原模板保留证据级别和 E-编号。局部模式仅记录命中规则，明确“范围外未审查”，不能把范围外自动视作规范不适用。

- 通过：全部纳入的适用对象和子条件均有符合证据；零候选和扫描摘要不能作为符合证据。
- 偏差：有当前已确认发现，规范要求与实际行为冲突明确；正式审查 F 与规则双向关联，局部模式关联单报告或轻量问题记录。
- 未证实：完成可静态核对后仍缺运行条件、必要材料或适用性证据，说明具体补法。尚未检查仅是部分完成过程状态，正常交付须继续完成。
- 不适用：有项目事实证明纳入子项条件不成立；ui-plus 未使用必须有依赖/调用盘点依据。aura-ui 三个字典组件纳入 FE-025，其余范围排除且不计未证实；纳入组件缺证如实记录。

规则跨模块或含多个条件时按对象保留分项，总体偏差优先，其次未证实；剩余对象不能因某一页已验证而一起通过。待补证候选会影响相关规则的符合结论，不能一边通过一边隐藏尚未排除的可能偏差。

证据逐条绑定获取时间、被审提交/文件摘要或材料版本、对象与范围、方法、结果和限制。构建/测试另写准确命令、工作目录、工具版本及退出码；运行/人工材料分别说明边界。原始日志与截图先脱敏，正式审查放包内 `证据/` 并分配 E-编号，变更审查与自检复用任务证据位置并从报告/记录链接。不得把静态证据提升为构建/运行证据，不沿用旧行号到新提交。

正式审查 F-发现包含原模板全部卡片字段。多个候选归并同一 F 时保留全部位置、原始命中数和理由；C 的确认偏差/排除/待补证均有上下文依据。纯建议独立列出，不计入偏差或优先级。变更审查与自检的问题字段按各自模式资料，不套用六文件卡片。

## 六文件实际核对

Agent 按 [交付清单](../checklists/审查交付.md) 核对原模板全部字段，不以六个文件名或 Check 通过代替核对。按模块/规则域分组；所有规则都有状态，零发现仍保留完整矩阵、扫描域、命令/方法与零结果。

核算并在报告和矩阵保持一致：

- 总规则 = 通过 + 偏差 + 未证实 + 不适用；适用 = 总规则 − 不适用；已判定适用 = 通过 + 偏差。
- 唯一候选 = 确认偏差 + 排除 + 待补证；原始命中另计，多个命中归并不得丢位置。
- 发现、偏差规则、候选和文件分别计数；P0～P3 只统计当前确认偏差，不对纯建议或待补证分级计数。
- 纳入/已检查/排除对象数量分开，不能把仅取 hash 的文件数作为语义审查覆盖。

检查 F↔规则、C→F、各记录→E 全部存在且含义一致；所有偏差都有真实位置和证据，所有通过都有相应范围证据。总览、矩阵、整改和候选文件不得结论矛盾。凭据不能出现在工具输出或落盘材料中；自由文本与源码片段另作脱敏复核。

## 正式审查整改复核

更新前保存原六文件及其引用材料，保留旧 E 的原版本和摘要；不得将旧 E 统一改写为最新项目指纹。新取证追加新 E 编号，旧 C/F 保留原身份与历史结论，记录本次复核版本、时间、整改提交、范围变化和证据。附件如有新版本使用新文件，不能覆盖旧附件；记录也不能删掉后重新编号。

只有新证据满足关闭条件才将 F 标为已关闭；原违规证据或开发者说明不能充当关闭证据。当前矩阵可依据新证据转为通过；历史 F 继续列在整改清单及复核记录，并从当前偏差和优先级统计中排除。候选保留当时确认结论，标明关联发现当前已关闭，因此历史确认候选数不必等于当前发现数，报告必须说明口径。

复核时同一编号不能替换成另一个根因/对象；真正新问题分配新编号。没有可靠旧材料时说明历史映射缺口，不伪造复核完成。执行完成状态与项目质量分别表达；发布准入遵循项目既定验收要求。

## 面向阅读者的结论

01 第5节使用中文对照表：规则中文名+ID、规范要求、实际检查情况、结论/缺证分类、证据位置与补证办法；02 首列包含中文规则名。正常审查连续完成全部可静态检查项，不能把尚未检查批量写成最终未证实。aura-ui 仅纳入 AuraDictTag / AuraDictText / AuraDictSelect、其余排除；ui-plus 正常检查，公共能力摘要分两行；各纳入子项分别取证后按规则汇总结论。规范Git来源只供维护追溯，运行读取随包知识，不联网拉取。
