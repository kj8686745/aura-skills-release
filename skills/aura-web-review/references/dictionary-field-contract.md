#### 动态字典字段与固定枚举

- 由可配置字典维护取值的字段，注释和字段说明保留中文业务含义及准确的字典 key（类型声明保留 `@dictKey`），不要求罗列当前全部 code/label。字典 key 须由真实接口、字典配置或既有契约核实，不能从字段名猜测；无法确认时记录具体缺口。只有机器标记仍不能代替中文业务含义。
- 动态字典字段按真实接口契约保留 `string` 或 `number` 等值类型，以及单选/多选、可选性和可空约定；不得仅根据当前字典项生成封闭字面量联合类型或 TS `enum`，也不以 `any` 或无依据的 `string | number` 代替契约。选项与显示名称从项目字典入口获取。
- 固定协议、状态机等封闭契约仍明确允许值及含义并保留类型约束；字段关联字典不等于协议可任意扩展。已有 API/OpenAPI 明确封闭枚举时先核对契约，不因关联字典直接放宽类型。字典中少数 code 参与流程或权限判断时，仅说明实际依赖值的业务含义并复用有依据的常量，不将这些值视为整个字典的穷尽列表。
- 在功能开发或类型调整范围内，核对新增合法字典值可按现有公共组件契约显示并保留原值提交，不能因本地枚举快照静默丢弃或改写。未知值展示按真实需求与组件公开契约处理，不为本规则额外增加兜底逻辑或掩盖字典加载、类型匹配问题。
- 纯注释/说明整理保持签名与执行行为；发现既有封闭类型可能与动态字典冲突时记录依据及建议，不借补注释修改类型。审查不能仅因动态字典字段未列全量取值而判缺项。

以下仅为注释格式示例，字典 key 与值类型必须替换为项目已核实契约：

```ts
interface DeviceRecord {
  /**
   * 设备状态，取值来自字典 device_status。
   * @dictKey device_status
   */
  status: string;
}
```
