# 开发自检模式

`mode=development-self-check` 是本技能的语义执行模式，供 `aura-web-develop` 功能开发闭环调用，也可明确指定；纯补注释/说明整理默认不触发。它没有对应 PowerShell 参数。变更审查与正式审查不进入此流程。

## 边界与输入

先按用户请求确定验证范围。普通补注释不进入本模式、不建立逐对象机器矩阵、快照、哈希或证据套件；只有明确要求自检/结构检查/审阅报告，或有真实来源的项目强制门禁时追加对应检查，不能以本技能旧要求冒充项目门禁。仅请求注释检查时覆盖 READ 中实际命中项及人工差异范围核对，不机械运行 27 条 FE 全项目检查、FE 扫描、ESLint、typecheck、build、测试、浏览器或 AST 对比。用户明确要求完整规范检查时保留其范围。

只读被检查业务源码、配置和依赖；审查不实施修复。记录执行者为开发自检；同一 Agent 开发后检查不构成独立人工或独立代理审查。接收用户任务类型（新开发/功能修改或纯注释/说明整理）、项目绝对路径、业务块与必要调用链、需求/原型、代码基线、业务说明、适用必需检查计划和检查记录位置。缺项先从任务和项目读取可确认事实；关键缺口记阻断，继续可独立检查。

沿用入口的敏感信息排除、授权范围及适用规范基线。完整规范检查时沿用 Aura 身份识别。以下字典与公共能力检查仅在功能开发或完整规范范围命中时执行：aura-ui 的 AuraDictTag / AuraDictText / AuraDictSelect 纳入 FE-025 并关联 FE-019，其余 aura-ui 范围排除；ui-plus 正常纳入，公共能力摘要分列。筛选/表单的 Select 与展示 Tag/Text 均按共用路线取证检查，不因开发自检模式跳过。

不运行 `Review-Frontend.ps1 -Action Collect/Check` 作为自检入口，不创建六文件报告或审查结果包。直接用现有只读工具记录范围、版本/摘要和证据；确需其它扫描时先核对副作用及授权，输出到任务证据目录。不得调用 Collect 后删除报告来伪装无报告模式。

纯注释/说明整理只允许修改注释和说明文档，不修改可执行代码、DOM 属性、组件、import、状态、接口、控制流、依赖或配置。既有 FE 功能偏差继续如实记录规则结论、证据与建议，标原有问题/本次未修改，不自动要求开发侧加重试、useForm、竞态或字典替换；不因这些旧偏差停止已授权整理。

## 规则适用与语义取证

功能开发范围涉及表单时，必须执行[表单生命周期取证](审查路由.md#表单生命周期取证)，逐个核对实际公共 `useForm` 调用链及适用整表/字段校验、重置、清校验；未接入、直接绕过、只导入、缺支持或缺证均不能返回自检通过。保留本次范围、纯注释及动态表单真实协议边界，不因用户没有点名 Hook 而跳过。

范围命中 Vue/TS/样式结构时，复用[职责决策表](../knowledge/PIGX前端开发规范/文件组织与职责拆分.md)判断默认 SFC、私有文件与共用层级、所有权及作用域；不因长度、无 Hook 或 CSS 未外置判偏差。沿现有自检记录命中项，不新增全仓扫描、固定拆分报告或重复构建；纯注释不触发重构。

常规功能自检在本次功能/交付批次稳定后集中一次，聚焦本批 diff 与必要受影响上下文，复用开发已读且未变的源码、规范与有效证据；按同版 [rules.json](rules.json) 和[审查路由](审查路由.md)选择实际命中规则，不机械逐条盘点 27 条 FE，不重新全文扫描项目或重复追已确认链路。用户明确全规范范围时才完整逐条核对；限定注释检查只读命中可读性正文。沿用[取证与报告](取证与报告.md#项目识别)中的身份识别及逐规则取证方法；其中脚本接口、六文件字段/编号/统计、包内证据目录和原报告复核只适用于正式审查，不向自检套用。

仅为请求范围内的规则和 READ 项使用轻量记录，保留原 ID、来源、范围关系、纳入/已检查/未检查对象、结论和证据。不为范围外规则填完整矩阵；必要范围说明标明未检查，不当作规范不适用；没有运行材料、没有检查或候选零命中均不等于通过。适用规则沿用“通过、偏差、未证实、不适用”判定；规则含多个对象/条件时保留分项。未证实说明所缺条件与补证办法，不适用要有事实。证据支持真实要求和实际行为，不凭方法名、注释存在、目录标题或机械词匹配判通过。

按本次影响补充必要的页面、组件/Composable/Store、领域 API、统一请求入口及数据消费上下文，核对需求、状态、权限、异常、取消、竞态和清理等适用条件；已读且未变链路直接复用，不为例行自检重新追全部链。静态事实与运行事实分别记录。扫描候选需上下文确认；零发现不证明全部对象符合。

范围命中分页时，仅核对前端传参与显示对应：沿页面 → API 参数 → 统一请求序列化，确认公共 Hook 使用 `current/size`，响应消费 `records/total` 并正确映射 `useTable/AuraPagination`；有排序再核对 `orders` 的 `column/asc`，无排序不强求。按已有[查询表格规范](../knowledge/PIGX前端开发规范/页面模式/查询表格页.md)判断，`pages` 可选，前端使用真实 TypeScript 数字类型，不照搬 Java `long`。真实接口协议不同的，只在项目已有 API 适配边界明确转换请求与响应，公共 Hook 和页面保持统一契约；返回专用字段不作为请求参数，不在页面维护多套分页状态。前端参数/消费代码证据即可支持本项，必要测试可用 Mock 验证传参与显示；不审计 API 实现或后端分页算法，不要求真实后端联调来证明这项，也不把脚本扫描称为分页语义已通过。

## 完整结构范围复核

仅当原任务要求整个页面或业务模块结构优化时，先核对原始授权范围及开发侧职责处理记录，再阅读必要入口、私有文件与新模块，复核各职责当前所有者。不能把开发侧自行选定的少数提取点当作用户完整范围，也不能只看 diff/新 Hook 而漏看入口剩余的独立业务流程；局部任务不因此扩大范围。

按职责规范判断应拆与可保留部分：没有硬性行数门槛；大而内聚可保留，仍混合多套可独立管理的请求/状态/生命周期时，应指出具体职责、影响和关闭条件。只有完整授权职责已实际核对、适用的结构缺口已关闭且必要验证有效，才可给该结构任务完成结论；未覆盖或未实现部分须列明，不能以若干文件变短/已抽两个 Hook 判通过。复用开发已读资料，记录在现有轻量检查记录，不新增全仓矩阵、固定报告或重复构建。

### READ-01/02 声明字段门槛

先固定授权完整文件清单，逐文件完整盘点 interface/type literal/class 的属性、嵌套/内联/交叉类型、数组项内属性、索引签名和枚举成员。指定整份文件时，全部声明字段均纳入，不因未消费、非字典或不在改动行跳过。每个字段保留或补齐自己声明相邻的准确中文；父对象、接口总注释、其他字段尾注释、子属性注释、英文类型名和仅 @dictKey 不能替代。方法各实际 @param 中文说明与字段声明说明分别核对；公共继承沿实际声明确认，外部依赖缺项单列，不擅改依赖或重声明类型。简单字符串枚举 alias 可按类型级中文说明核验，不虚构字段。

本技能随包[只读检查器](../scripts/check-api-comments.cjs) 是可选结构诊断，仅用户明确要求结构检查或真实项目强制门禁时运行；不能因 TS/TSX 注释任务自动触发：`node <本技能目录>/scripts/check-api-comments.cjs --project <已有项目根> --files <明确文件1.ts> <明确文件2.ts> [--output <新建证据.json>]`。无需安装开发技能；develop维护事实源，本技能脚本为字节一致副本。project仅解析其已安装TypeScript；相对文件按project解析，绝对路径可为隔离样本，不自动扩展scope；例行 development-self-check 不自动运行该结构诊断。默认stdout；output只创建新文件、不得覆写源文件。不安装工具、不写源码、不作全项目typecheck。

脚本递归检查property/method signatures、type literals、class属性及参数属性、index signatures、enum members，覆盖数组/内联/交叉嵌套声明并报同容器重复普通属性；具名函数实现、变量箭头/函数表达式、class方法/访问器和函数属性核对用途/实际各@param/@returns中文及分行结构，匿名回调不当作具名方法。只认本字段直接相邻注释，支持多行字段结束处同行尾注释，前成员尾注释不可借用。JSON保留完整scope、逐文件字段/方法/参数数、状态及每个缺项的真实路径行号。

退出0仅表示所请求结构完整且无机械缺项，1为缺项/重复声明，2为不完整（缺依赖/文件、非TS/TSX、语法错误、mapped type、动态计算属性、解构方法参数等）。外部类型/继承只列入口，须人工追踪；脚本不判中文业务准确性、字符串枚举alias取值语义、跨文件声明合并和继承链，不证明业务语义或运行行为通过。不支持、未检查、能力不足和继承缺证均不得通过。请求审查时按实际范围人工核对每文件字段含义、自己的注释位置及语义结论，记录完整覆盖与缺口，不强制逐字段数据表；运行结构诊断时另记结构结果。所有清单文件所请求检查完成、缺项关闭，执行结构诊断时结构和语义同时满足，才可限定范围通过，不能只补字典/挑两文件声称整批通过。

仅维护技能时只读业务资料，验证使用隔离副本，不实施真实业务修复。纯注释权限、保持签名与行为、不全量格式化约束继续适用。

## 轻量检查记录与返回

优先写任务指定记录位置；无约定可用 `docs/development-checks/<任务>/检查记录.md`。局部功能可将检查与最终交付结论合在这一份简短开发记录；完整新功能或用户要求独立报告时，记录保留过程证据，由开发侧另交报告，不重复全文。输出内容按实际事实填写：

- 模式、执行者、时间、技能实际路径/版本、需求和业务说明路径、业务范围/上下文、提交及未提交状态或文件摘要。
- 本批实际命中规则与补充项：原 ID/补充 ID、来源、范围和必要结论/证据、未决缺口及不适用理由；不要求 27 条 FE 全枚举或逐对象机器矩阵。aura-ui 三个字典组件结果、其余排除与 ui-plus 结果分列。
- 可读性取证保留实际检查的变量声明用途覆盖、方法步骤、国际化字段/列及主要操作的注释位置和结论，按业务语义核对覆盖与准确性；文件头、大区块或注释数量不代替逐项证据。
- 问题稳定标识、要求与实际差异、具体位置/影响、修复建议及关闭条件；复查时保留问题、修复位置、代码版本、受影响项的新证据和当前结果，不覆盖失败历史。明确记录当前有效、受后续变更影响待复查或历史状态；旧记录保留原范围与证据并链接后续记录，不将旧快照视为当前通过。
- 测试与验证：记录实际命令、工作目录、工具版本、退出码、结果和必要日志位置。按开发侧本批检查计划核对已有证据；覆盖源码、配置、依赖、环境未变且仍覆盖本批可复用，后续仅文档/注释变化不重跑无关业务检查。build 的类型检查可复用须由真实 package.json 确认且范围/配置一致，不重复完整 typecheck；未运行、未触发、不适用与复用依据分别如实写明。
- 按任务类型总结：纯整理返回“注释/说明整理范围通过 / 需整改 / 阻断或检查未完成”，分列可读性/行为保持与既有 FE 功能偏差；功能任务返回“通过 / 需整改 / 阻断或检查未完成”，剩余必需项及下一步。不以六文件命名、E/C/F 卡片或完整报告统计作为本模式门槛。

READ-01/03/04 的适用注释或业务说明缺项、不可读或与真实实现不符记偏差并返回需整改，不只作 warning；由开发侧修改，再逐项复核对应方法步骤、模板字段与主要操作的新证据。

明确要求自检的整理任务在所请求可读性及行为保持检查完成、缺陷关闭后返回限定范围结论；仅用户要求报告时生成“注释/说明整理审阅报告”，明确既有功能偏差、范围和未修改事项，不宣称整体 FE 合规。若用户明确要求全规范通过，旧功能偏差阻断该目标，列具体需授权修改，继续独立整理；不一律反复询问授权。

新开发/功能修改仅全部适用必需检查与测试通过、授权内偏差关闭且没有必需项未证实或未执行时返回“通过”；不适用有事实依据，范围外事项不虚构结论。可静态取证未完成时继续检查，不将尚未检查批量记为最终未证实。

将问题和记录位置按任务授权交回开发技能整改；纯整理只改注释/文档、既有功能偏差只记录，修改后重查受影响对象并更新证据；不改业务代码，不降低检查门槛。环境、材料、授权或业务决定缺失时返回阻断及待补条件，继续独立检查。功能任务只有授权内全部必需项通过后才写最终交付结论，标“自检通过，待人工审查”；局部功能可合并为一份简短开发记录，完整新功能或要求独立报告时由开发侧保留报告及过程记录。明确要求验证的整理任务按请求范围返回检查结论，仅要求报告时交整理审阅报告。后续修改只重取受影响证据，整体仅核对受影响跨块衔接；不每个文件、业务子块或代理完成就重跑整套或生成报告。常规功能无需 AST/转译身份一致性门禁；仅明确行为保持重构、纯注释验证请求或诊断变化时选用。现有项目门禁、用户范围、MF 冷启动及公共包消费等真实触发验证继续保留。
