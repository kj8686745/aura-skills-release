# 查询提交与选择器规模取证

正式审查、变更审查和功能开发自检命中查询条件或选择器时采用；限定任务不扩大为全项目迁移。正文依据为随包同版[请求规范](../knowledge/PIGX前端开发规范/02-请求路由权限与数据适配.md)、[公共能力](../knowledge/PIGX前端开发规范/aura-web-kit能力清单与接入规范.md)及[组件规范](../knowledge/PIGX前端开发规范/组件复用与公司基础组件库规范.md)。

## 查询提交取证（FE-006 / FE-010 / FE-021 / FE-027）

沿查询模型 → API queryFormat范围配置 → 公共请求格式化 → 请求序列化 → 实际 params/body/filter 追踪，分别核对列表和导出，不凭格式化函数名或静态扫描零命中判通过。

- 应省略普通对象中 undefined、null、空字符串、纯空白字符串、空数组、空普通对象字段；普通对象递归格式化后为空也省略。核对结果对象确实不含键，不能把赋 undefined 当成最终不传。
- 应保留 0、false、非空原字符串和 Date 等特殊实例引用；非空数组只复制容器，保持元素引用、内部空值及位置。`[null]`、`[{}]` 不能自行压缩或重排。不原地修改页面查询模型，也不能把结果宣称为完整深快照。
- 格式化仅限 GET 查询 params、POST 查询条件对象及导出 filter。未显式选择范围而全局删除空值、误删新增/编辑 null 的清空语义、格式化导出外层协议控制字段均须据实际影响判偏差；接口明确要求空值时，核对字段、契约与显式保留证据，不把真实例外机械报错。
- 业务 API 优先通过统一 request 的显式 queryFormat 配置格式化提交参数，避免每个模块重复导入工具：GET 使用 { params: true }，POST 查询使用 { data: true }，混合导出仅使用 { data: { paths: [['filter']] } }。默认不开启，不按 HTTP 方法推断查询；只作用于选定目标，空 filter 删除键而范围外字段保持。在 JSON 归一化与加密前执行，不能格式化路径、请求头或未选定的写入字段。配置和 preserveEmptyPaths 路径均相对 params/data 根。 核对已安装包的公开声明与实现；该能力已随1.9.5发布并完成私服读回，不能根据旧1.9.3版本或源码存在推定消费者支持。formatQueryParams纯工具仅按非请求构造等需要直接使用，不要求每API重复导入。
- 纯字段格式化不需要独立 Hook；不能误用写入 JSON 归一化代替查询格式化，也不能推定 useTable/全局请求已自动格式化。

`preserveEmptyPaths` 只保留精确字段的空值，不使非空父对象免于子字段格式化。例外不改变原序列化协议；undefined 即使保留在对象中，GET 仍可能省略、原 JSON 归一化仍可能转 null。契约明确要求 null 时应检查实际 null，不以保留 undefined 证明已传约定值。

必要证据覆盖空键缺失、有效假值、嵌套空对象、数组结构、特殊值、源对象保持、契约空值例外与列表/导出同条件。无法观察请求序列化后的结果时，区分静态判断与未证实，不声称真实传参通过。

导出参数按真实接口契约构造。分页导出或字段具有业务含义时，保留接口需要的 current、size 等参数；只有契约明确不接收列表分页时，才从筛选副本移除对应字段，不得仅凭字段名删除或把 current、size 当作完整分页字段清单。queryFormat 只处理空值，不推断分页或其他业务语义。不得修改原查询模型；导出候选列表的分页、排序及外层控制字段分别按各自接口契约处理。

### 请求配置示例

```ts
request({ url, method: 'get', params: query, queryFormat: { params: true } });
request({ url, method: 'post', data: query, queryFormat: { data: true } });
request({ url, method: 'post', data: { ids, fields, format, filter: query }, queryFormat: { data: { paths: [['filter']] } } });
```

仅示意配置，URL、字段及实例沿项目真实协议。未配置目标保持原语义，配置不传入HTTP头或body；不能假定旧下载Hook接受额外配置参数。

## 选择器规模取证（FE-025 / FE-027）

候选数量较大、无明确上限或可能持续增长时，必须使用 `el-select-v2`，或已核实具备等效虚拟化能力的公共选择组件；普通 `el-select` 一次性渲染全部选项属于不符合。候选数量明确且规模较小时允许普通组件。按数据规模与渲染成本判断，不列业务类别，也不设缺少依据的统一数字阈值。

先确认选项来源、数量/上限与增长特征，再核对目标依赖版本、实际组件 Props/Events/Slots/options/value-key/行高以及运行渲染。仅出现 select-v2 标签、filterable、collapse-tags、远程搜索、分页或滚动条，不能证明虚拟化正确；公共组件名称也不能代替其真实渲染证据。官方契约入口：[Virtualized Select](https://element-plus.org/en-US/component/select-v2.html)。

按实际范围核对候选总量与可见窗口 DOM 数、滚动后的选择、值类型及单多选、搜索/清空/回显和自定义多行高度。辅助候选失败应为空选项，不能直接导致整块表单错误；详情等主数据失败另判，不机械要求全部错误静默。缺少规模或运行证据保留具体未证实项，不把少量候选样本、静态扫描或截图当成全量行为通过。
