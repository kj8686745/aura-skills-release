# FxftMap 地图接入取证（FE-025）

本技能补充门禁适用于 `formal-review`、`change-review` 和 `development-self-check` 审查范围内的所有地图功能。限定范围不扩展为全项目审查；无地图有盘点依据才标不适用，纯注释/说明检查保持原请求范围。门禁已按用户要求补入天玑前端规范工作树，并更新随包相关规范段；源提交待绑定，见[地图规范](../knowledge/AURA前端开发规范/2D地图开发规范.md)，来源见[维护记录](fxft-map-source.json)。

## 必查链路

沿实际地图入口、私有组件、配置加载和实例操作追踪下表，不以名称、import、注释、扫描零命中或空组件标签判通过。保留实际文件/符号、被审版本、所需运行证据及分项结论，归入现有报告或自检记录，不新增报告体系。

| 检查项 | 必须取得的证据 |
| --- | --- |
| 实际地图组件 | 使用 `@fxft/ui-plus` 的 `FxftMap` 承载地图功能；声明、锁文件、实际安装公开导出/类型及 import/Resolver 与真实渲染链一致。不得只 import、挂空壳，或绕接底层 SDK 代替组件。 |
| 默认底图、中心、缩放 | 追踪 `@fxft/aura-web-kit/hooks/map-config` 的 `loadMapConfig()` 真实返回值至有效 `FxftMap` Props：`defaultLayer`、`baseLayers`、`center`、`zoom` 全部接入。检查对象合并、展开顺序、computed、后续赋值、父级 Props 和初始化流程，不能被页面硬编码覆盖，也不能仅解构未使用。配置就绪后才挂载组件。 |
| 缺失坐标兜底 | 先判断业务是否明确需要无坐标打点。需要时，实际消费公共结果 `fallbackCenter`，不得拿 `center` 冒充；有效坐标继续使用业务坐标。选择空态、过滤无效点或仅展示有效坐标的场景，记录具体理由，兜底子项可不适用，不要求创建假点。 |
| 组件就绪与公开能力 | 区分配置 ready 与组件 `load`；绘点、轨迹、视角等实例操作在 `load` 后使用已安装公开方法，事件载荷与类型一致。选点采用 `map-click` 的 `coordinate.x/y` 与公开 `addPoint`，稳定 ID、独立图层、`clear: true` 保持单 marker，未误用几何绘制流程。按实际功能取证，不要求所有页面都做选点。 |
| 尺寸与资源 | 父子高度链有效，尺寸变化/隐藏恢复按组件已公开能力处理；JS 与组件 CSS 经实际 Resolver/显式入口加载，不以构建成功代替地图显示与交互。 |

`loadMapConfig()` 在已验证的 web-kit `1.10.4` 返回 `center`、`fallbackCenter`、`zoom`、`defaultLayer`、`baseLayers`、`csys`、`amapKey`；ui-plus 验证版本为 `1.1.3`。其他项目核对实际安装公开契约，不凭参考版本推断可用，也不自动升级。请求初始化应复用项目请求栈已执行的 `configureMapRequest(request)`，页面不新建认证/HTTP 栈。

## 系统字段与排除项

| 系统字段 | 应用消费 |
| --- | --- |
| `sysMap` | 公共服务归一为 `defaultLayer`、`baseLayers` |
| `sysMapCenter` | `center`，初始视图中心 |
| `sysMapScaling` | `zoom`，初始缩放 |
| `sysMapFallbackCenter` | `fallbackCenter`，业务需要无坐标兜底时消费 |

页面不复制底图映射或默认数值；编辑面板的默认值、缩放校验范围不作为消费端契约。公共服务对无效兜底配置回退 `center` 属公共回退语义，不等于页面可绕过 `fallbackCenter`。

**高德 Web 服务 Key（`amapKey` / `sysMapAmapKey`）明确排除必接与通过门禁。** 不因缺 Key、未读取或未接入 Key 判地图偏差、未证实或失败；不借地址检索设置 Key 必接条件；实际地址服务仍按需求验收功能，Key 排除不豁免真实功能失败。坐标系 `csys` 仅按真实数据坐标需求核对转换，不虚构为 `FxftMap` 必传 Props，不默认要求纠偏。

## 判定与通过条件

- 已确认未接、假接、漏接或硬编码覆盖，记 FE-025 地图分项“偏差”，列具体消费断点、影响和关闭条件；该地图项不得通过。
- 必要契约、调用或运行证据缺失，记“未证实”并写补法；该地图项及覆盖它的开发自检不得宣称通过。确认静态事实与实际运行结论分开，不把未检查当合规。
- 所有适用门禁有充分证据且无未关闭偏差/缺证，才判地图项通过；不适用子项须有业务场景依据。其他独立审查继续，不因地图问题暂停全部工作。

已验证版本中，请求未绑定会拒绝加载；配置请求失败由公共服务回退默认配置并缓存 Promise，并发调用合并，失败默认同样缓存，没有公开自动刷新/重试 API。核对页面是否按此真实语义处理，不把再次调用当重新读取，也不因公共默认回退本身误判页面漏接。按本次范围复用有效证据，不为审查写入全局系统配置或修改被审源码。
