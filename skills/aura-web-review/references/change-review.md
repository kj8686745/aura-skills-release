# 变更审查模式

`mode=change-review` 用于明确限定 files、diff、一次变更或局部模块的日常只读审查，默认交付一份报告。全项目、完整规范或显式正式审查按入口切换 `formal-review`；开发闭环明确使用 `development-self-check`。模式不是脚本参数，不调用 `Review-Frontend.ps1` 的 Collect/Check，不创建六文件或专用结果包。

## 范围与取证

确认实际项目、提交/比较基线及未提交状态，记录明确文件或模块清单；diff 任务同时核对新增、修改、删除和未跟踪文件，必要调用方、配置与公开声明只作判定上下文。项目识别、敏感信息排除和只读边界沿用 [取证与报告](取证与报告.md)。已有明确范围不重新扩大全项目；缺比较基线时先用任务和 Git 事实确认，无法确认的部分如实列为缺口。

按 [审查路由](审查路由.md) 和 [rules.json](rules.json) 选命中规则，阅读相关正文及必要上下文，核对需求、实际行为与影响。只查命中规则，不建全 27 条矩阵；FE-019/025 等真实命中门槛仍须完整取证。请求 API/类型注释检查时，按 [READ-01/02 声明字段门槛](development-self-check.md#read-0102-声明字段门槛)覆盖授权完整文件，每字段自己的相邻中文要求不减，不因此套用开发闭环的其它交付要求。

只使用已有且符合授权范围的只读验证；先核对项目命令副作用，不自动执行全量 lint、build 或测试，不安装依赖。必要运行证据缺失时保留未证实，继续其余可静态检查项。零检索命中不等于符合，候选须结合上下文判定。

## 单报告内容

沿用项目指定输出位置；无约定可在现有审查文档目录保存 `<任务名>-变更审查报告.md`。仅保存需要的脱敏证据，长日志已有位置直接链接，不为单报告额外生成空目录或索引。报告按实际内容组织，至少包含：

- **版本与范围**：项目/仓库、实际分支与提交、比较基线、未提交状态、文件或模块、必要上下文与排除边界；技能真实路径/版本、规范来源和检查时间。无 Git 时写可取得的摘要及限制。
- **适用规则与结果**：规则中文名及原 ID、规范要求、实际检查对象与结论；使用“通过、偏差、未证实、不适用”，不为范围外规则填矩阵或宣称不适用。
- **问题与证据**：每项稳定标识、具体位置/符号、规范与实际差异、触发条件和影响、证据及其版本、整改建议与关闭条件。优先级沿用正式报告 P0～P3 口径，纯建议与待补证不计确认偏差。
- **验证及未覆盖项**：实际命令、工作目录、工具版本、退出码、结果与证据；未执行原因、缺证、范围外对象及可补证办法。静态、测试、运行和推断分开。
- **结论与下一步**：限定本次变更/模块的审查结论、剩余问题和建议顺序；零发现也写真实覆盖与限制，不宣称全项目合规或发布准入通过。

复核保留原问题标识和历史证据，追加整改版本、受影响项新证据及结果；新证据满足关闭条件才关闭。交付前核对版本未失效、范围内可静态项已完成、结论与证据一致且已脱敏；尚未完成写部分完成或阻断，不能把未检查改称未证实后宣称完成。
