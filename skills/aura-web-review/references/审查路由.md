# 前端审查规则路由

完整原规则 ID、必要性与正文位置见 [rules.json](rules.json)。正式审查保留全部 27 条及结果矩阵；[变更审查](change-review.md)与[开发自检](development-self-check.md)按限定范围和必要上下文选择命中规则，不逐条枚举或重复已确认链路，不要求六文件矩阵。用户明确全项目/完整规范审查时走正式模式；开发闭环明确自检的，仍在自检内覆盖其所请求规则。下表为三种模式共用的选读和取证路由，不另造技术要求。

仅选择目标前端项目的源码、配置、依赖与已有产物。接口字段使用公开契约或已有脱敏响应；没有材料时保留未证实，不查找其他领域代码补证。规范副本为前端审查视图，开发示例不构成修改或安装授权。

FE-001 ～ 004、019、024 命中组织问题时，读取[统一职责决策表](../knowledge/PIGX前端开发规范/文件组织与职责拆分.md)，从状态/资源所有者、实际消费者与导入方向取证。确认偏差指出具体职责混杂、重复状态、反向依赖或样式污染；Dialog/Drawer 同一般区域，数量、类型、长度、无 Hook、未外置 CSS 均不能单独判偏差。可选提取建议不计偏差，缺必要证据标未证实，尚未检查不能冒充合理保留。少量私有 TS/SCSS 同级、单一内聚大文件和有理由保留的大样式不机械判偏差；纯注释不增加结构整改。

## 覆盖层可见时的刷新取证（FE-014 / FE-016 / FE-021）

正式审查、变更审查和功能开发自检共用 [FE-016 正文](../knowledge/PIGX前端开发规范/03-表单异步与资源反馈.md)及[1.9.6 静默契约](../knowledge/PIGX前端开发规范/aura-web-kit能力清单与接入规范.md#已加载列表的静默刷新196-已发布)。从实际操作成功回调追踪到被同步区域及请求：确认覆盖层是否仍可见、目标是否为背后已加载的同一业务资源，再核对实际安装包、第二参及既有分页/选择语义。手工列表按同一交互判断，不要求迁移 Hook；缺包能力不能凭公共源码或 `silent` 字样判通过，当前目录按实际安装 1.9.6 / 115 入口核对，旧包不覆盖本能力门槛。

延迟响应检查旧内容保持、无额外区域遮罩/spinner、无 Empty 闪烁，成功替换与失败原资源反馈；同时验证首次/空表回落、主动查询/重试及提交按钮的前景 Loading。覆盖层仍开着却默认刷新造成双遮罩、全局关 Loading、用透明背景/z-index/手改 loading 掩盖，或延后到 close 才刷新，应据真实行为判定；覆盖层已关闭的刷新不机械要求静默。旧响应与最新请求的归属仍须正确，无运行证据则记录行为未证实，不扩大限定范围或纯注释任务。

## 查询与选择器共用取证（FE-006 / FE-010 / FE-021 / FE-025 / FE-027）

查询与选择器范围按[专项取证](query-select-contract.md)执行：追踪空条件到最终提交，核对候选规模、真实虚拟化窗口及交互；正式、变更和功能自检同样适用，不能只因标签出现判通过。

## 权限实现共用取证（FE-007 / FE-019）

三种审查模式命中权限时均按随包[FE-007](../knowledge/PIGX前端开发规范/02-请求路由权限与数据适配.md)追踪模板指令、共用权限常量、公开 `usePermissions` 的脚本兜底与组件初始化边界。检查受限打开/查询/保存/重置入口；Tab/Drawer 的可挂载项、激活项及打开状态先在脚本受控，不能以 DOM 指令代替阻止 setup/请求。模板直接调用权限方法、散落同业务权限码、只隐藏仍初始化需据实判断；保留非权限业务条件与不受限展示，不扩全项目机械替换。

按实际范围取证无权、单项、未就绪、恢复、撤回和直接调用；无运行证据时标明未证实，静态检索零命中不判行为通过。只读审查不实施业务修复，接口实际授权仍在结论范围外。

## 国际化公共复用取证（FE-019）

依据随包[工程规范](../knowledge/PIGX前端开发规范/工程与代码生成规范.md)的既有分层复用要求执行，来源与检查边界见[维护记录](i18n-reuse-source.json)。本节由正式审查、变更审查、功能开发自检共用；只审注释时不扩为语言整改。

1. **确定对象**：变更/自检从 diff、未跟踪语言文件及新增/替换调用盘点本次新增 key、修改值和最终引用；不能只查业务 `.vue` 或只查语言文件。正式全项目按其全部纳入文案核对，限定审查不扩为历史语言包整改。语言注册与相邻模块只读作判断上下文。
2. **核对公共定义**：逐项搜索全局、业务域、当前模块的中英文原文、近义表达及 key；确认用途、插值、翻译语境和实际注册后，判断应复用全局 key、复用/上提业务域 key，或保留页面专属 key。复用的旧 key 也要核对存在与注册，不能凭 `common` 名称或开发记录推定有效。
3. **判定候选**：不同 key 双语值相同只能提示重复，语义相同且复用条件满足才确认偏差；同文异义/不同插值等保留独立键须有证据。仅中文相同、不同文字表达的同义内容、动态/导入定义及远程注册仍需人工判断；扫描零候选不免检。提取后核对本次调用替换与旧键消费者，涉及远程公开契约时不能未经确认删除旧键。
4. **留下结论**：在所选模式现有记录中简记“本次 key/用途 → 检索范围及公共命中 → 最终 key/层级 → 复用、提取或保留依据/调用位置”；同一文案合并多处调用，不新增报告体系。缺检索、动态定义未核实、候选未判定或注册缺证时保留具体未证实/未检查项，不能写 FE-019 通过。

审查不依赖另一技能的安装。若开发提供 `-StrictUiContracts` 结果，只作为输入证据：它使用静态 `zh-cn.ts` / `en.ts` 索引，不执行语言模块；输出涉及选中定义或选中字面量调用的重复候选及定义位置，不输出文案值。退出 `2` 的候选可人工排除并记录依据，不要求为清零改业务或重复运行；退出 `0` 也只代表可扫描项。缺少扫描器时直接只读检索完成本节，不借此跳过公共复用检查。

## 表单生命周期取证

正式审查、变更审查和功能开发自检中，范围涉及业务表单即按同版 [FE-013 正文](../knowledge/PIGX前端开发规范/03-表单异步与资源反馈.md)及[工程规范](../knowledge/PIGX前端开发规范/工程与代码生成规范.md)检查；页面、Dialog、Drawer、内嵌编辑和私有组件均纳入相应范围。查询表单按实际校验/重置操作检查；只作排版、无生命周期操作的只读区域不要求空导入。非 Element Plus 表单核对真实适配契约，无法覆盖时记缺口并保留真实组件校验协议，不强行接入布尔适配器或虚构 Hook 能力。

先核对已安装 `@fxft/aura-web-kit/hooks/form` 导出和声明，再沿“表单 ref/模型 → 校验/提交、重置、打开回填 → 实际方法”追踪到公共 `useForm`。真实适用方法为 `validateForm/resetForm/clearFormValidate`；不要求无对应操作的表单全部解构。仅导入、仅重置用 Hook 而校验仍直调实例，或业务属性恰好名为 `useForm`，均不能证明完整接入。别名和私有 Composable 继续追踪最终调用；业务内复制公共实现仍属偏差。

字段联动/分步校验还须核对公共 `validateFormFields` 与 `FormFieldPaths`：支持版本中业务直接调用实例 `validateField` 属绕过；包缺方法时记缺口并给出升级或补证要求，不能凭同名局部函数判接入。空路径、未挂载、缺能力及校验失败不得放行；字段名、点路径/分段路径需与实际 FormItem prop、规则和挂载一致，局部校验不能替代业务要求的整表提交校验。

web-kit 提交 `df7206233306299fdb4d327a22f5d34c8177faed` 同时补充了 VueUse 初值克隆和字段校验。旧版已发布 1.9.0/1.9.1 不能凭版本号推定有这些能力；以项目实际公开声明及包内容取证，缺支持不能虚构 API，既有框架基线不在审查中自动提升。新重置保持模型身份和缺省字段置 undefined；核对嵌套初值不被编辑污染、反复重置恢复、特殊类型保持约定含义，以及不支持值在修改前失败。来源状态见[维护记录](form-hook-source.json)。

核对异步校验前防重、校验为 false/未挂载时不发送请求、关闭或换目标后旧校验不提交新对象，以及重置初值和复用后的历史校验清理。直接 `validate/resetFields/clearValidate` 需确认对象确为业务表单实例；公共包内部、其他对象同名方法不能机械报错。按实际证据判偏差或未证实，静态通过不冒充运行验证。

在所选模式已有报告/记录中简记各纳入表单的调用位置或符号、适用生命周期和结论，不新增六文件或逐字段机器矩阵。限定任务不扩为全项目迁移；纯注释检查保持原范围，明确要求完整规范检查时才报告相应既有功能偏差，审查始终不修改业务实现。

## 字典展示共用取证（FE-019 / FE-025）

字段说明与类型先按 [FE-010 动态字典字段与固定枚举](dictionary-field-contract.md)区分：动态字典保留中文含义、准确 key 与 `@dictKey`，不以未罗列全量取值判缺项，也不要求按当前字典选项生成封闭 TS 类型；固定协议、已明确的接口枚举与业务判断所依赖值仍须核对约束和含义。适用于正式审查、变更审查及命中的开发自检；纯注释范围不要求修改类型。来源见[字段契约维护记录](dictionary-field-source.json)。

三组件的 Props、选项字段、入口、空值及方法/插槽先读随包 [组件库入口](../knowledge/PIGX前端开发规范/aura-ui组件库/README.md)，不要求跨技能安装。

本节适用于三种模式中命中的字典范围；当前表格规则来自 FE-012 规范工作树，来源见[待绑定记录](dictionary-source.json)，历史补充见[原变更记录](readability-source.json)。

表格、详情及交互文案的组件选择统一按 [FE-012 字典展示规则](dictionary-table-contract.md)执行（[待绑定来源](dictionary-source.json)）：字典展示以原始 code + options 按语义选择组件；状态/结果/严重级别等独立分类标识优先 `AuraDictTag`，连续描述、规则摘要、句内枚举与行内交互提示可 `AuraDictText`，即使在表格内。触发规则摘要“离开区域 · 持续 · 时长”保留 Text 与行内排版，不强制逐片段改为 Tag。嵌套/弹窗表格、私有组件和动态列均检查同一语义边界，筛选继续按 Select 契约。真实实体/物模型事件名称先确认无字典关联，不凭 `*Name` 后缀机械整改。

沿“接口原始 code + `@dictKey`/真实字典关联 → 表格列/私有组件/可配置或动态列 → 最终组件渲染”取证，逐项核对传入的原始值、options 来源以及 formatter/slot/render 分支，不能只看组件名出现或零扫描命中。静态扫描不能证明动态列与交互语义均符合，未能追踪的链路保留缺证。核对实际依赖/锁定版本、已安装 exports/types、显式 import 或自动导入/Resolver 注册及真实使用；只检查公开契约，不开展 SDK 底层审计。组件或依赖缺失按证据记偏差或缺证，不自动升级，也不转为手写映射。源码仓库名 `aura-web-sdk` 的 UI 包公开名为 `@fxft/aura-ui`；不得虚构 `@fxft/aura-web-sdk` 包名或把 `DictTag` / `DictText` 当作已核实的公开导出。

筛选/表单使用 AuraDictSelect 时，FE-019 / FE-025 核对选项真实来源、modelValue 与 valueKey 类型一致性、multiple 数组、labelKey、placeholder、公开 change/update:modelValue 事件及远程加载条件；不用其他展示组件的 String 匹配规则替代 Select 取证。filterable 属 ElSelect 透传能力，未暴露的方法或插槽不能虚构。

组件默认行为仅是公开契约事实，不意味着业务必须自行增加兜底。fallback 或未知值展示按真实需求配置；未经要求不新增转换、硬编码或覆盖值，不用自设 fallback 掩盖字典类型、选项来源或编码匹配错误。说明当前用途时写具体业务语义，不把组件默认行为描述成业务额外实现。 审查需区分未传 fallback 时 SDK 默认显示原值与业务自写兜底，不能凭原值显示推定页面新增转换；仍沿真实字典与编码取证。

## 规范选读

正式审查或首次确认项目边界时读 [前端总览](../knowledge/PIGX前端开发规范/PIGX前端开发总览.md)；已确认项目的局部审查直接按 rules.json 命中的 standard 路径读取正文和必要正反例。完整 27 条是本版前端规则集合，不要求局部任务全读，不延伸到其他领域。范围外要求单列边界，不把自己的建议写成正式规则。

本轮只读盘点脚本不替代模块联邦专项审计。需要使用专项工具时先确认可用；其 error/warning/manual 仍作为取证输入复核，不能直接换算为本结果包的规则状态。完整的冷启动、首次菜单与往返证据按模块联邦正文获取；静态配置通过不能代替运行验证。

## 判定

通过要求全部纳入适用对象有符合证据；偏差关联确认发现；未证实说明缺少什么证据及补证办法；不适用要有项目事实、范围和规则条件支持。多模块按对象保留分项，整体偏差优先，其次未证实。候选、规则、发现和对象各自统计。
