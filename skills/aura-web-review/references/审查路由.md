# 前端审查规则路由

完整原规则 ID、必要性与正文位置见 [rules.json](rules.json)，每条必须在结果矩阵中保留。下表只指导选读和取证，不另造技术要求。

仅选择目标前端项目的源码、配置、依赖与已有产物。接口字段使用公开契约或已有脱敏响应；没有材料时保留未证实，不查找其他领域代码补证。规范副本为前端审查视图，开发示例不构成修改或安装授权。

| 规则 | 检查对象 | 取证关系与边界 |
| --- | --- | --- |
| FE-001～005 | 页面、私有组件、共享组件、Store、状态视图 | 追踪职责与状态来源，逐项检查加载/空/失败/权限等适用状态；截图不证明全部交互 |
| FE-006～008、010～012 | 页面调用、领域API、请求适配、Mock、路由和权限 | 页面→API→统一请求，字段适配→展示；请求适配层允许封装，仅检查前端可见性与权限上下文，接口实际授权不在结论范围 |
| FE-009、013～018 | 表单校验、提交、弹窗、并发请求、分页、文件、时间枚举 | 操作发起→校验→提交→反馈/取消/销毁；检查旧响应与重复操作，缺运行环境时保留未证实 |
| FE-019 | 工程、命名、页面模式、字典与国际化、表单Hook | 对照生成与页面模式查真实职责；方法名命中不证明业务层重复实现 |
| FE-020～021 | 框架保护区、config/aura、web-kit公开入口与版本 | 先核对安装包exports和类型，再判断是否复制公共能力；源码新版本不能代替项目已安装能力 |
| FE-022 | 菜单、路由、remote身份和实际入口 | 菜单响应/路由→页面/expose，必要菜单字段或配置材料缺失时未证实，不虚构菜单与权限码 |
| FE-023 | Vite、依赖、exposes、shared、runtime、manifest与产物 | 采用1.23.5/1.9.0与TS5.9.3配套；配置→最终发现报告/optimizeDeps→独立/宿主加载；不依赖另一个技能安装 |
| FE-024 | scope根节点、主题、CSS、import/public资源 | 挂载范围→样式/资源URL→提供方产物；字符串扫描只是候选 |
| FE-025 | 组件公开入口、实际resolver与ui-plus | 核对FxftMap、FxftWebVideo、FxftWebMultiVideo；aura-ui本轮范围排除、不计未证实；ui-plus正常核对依赖/导出/resolver/调用，FE-025只判纳入子项 |
| FE-026 | 系统字体源、Iconfont配置与加载 | 配置→初始化→CSS/字体请求；无运行证据不宣称冲突校验成功 |
| FE-027 | 类型、lint、构建、产物、独立和远程运行 | 读取项目真实scripts并检查副作用；TS/ESLint配套、专用配置检查和业务全量检查结论分开 |

## 规范选读

先读 [前端总览](../knowledge/PIGX前端开发规范/PIGX前端开发总览.md)，然后按 rules.json 命中的 standard 路径读取正文和必要正反例。完整27条是本版前端规则集合，不延伸到其他领域。范围外要求单列边界，不把自己的建议写成正式规则。

本轮只读盘点脚本不替代模块联邦专项审计。需要使用专项工具时先确认可用；其error/warning/manual仍作为取证输入复核，不能直接换算为本结果包的规则状态。完整的冷启动、首次菜单与往返证据按模块联邦正文获取；静态配置通过不能代替运行验证。

## 判定

通过要求全部纳入适用对象有符合证据；偏差关联确认发现；未证实说明缺少什么证据及补证办法；不适用要有项目事实、范围和规则条件支持。多模块按对象保留分项，整体偏差优先，其次未证实。候选、规则、发现和对象各自统计。
