# AURA 技术详细设计

形成能指导实现的技术设计，不直接改业务代码。版本见 `VERSION`；仅追溯来源时检索[来源记录](references/source.json)，不预读来源记录或全部规范。

## 选择任务和资料

先按[详细设计规范](references/standards/02-详细设计规范/01-详细设计规范.md)的 `AURA-DES-001/002` 判断完整或简化设计。纯文案、样式或机械修改不强制完整设计；已有设计先核对有效性与本次差异。

| 当前任务 | 按需读取 |
| --- | --- |
| 新建设计 | 从[文档模板](references/standards/02-详细设计规范/02-技术详细设计文档模板.md)选择适用部分；按下述证据链完成一份主设计 |
| 修订已有设计 | 先读原设计和本次差异，再按[任务路由](references/任务路由.md)的修订路径，仅更新受影响模块、契约、图和实施步骤；保留有效编号与未变内容 |
| 只读复核设计 | 按[任务路由](references/任务路由.md)的复核路径，输出问题、位置、规则、证据及准入建议；未要求修改时不改原设计或代码 |

需要理解多模块组织时，按问题选读[设备审核通知示例](references/standards/02-详细设计规范/03-技术详细设计文档示例-设备审核通知.md)的相关章节；它不是项目事实或可直接复用的框架实现。

## 形成和复核设计

先读取需求、原设计、现有项目结构、相关代码与公开契约，记录关键事实的路径及版本；区分事实、约束和假设。按“需求/风险 → 技术取舍 → 模块与契约 → 数据及运行链路 → 实施和验证”形成证据链。只读命中规则及其正反例，不为单次修订全文加载所有资料。

一项业务一份主设计，多模块在同文档中给出拓扑及实现卡片；编号贯通契约、图和步骤。沿用项目/模块 docs 及既有索引，不按模块复制主设计。已有模块接口文档引用具体章节，不重复维护整套字段；影响方案的失败、权限和兼容决策仍在设计中可见。

设计深度按真实影响决定；未核实的契约、版本、配置、能力或运行行为保持待确认。缺口会改变关键业务、安全或恢复方案时保留未决项并请求负责人决定，其余独立部分继续。不以代码可推断代替负责人对业务规则的确认。

## 检查与交付

Python 3，仅只读检查指定设计文件，在本技能目录执行：

```text
python -X utf8 scripts/check-detailed-design.py --design <设计文件> --mode full
# 简化设计用 --mode simplified；需要逐项结果时追加 --json。
```

脚本核对占位内容、模块/契约编号、模块卡片、准入选项及本地文档链接；不全文读取脚本实现。退出 0 仅说明这些机械项未发现问题，1 为确定错误，2 为占位或格式不支持等检查不完整。失败后读具体位置，修正或记录未完成项；不按脚本提示重写无关章节。使用参数见[使用说明](USAGE.md)。

仍须按 `AURA-DES-003～012` 复核技术链路、方案取舍、失败恢复、权限、配置部署、兼容与联调计划。按规范给出“可进入编码 / 有条件进入编码 / 阻断”；有条件时明确可先实施范围、负责人、解除条件和复核时点。脚本无错误不能证明设计充分，未执行的构建或联调不写成通过。交付说明实际文档位置、本次变化、准入依据和未决项，不另造过程附件。

进入实现时才衔接对应开发技能；新增/变更接口契约时衔接可用的接口技能同步模块文档，缺少该技能时明确文档待办，不假称已调用。设计涉及能力时只读命中的公开资料，不加载内部治理；本技能不替代项目规范审查。
