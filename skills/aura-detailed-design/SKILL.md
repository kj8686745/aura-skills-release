# AURA 技术详细设计

询问如何调用本技能时，阅读[使用说明](USAGE.md)。技能版本见 `VERSION`，对应 `0.1.0-draft` 详细设计规范，当前可公开试用，行为验收待完成；三份随包资料的提交与摘要见[来源记录](references/source.json)。规范正文是规则来源；本技能只负责按任务选读、形成设计和复核设计，不另定义技术规则。

## 选择任务和资料

先按[详细设计规范](references/standards/02-详细设计规范/01-详细设计规范.md)中的 `AURA-DES-001/002` 判断本次变更是否需要完整或简化设计。纯文案、样式或不改变行为的机械修改，不机械生成完整设计；已有有效设计覆盖的变更，先核对差异再决定是否补写。

| 当前任务 | 按需读取 |
| --- | --- |
| 判断设计触发、深度、边界或评审是否足够 | [详细设计规范](references/standards/02-详细设计规范/01-详细设计规范.md)中命中的规则和正反例 |
| 编写一项业务变更的技术详细设计 | [详细设计规范](references/standards/02-详细设计规范/01-详细设计规范.md)和[文档模板](references/standards/02-详细设计规范/02-技术详细设计文档模板.md)；只填写适用章节 |
| 理解多模块文档如何贯通架构、契约、数据和实现路线 | 按问题查看[设备审核通知示例](references/standards/02-详细设计规范/03-技术详细设计文档示例-设备审核通知.md)，不照搬其中业务接口和技术事实 |

## 形成和复核设计

先读取需求、现有项目结构、相关代码与公开契约，区分已证实事实、外部约束和待确认假设。用同一份主文档说明一项业务的总体技术方案；涉及多个模块时，先给模块拓扑与协作关系，再为每个实际变更模块编写技术实现卡片。模块、契约、图与实施步骤使用一致的编号。

设计应让开发者能够定位工程落点，理解主流程、失败路径、状态、数据所有权、权限与上下文、外部能力入口、兼容和恢复方式，并按技术实现路线图执行。设计深度由真实影响决定；不适用项说明原因，未核实的接口、版本、配置或运行行为保持“待确认”，不能从示例推断为项目事实。

交付前按规范 `AURA-DES-003` 至 `AURA-DES-012` 和模板自检：关键决策能追溯到需求或风险，模块与契约编号一致，主链路和异常链路闭合，方案取舍、配置部署、联调与验证计划明确。按规范给出“可进入编码 / 有条件进入编码 / 阻断”结论，有条件时写清可先实施范围与解除条件；未执行的构建、联调或测试不能写成通过。

本技能不替代前后端基础编码、接口契约或能力包使用技能。任务进入代码实现时再调用对应开发技能；设计涉及专项能力时，只读取命中的公开能力说明和契约，不加载内部治理资料。关键业务规则、权限语义或公开契约缺失且会改变方案时，保留未决项并请求负责人确认，不自行决定。
