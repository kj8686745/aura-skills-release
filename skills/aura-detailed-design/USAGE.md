# 技术详细设计技能使用说明

业务变更涉及模块协作、数据或状态、接口、权限、外部能力或运行边界，需要编写或复核编码前的技术详细设计时，可让 Codex 自动选择本技能，也可显式调用 `$aura-detailed-design`。

提供需求或问题、目标项目位置、已有接口与架构资料，以及已确认的业务规则即可。技能会先核对项目事实和设计触发条件，再使用随技能提供的规范、模板和示例；不要求使用者填写一份技能专用表单。

示例：`$aura-detailed-design 根据当前工程和设备审核需求，形成一份覆盖前端、后端和通知模块的技术详细设计；列出未核实的契约和必须确认的问题，不修改业务代码。`

已有设计可直接说：`只调整现有设计中 M-02 的持久化方案，核对受影响的契约、失败链路和实施步骤，保持其余章节不变。` 只需评审时说明“只读复核”，技能应交付带规则和原文位置的问题与准入建议，不直接修改文档或业务代码。

完整设计以一份主文档承载多个模块卡片，沿用项目/模块 docs 和索引；已有接口文档通过具体章节链接关联，不复制成两套完整字段定义。完整或简化设计由真实影响判断，不要求所有任务填满模板。

## 文档机械检查

需要 Python 3，仅标准库；在本技能目录执行，`--design` 可用绝对路径或相对当前目录的路径，包含空格时加引号：

```text
python -X utf8 scripts/check-detailed-design.py --design <设计文件.md> --mode full
python -X utf8 scripts/check-detailed-design.py --design <设计文件.md> --mode simplified --json
```

脚本不写文件、不访问网络、不执行文档中的命令，也不扫描项目源码。完整模式检查模板约定的模块清单、契约清单及变更模块卡片、编号引用；确无模块或契约时，在对应清单节写“无”并说明原因。简化模式不要求完整表格，但核对模板规定的八项简化记录。两种模式均检查常见模板占位、单一准入选项和本地 Markdown 文档链接；远端链接与章节锚点不自动验证。

默认仅输出摘要与问题位置，`--json` 提供完整结构化结果。退出 `0` 表示支持范围内的机械检查无已识别问题；`1` 为确定错误（如重复编号、失效文档链接或输入不可读）；`2` 为未完成（如残留占位、缺少或不支持的模板结构）。自定义表头、复杂 Markdown 表格或代码块中的模型不能可靠解析时，应人工复核，不能为迎合工具改变既有有效技术方案。

脚本不检查架构正确性、真实代码一致性、幂等可靠性、权限有效性或设计充分性。编码准入仍须依据规范、代码及公开契约；记录预期验证不能当作已运行验证。当前版本及发布资格分别由 `VERSION` 和管理工具中的目录登记决定，本地改造不自动发布或安装。
