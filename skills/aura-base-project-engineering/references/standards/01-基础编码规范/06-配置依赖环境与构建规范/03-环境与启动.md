# AURA（天玑）基础编码规范：环境与启动

<!-- 规范版本：0.1.0-draft -->

**适用对象**：使用 AURA 开展业务应用、服务、工具和平台工程开发的团队和开发人员

**规范目标**：让环境入口、启动过程、健康状态和初始化失败行为可发现、可解释、可恢复。

**边界说明**：本文件负责环境入口和启动行为；配置键与动态配置见本目录配置管理，构建命令与产物见构建与交付。

## 一、环境与启动规则

### AURA-BASE-ENV-001：环境入口必须唯一且可发现

**必要性**：必须

**为什么需要**：统一环境入口可以让开发者快速判断启动方式、配置来源和服务依赖，避免不同脚本产生不一致行为。

项目必须明确启动入口、环境配置入口、覆盖优先级和本地运行方式。不得依赖个人机器上的隐式变量、缓存文件或口头配置才能启动。

**正确写法**：根 README 明确启动命令、配置入口、覆盖顺序和本地依赖，换一台机器即可按说明启动。

**错误写法**：依赖个人环境变量、IDE 配置或本机缓存才能启动。

**判断要点 / 验证方式**：在干净环境按文档启动，记录缺失入口和隐式依赖。

### AURA-BASE-ENV-002：启动行为必须可解释

**必要性**：必须

**为什么需要**：启动阶段明确校验、默认值和失败原因，才能快速区分配置错误、依赖不可用和代码故障。

启动类和初始化逻辑只负责启动、框架装配和必要初始化，不得隐藏业务写入、无限等待或不可控的外部调用。初始化任务必须说明关键性、超时、失败和重试策略。

**正确写法**：初始化任务声明关键性、超时、重复执行行为和失败策略；会写入业务数据的任务具备幂等或冲突保护，非关键预热失败进入可定位的降级状态。

**错误写法**：启动线程全表加载、无限等待下游，异常被吞掉后仍报告启动成功。

**判断要点 / 验证方式**：测试重复启动、依赖超时、部分失败、重试和重新触发。

### AURA-BASE-ENV-003：存活与就绪必须区分

**必要性**：必须

**为什么需要**：存活表示进程仍在运行，就绪表示能够接受业务工作，区分两者可以避免流量进入尚未可用的实例。

对于向外提供服务且参与流量路由的项目，存活表示进程能够运行，就绪表示服务具备接收流量的条件。必要依赖不可用时应影响就绪；非关键依赖应以降级状态和可定位告警表达，不得通过健康检查泄露敏感信息。不接收流量的命令行工具和一次性任务不要求提供存活/就绪探针，应以退出状态或任务结果表达成功与失败。

**正确写法**：存活探针只判断进程，必要数据库不可用时就绪失败，非关键依赖以降级状态告警。

**错误写法**：存活和就绪使用同一个端点，或关键依赖不可用时仍接收流量。

**判断要点 / 验证方式**：分别模拟进程、数据库、配置中心和非关键依赖故障。

## 二、典型使用示例：服务启动与就绪

**场景目标**：服务启动时校验必要配置和关键依赖，区分进程存活、业务就绪与非关键依赖降级，避免未准备好的实例接收流量。

**输入条件**：服务依赖数据库和配置中心；外部统计服务为非关键依赖；服务需要被流量路由组件探测。

**正确结构**：

```text
启动
 ├─ 校验必要配置与配置来源
 ├─ 建立数据库连接（有界超时）
 ├─ 数据库可用 → 就绪
 ├─ 统计服务不可用 → 保持存活、标记降级、告警
 └─ 必要配置或数据库不可用 → 启动失败或保持未就绪
```

```yaml
health:
  liveness: /health/live       # 只说明进程仍能工作
  readiness: /health/ready     # 说明已具备接收业务流量的条件
startup:
  database-timeout: 5s
  fail-on-missing-required-config: true
```

启动初始化不得写入业务数据或无限等待下游；有副作用的初始化必须幂等并明确失败策略。

**错误结构**：把存活和就绪合为同一个端点，数据库不可用仍返回就绪，或在启动线程中全表加载并无限等待统计服务。

**验证步骤与预期结果**：

1. 删除必要配置启动，预期失败并输出可定位的配置错误。
2. 模拟数据库不可用，预期实例不就绪；恢复数据库后按约定重新进入就绪。
3. 模拟统计服务不可用，预期实例保持存活但呈现降级状态和可定位告警。
4. 重复触发初始化，预期不重复写入业务数据。

## 三、开发者自检

- 是否能在干净机器按文档找到唯一启动入口；
- 启动失败、初始化超时和重复触发是否有可定位结果；
- 存活、就绪和降级状态是否表达不同含义；
- 一次性任务是否使用退出状态或任务结果，而不是虚构服务探针。
