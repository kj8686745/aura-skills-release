# AURA 系统初始化与工程维护

按当前任务建立或调整必要工程结构，保留现有有效入口。版本见 `VERSION`；仅追溯时检索[来源记录](references/source.json)中命中条目，不全文预读来源、矩阵或所有规范。

## 直接选路

| 当前任务 | 读取与完成边界 |
| --- | --- |
| 新建工程 | [工程结构](references/standards/01-基础编码规范/01-工程结构命名与项目文档规范/01-工程结构与代码组织.md)的 STRUCT-001～004 和[项目文档](references/standards/01-基础编码规范/01-工程结构命名与项目文档规范/03-项目文档与资料组织.md)的 DOC-001～004：核对真实模板及版本，建立根 README、根 docs 入口、必要代码与构建定义，不生成未来可能用到的层 |
| 增加或调整模块 | 同上命中条款，以及[职责分层](references/standards/01-基础编码规范/02-架构分层与模块边界规范/01-职责分层与依赖方向.md)：明确职责、依赖方向、实际入口和父工程登记；模块有独立资料时就近放 docs，否则不造空文档 |
| 局部配置、依赖或构建变更 | 从[任务路由](references/任务路由.md)直接选配置、依赖、环境或构建一项；保持其余结构，仅同步受影响入口、文档和验证方式 |

命名、版本交付等专项也从任务路由定位。只读当前规则、正反例及必要上下文；不要把总索引和路由串成必读链。

## 实施与交接

先识别项目根、真实构建方式、现有目录和任务范围，再修改。新工程优先用目标项目指定的真实框架模板；本包的规范结构示例不是脚手架。找不到框架模板、BOM 或准确版本时指出具体缺口，不虚构依赖坐标；可继续不依赖缺失事实的部分。

代码目录只按当前职责创建，不用空 DTO、Controller、Service、Mapper 或 package-info.java 凑层次。单纯工程维护不加载 HTTP、数据库、消息、调度或实时能力；进入具体后端业务时衔接可用的后端开发技能，能力用法从其包内模块选读，不再找独立能力使用技能。前端工程沿目标框架现行模板，不从共享规范例图推断其页面或模块联邦实现。

项目已有 AI 工作入口时沿用，不覆盖用户指令或重复生成会话状态；只有用户需要 AI 工作流初始化/续接且技能可用时才组合对应入口，普通工程调整不强制初始化会话。

## 检查

PowerShell 7，在技能目录按实际路径执行：

```powershell
./scripts/check-project-engineering.ps1 -ProjectPath <项目根> -ModulePath <本次模块>
# 新建工程或涉及根入口时追加 -IncludeProjectEntry，检查根文档及构建声明。
```

脚本只读处理指定目录的构建声明、模块路径、文档引用及空目录线索；根入口检查按范围显式选择。先看摘要，需要细节时用 `-Json`，较大结果用 `-OutputPath <临时JSON>` 后筛选 `issues` 等字段。参数和边界见 [USAGE.md](USAGE.md)，不必全文加载脚本实现。

退出 0 仅表示本次静态检查无已识别问题；1 为确定错误或执行失败；2 为候选/缺证据。模块职责、文档充分性、真实模板匹配和构建/依赖行为仍需复核。按项目实际执行相称的构建与验证，缺环境时明确未运行，不用目录存在或静态通过代替构建成功。

只报告本次新增/修改的工程入口、模块/依赖、文档、实际命令及未验证项；不自动执行全项目审查、提交、部署或发布。
