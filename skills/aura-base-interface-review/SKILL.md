# AURA 存量接口审查与调整

询问如何调用本技能时，阅读[使用说明](USAGE.md)。

本技能只用于已有系统的接口审查、契约收敛和迁移准备。新接口设计、模块接口文档编制使用 `aura-base-interface-development`；后端代码调整使用 `aura-base-backend-development`；规范治理、技能同步和发布检查使用 `aura-standard-maintainer`。本技能不因为发现差异就直接修改代码，也不把静态扫描结果写成运行时已验证。

本技能版本为 `1.0.0`，按随包快照适配 `0.1.0-draft` 基础编码规范。先在[规范矩阵](references/standards/01-基础编码规范/规范矩阵.md)定位适用规则，再按命中的规则与示例读取，不批量加载全部规范。

## 审查前提

开始前必须明确项目、分支或版本、服务边界、接口模块、前后端或服务间调用范围、是否允许修改代码，以及可取得的运行环境和调用证据。缺少项目边界、当前版本或关键调用方信息时，先输出“阻断/待补证据”，不得用猜测补齐。

## 审查步骤

### 1. 建立存量接口清单

只读盘点并按模块记录：

- 路由、HTTP 方法、网关前缀、Controller 或事件入口；
- 请求 DTO、响应 DTO、`R<T>`、历史响应封装、裸 `Map`、实体直出和字段转换；
- `PageResult<T>`、`Page/IPage`、历史分页对象及分页字段；
- 异常处理器、HTTP 状态码、业务错误码、`requestId`、`retryable` 和错误消息；
- 认证、用户、租户、数据范围和高风险动作权限；
- 前端 API 封装、Feign/HTTP 客户端、SDK、网关路由、接口文档和示例；
- 写入副作用、幂等条件、超时、重试、异步受理与最终状态查询。

每项都标记来源路径、代码位置、版本和证据类型，不只记录“存在/不存在”。

### 2. 形成统一契约对照表

将实际实现与当前规范逐项对照，至少覆盖：

| 对照维度 | 必须判断 |
| --- | --- |
| 响应包络 | 是否统一 `R<T>`；`code`、`msg`、`data`、`ok` 及错误字段是否稳定；不能因为调用方“内部/外部”再分出两套响应包络 |
| 业务数据 | 是否使用请求/响应 DTO；是否泄露持久化实体、内部字段、权限字段或未约定字段 |
| 分页 | 是否对外呈现 `PageResult<T>` 的 `records/total/size/current/pages`；ORM 的 `Page/IPage` 是否被错误暴露 |
| 错误 | HTTP 状态、业务 `errorCode`、安全消息、`requestId`、`retryable` 和调用方处理是否一致 |
| 路径与方法 | API 前缀、资源名、动作命名、方法语义和网关转发是否一致 |
| 身份权限 | 调用方身份、租户、数据范围和高风险动作是否都有代码或运行证据 |
| 兼容性 | 现有调用方是否能继续工作；是否有明确适配层、迁移窗口、版本标识和下线条件 |

不得把认证方式、数据范围或公开字段裁剪误判成另一套响应契约；只能记录为同一契约下的调用边界差异。

### 3. 识别调用方与影响范围

对每个差异追踪提供方、直接调用方、间接调用方和文档使用者。至少检查前端 API 层、Feign/HTTP 客户端、SDK、定时任务、消息消费者、网关和外部登记方。无法确认的调用方标记为“未知”，未知调用方不得直接进入破坏性迁移。

### 4. 分级并安排调整顺序

每条结果使用规则 ID、严重程度、影响范围、证据、建议动作和状态输出：

- **阻断**：公共调用方未知、认证/租户边界不明、破坏性变更没有迁移条件、运行契约与代码无法判定；
- **高**：响应包络、分页或错误语义会直接导致调用方解析失败；
- **中**：文档、字段说明、状态枚举、兼容窗口或错误处理不完整；
- **低**：命名、示例、注释或非行为性结构问题。

建议顺序为：先补齐现状和契约文档，再建立适配层或兼容转换，随后迁移提供方和调用方，最后在调用方清零、运行证据齐全后移除旧实现。不得先删旧接口再寻找调用方。

### 5. 授权后执行调整

只有用户明确授权代码或文档修改时，才进入调整阶段。先更新模块接口文档和兼容矩阵，再由后端技能调整 DTO、适配层、分页转换和异常映射；前端、SDK、网关或其他服务由各自技能在同一迁移顺序下处理。一次变更只保留一套新契约；兼容旧调用方必须有登记的期限、入口和删除条件。

调整后分别核对静态代码、文档、构建、自测和真实请求结果。单次查询、编译通过或搜索命中不能证明所有调用方和运行时行为已经完成迁移。

## 交付格式

按[存量接口审查报告模板](templates/存量接口审查报告模板.md)输出一份按模块组织的审查结果，不为每个接口机械创建一份文件。模板中的表格可以按模块追加行，但不能删除范围、证据、影响和结论字段。固定包含：

1. 审查范围、项目版本、证据边界和未覆盖项；
2. 存量接口清单与调用方清单；
3. 统一契约对照表（响应、业务数据、分页、错误、权限、兼容）；
4. 按规则 ID 编号的差异表：严重程度、现状、证据、影响、建议动作、责任技能、状态；
5. 分阶段调整顺序、每阶段完成条件和停止条件；
6. 正常、参数错误、认证/权限、重复请求、超时和版本兼容的验证记录；
7. `通过`、`需调整`、`阻断`、`未验证` 四类结论，不能用“已扫描”替代“已验证”。

审查结果只描述实际观察到的代码、文档和运行证据；没有证据的字段写明未知，不虚构框架能力、调用方或接口行为。
