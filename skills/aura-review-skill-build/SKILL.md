# AURA 审查技能构建

供内部领域负责人建设审查技能。交付目标技能的完整目录和建设验证记录，技术规则以负责人指定的同版规范为准。已有后端审查技能只提供流程参考，不将其后端规则套到前端。

## 资料与输入

先读[审查技能构建规范](references/governance/01-管理规范/审查技能构建规范.md)，编写目标技能的输出要求时读[审查结果包模板](references/governance/05-技能构建/审查结果包模板.md)。涉及证据深度、调用链、误报归并或经验复用时，再读构建规范的“审查经验沉淀与最终产出要求”。随包依据与版本见[来源记录](references/source.json)；查询如何交给负责人使用时读 [USAGE.md](USAGE.md)。

从用户任务、项目入口和 Git 信息确定领域、规范位置及版本、目标技能目录、框架适用范围与验证样本。缺少可自动确定的信息不重复询问；缺少关键规则或真实样本时列出未完成项，继续编写已有依据的部分。

## 建设工作流

1. **核对现有技能**：定位当前领域开发/审查技能及来源，决定新增还是更新。直接项目审查任务不进入构建流程，改由当前可用的领域审查技能处理；不能假称已经调用不存在的技能。
2. **建立规则路由**：按构建规范的规则要求，从指定领域规范映射规则 ID、必要性、检查对象、取证办法及证据局限。覆盖全部适用规则域，不只复用旧报告中已经发现的问题。若该领域存在基础能力包，必须把基础能力复用列为默认审查域；其他能力包只有在需求、依赖、配置、路由或代码行为触发时才纳入。前端选读构建规范第三节的前端范围。
3. **编写目标技能**：建立短 `SKILL.md`、`VERSION`、`USAGE.md`、`agents/openai.yaml`，携带按需规则引用与统一结果包模板。触发描述区分开发、审查和审查技能建设；默认可自动发现。具体执行资料分文件承载，不把整套规范塞进入口。
4. **落实自动审查与报告**：写入从版本冻结、全量资产盘点、基础能力复用与专项能力触发盘点、规则覆盖证明、跨文件调用链取证、候选归并、逐规则判定到六文件结果包复核的连续工作流。每个规则域必须说明纳入、实际检查和排除对象；命中必须经过调用链或配置链判定。环境缺口记未证实，继续其余步骤；不把每个阶段变成确认问题。报告按下述约定交付。
5. **验证真实行为**：先核对结构、相对链接和来源一致性，再用授权的隔离样本验证合规、违规、合理例外、缺证据及环境失败情形；同时验证显式/自然语言触发和相邻任务不误触发。实际检查结果包的规则覆盖、证据及统计，不能仅测试标题是否存在。无样本或未执行时如实记录，目标技能保留候选资格。
6. **沉淀经验并移交负责人**：把可复用的证据字段、调用链节点、误报排除条件和整改关闭条件写入目标技能的路由或参考资料；删除项目专属路径和偶然命中。合并记录来源、目标技能位置、规则映射范围、验证结果和剩余缺口；登记方向标签与发布状态。源码放技能仓库，构建依据和验证记录放规范仓库治理区。版本、提交、推送、发布分别报告；不以构建成功推断发布完成。

## 最终报告约定

目标审查技能必须把本包[结果包模板](references/governance/05-技能构建/审查结果包模板.md)复制到自己的 `references/审查结果包模板.md` 并由入口引用。审查执行产物固定为：

- `00-结果包说明.md`：版本、范围、状态与文件导航。
- `01-审查报告.md`：结论、覆盖摘要、逐项偏差卡片、符合项和补证项。
- `02-规则核查矩阵.md`：逐规则状态、必要性、覆盖范围与证据。
- `03-证据与执行记录.md`：资产数量、命令、环境、原始结果位置与限制。
- `04-整改与复核清单.md`：整改动作、关闭条件及复核证据。
- `05-扫描候选与判定.md`：原始命中、归并关系、确认/排除/待补证。

领域负责人可按模块分节并增加必要领域信息，保留公共字段、状态和统计口径。每个结果包还必须包含审查对象目录、规则覆盖证明、调用链或配置链摘要、证据等级与限制、候选归并关系、发现关闭条件和复核前后差异。原始日志、截图仅在需要时归入 `证据/`；不按每条发现增加报告文件。发现必须关联原规范 ID 和可复核证据；正则命中只是候选。严重性与证据等级分开，审查执行状态与项目质量结论分开，未提供评分规则时不自造分数。

本构建规范及内部建设记录只供维护者使用；生成的审查技能携带领域规范、执行路由和结果包模板，不携带内部构建流程。后端已存在的规则、响应及分页契约不得在建设前端技能时重新定义。
