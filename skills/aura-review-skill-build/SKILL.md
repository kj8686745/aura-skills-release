# AURA 审查技能构建

供内部领域负责人建设审查技能。交付目标技能的完整目录和建设验证记录，技术规则以负责人指定的同版规范为准。已有后端审查技能只提供流程参考，不将其后端规则套到前端。

## 资料与输入

新建技能时读取[构建规范](references/governance/01-管理规范/审查技能构建规范.md)的输入与六条构建规则；修改既有技能时只读命中规则和经验条目。确定输出时从[报告模板](references/governance/05-技能构建/审查结果包模板.md)选择单报告或六文件结构，不全文加载两套模板。版本读 `VERSION`，追溯时检索[来源记录](references/source.json)的命中条目；用法见 [USAGE.md](USAGE.md)。

从用户任务、项目入口和 Git 信息确定领域、规范位置及版本、目标技能目录、框架适用范围与验证样本。缺少可自动确定的信息不重复询问；缺少关键规则或真实样本时列出未完成项，继续编写已有依据的部分。

## 建设工作流

1. **核对现有技能**：定位当前领域开发/审查技能及来源，决定新增还是更新。直接项目审查任务不进入构建流程，改由当前可用的领域审查技能处理；不能假称已经调用不存在的技能。
2. **建立规则路由**：按构建规范的规则要求，从指定领域规范映射规则 ID、必要性、检查对象、取证办法及证据局限。覆盖全部适用规则域，不只复用旧报告中已经发现的问题。若该领域存在基础能力包，必须把基础能力复用列为默认审查域；其他能力包只有在需求、依赖、配置、路由或代码行为触发时才纳入。前端选读构建规范第三节的前端范围。
3. **编写目标技能**：建立短 `SKILL.md`、`VERSION`、`USAGE.md`、`agents/openai.yaml`，携带按需规则引用与统一结果包模板。触发描述区分开发、审查和审查技能建设；默认可自动发现。具体执行资料分文件承载，不把整套规范塞进入口。
4. **落实连续审查与报告**：冻结范围/版本，建立对象与分批队列，逐规则×适用单元取证；执行进度、技术结论、证据缺口分别登记。每批自动续下一批，未查不写成缺环境，不自行把全项目降抽查。后端对应基础功能必查，专项按触发。报告由实际判断整理，脚本仅处理范围/资产、依赖声明、候选采集和格式统计，不按域或无候选默认生成结论；涉及 SDK 时只审项目内的声明、配置、调用和适配，行为链在项目内 Client/Adapter 出口停止，不把 SDK 内部源码或依赖仓库纳入对象目录。实际中断在同包留下一步，不逐阶段等确认。
5. **验证真实行为**：核对结构、链接和来源，再在授权隔离样本验证符合、偏差、合理例外、缺证据、跨文件链和环境失败，并分别试用两模式；追加无扫描候选偏差、未完静态批次与套话矩阵反例。工具检查与独立试用分别留结果，人工复核覆盖和真实依据，不能以返回 0 代替判断。无样本或未执行时记录缺口，不晋级发布资格。
6. **沉淀经验并移交负责人**：把可复用的证据字段、调用链节点、误报排除条件、SDK 停止界面和整改关闭条件写入目标技能的路由或参考资料；删除项目专属路径和偶然命中。合并记录来源、目标技能位置、规则映射范围、可脚本化边界、验证结果和剩余缺口；登记方向标签与发布状态。源码放技能仓库，构建依据和验证记录放规范仓库治理区。版本、提交、推送、发布分别报告；不以构建成功推断发布完成。

## 最终报告约定

目标审查技能携带本包[双模式模板](references/governance/05-技能构建/审查结果包模板.md)到自己的 `references/审查结果包模板.md`，由入口按任务选读。日常变更默认只交一份报告，保留基线、结论、对象与规则覆盖、发现与证据、候选、整改六章；全项目保留下列六文件，专项按范围选择。不按接口或发现拆文件：

- `00-结果包说明.md`：版本、范围、状态与文件导航。
- `01-审查报告.md`：结论、覆盖摘要、逐项偏差卡片、符合项和补证项。
- `02-规则核查矩阵.md`：逐规则状态、必要性、覆盖范围与证据。
- `03-证据与执行记录.md`：资产数量、命令、环境、原始结果位置与限制。
- `04-整改与复核清单.md`：整改动作、关闭条件及复核证据。
- `05-扫描候选与判定.md`：原始命中、归并关系、确认/排除/待补证。

两种模式保留相同证据与统计口径。唯一规则按单元状态汇总，不按子行计数；F、C、原始命中、资产数量分别统计，未查对象保留。候选须经调用/配置链判定，严重性、证据类型与置信度分开；未定义评分不自造分数。复核保持基线与稳定 ID，结果归并同一报告/包，不每轮另建过程报告。

## 报告格式自检

PowerShell 7，在本技能目录执行：

```powershell
./scripts/check-review-result.ps1 -Mode Change -ResultPath <单报告.md>
./scripts/check-review-result.ps1 -Mode Project -ResultPath <六文件目录>
```

默认仅摘要，需要细节时加 `-Json`。脚本核对可解析结构、ID、统计、进度矛盾及重复依据风险；0 为未识别问题，1 为确定矛盾，2 为格式/取证需复核或仍有待办。`status` 是工具状态，`executionState` 是报告自述进度，均不证明项目合规或真实关闭；旧版仅兼容检查。新建目标技能需此工具时携带同源副本并登记摘要，不依赖本技能安装路径；既有技能在对应改造时接入，不静默更换模板。

复核保留历史F卡片：唯一当前整改状态已关闭且具备关闭条件和不同于初审的已定义新E回指，才允许当前矩阵不再列为偏差；重新打开后恢复当前偏差关联。工具只核对记录结构，历史发现总数与结构上关闭/其余卡片分别统计，不裁定真实关闭。

本构建规范及内部建设记录只供维护者使用；生成的审查技能携带领域规范、执行路由和结果包模板，不携带内部构建流程。后端已存在的规则、响应及分页契约不得在建设前端技能时重新定义。
