# 审查技能构建使用说明

交给前端或后端负责人时，提供整个 `aura-review-skill-build` 文件夹，包含 `references/`；安装到使用工具识别的技能目录后使用。也可直接让 AI 读取本目录的 `SKILL.md`。本技能是内部建设工具，不放入普通业务开发者的对外技能发布集合。

## 前端负责人可直接使用的任务

```text
使用 $aura-review-skill-build 建设 aura-frontend-compliance-review。
以 aura-code-nexus 中当前由前端负责人维护的前端规范为准，先记录规范提交；
结合现有前端技能核对适用框架和取证办法。
技能源码放到 aura-skills/skills/aura-frontend-compliance-review。
要求一次调用连续完成可执行审查；变更审查交单报告，全项目审查交六文件结果包。
通过指定的隔离样本验证正确、违规、合理例外和证据不足的判断。
没有提供样本时先完成技能建设并列出验证缺口，不把行为验证写成通过。
```

如果两个仓库不在当前工作区，补充实际位置即可；真实验证项目及允许的构建/浏览器执行范围由交接者给定。已有的前端开发技能仍负责开发任务，本任务另建审查技能。

## 更新后端审查技能

```text
使用 $aura-review-skill-build 复核现有 aura-backend-compliance-review，
按统一双模式模板检查规则覆盖、证据判定、连续流程和报告格式。
保留已有有效规则与后端事实，把需迁移部分及验证结果归并记录。
```

负责人应交回目标技能完整目录、规范来源版本、规则路由，以及实际执行的验证结果包和未解决缺口。创建了文件不等于完成真实项目审查或正式发布。

## 检查目标技能产生的报告

在本技能目录运行，要求 PowerShell 7：

```powershell
./scripts/check-review-result.ps1 -Mode Change -ResultPath <单报告.md> -Json
./scripts/check-review-result.ps1 -Mode Project -ResultPath <结果包目录> -Json
```

这是报告格式、可解析 ID 和统计自检，不扫描业务项目、不验证真实技术结论。返回 1 时按具体错误修正产物；返回 2 时人工核对不完整格式、多基线表或未裁定项，不删证据强行过检。零发现不能替代规则覆盖，基础能力和专项能力不能混为同一审查要求。真实来源、例外、调用链、未检查项及未运行结果仍由建设者和复核者确认。技能不自动上传、安装或变更发布状态。
