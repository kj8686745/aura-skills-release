# 深度审查与证据交付

按任务固定仓库、分支、完整提交、时间窗口与日期口径、作者别名、抽查或全量、规范适用性及人员分组。已有清楚范围直接执行。以技术身份和用户策略判断规范适用性，独立 SDK 按公开契约取证。某工作空间明确免审部分项目的 AURA 规范时，报告01标“排除”并写明依据，仍审 D/R/G，四份文件照常出。该策略由任务给出。

沿真实业务入口再查调用者、依赖、数据、状态、返回、异常清理和并发。用正例、失败路径及条件序列对照；同一技术原因只生成一个主发现，其他 F/D 或人员报告回指它。区分本窗口引入、存量首次确认和历史复核；缺引入证据就保留时间归属待核。可将六方向的结论压成小表，已查、未查及排除均给依据。

| 场景 | 找到完整证据后怎样判断 |
| --- | --- |
| 新类型与旧依赖 | 对照消费方实际解析坐标、声明版本、类型引入提交和公开入口。能证明坐标下没有类型时写触发及后果；解析受阻仅影响实测主张。修正声明或配套发布版本并核对新旧消费者，未经产物核对不假定所有已发布 JAR 等同源码。 |
| DDL 与通用查询 | 比较租户、软删或状态谓词与各实体真实表结构和迁移，沿失败到业务后果。使用可重复 SQL 或相称隔离环境复查真实列和结果，Mock 空列表只证明替身。 |
| 资源和异常清理 | 某步取得资源后、try 前创建第二资源失败，追踪第一个资源是否进入 finally。查询失败留下 PENDING 占位时，核对谁持有、是否回收、下次为何被抑制。建议使获取后每条失败路径可清理，并核对幂等和所有权。 |
| 代次与租约 | 写明 A 读取、B 恢复/发布、A 晚返回覆盖的交错；或执行者 A 超时失权、B 接手、A 再发布。核对发布侧和消费侧能否用代次、条件写或租约标记识别旧结果。只延长租约无法封住旧执行者。 |
| 权限与隐私 | 依据实际需求、已选授权策略与数据流。已有角色/名单/发布成员规则逐层查；假想的新限制不进入缺陷。只有真实日志、响应或存储路径及其暴露内容支持对应隐私判断。 |
| 前端生命周期 | 用 Vue/TS 入口、实际依赖版本、组件生命周期、请求/事件与客户端数据流定位。回放关闭、换目标、A 慢 B 快、旧错误/旧 finally。网络请求重复与真实重复写入分别记录。 |

条件缺陷须有完整触发和错误后果，可由源码与明确契约确认。无浏览器、无压测目标、未执行测试等进入验证边界。实际待补证写明缺哪个事实、什么结果改变结论、现有材料为什么无法获得和最小补证。保留环境受阻和实际 suite 计数，不能借历史记录宣称当前通过。

报告02把缺陷快查及推荐方案放前面。每项记录源码定位、原文、触发、影响、修改位置、实施顺序与关闭条件。原文复制连续 Git 行段，省略敏感行时改选可核验片段。修复示意单独标注，拟新增的类、方法或配置要明示。报告03核对真实消费者和现有模块归属，允许合理不提炼；报告04说明已证实的局部机制和限制，与同链缺陷互引。没有发现时写清检查依据及零项结论。

查询与 DDL、调用与依赖声明等需要多处证据的同一缺陷，先填原有的“源码定位”和“源码原文”，再连续填写“源码定位 2”和“源码原文 2”等成对字段。定位格式与主片段一致，原文分别紧随各自字段置于围栏。使用各片段真实仓库与提交。工具分别核对并记录每一段，缺陷仍按一项计。

## 核验与转发

PowerShell 7 和 Python 3.9+ 执行新版报告检查。先按模板完成四份 Markdown，附件只留必要的脱敏文本。为源码验证在报告目录外建本地 JSON 映射，键为报告中“源码定位”使用的仓库标识，值为 `{"path":"本地仓库根目录","origin":"已核对且无凭据的 origin URL"}`。该映射仅供核验，不随 ZIP。原 v2.0 四份报告仍用原字段校核，历史单报告或六文件用 `-Legacy`。

```text
pwsh -NoProfile -File scripts/check-review-result.ps1 -Mode Change -ResultPath <四份报告目录> -SourceMap <仓库映射JSON> -Json
python -B -X utf8 scripts/review-share.py --report-dir <四份报告目录> --sources <仓库映射JSON> --output <新建ZIP>
python -B -X utf8 scripts/review-share.py --verify-archive <收到的ZIP> --expected-sha256 <可信渠道提供的ZIP摘要>
```

全项目用 `-Mode Project`，纳入规范时可传 `-MatrixPath` 核对规则。导出需 `markdown-it-py`（可在本机 Python 环境执行 `python -m pip install markdown-it-py`），接收端仅需浏览器/解压工具。ZIP 含同源四份 Markdown、自包含 HTML、清单及正文相对引用的证据目录文本附件（Markdown、JSON、TXT、CSV）。其他格式先转成读者可直接阅读的脱敏摘录。工具读取指定 Git blob 并核对原文，只有 CRLF 转 LF 的归一化；确认缺陷的 ZIP 必须提供本地映射。仓库网页链接仅补充，需另行核对登录权限和页面。

四维格式、统计、源码及包内链接均需核对，再用真实浏览器以断网或拦截请求方式打开 HTML，检查导航、附件正文、窄屏及桌面阅读。人工复核技术依据及脱敏；模式检查只是线索，不能覆盖所有凭据、确定业务因果或代表项目运行验收。

分享导出返回 ZIP 的 SHA-256。接收方可以离线核对文件集合、报告和 HTML 摘要，使用可信渠道收到的 ZIP 摘要确认包是否一致。只校验内部清单时可省略摘要参数，结果会明确显示是否比对了外部摘要。需要独立复查源码时再传入本地 `--sources`，否则实际回读 Git 的摘录数为零。2.1.0 已生成的旧单段分享包仍可做完整性检查。
