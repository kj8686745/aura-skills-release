# templates 与 examples 分工

## 核心区别

| 目录 | 定位 | 使用方式 |
|------|------|----------|
| `templates/` | 可复制的最小生成骨架和强约束 | 新增页面、API、Pinia、组件时先匹配模板，按模板起步 |
| `examples/` | 完整示例、风格参考、组合实践 | 需要看真实写法、样式组合、交互细节时参考，不作为强制结构 |

## templates 放什么

- 文件结构建议。
- 必须遵守的项目约束。
- 最小可运行代码骨架。
- 分场景生成模板。
- 不写过多真实业务字段。
- 不绑定具体页面接口。

## examples 放什么

- 更接近真实业务的完整 `.vue` 示例。
- 多个规范组合后的成品参考。
- Tailwind + Element Plus 主题变量写法。
- 插槽、双向绑定、弹窗、列表卡片等完整组件实践。
- 可以模仿风格，但不能无脑照搬业务字段和接口。

## 判断规则

- 如果内容是“生成一个新文件应该从这里复制起步”，放 `templates/`。
- 如果内容是“看这个学习最终效果和风格”，放 `examples/`。
- 如果内容是“步骤和决策流程”，放 `recipes/`。
- 如果内容是“原则、约束、项目画像”，放 `references/`。
