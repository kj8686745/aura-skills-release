# 代码生成约束

## 适用场景

- 模型生成 PIGX 项目页面代码时必须遵循的规则
- 作为所有页面生成任务的底线约束
- 补充各页面模式规范中未覆盖的通用约定

---

## 一、脚本写法约束

### 1. 必须使用 `<script setup lang="ts">`

```vue
<script lang="ts" name="ModulePageName" setup>
```

- `lang="ts"` 必须
- `name="..."` 通过 `vite-plugin-vue-setup-extend` 支持，用于 keepAlive 标签缓存识别
- 命名规范：`name` 值采用大驼峰，如 `SystemDictPage`、`AdminClientForm`

---

### 2. Vue 响应式 API 无需手动 import

`unplugin-auto-import` 已配置自动导入，以下 API **直接使用，不写 import**：

```typescript
// 正确 ✅
const count = ref(0);
const state = reactive({});
const result = computed(() => count.value * 2);
onMounted(() => {});
nextTick(() => {});
watch(count, () => {});

// 错误 ❌
import { ref, reactive, computed, onMounted } from 'vue';
```

同样自动导入的还有：`watchEffect`、`toRef`、`toRefs`、`defineProps`、`defineEmits`、`defineExpose`、`useRoute`、`useRouter`

---

### 3. 项目内部路径使用 `/@/` 别名

```typescript
// 正确 ✅
import { fetchList } from '/@/api/admin/client';
import { useTable } from '/@/hooks/table';
import { useMessage } from '/@/hooks/message';

// 错误 ❌
import { fetchList } from '../../../api/admin/client';
import { fetchList } from '@/api/admin/client';
```

## 二、模板写法约束

### 4. 按钮权限必须使用 `v-auth`

```vue
<!-- 正确 ✅ -->
<el-button v-auth="'sys_client_add'" @click="openDialog()">新增</el-button>

<!-- 错误 ❌ — 不要省略权限控制 -->
<el-button @click="openDialog()">新增</el-button>
```

权限码命名规范：`模块_实体_操作`，如 `sys_client_add`、`sys_client_del`

---

### 5. 子组件使用 `defineAsyncComponent` 异步引入

```typescript
// 正确 ✅
const FormDialog = defineAsyncComponent(() => import('./form.vue'));

// 错误 ❌
import FormDialog from './form.vue';
```

仅限同模块内的子组件（弹窗、抽屉、子列表）。全局组件和第三方库组件不需要手动引入。

---

### 6. 全局注册组件直接使用，无需 import

以下组件无需在页面中 import：

```vue
<!-- 直接使用，无需 import ✅ -->
<pagination v-bind="state.pagination" @size-change="..." @current-change="..." />
<right-toolbar v-model:showSearch="showSearch" @exportExcel="..." @queryTable="..." />
<dict-tag :options="xxx_dict" :value="row.xxx" />
<dict-select v-model="form.status" dict-type="xxx" />
<upload-file v-model="form.url" />
<upload-img v-model="form.avatar" />
<org-selector v-model="form.deptId" />
<splitpanes><pane>...</pane></splitpanes>
```

---

### 7. 查询表格列必须统一写法

```vue
<el-table
  :data="state.dataList"
  v-loading="state.loading"
  @sort-change="sortChangeHandle"
  :cell-style="tableStyle.cellStyle"
  :header-cell-style="tableStyle.headerCellStyle"
>
  <el-table-column type="selection" width="40" align="center" />
  <el-table-column type="index" label="#" width="60" />
  <el-table-column prop="fieldName" label="字段名" show-overflow-tooltip />
  <el-table-column prop="status" label="状态" show-overflow-tooltip>
    <template #default="scope">
      <dict-tag :options="status_dict" :value="scope.row.status" />
    </template>
  </el-table-column>
</el-table>
```

- `type="selection"` 固定 `width="40"`，并设置 `align="center"`
- `type="index"` 固定 `width="60"`；标题较长时可用 `width="80"`
- 普通数据列默认加 `show-overflow-tooltip`
- 自定义列插槽统一使用 `#default="scope"`，不要把 `#default="{ row }"` 作为生成默认写法
- 表格样式必须来自 `useTable(state)` 返回的 `tableStyle`

```typescript
const { getDataList, currentChangeHandle, sizeChangeHandle, sortChangeHandle, downBlobFile, tableStyle } = useTable(state);
```

## 三、API 层约束

### 8. API 函数命名规范

```typescript
// src/api/module/xxx.ts

export const fetchList = (query: any) =>
  request({ url: '/module/xxx/page', method: 'get', params: query });

export const getObj = (id: string) =>
  request({ url: `/module/xxx/${id}`, method: 'get' });

export const addObj = (data: any) =>
  request({ url: '/module/xxx', method: 'post', data });

export const putObj = (data: any) =>
  request({ url: '/module/xxx', method: 'put', data });

export const delObj = (ids: string[]) =>
  request({ url: '/module/xxx', method: 'delete', data: ids });
```

---

### 9. 不得直接使用 axios

```typescript
// 错误 ❌
import axios from 'axios';
axios.get('/api/xxx');

// 正确 ✅ — 统一走 request.ts
import request from '/@/utils/request';
```

## 四、国际化约束

### 10. 文本必须使用 i18n，不硬编码

```vue
<!-- 正确 ✅ -->
{{ $t('common.addBtn') }}
{{ $t('common.queryBtn') }}
{{ $t('common.delConfirmText') }}

<!-- 临时文本可暂时硬编码，但需标注 TODO -->
<!-- TODO: i18n -->
<span>暂无数据</span>
```

### 11. 模块 i18n 文件组织方式

每个业务模块在 `views/xxx/i18n/` 目录下放国际化文件：

```
views/
└── admin/
    └── client/
        ├── index.vue
        ├── form.vue
        └── i18n/
            ├── zh-cn.ts
            └── en.ts
```

## 五、样式约束

### 12. 页面样式使用 `<style scoped>`

```vue
<style scoped>
.xxx { ... }
/* 穿透子组件样式 */
:deep(.el-table__cell) { ... }
</style>
```

### 13. 不引入全局样式类，必须使用已有工具类

项目已有工具类（`mb8`、`mt8`、`ml10`、`mr10`、`mb20` 等）直接用，不另写相同效果的 CSS。

### 14. 新页面必须遵守 flex 高度链路

新增业务页面默认使用项目外壳提供的高度体系：

```text
html/body/#app -> layout-container -> layout-main -> layout-parent -> layout-padding -> layout-padding-auto layout-padding-view
```

- 最外层使用 `<div class="layout-padding">`
- 内容区使用 `<div class="layout-padding-auto layout-padding-view">`
- 查询表格页按“查询区、工具栏、表格、分页”纵向放置，让 `el-table` 自动占满剩余高度
- 不要在业务页另写 `height: 100vh`、全局固定高度或独立滚动外壳

---

## 六、生成强制判断顺序

当原型 HTML 与规范冲突时，按以下强制顺序判断：

1. 本文档的代码生成约束（强制）
2. 对应页面模式规范文档（强制）
3. PIGX 标准样例（推荐）
4. 原型 HTML 结构（校准）
5. 原型截图（校准视觉）

## 七、常见错误清单

| 错误 | 正确做法 |
|------|----------|
| `import { ref } from 'vue'` | 直接用，无需 import |
| `import FormDialog from './form.vue'` | 用 `defineAsyncComponent` 异步引入 |
| 路径用 `@/` 开头 | 改为 `/@/` |
| 表格手写分页逻辑 | 用 `useTable` hook |
| 表格不传 `tableStyle` | 解构并绑定 `useTable(state)` 返回的 `tableStyle` |
| `selection` / `index` 列不设宽度 | 分别设置 `width="40"` / `width="60"` |
| 普通表格列缺少 tooltip | 添加 `show-overflow-tooltip` |
| 表格插槽写法不统一 | 使用 `<template #default="scope">` 和 `scope.row` |
| 弹窗直接 `visible = true` 打开 | 通过 `defineExpose({ openDialog })` 暴露方法 |
| 请求写在模板 `created`/`onMounted` 中 | 抽到 `src/api/` 层 |
| 不加 `v-auth` 权限控制 | 每个操作按钮加对应 `v-auth` |
| `<script setup>` 没有 `name` 属性 | 加上 `name="XxxPage"` |
| 新页面另写 `height: 100vh` 或自建滚动外壳 | 遵守项目 flex 高度链路，使用 `layout-padding` 容器 |
