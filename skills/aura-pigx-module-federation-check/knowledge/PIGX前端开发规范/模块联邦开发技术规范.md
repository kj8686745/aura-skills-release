# 综合端模块联邦开发指南

## 前言：什么是模块联邦综合端

模块联邦允许多个前端工程独立开发、构建和部署，并在浏览器运行时按需加载彼此提供的页面、组件、API 或工具。每个工程仍然拥有自己的仓库、版本和发布节奏，不需要把所有业务打进一个大包。

综合端同时承担两种角色：

- **消费方**：加载 aura-core 提供的布局、主题和公共能力，也可以按业务需要加载其他远程模块。
- **提供方**：把自己的页面、组件、API、工具、国际化和样式提供给其他综合端。

综合端既可以独立运行，也可以作为远程模块被其他综合端加载。它不是 iframe；远程加载时也不会加载提供方的 index.html，所以国际化、Tailwind、页面 CSS 和静态资源都必须按本指南适配。

一个典型场景如下：

~~~text
订单综合端
├── 消费 aura-core 的布局、主题和公共能力
├── 独立运行订单业务
└── 对外提供 ./views/order/list/index.vue

其他综合端
└── 通过 /aura-order-web/views/order/list/index.vue?type=moduleFederation
    动态加载订单列表页面
~~~

运行时加载链路：

~~~text
后端菜单 componentPath
→ 解析 remoteName 和 expose path
→ 注册远程入口
→ 加载远程 i18n、Tailwind 和页面 CSS
→ 加载远程 Vue 页面
→ 挂载到当前综合端内容区
~~~

## 一、创建项目后必须先改名

### 1. 开发环境要求

模板已验证的开发环境为 Node.js 20.12 及以上版本、pnpm 10.28.0。Node.js 18 缺少模块联邦构建链使用的 `node:util.styleText`，不能用于本模板构建。

~~~bash
node --version
pnpm --version
pnpm install --frozen-lockfile
~~~

正确版本示例：

~~~text
v22.22.1
10.28.0
~~~

### 2. 占位名称不能直接使用

模板中的 pigx-nexus、pigxNexus 只是脚手架占位名称。真实业务项目必须修改，不能让两个项目使用相同的 remoteName、remoteEntryName 或 systemId。

三个名称的职责不同：

| 配置 | 示例 | 用途 |
| --- | --- | --- |
| remoteName | aura-order-web | 模块联邦容器名、后端菜单第一段、运行时注册名、Tailwind scope |
| remoteEntryName | auraOrderWeb | 独立部署访问前缀，例如 /auraOrderWeb/ |
| systemId | order-web | Token、Storage 和运行时站点配置隔离 |

错误示例：

~~~text
订单端 remoteName = pigx-nexus
物联端 remoteName = pigx-nexus
~~~

正确示例：

~~~text
订单端 remoteName = aura-order-web
物联端 remoteName = aura-iot-bus
~~~

### 3. 修改模块联邦身份

文件：src/config/moduleFederationBaseConfig.ts

修改前：

~~~ts
export const currentRemoteConfig = {
	remoteName: 'pigx-nexus',
	remoteEntryName: 'pigxNexus',
	i18nScanDirs: [] as readonly string[],
	tailwindStyleExpose: './styles/moduleFederationTailwind.ts',
	auraCoreThemeExpose: './theme-core/theme/index.ts',
};
~~~

订单业务修改后：

~~~ts
export const currentRemoteConfig = {
	remoteName: 'aura-order-web',
	remoteEntryName: 'auraOrderWeb',
	i18nScanDirs: ['src/views/order'] as readonly string[],
	tailwindStyleExpose: './styles/moduleFederationTailwind.ts',
	auraCoreThemeExpose: './theme-core/theme/index.ts',
};
~~~

### 4. 同步修改其他身份配置

必须同步检查：

1. src/config/siteConfig.ts 的 systemId、globalTitle、adminTitle。
2. package.json 的 name。
3. postcss.config.js 中的 REMOTE_SCOPE。
4. src/styles/moduleFederationTailwind.css 中的根 scope。
5. index.html 中的启动缓存键。
6. src/i18n/moduleFederation.ts 的导出名。
7. src/i18n/index.ts 中对应的导入名和使用位置。
8. README 中的项目名称。
9. VITE_PUBLIC_PATH 和 Nginx 实际部署前缀。

订单项目的 scope 示例：

~~~js
// postcss.config.js
const REMOTE_SCOPE = '.aura-mf-remote-scope.aura-mf-remote-aura-order-web';
~~~

~~~css
/* src/styles/moduleFederationTailwind.css */
.aura-mf-remote-scope.aura-mf-remote-aura-order-web {
	width: 100%;
	height: 100%;
	min-height: 100%;
}
~~~

检查是否还有模板占位名称：

~~~bash
rg "pigx-nexus|pigxNexus" src .env .env.development .env.production package.json vite.config.mts postcss.config.js README.md
~~~

指南中的示例文字可以保留；业务源码、环境变量和构建配置中不得残留占位名称。

## 二、对外提供模块

### 1. 配置页面 expose

文件：src/hooks/moduleFederation.ts

~~~ts
export const pageExposes = {
	'./views/order/list/index.vue': './src/views/order/list/index.vue',
	'./views/order/detail/index.vue': './src/views/order/detail/index.vue',
};
~~~

左边是其他综合端使用的 expose key，右边是当前项目真实文件路径，两者必须一一对应。

订单列表对应的后端菜单 componentPath：

~~~text
/aura-order-web/views/order/list/index.vue?type=moduleFederation
~~~

路径拆解：

~~~text
aura-order-web                       → 提供方 remoteName
./views/order/list/index.vue         → 提供方 expose key
?type=moduleFederation               → 模块联邦菜单标识
~~~

错误示例一：

~~~text
/auraOrderWeb/views/order/list/index.vue?type=moduleFederation
~~~

错误原因：第一段使用了 remoteEntryName。菜单第一段必须使用 remoteName。

错误示例二：

~~~text
/aura-order-web/order/list/index.vue?type=moduleFederation
~~~

错误原因：菜单路径缺少 views，与 expose key 不一致。

### 2. 提供组件、API 和工具

~~~ts
export const componentExposes = {
	'./components/OrderStatusTag.vue': './src/components/OrderStatusTag.vue',
};

export const apiExposes = {
	'./api/order/index.ts': './src/api/order/index.ts',
};

export const utilsExposes = {
	'./utils/order-format.ts': './src/utils/order-format.ts',
	'./utils/mitt': './src/utils/mitt.ts',
	'./moduleFederation/runtime': './src/hooks/moduleFederation.ts',
};
~~~

所有分类最终必须合并到 exposeModules：

~~~ts
export const exposeModules = {
	...pageExposes,
	...apiExposes,
	...componentExposes,
	...utilsExposes,
	...styleExposes,
	...i18nExposes,
};
~~~

### 3. 提供国际化

先在 src/config/moduleFederationBaseConfig.ts 配置业务语言目录：

~~~ts
i18nScanDirs: ['src/views/order'] as readonly string[],
~~~

推荐目录：

~~~text
src/views/order/list/i18n/zh-cn.ts
src/views/order/list/i18n/en.ts
src/views/order/detail/i18n/zh-cn.ts
src/views/order/detail/i18n/en.ts
~~~

构建时 vite-plugins/generate-i18n-imports.ts 会生成 src/i18n/moduleFederation.ts。该文件是生成文件，禁止手工维护业务导入。

构建后检查：

~~~bash
rg "order.*ZhCn|order.*En" src/i18n/moduleFederation.ts
~~~

标准 i18n expose 保持不变：

~~~ts
export const i18nExposes = {
	'./i18n/langs': './src/i18n/moduleFederation.ts',
};
~~~

### 4. 提供 Tailwind 和页面 CSS

远程项目的 index.html 不会被消费方加载，因此不能只在 index.html 引入 Tailwind。

模板通过以下标准 expose 提供 scoped Tailwind：

~~~ts
export const styleExposes = {
	'./styles/moduleFederationTailwind.ts': './src/styles/moduleFederationTailwind.ts',
};
~~~

PostCSS 会把 Tailwind 选择器限制到当前 remoteName 对应的 scope。不要让宿主项目扫描远程源码来生成 Tailwind，这会造成样式缺失和项目耦合。

页面自己的 CSS 会从 mf-manifest.json 中按 expose 精确加载，不需要业务页面手工插入 link。

### 5. 静态资源必须转换

通过 import 引入的图片、SVG、视频等，在用于 src、背景图或配置项前，必须经过 getStaticResourceUrl。

正确示例：

~~~ts
import orderBannerSource from '/@/assets/images/order/banner.png';
import { getStaticResourceUrl } from '/@/hooks/moduleFederation';

const orderBanner = getStaticResourceUrl(orderBannerSource);
~~~

~~~vue
<template>
	<img :src="orderBanner" alt="订单中心" />
</template>
~~~

配置项示例：

~~~ts
const cards = [
	{
		title: '待处理订单',
		icon: getStaticResourceUrl(pendingOrderIconSource),
	},
];
~~~

public 目录资源使用 getPublicResourceUrl：

~~~ts
import { getPublicResourceUrl } from '/@/hooks/moduleFederation';

const workerUrl = getPublicResourceUrl('/workers/order-worker.js');
~~~

错误示例：

~~~vue
<img src="/assets/images/order/banner.png" alt="订单中心" />
~~~

错误原因：作为远程页面运行时会请求宿主的 /assets，而不是提供方资源。

CSS 中不要硬编码根路径：

~~~scss
/* 错误 */
.banner {
	background-image: url('/assets/images/order/banner.png');
}
~~~

需要动态前缀时，改成组件样式：

~~~ts
const bannerStyle = {
	backgroundImage: 'url(' + getStaticResourceUrl(orderBannerSource) + ')',
};
~~~

~~~vue
<div class="banner" :style="bannerStyle"></div>
~~~

### 6. 提供方构建产物

执行：

~~~bash
pnpm build
~~~

至少应存在：

~~~text
dist/remoteEntry.js
dist/mf-manifest.json
dist/assets/*.js
dist/assets/*.css
~~~

检查 manifest 是否包含页面：

~~~bash
rg "views/order/list/index.vue|i18n/langs|moduleFederationTailwind" dist/mf-manifest.json
~~~

## 三、引入远程模块

模板只预置 aura-core。需要消费自己的业务远程时，参考 aura-core 的配置方式扩展。

以下示例表示当前综合端要消费 aura-order-web。

### 1. 增加运行时远程名称

文件：src/config/moduleFederationBaseConfig.ts

~~~ts
export const moduleFederationRemoteNames = ['aura-core', 'aura-order-web'] as const;
~~~

remoteName 必须与提供方 currentRemoteConfig.remoteName 完全一致。

### 2. 增加运行时入口

文件：src/config/remoteConfig.ts

~~~ts
export const moduleFederationRemoteEntries = {
	'aura-core': import.meta.env.VITE_AURA_CORE_REMOTE_PATH,
	'aura-order-web': import.meta.env.VITE_AURA_ORDER_WEB_REMOTE_PATH,
};
~~~

### 3. 增加环境变量

~~~dotenv
# .env
VITE_AURA_ORDER_WEB_REMOTE_PATH=/auraOrderWeb/mf-manifest.json

# .env.development
VITE_AURA_ORDER_WEB_PROXY_PATH=http://localhost:5174
~~~

变量名建议由 remoteName 转为大写下划线：

~~~text
aura-order-web
→ AURA_ORDER_WEB
→ VITE_AURA_ORDER_WEB_REMOTE_PATH
~~~

入口可以直接指向 mf-manifest.json；如果使用 remoteEntry.js，模板运行时也会按约定推导同目录下的 mf-manifest.json，用于加载 expose CSS。

### 4. 增加本地开发代理

文件：vite.config.mts

~~~ts
'/auraOrderWeb': createProxyConfig({
	target: env.VITE_AURA_ORDER_WEB_PROXY_PATH,
	rewriteFrom: '/auraOrderWeb',
	rewriteTo: '/',
	enableLog: true,
}),
~~~

代理路径 auraOrderWeb 必须与提供方 remoteEntryName 和实际部署前缀一致。

### 5. 通过后端菜单动态加载页面

后端菜单配置：

~~~text
/aura-order-web/views/order/list/index.vue?type=moduleFederation
~~~

这种方式由 getModuleFederationLoader 和 enhanced runtime 动态加载，只需要：

1. moduleFederationRemoteNames。
2. moduleFederationRemoteEntries。
3. 环境变量。
4. 本地开发需要时的代理。
5. 正确的后端菜单 componentPath。

不需要把该业务远程加入 Vite 编译期 remotes。

菜单管理界面中的“带参”必须开启，并在“组件”字段完整填写 `componentPath`。同一个模块联邦菜单在提供方自身会先解析本地 `src/views` 页面；只有本地不存在时才由远程注册表加载。字段填写、`remoteName` 与 `remoteEntryName` 的区别、以及完整解析示意图见[路由与菜单规范](./路由与菜单规范.md#四模块联邦菜单后台配置与解析规则)。

### 6. 在源码中引入远程模块

源码直接消费远程模块时，无论使用静态 import 还是动态 import，除运行时配置外，还要修改 src/config/viteModuleFederationConfig.ts：

~~~ts
export const getModuleFederationRemoteEntries = (
	env: Record<string, string | undefined>
) => ({
	'aura-core': env.VITE_AURA_CORE_REMOTE_PATH,
	'aura-order-web': env.VITE_AURA_ORDER_WEB_REMOTE_PATH,
});
~~~

并补充 TypeScript 声明：

~~~ts
declare module 'aura-order-web/components/OrderStatusTag.vue' {
	import type { Component } from 'vue';

	const component: Component;
	export default component;
}
~~~

#### 模板使用的远程 Vue 组件必须异步引入

只要远程 Vue 组件会直接出现在当前页面的 template 中，就必须使用 `defineAsyncComponent` 建立异步渲染边界：

~~~vue
<template>
	<OrderStatusTag />
</template>

<script setup lang="ts">
import { defineAsyncComponent } from 'vue';

// @ts-ignore 模块联邦远程组件由 Vite 运行时解析。
const OrderStatusTag = defineAsyncComponent(() =>
	import('aura-order-web/components/OrderStatusTag.vue').then(
		(module) => module.default ?? module
	)
);
</script>
~~~

禁止把远程 Vue 组件静态默认导入后直接交给 template 渲染：

~~~ts
// 错误：远程模块未就绪时，模板渲染可能读取到同步代理并抛出 Promise。
import OrderStatusTag from 'aura-order-web/components/OrderStatusTag.vue';
~~~

当前模块联邦运行时按需加载 expose，不保证远程组件在页面开始渲染前已经完成。静态默认导入可能暂时得到未就绪的同步代理，Vue 模板读取组件属性时会中断渲染，表现为内容区空白、`Unhandled error during execution of render function` 或控制台抛出 Promise。

适用边界：

~~~text
本地模板组件           → 正常静态 import
远程模板组件           → defineAsyncComponent + 动态 import
后端菜单远程页面       → 由 getModuleFederationLoader 动态加载，不重复包装
远程 API、类型和工具   → 按对应模块规范引入，不使用 defineAsyncComponent
~~~

配置边界：

~~~text
后端菜单动态页面   → 运行时 entries
源码直接消费远程模块 → 运行时 entries + 编译期 remotes + TypeScript 声明
~~~

不要因为一个动态菜单页面就把业务远程加入编译期 remotes，否则会增加启动时远程依赖和首次加载成本。

### 7. 消费远程 i18n 和样式

提供方遵守标准 expose 后，消费方内容壳会自动加载：

~~~text
aura-order-web/i18n/langs
aura-order-web/styles/moduleFederationTailwind.ts
~~~

业务页面不应重复注册语言包或手工插入同一份 Tailwind link。

### 8. 统一注入 Element Plus 国际化

消费方加载远程路由时，必须在 `moduleFederationRegistry.ts` 的 `wrapRemoteComponent()` 中统一注入 `ModuleFederationElementProvider`，业务页面和提供方 expose 不要重复包裹 `ElConfigProvider`。

Provider 根据宿主 `vue-i18n` 的当前 `locale` 注入 Element Plus 的中文或英文语言包：

~~~vue
<ElConfigProvider :locale="elementLocale">
	<slot />
</ElConfigProvider>
~~~

注意 `ElConfigProvider` 透传 slot 时会以 Fragment 形式渲染，不能作为远程路由最外层节点。`aura-mf-remote-scope` 必须保持为真实根节点，Provider 放在其内部：

~~~text
aura-mf-remote-scope（真实根节点）
└── ModuleFederationElementProvider
    └── 远程页面
~~~

这样远程页面的日期选择器、分页和空状态等 Element Plus 内置文案会跟随宿主语言切换，同时路由切换动画和运行时指令能够正常挂载，避免 Vue 警告或空白页面。

宿主和远程应用必须统一使用 Element Plus `2.14.3`，并在模块联邦 `shared` 中配置单例：

~~~ts
'element-plus': { singleton: true, requiredVersion: '^2.14.3' }
~~~

## 七、常见故障排查

### 1. 提示远程应用未配置

错误现象：

~~~text
模块联邦远程应用未配置：aura-order-web
~~~

检查：

~~~bash
rg "aura-order-web|VITE_AURA_ORDER_WEB_REMOTE_PATH" src/config .env*
~~~

确认运行时清单、入口映射和环境变量三处都已配置。

### 2. manifest 中找不到 expose

错误现象：

~~~text
manifest 中未找到 expose：aura-order-web/./views/order/list/index.vue
~~~

对照：

~~~text
提供方 pageExposes: ./views/order/list/index.vue
后端 componentPath: /aura-order-web/views/order/list/index.vue?type=moduleFederation
~~~

重新构建提供方并确认 mf-manifest.json 已更新。

### 3. 页面能加载但样式缺失

检查提供方是否保留：

~~~text
./styles/moduleFederationTailwind.ts
~~~

检查 CSS 是否带当前远程 scope，并确认消费方成功请求 expose 对应 CSS。

### 4. 图片、字体或 Worker 404

错误请求：

~~~text
http://宿主地址/assets/order-banner.png
~~~

期望请求：

~~~text
http://提供方地址/auraOrderWeb/assets/order-banner.png
~~~

检查 import 资源是否经过 getStaticResourceUrl，public 资源是否经过 getPublicResourceUrl，CSS 是否硬编码根路径。

### 5. 首次进入抛出 pending Promise

提供方 expose 如果静态引用另一个远程，应确认该远程已加入提供方的编译期 remotes。消费方内容壳会等待 pending 依赖并重试，但错误的依赖拓扑仍需在提供方修正。

### 6. 发布后仍加载旧 chunk

先点击页面中的“重新加载”。重试会刷新远程容器，并清理该远程的 manifest、样式和 i18n 缓存。

如果仍失败，检查网关和浏览器是否缓存了旧 mf-manifest.json。

pnpm install --frozen-lockfile

rg "pigx-nexus|pigxNexus" src .env* package.json postcss.config.js

最后在独立运行和宿主加载两种模式下各验证一次：

1. 登录页与首页正常。
2. 后端菜单动态页面正常。
3. 远程 i18n 正常切换。
4. Tailwind 和页面 CSS 无缺失、无宿主污染。
5. 图片、字体和 Worker 无 404。
6. 远程失败不会中断其他菜单。
