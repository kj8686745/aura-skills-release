# Aura PIGX 模块联邦检查

当前版本：`1.0.0`。

把本技能作为只读审计器使用。默认输出问题证据和修复建议；只有用户明确要求修复时才修改被检查项目。

## 规范优先级

发生冲突时按以下顺序判断：

1. 用户当前任务中的明确要求。
2. 被检查项目的源码、类型定义、实际依赖和构建产物。
3. `knowledge/PIGX前端开发规范/模块联邦开发技术规范.md`。
4. `references/integrated-rule-matrix.md` 和本技能脚本。

当前模板以 `element-plus@2.14.3` shared singleton 为有效基线，不采用旧清单中“Element Plus 不加入 shared”的过期规则。

## 强制工作流

1. 先读取 `references/integrated-rule-matrix.md`，了解规则边界和严重级别。
2. 运行：

   ```powershell
   .\scripts\check-module-federation.ps1 -ProjectPath <项目路径>
   ```

3. 根据识别结果处理：
   - `Integrated`：继续综合端完整审计。
   - `Provider`：立即停止，说明首版尚不支持生产端专项审计。
   - `Consumer`：立即停止，说明首版尚不支持消费端专项审计。
   - `Unknown`：立即停止，列出不足或冲突的识别证据，不猜测项目类型。
4. 需要机器可读结果时追加 `-Json`；需要核验指定构建清单时追加 `-ManifestPath`；需要检查后台菜单时通过 `-ComponentPath` 传入真实组件值。
5. 对综合端按 `checklists/integrated-validation.md` 补充 build、独立运行和宿主加载验证。
6. 只在用户明确要求后依据报告修复确定问题；不得自动修改名称、部署地址、远程拓扑或后台菜单。

## 端类型边界

- 综合端必须同时具备 PIGX 综合端基础配置、标准 expose 聚合、运行时远程注册表和 Vite Module Federation 配置。
- 生产端是存在对外 exposes、但不具备 PIGX 综合端运行时外壳的项目。
- 消费端是存在 remotes、运行时远程注册或远程加载行为、但不具备综合端和生产端特征的项目。
- 同时命中生产端和消费端、或证据不足时归类为 `Unknown`。

处理器按 `scripts/rules/<ProjectType>.ps1` 动态发现。首版只提供 `Integrated.ps1`；该处理器必须完整检查综合端内部的提供方 exposes、消费方 remotes、后台菜单和远程模块导入。后续新增独立生产端或消费端支持时，再增加 `Provider.ps1` 或 `Consumer.ps1`，无需修改主入口和报告模型。

## 报告约定

检查结果必须包含：项目类型、识别证据、规则编号、严重级别、文件、行号、问题和修复建议。

- `error`：可以从当前项目确定的违规，退出码为 `1`。
- `warning`：高风险候选项或缺少构建验证，不单独导致失败。
- `manual`：必须结合部署环境、后台菜单或运行时验证的事项。
- `pass`：已通过的关键检查或最终通过结论。

退出码：`0` 表示综合端通过，`1` 表示综合端存在错误，`2` 表示参数或类型无法识别，`3` 表示识别为首版未支持的生产端或消费端。

## 交付格式

1. **项目类型**：类型、识别证据和是否进入专项检查。
2. **确定错误**：按规则编号列出文件、行号和修复方向。
3. **风险与人工项**：说明无法仅靠静态扫描确认的内容。
4. **验证结果**：脚本退出码、build 和运行时检查结果。
5. **剩余边界**：明确生产端、消费端、后台菜单或部署环境中未覆盖的部分。
