# 数据安全与内容防护能力包

**能力包编号**：AURA-CAP-COMMON-DATA-SECURITY  
**所属能力域**：通用工具类  
**当前源码依据**：`aura-core-common` `dev@4a2a1f1`；业务项目须核对实际依赖版本

## 1. 能力定位

本能力包说明业务应用如何选择敏感字段脱敏、XSS 内容清理、实体字段保护和 API 报文加解密。各保护能力有不同的启用条件，不能仅凭引入模块就认定防护已生效；XSS 模块缺省配置下的字符串裁剪行为见详细说明。

这些能力用于保护数据在接口、日志、数据库和传输过程中的安全，不替代身份认证、接口权限、租户隔离和密钥管理制度。

## 2. 能力组成

| 能力 | 公共模块 | 主要用途 |
| --- | --- | --- |
| 敏感字段脱敏 | `aura-common-sensitive` | 显式调用工具脱敏，或由 `@Sensitive` 按权限决定序列化结果 |
| XSS 内容防护 | `aura-common-xss` | 显式清理文本，或在启用配置后清理命中路径的输入；未启用清理时仍须留意默认的字符串裁剪行为 |
| 字段与实体保护 | `aura-common-cipher` | 项目提供 `CipherProvider` 后，按实体规则保护字段与完整性 |
| API 报文保护 | `aura-common-encrypt-api` | 显式启用后按统一协议处理 HTTP 报文 |

## 3. 使用选择

```text
只是不希望展示完整敏感值 → 脱敏
需要阻断脚本注入 → XSS 清理
数据库中不能保存明文 → 字段/实体加密
接口传输内容需要密文 → API 报文加解密
```

同一字段可能同时需要加密和脱敏：数据库保存密文，接口按权限输出脱敏值；日志须单独处理，不能从 VO 注解推断日志已脱敏。

## 4. 使用前必须明确

- 保护对象、保护位置和允许展示的角色；
- 密钥来源、轮换、失效和恢复方式；
- 加密失败、解密失败、完整性校验失败的处理；
- 哪些富文本标签允许保留，哪些内容必须清理；
- 日志、审计、缓存和导出是否会复制敏感数据。

## 5. 使用边界

- 不能把脱敏当成加密，脱敏值不能恢复原文；
- 不能把 XSS 清理当成权限校验；
- 不能在代码、配置提交或日志中硬编码密钥；
- 不能对已经加密的数据重复加密而没有版本标识；
- 不能把 `@Sensitive` 当成永不输出原文的保证，也不能把未开启的 XSS 配置当成已清理输入；
- 不能把内部加密拦截器、密钥解析器和自动配置类当作业务直接 API。
