# 数据安全与内容防护能力清单

| 能力 | 模块 | 可使用入口 | 入口级别 | 说明 |
| --- | --- | --- | --- | --- |
| 字段脱敏 | `aura-common-sensitive` | `DesensitizedUtils`；`@Sensitive` 用于 Jackson 字段序列化 | 业务入口 | 工具显式脱敏；注解受 `SensitiveService` 判断控制，不能保证所有上下文都脱敏 |
| XSS 清理 | `aura-common-xss` | `XssUtil.clean`；`security.xss.enabled` | 业务/配置入口 | 默认不清理 XSS；配置缺省时自动配置仍可能裁剪 JSON/Form 字符串；启用清理后仍受路径、输入类型和忽略规则限制 |
| 实体字段保护 | `aura-common-cipher` | `@CipherProtectedEntity`、`CipherProvider`、`CipherEngine` | 扩展入口 | 无可用 `CipherProvider` 时不会形成完整加解密链路 |
| API 报文保护 | `aura-common-encrypt-api` | `security.api.encrypt.enable`、`NoEncrypt` 方法注解 | 配置/契约入口 | 默认关闭；启用后需核对请求体、响应体与 GET 参数协议，尤其是多值参数和例外路径 |

## 1. 非业务直接入口

以下内容属于内部实现，业务代码不得直接依赖：

- 自动配置类；
- MyBatis 加密拦截器；
- 请求/响应 Advice；
- 查询参数过滤器；
- 密钥解析器的内部实现；
- XSS Holder 和内部拦截器。

`ApiCryptoUtil` 是报文处理实现工具，不是普通业务接口的直接加密入口；`@Sensitive` 只影响命中的 Jackson 序列化字段，不自动覆盖日志、数据库、缓存或导出。

## 2. 安全能力关系

```text
认证/权限 → 判断谁可以访问
租户/数据权限 → 判断可以访问哪些数据
加密 → 保护存储或传输中的原文
脱敏 → 控制展示和日志中的可见内容
XSS 清理 → 清理不可信文本内容
```

这些能力相互配合，不能互相替代。
