# aura-cap-data-security-use 任务路由与执行指南

仅在当前任务命中本能力包时读取本文件。先确认项目版本、已启用模块和任务边界，再打开命中的能力条目；不要把整份能力包说明一次性加载。

## 开发时

1. 先定位数据在哪一层需要保护：展示、输入、数据库或 HTTP 报文；不要因为一个字段涉敏就同时启用全部模块。
2. 始终禁止原文输出的日志、审计和导出显式脱敏；`@Sensitive` 只处理命中的 Jackson 字段，默认权限判断可能输出原文，应核对豁免标识或项目覆盖实现。
3. XSS 任务核对 `security.xss.enabled`、路径和输入类型。默认不执行 XSS 清理，但缺省配置仍可能装配字符串裁剪；富文本白名单与实际渲染结果需要在项目中验证，不能用输入清理替代输出处理。
4. 实体保护任务先确认项目提供可用 `CipherProvider`，并核对 `aura.cipher.enabled` 与 `aura.cipher.mybatis-auto-enabled`，再使用实体规则；只加注解或依赖不能宣称已加密。核对写入密文、读取验签与解密、篡改和失败结果。
5. API 报文加密任务先确认客户端协议与服务端配置一致，再检查 POST、单值 GET 参数、响应、例外路径及错误密文；当前 GET 过滤器不保留同名多值参数，默认也未启用加密，不把它当作身份认证或防重放能力。

## 边界

项目版本不同或关键前置条件缺失时，说明缺口和待验证行为，不编造框架 API、密钥或运行结果。本技能不修改公共模块内部实现，也不携带内部治理与审查规则。
