# AURA 能力包构建

内部建设技能：核实已有能力并交付候选，不是业务接入技能，也不决定发布。规范正文是事实源；版本见 VERSION，仅追溯时检索[来源记录](references/source.json)。

## 定位本次任务

先分清新建、更新已有包或只做业务接入，后者转对应研发任务，不进入建设。按已给路径、当前仓库和明确相关工作区识别事实，不全盘搜索。已有边界、版本和目录直接核对，只有输出根、包边界或公开契约存在关键歧义时合并提问；普通缺口记入原有内部记录，独立部分继续。

## 建设与复核

写前核对规范仓库根、remote、分支、已有包及输出绝对路径；源码只读，不能用当前业务 cwd 代替输出根。新包写在规范库治理区的“内部定义与版本记录.md + 候选对外内容”；已准入包的授权修订沿用现行文件。域本身只有一包时不再嵌套同名目录。缺规范库时只做只读分析并请求路径，不回退业务 docs 或技能安装目录。

从指定源码提交、SDK 导出/制品、配置、公开契约和实际消费者反向核验。按项记录公开可用、受限、内部、未验证或废弃及具体证据；类名存在不等于公开能力，旧文档只是线索。冲突保留两边证据交负责人决定，未证实的默认值、方法和失败行为不补造成可用事实。整体 AURA 版本未核定时记待核定，不阻塞其他事实盘点。

对外最多三份：能力说明回答“有什么、何时用、得到什么”；接入与使用手册合并依赖配置、逐规则相邻正反例、完整任务、接口及共享模型、失败和验证；版本与兼容记录集中当前组合及历史。同版已有参考可引用具体章节，不一接口一文件。每份按总述—任务展开—结果与边界收束；少于三份时仍保留必要信息，不另建总入口或模型集。证据、建设计划和候选状态留在一份内部记录。

按模板逐节复核一条完整任务路径和一条参数查阅路径：准备、真实入口、字段与约束、操作、观察结果和失败处理均可定位；每条使用规则有编号、必要性及相邻正反例。对照源码入口→能力→规则→示例的映射核对覆盖，不用标题/接口数量代替内容充分。文档示例不冒称已运行；试用/发布所需的可运行示例、准确版本及证据不足时保留缺口。

后端默认设计后端开发入口内的使用模块候选，保留命中任务、公开资料、版本、接入和验证路由，不新增独立 SKILL.md；仅确有独立任务时再提出。实际技能源码只在 aura-skills，未准入模块不直接进入已就绪入口。不要自动复建已经删除的独立能力技能。

## 只读检查与交付

Python 3.9+ 标准库，在技能目录运行。目录参数均为相对规范库的实际路径：

```text
python -B -X utf8 scripts/check-capability-delivery.py --standards-root <规范库> --package-path <候选或现行包目录> --phase preflight --mode candidate --json
# 写完后改用 --phase content，并追加 --internal-record <内部记录路径>；授权修订现行包用 --mode update。
```

工具核对仓库与输出归属、三份以内文档、编号、已识别规则块的必要性及正反例标记、本地引用和明显过程内容线索；不读全部源码，不写文件。0/1/2 分别表示机械项无已识别问题、确定错误、检查不完整；参数及限制见[使用说明](USAGE.md)。不能凭过检宣布能力存在、内容充分或已可发布。

按构建规范001～016及所选模板完成语义复核后，归并原内部记录，交付路径、来源版本、变更、实际验证、未证实与阻断项。只完成本地建设时不提交、推送、改公开索引、搬入正式集合或宣布发布；普通步骤不逐项等待继续。独立使用需提供本技能完整目录，不能只复制入口。
