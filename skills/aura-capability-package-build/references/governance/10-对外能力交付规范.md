# AURA（天玑）对外能力交付规范

**适用范围**：AURA 向业务应用、集成服务或第三方调用方提供平台能力时的说明、接口和 SDK 交付。
**不适用范围**：内部治理过程、能力包建设过程、源码审查记录和未公开的内部实现。

## 一、两类交付物的边界

AURA 对外能力交付分为两类文档，二者可以在同一能力包中互相引用，但不能把内容混写成一份模糊说明：

| 类型 | 解决的问题 | 主要读者 | 核心产物 |
| --- | --- | --- | --- |
| 平台能力使用说明 | AURA 有什么能力、什么时候使用、接入前需要什么、使用后得到什么 | 业务应用开发者、平台使用者 | 能力地图、使用前提、调用流程、结果和边界 |
| API/SDK 对外交付手册 | 已发布的 OpenAPI 或 SDK 如何引入、配置、调用、迁移和处理失败 | API 调用方、SDK 使用者、集成开发者 | 版本说明、依赖、接口契约、SDK 方法、示例、迁移和兼容 |

平台能力使用说明回答“是否适合、如何完成平台任务、得到什么结果”，包含控制台、配置或组件的具体操作；API/SDK 手册回答“如何通过接口或 SDK 接入”。SDK 不是能力包本身，SDK 是能力对外交付的一种入口。

## 二、交付关系

一个能力包可以包含多个平台能力，也可以同时提供 HTTP OpenAPI 和 Java/其他语言 SDK。推荐关系如下：

```text
能力包总入口
  ├─ 平台能力使用说明：能力地图、场景选择、前置条件、结果边界
  └─ API/SDK 对外交付手册：版本、依赖、接口契约、SDK 方法、迁移与兼容
```

平台能力说明不得复制 API/SDK 全量字段；API/SDK 手册不得重新定义能力包的业务边界。二者通过稳定的能力编号、接口编号、SDK 模块版本和文档链接关联。

## 三、统一要求

### AURA-BASE-API-027：先说明能力边界，再提供具体入口

**必要性**：必须

**正确写法**：先在能力地图说明“视频通道查询”，再链接 `/openapi/video/channel/queryPage`。

**错误写法**：只给一串 SDK 方法，不说明能解决什么问题。

**判断要点 / 验证方式**：能力入口与 API/SDK 手册可以互相定位。

### AURA-BASE-API-028：平台能力说明与 API/SDK 手册分工明确

**必要性**：必须

**正确写法**：能力说明写场景和结果，SDK 手册写依赖、方法、请求响应。

**错误写法**：在能力说明中复制完整 SDK 参数表并另写一套错误语义。

**判断要点 / 验证方式**：抽查两份文档是否出现重复且不一致的契约。

### AURA-BASE-API-029：集中记录 API/SDK 版本、依赖和发布顺序

**必要性**：必须

**正确写法**：集中列服务、API、SDK、示例的准确版本、获取入口和调用方升级顺序；内部制品发布命令留在维护资料。

**错误写法**：只在代码片段中散落版本号。

**判断要点 / 验证方式**：版本表、构建文件和制品坐标一致。

### AURA-BASE-API-030：对外 HTTP 接口使用统一 OpenAPI 路径和登记契约

**必要性**：必须

**正确写法**：`/openapi/video/**` 与 `@PlatfomApi(code,version,name,requestPath)` 一致。

**错误写法**：使用内部路径或只写网关转发后的地址。

**判断要点 / 验证方式**：实际 URL、注解和网关目录三方一致。

### AURA-BASE-API-031：SDK 方法可追溯到具体 API 契约

**必要性**：必须

**正确写法**：`assets(...)` 明确对应方法、路径、请求 DTO 和响应模型。

**错误写法**：SDK 方法名与接口路径无法对应。

**判断要点 / 验证方式**：SDK 方法矩阵逐项可回查。

### AURA-BASE-API-032：按字段说明请求、响应、错误和异步结果

**必要性**：必须

**正确写法**：字段表列出类型、必填、默认、空值和业务含义，并给完整响应示例。

**错误写法**：只描述“返回成功/失败”。

**判断要点 / 验证方式**：逐接口契约和模型表完整。

### AURA-BASE-API-033：完整说明迁移、兼容和回滚

**必要性**：必须

**正确写法**：分页字段变更同时说明服务端、SDK 和调用方迁移。

**错误写法**：只升级 SDK，不说明服务端字段变化。

**判断要点 / 验证方式**：迁移表覆盖请求、响应、签名和调用方。

### AURA-BASE-API-034：不得把未验证结果写成已完成

**必要性**：必须

**正确写法**：明确“已核对源码，未执行 deploy”。

**错误写法**：文档写“已发布”但无制品或流水线证据。

**判断要点 / 验证方式**：发布说明区分静态核对、构建、发布和部署。

## 四、API/SDK 手册的最小内容

API/SDK 对外交付手册至少包含：版本与交付边界、依赖与引入、网关和认证、接口总览、逐接口请求/响应/错误契约、SDK 方法映射、典型流程、迁移兼容、发布顺序和限制。分页、文件流、事件推送、异步任务和批量写入按实际能力补充，不能用普通 CRUD 示例代替。

## 五、平台能力说明的最小内容

平台能力使用说明至少包含：能力定位、能力地图、适用与不适用场景、接入前提、最小使用路径、结果说明、失败和边界、与相邻能力的选择关系、版本限制，以及到 API/SDK 手册和示例的链接。

## 六、状态边界

先展示使用目标和首次成功路径，再提供按模块查阅的参考。平台说明按“任务、操作、结果、失败处理”组织；API/SDK 手册按“引入配置、首次调用、公共约定、模块接口、排错升级”组织。不承诺固定几分钟完成，不让使用者先读所有字段才能开始。

表格用于能力比较、参数及版本查阅，不替代操作步骤。代码提供必要注释，JSON 保持合法，字段解释放相邻表格。快速示例与详细参考使用同一契约；没有实际 SDK 时不生成 SDK 章节。仅在对象关系或调用顺序不易理解时加图。

文档存在不等于能力已发布。能力、API、SDK 和示例分别记录自己的来源版本和状态；只有整体版本收录后，才可对外宣称属于该 AURA 版本。安装、任务触发和业务方实际使用属于使用方行为，不作为本规范文档的组成内容。
