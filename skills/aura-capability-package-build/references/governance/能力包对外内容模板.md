# 能力包对外内容模板

**用途**：指导能力负责人编写供业务开发者阅读的能力包。每个能力包对外最多三份 Markdown 文件，按“了解能力 → 完成接入与使用 → 核对版本”阅读。使用时替换占位内容，不把本模板、审查过程或内部证据复制到对外目录。

能力少时可以少于三份，内容须仍可定位。控制台、组件、配置与 API/SDK 是能力的不同入口；没有 API/SDK 时删去手册中的接口章节，不生成空文件。平台说明和 API/SDK 交付手册的专项模板只提供章节内容，不能因此增加对外文件数。

## 统一编排与检查

每份文件都按“总—分—总”编排：开头说清读者目的和能得到的结果；中段按任务或模块列出事实与步骤；结尾回收结果、限制和下一步入口。字段表只在接入手册维护，其他位置用能力编号和章节链接指向它。版本及兼容结论只在版本记录维护，说明和手册链接该记录。

能力使用稳定编号，例如 `AURA-CAP-IOT-BUS-DEV-001`。每条规则使用稳定规则 ID 并标注“必须 / 条件必须 / 可选”；正例和反例紧贴规则。任务导航可在已列明共同前缀后使用编号后缀，但不得形成第二套编号。

表格用于能力选择、字段和结果对照；操作顺序、解释和代码放在表格外。代码块标注语言，说明输入来源、关键动作和可观察结果。接口卡片区分请求、参数、SDK 示例、响应、失败和注意；共享数据模型只定义一次，由相关接口链接。标题以任务或对象命名，不按单条接口、规则或示例拆文件。

发布前按两个路径复核：先从能力说明中的任务定位到手册中的前提、规则、代码和结果，再从某个接口定位到完整字段及其共享模型。标题和接口编号齐全不等于字段、约束、成败示例或实际运行已齐全。无证据的行为和兼容结论保留在内部记录。

能力说明侧重“有什么、能做什么、为什么选择它”。可摘述首次使用路径，但不在此复制完整代码、字段表和使用规则。价值须对应真实公开能力及可观察结果，不写空泛前景。
