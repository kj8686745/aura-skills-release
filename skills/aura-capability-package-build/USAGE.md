# 能力包构建使用说明

当前版本：0.5.0，供内部能力负责人交付使用。发布工具中保留内部标签，通过“上传内部技能”进入同一发布仓库；技能产出能力包候选，候选仍需复核，不因此将本技能标为建设中。

可以直接说：“使用 $aura-capability-package-build，把当前项目的文件存储能力整理成能力包。”技能先识别已有项目和能力目录，说明建议范围；缺少规范仓库位置等关键信息时再引导补充，不要求先填写完整模板。确认后连续建设和检查，普通步骤不逐项确认。续接会复用已确认范围和现有内部记录。

先读[研发人员能力包建设与归档指南](references/governance/研发人员能力包建设与归档指南.md)，其中包含工作区准备、可复制提问、输出目录和归档流程。必须提供规范仓库位置与源码位置；前者接收文档，后者默认只读。只安装技能但没有规范仓库时，不会在业务项目下代建能力包。

> 使用 $aura-capability-package-build，将指定版本的平台功能整理为能力包。先核实真实功能，再写任务操作与结果；只有实际提供 API/SDK 的部分才生成按模块组织的接入手册。保留内部证据，不把建设过程写进使用说明。

支持三类任务：平台操作说明、API/SDK 接入手册、同一能力包的组合交付。交付内容按任务选择模板，不要求每次输出全部文件。完成标准包括读者能走通一个任务及查到准确参数，而不只是填满章节。

续接已有内容时可以说：“按模板复核当前能力包，统一排版，逐接口列出字段与示例缺口，并更新使用模块候选。”技能会区分排版完成、契约内容完整和实际运行验证，检查结论归入已有内部记录。

面向内部能力负责人，交付本技能的完整目录和指定版本的源码、SDK、公开契约位置。无需安装业务使用技能才能建设能力包。

> 使用 $aura-capability-package-build，根据提供的 SDK 版本建设文件处理能力包，核实公开能力、配置、输入输出、失败行为与示例；后端使用内容按模块交给后端开发入口，保留候选状态。

技能产出能力说明、使用规则、示例、使用模块候选及归并的内部证据记录。能力说明先回答“有什么、何时用、带来什么结果”；使用规则才说明如何接入。源码不存在或尚未核实的能力不能写成可用。

后端使用模块保留自己的来源和能力边界，但不新增自动触发的独立技能。需要独立入口时先说明其独立任务；不是每增加一个能力包都增加一个安装项。

只建设当前任务指定的能力包，不重写基础规范、不替换前端负责人基线、不自行发布。包的构建与版本验收、纳入研发技能和对外发布是不同状态。
