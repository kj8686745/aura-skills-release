# 管理端菜单与按钮权限流程

仅在用户要求创建正式菜单或按钮权限时读取本参考。只有用户已明确授权本次写入，并提供目标环境、可用管理端 Token、租户和父菜单定位信息后，才能调用管理端 API。

## 准备清单

从真实页面和路由生成以下待确认项：

- 页面菜单：名称、路径、组件路径、权限编码、图标、排序、可见性和父菜单定位；
- 按钮权限：每个 `v-auth` 的权限编码、名称、所属页面菜单；
- 模块联邦菜单：完整 `componentPath` 与“带参”要求。

权限编码采用以下优先级：

1. 用户明确指定页面菜单或按钮权限时，原样采用指定编码，不改写为模板格式；
2. 用户未指定时，读取当前项目的路由/菜单规范和相邻业务模块的真实 `v-auth`；按既有业务域与动作命名规则生成。例如项目现有规范采用 `order_add` 时，同一风格的新业务使用“业务域_动作”，而不是引入新的分隔符、英文缩写或固定前缀；
3. 无法从当前项目确定命名规则时，交付候选清单并说明依据不足，不猜测框架外的权限前缀。

页面菜单与按钮均按路径、组件路径和权限编码精确查重。按钮权限的 `parentId` 必须使用查询或创建后得到的真实页面菜单 ID，不得猜测、复用历史 ID 或把按钮挂到栏目菜单。每个页面中的 `v-auth` 必须与对应后台按钮权限编码完全一致。

## 受控幂等写入

1. 只使用本次明确指定环境的管理端 REST API 基地址，令牌和租户仅通过运行时请求头传入；不得写入脚本、源码、Markdown、日志或版本库。
2. 先查询菜单树和目标详情，递归展开后定位真实父级，并比对路径、组件路径和权限编码。
3. 缺失目标执行新增；已存在目标只更新本次明确的字段，并保留真实菜单 ID。不得删除、批量覆盖或修改未在需求中列出的菜单。
4. 页面菜单创建或更新完成并取得真实 ID 后，再逐个新增或更新对应按钮权限。
5. 写入后重新查询菜单树和详情，逐项核验父级、名称、路径、组件、权限、菜单类型、排序、显示和带参字段；以 API 成功响应和复查数据为验收依据，不以管理端页面显示为依据。

## 条件不足时的交付

不得发起外部写入。交付需给出页面菜单和按钮权限清单，并明确缺少以下哪项：目标环境、明确写入授权、管理端 Token、租户、父菜单名称/路径/ID 或接口字段约定。

## 模块联邦菜单

远程菜单的 `componentPath` 必须由提供方 `remoteName`、真实 expose key 和 `?type=moduleFederation` 组成，并在管理端开启“带参”。动态菜单只依赖运行时远程配置；不因菜单配置而新增编译期 remote。
