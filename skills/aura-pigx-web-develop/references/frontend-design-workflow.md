# PIGX 页面视觉设计协作流程

本参考用于在 `aura-pigx-web-develop` 中协作调用 `$frontend-design`，不复制其完整设计方法。完整设计原则以当前环境的 `frontend-design/SKILL.md` 为准。

## 触发范围

新增或改造用户可见的业务页面、CRUD、看板、地图/视频容器和跨页面视觉组件时使用；纯后端、隐藏页、无界面组件修复和模块联邦纯审计不触发。

## 执行顺序

1. 读取 PIGX 页面模式、样式布局规范和现有主题变量。
2. 按 `skill-dependency-workflow.md` 检查 `$frontend-design` 是否安装；缺失时提示用户，获得明确安装授权并确认可用后再调用，说明业务对象、目标用户、页面单一任务、已有品牌约束和可复用组件。
3. 记录可落地的视觉令牌：主题色、文字层级、字体、间距、圆角、边框/阴影、状态色和动效策略；优先映射到项目已有 `--el-*`、`--next-*`、`--fxft-*` 变量。
4. 实现时保持 PIGX 页面模式、`layout-padding`、组件复用、消息 Hook、权限和资源路径规范；不得为了视觉效果新增全局 Element Plus 覆盖。
5. 完成后再次按 `$frontend-design` 自评：检查视觉层级、重复模板感、响应式、键盘焦点、错误/空态文案和 reduced-motion；将未完成项列入交付风险。

## 协作提示词

- `为这个 PIGX CRUD 页面确定与业务对象匹配的视觉方向和令牌，保留现有主题变量。`
- `基于现有页面模式统一列表、筛选、空态和操作按钮的视觉层级，并给出可实现的间距与动效建议。`
- `实现完成后按 frontend-design 自评，检查是否模板化、响应式、键盘焦点和 reduced-motion。`
