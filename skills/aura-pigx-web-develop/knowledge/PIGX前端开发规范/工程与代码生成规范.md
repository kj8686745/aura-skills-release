# 工程与代码生成规范

## 一、基础写法

- Vue 页面统一使用 `<script setup lang="ts">`。
- 项目内部路径使用 `/@/`，不使用层层 `../../../`。
- Vue、Vue Router、Pinia 常用 API 已由 Vite 自动导入；以生成的 `auto-imports.d.ts` 为准。
- 新增类型、函数和文件使用有业务含义的英文名称；注释、错误提示和文档使用简体中文。
- 页面内组件按需异步加载，避免把非首屏大组件放入主图。
- 路由页面模板必须保持一个真实元素根节点，根元素统一使用 `class="layout-padding"`；业务区域置于 `class="layout-padding-auto layout-padding-view"`，Dialog、Drawer 等弹窗可与业务区域并列置于根节点下；复用列表页组件时，该组件的真实根元素同样遵循此结构。

```ts
const OrderForm = defineAsyncComponent(() => import('./components/order-form.vue'));
```

## 二、目录和命名

```text
src/views/order/list/
├── index.vue
├── components/
│   ├── order-form.vue
│   └── order-detail.vue
├── composables/
│   └── use-order-query.ts
└── i18n/
    ├── zh-cn.ts
    └── en.ts

src/api/order/index.ts
```

- Vue 文件使用 kebab-case；路由页面入口通常为 `index.vue`。
- API 函数使用 `get/list/create/update/delete` 加业务名。
- 不以 `common`、`temp`、`new`、`test` 命名正式业务模块。

## 三、API 封装

业务请求统一使用懒加载请求入口：

```ts
import request from '/@/utils/request';

export const getOrderPage = (params: OrderPageQuery) =>
	request({ url: '/order/page', method: 'get', params });

export const createOrder = (data: OrderForm) =>
	request({ url: '/order', method: 'post', data });

export const updateOrder = (data: OrderForm) =>
	request({ url: '/order', method: 'put', data });

export const deleteOrders = (ids: Array<string | number>) =>
	request({ url: '/order', method: 'delete', data: ids });
```

禁止：

- 页面直接 `import axios from 'axios'`。
- 业务代码重复创建请求实例、重复拼接 Token 或租户头。
- 捕获认证异常后自行清 Token、刷新页面或跳登录。
- 在源码中写死域名、IP、Token、Cookie或密码。

## 四、列表页和 useTable

标准分页列表使用 `/@/hooks/table`：

```ts
import { BasicTableProps, useTable } from '/@/hooks/table';
import { getOrderPage } from '/@/api/order';

const state = reactive<BasicTableProps>({
	pageList: getOrderPage,
	queryForm: {
		keyword: '',
	},
	tableAlign: {
		name: 'left',
		amount: 'right',
	},
});

const {
	getDataList,
	currentChangeHandle,
	sizeChangeHandle,
	sortChangeHandle,
	tableStyle,
} = useTable(state);
```

```vue
<el-table
	:data="state.dataList"
	v-loading="state.loading"
	:cell-style="tableStyle.cellStyle"
	:header-cell-style="tableStyle.headerCellStyle"
	@sort-change="sortChangeHandle"
>
	<el-table-column prop="name" label="订单名称" />
	<el-table-column prop="amount" label="金额" sortable="custom" />
</el-table>

<Pagination
	v-bind="state.pagination"
	@size-change="sizeChangeHandle"
	@current-change="currentChangeHandle"
/>
```

- 未配置的列默认居中；文本列可左对齐，数字列可右对齐。
- 不手写与 `useTable` 重复的分页、排序、下载逻辑。
- 搜索通常调用 `getDataList()` 回第一页；保留当前页刷新使用 `getDataList(false)`。

## 五、权限、表单和国际化

```vue
<el-button v-auth="'order_add'" type="primary" @click="openCreate">新增</el-button>
```

- 后端权限按钮必须使用项目 `v-auth` 约定。
- 表单提交前执行 `validate`，提交期间禁用按钮，成功后再关闭弹窗和刷新列表。
- 用户可见的可翻译业务文案进入页面 `i18n/zh-cn.ts`、`i18n/en.ts`。
- 对外提供模块时，业务目录必须加入 `currentRemoteConfig.i18nScanDirs`，生成的 `src/i18n/moduleFederation.ts` 禁止手工修改。

## 六、静态资源

```ts
import orderIconSource from '/@/assets/images/order/icon.png';
import { getPublicResourceUrl, getStaticResourceUrl } from '/@/hooks/moduleFederation';

const orderIcon = getStaticResourceUrl(orderIconSource);
const workerUrl = getPublicResourceUrl('/workers/order-worker.js');
```

禁止在模板或 CSS 中硬编码 `/assets/...`。详见[样式布局与静态资源规范](./样式布局与静态资源规范.md)。

## 七、代码生成检查

- [ ] 只生成需求内文件，不覆盖已有业务代码。
- [ ] 使用真实的模块联邦（综合端）API、组件和 Hooks，不虚构导入路径。
- [ ] 页面具备加载、空、错状态和权限控制。
- [ ] API、类型、页面、子组件职责分离。
- [ ] 列表页绑定 `tableStyle`，按需配置 `tableAlign`。
- [ ] 静态资源已转换，未写死部署前缀。
- [ ] 需要远程提供的页面已完成 expose、i18n和样式检查。
- [ ] 新增中文文件为 UTF-8 无 BOM。
