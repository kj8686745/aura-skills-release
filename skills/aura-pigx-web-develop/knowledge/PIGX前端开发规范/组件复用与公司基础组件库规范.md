# 组件复用与公司 UI 规范

## 一、组件选择顺序

1. 模块联邦（综合端）已有全局组件和 Hooks。
2. 公司 UI 规范提供的 `@fxft/ui-plus` 能力。
3. Element Plus。
4. 当前业务目录内的业务组件。
5. 确认无法复用后才新增跨业务公共组件。

本规范只覆盖公司 UI 规范范围，不展开 `@fxft/biz-plus-main`。

## 二、模块联邦（综合端）全局组件

当前 `src/components/index.ts` 注册的常用组件包括：

| 组件 | 用途 |
| --- | --- |
| `Pagination` | 标准分页，直接绑定 `state.pagination` |
| `RightToolbar` | 查询表格右侧工具栏 |
| `DictTag`、`DictSelect` | 字典展示和选择 |
| `UploadFile`、`UploadImg`、`UploadImgPlus` | 文件和图片上传 |
| `Editor` | 富文本编辑器 |
| `DelWrap` | 删除确认包装 |
| `TagList` | 标签列表 |
| `SvgIcon` | 项目 SVG 图标 |
| `ChinaArea` | 行政区划选择 |
| `OrgSelector` | 组织选择 |
| `Sign` | 签名板 |
| `CollapsePanel` | 折叠面板 |
| `Splitpanes`、`Pane` | 分割面板 |

全局组件可以直接在模板中使用，但生成代码前仍应检查当前模板注册表，禁止依据旧项目虚构组件。

## 三、安装 @fxft/ui-plus

公司 UI 规范相关依赖位于公司 Nexus 私服，安装前必须完成 `.npmrc`、用户认证和读取权限检查。详见[公司 UI 规范下载与权限配置说明](./公司组件库下载说明/README.md)。

`@fxft/ui-plus` 是业务按需安装的公司 UI 规范依赖，不是模块联邦（综合端）模板的核心依赖。框架不得自动安装、预置其 Resolver 或假定所有业务项目都可使用；业务项目根据地图、视频等实际需求接入。

模块联邦（综合端）项目使用 pnpm。安装时固定已验证版本，升级必须重新核对公开 API：

```bash
pnpm add @fxft/ui-plus@1.0.32 --save-exact --registry=https://repository.fxft.online/repository/npm-public/
```

私有 registry 和读取认证按[公司 UI 规范下载与权限配置说明](./公司组件库下载说明/README.md)配置，不写入业务运行时代码。随附 `.npmrc` 仅限公司内部使用，不得对外分发。未经项目负责人确认不得自行安装或升级依赖。

## 四、模块联邦项目推荐接入

远程页面被消费时不会执行提供方 `main.ts`，因此禁止只依赖：

```ts
app.use(FxftUiPlus);
```

否则独立运行可用，远程运行可能提示组件未解析。推荐在 Vite 编译期按需解析组件和样式。

模块联邦（综合端）项目已安装 `unplugin-vue-components`，只需合并组件解析插件配置：

```ts
import Components from 'unplugin-vue-components/vite';
import { FxftUiPlusResolver } from '@fxft/ui-plus/resolver';
import { createComponentOverrideResolver } from './src/config/componentOverrides';

export default defineConfig({
	plugins: [
		Components({
			dts: false,
			dirs: [],
			resolvers: [createComponentOverrideResolver(pathResolve), FxftUiPlusResolver()],
		}),
	],
});
```

合并要求：

- 不覆盖已有 Vite 插件、imports 或 resolver。
- 同一 resolver 不重复注册。
- 框架提供的 `createComponentOverrideResolver` 必须保留，并放在业务组件库 Resolver 之前。
- 样式由 resolver 按组件注入并随远程 expose 构建。
- Element Plus 固定为 `2.14.3`，并在 Module Federation `shared` 中保持 singleton。
- `@fxft/ui-plus` 属于业务依赖，不加入框架 shared。

框架的组件覆盖表默认为空。业务可以按实际需要登记自己的覆盖项，例如某个业务项目覆盖 `ElEmpty`；这属于业务选择，不代表框架预置该组件。

## 五、显式 import

不使用 resolver 的局部场景可显式 import：

```vue
<script setup lang="ts">
import { FxftMap, FxftVideoPlayer } from '@fxft/ui-plus';
</script>
```

显式 import 必须确认对应组件样式已正确引入。不要同时全量注册、resolver 和显式重复引入同一套全局样式。

## 六、组件拆分规则

- 页面私有组件放在页面目录 `components/`。
- 只共享业务逻辑时优先抽 composable，不为复用一段请求强行抽 UI 组件。
- 组件 Props 明确类型，不传整个页面 state。
- 组件通过 `emit` 表达业务动作，不直接修改父组件数据。
- 复杂弹窗、抽屉、地图、视频使用 `ref` 时只调用公开 Exposes。
- 不访问组件库内部 DOM、下划线字段或底层 SDK实例。

## 七、地图和视频组件

| 场景 | 组件 | 专项规范 |
| --- | --- | --- |
| 2D 地图、点位、轨迹、热力、绘制 | `FxftMap` | [2D 地图开发规范](./2D地图开发规范.md) |
| 单路直播、录像、点播、PTZ | `FxftVideoPlayer` | [视频开发规范](./视频开发规范.md) |
| 多路分屏、拖拽换位、轮巡 | `FxftMultiVideoPlayer` | [视频开发规范](./视频开发规范.md) |

禁止绕过组件库重复引入地图 SDK，或直接封装 `JessibucaPro`、`JessibucaProMulti`。

- [ ] 已先检查模块联邦（综合端）全局组件和公司 UI 规范。

- [ ] resolver 合并而非覆盖已有 Vite 配置。
- [ ] 远程页面不依赖提供方 `main.ts` 全局注册。
- [ ] 组件样式出现在远程构建产物中。
- [ ] Element Plus 使用 `2.14.3` 并保持 Module Federation singleton。
- [ ] `@fxft/ui-plus` 仅在业务需要时安装，未作为框架模板依赖或 shared。
- [ ] 框架覆盖 Resolver 保留且位于业务组件库 Resolver 之前。
- [ ] 只调用组件公开 Props、Events、Slots和Exposes。
- [ ] 独立运行和远程运行均能正确解析组件及样式。
