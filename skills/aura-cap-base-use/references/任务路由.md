# aura-cap-base-use 任务路由与执行指南

仅在当前任务需要选择能力章节、接入检查或示例时读取本文件。先命中任务，再打开对应能力文档；不要把路由表当作新的规范。

## 开发时

文件存储接入时使用[接入检查](../checklists/capability-integration.md)复核实现、权限、流与结果边界；其他能力按命中的能力文档执行，不因一个任务加载整包。

1. 核对项目的 AURA 版本、所需公共模块、配置和能力状态。依赖与启动配置先读[基础能力接入要点](standards/05-能力包/01-通用工具类/03-基础通用支撑能力包/04-基础能力使用规范.md)中的 `AURA-CAP-BASE-001`、`002`、`017`～`020`；使用文件存储时再读[文件存储能力说明](standards/05-能力包/01-通用工具类/03-基础通用支撑能力包/08-文件存储能力说明.md)中的 `AURA-CAP-BASE-021`～`027`。其共同依赖和配置要求回到文中引用的基础规范，不得因示例出现某个类就推断当前项目已具备该能力。
2. 根据命中的任务读取详细说明、接入要点及示例，沿用公开入口完成业务实现。不要复制公共包内部实现，也不要把内部 `R<T>` 契约用于公开 OpenAPI。
3. 写接口同时核对当前用户、权限、租户和审计边界。`@Idempotent` 仅在项目中确认服务端拦截实际生效并验证重复请求结果后使用；注解存在本身不是防重证明。
4. 完成后分别按适用的基础规则和命中的能力接入要点检查正常、错误与边界结果，并记录项目中实际验证过的行为。文档示例不能代替项目联调。

文件存储任务必须额外核对：对象键是否由服务端生成、文件是否绑定业务和租户、读取/删除是否再次鉴权、流是否关闭，以及 `file.oss.info` 或签名 URL 是否已有接口和审计证据。不能只因为 `FileTemplate` 可以注入就宣称文件访问已安全可用。

## 边界

项目版本与技能引用的规范不匹配、能力清单没有公开入口，或关键配置和失败行为无法确定时，停止按本技能推断实现并说明缺口。本技能不制定新规范、不决定能力发布状态，也不读取内部治理、审查或评分资料。
