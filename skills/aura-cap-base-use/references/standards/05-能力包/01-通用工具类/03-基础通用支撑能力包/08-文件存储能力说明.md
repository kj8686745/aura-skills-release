# 文件存储能力说明

**能力编号**：AURA-CAP-BASE-021～AURA-CAP-BASE-027  
**能力名称**：`aura-common-oss` 文件存储  
**能力包**：AURA-CAP-BASE 基础通用支撑能力包  
**版本**：0.1.0-draft  
**源码依据**：`aura-core-common` `dev@e311702` 的 `aura-common-oss`；目标项目须核对实际依赖版本和运行结果  
**状态**：候选能力说明

## 1. 能力定位

`aura-common-oss` 为业务提供统一的文件存储入口，使业务代码通过 `FileTemplate` 访问本地磁盘或兼容 AWS S3 协议的对象存储。业务模块不直接创建 MinIO、S3 或其他厂商客户端，也不把具体存储实现写进 Controller 或 Service 的业务编排中。

这项能力解决的是“文件放在哪里、如何上传/读取/删除以及如何切换存储实现”的公共技术问题；以下内容仍由业务模块负责：

- 文件属于哪个业务对象、用户和租户；
- 谁可以上传、读取、下载或删除；
- 文件元数据、版本、状态和业务关联如何保存；
- 文件内容校验、病毒扫描、敏感信息处理和生命周期策略；
- 大文件导出、异步任务和实时进度通知。

文件任务、Excel、SSE 和 WebSocket 的组合用法见[文件任务与实时交互能力包](../04-文件任务与实时交互能力包/总入口.md)。该能力包不再重复定义 `FileTemplate` 的基础接入契约。

## 2. 能力清单

| 能力编号 | 能力 | 公开入口/配置 | 使用结果 | 适用边界 |
| --- | --- | --- | --- | --- |
| AURA-CAP-BASE-021 | 统一文件存储入口 | `FileTemplate` | 业务可在不绑定具体厂商 SDK 的情况下上传、读取、删除对象 | 必须先确认目标项目实际注入的实现 |
| AURA-CAP-BASE-022 | 本地文件存储 | `LocalFileTemplate`、`file.local.*` | 本地开发或单机部署可将对象保存到配置的根目录 | 不适合作为未评估容量、备份和多实例一致性的生产方案 |
| AURA-CAP-BASE-023 | S3 兼容对象存储 | `OssTemplate`、`file.oss.*` | 可接入 MinIO、云对象存储等 S3 兼容服务 | endpoint、区域、路径风格和权限必须按目标厂商核对 |
| AURA-CAP-BASE-024 | Bucket 管理 | `createBucket` 及对应管理入口 | 在初始化或运维流程中创建、查询和删除存储桶 | 不应在每次业务上传时无条件创建桶 |
| AURA-CAP-BASE-025 | 对象写入与读取 | `putObject`、`getObject` | 写入对象并取得对象流 | 输入流、内容类型、对象键和异常处理必须明确 |
| AURA-CAP-BASE-026 | 对象删除 | `removeObject` | 删除对象并由业务同步处理元数据状态 | 删除前必须完成业务权限和归属校验 |
| AURA-CAP-BASE-027 | 签名 URL 与可选 HTTP 端点 | `OssTemplate.getObjectURL`、`file.oss.info` | 在已核对实现和权限后提供限时访问或运维接口 | 仅 OSS 实现支持的扩展不能写成 `FileTemplate` 的通用能力 |

## 3. 依赖接入

### 3.1 Maven 依赖

按项目采用的 AURA 版本引入模块，不在业务项目中单独固定与平台 BOM 冲突的版本：

```xml
<dependency>
    <groupId>net.fxft</groupId>
    <artifactId>aura-common-oss</artifactId>
    <version>${aura.version}</version>
</dependency>
```

接入前确认：

1. 项目确实使用包含 `aura-common-oss` 的 AURA 版本；
2. `FileTemplate`、`LocalFileTemplate` 和 `OssTemplate` 的包路径与方法签名和当前源码一致；
3. 当前应用只配置了预期的存储实现，若同时存在多个 Bean，已确认注入优先级；
4. 业务模块的文件权限、租户、元数据和异常处理已经设计。

### 3.2 配置项

配置前缀为 `file`。下表依据上述源码与自动配置；目标项目仍须按实际依赖版本核对。

| 配置项 | 类型 | 文档默认值 | 作用 | 使用要求 |
| --- | --- | --- | --- | --- |
| `file.bucket-name` | String | `local` | 默认存储桶名称 | 业务对象键不能只依赖默认桶名表达归属 |
| `file.local.enable` | boolean | `true` | 是否启用本地存储 | 生产多实例部署前必须评估共享盘、备份和一致性 |
| `file.local.base-path` | String | 未指定 | 本地文件根目录 | 使用绝对路径或明确的受控工作目录，不接受用户输入拼接路径 |
| `file.oss.enable` | boolean | `false` | 是否启用 OSS/S3 实现 | 启用后核对 Bean 优先级和实际连通性 |
| `file.oss.endpoint` | String | 未指定 | 对象存储服务地址 | 由环境配置提供，不写入代码 |
| `file.oss.custom-domain` | String | 未指定 | 外链域名 | 仅在访问权限、HTTPS 和域名归属已确认时配置 |
| `file.oss.path-style-access` | boolean | `true` | S3 路径风格访问 | 按对象存储厂商兼容要求配置 |
| `file.oss.access-key` | String | 未指定 | 访问身份 | 只能来自密钥管理或环境注入 |
| `file.oss.secret-key` | String | 未指定 | 访问密钥 | 禁止进入 Git、日志、接口响应和示例真实值 |
| `file.oss.app-id` | String | 未指定 | 部分厂商的应用标识 | 仅目标厂商要求时配置 |
| `file.oss.region` | String | 未指定 | 服务区域 | 按存储服务实际区域配置 |
| `file.oss.max-connections` | Integer | `100` | HTTP 最大连接数 | 按并发、文件大小和服务端限制评估，不直接照搬默认值 |
| `file.oss.skip-md5-check` | boolean | `false` | 是否跳过下载 MD5 校验 | 关闭校验前必须有完整性依据和风险说明 |
| `file.oss.info` | boolean | `false` | 是否启用 `OssEndpoint` | 开启前必须完成接口鉴权、路径、审计和暴露范围审查 |

### 3.3 配置示例

以下示例只展示结构，敏感值必须由环境或密钥管理系统注入：

```yaml
file:
  bucket-name: aura-bucket
  oss:
    enable: true
    endpoint: ${FILE_OSS_ENDPOINT}
    access-key: ${FILE_OSS_ACCESS_KEY}
    secret-key: ${FILE_OSS_SECRET_KEY}
    region: ${FILE_OSS_REGION:cn-north-1}
    path-style-access: ${FILE_OSS_PATH_STYLE:true}
    info: false
```

本地开发可使用：

```yaml
file:
  bucket-name: local
  local:
    enable: true
    base-path: ${FILE_LOCAL_BASE_PATH}
```

不允许将 `minioadmin`、真实 Access Key、Secret Key 或生产 endpoint 固定写入示例和代码仓库。

## 4. 业务接入流程

```text
确认业务对象、租户和文件权限
→ 选择本地或对象存储实现
→ 引入 aura-common-oss 并核对配置
→ 生成受控对象键
→ 通过 FileTemplate 写入对象
→ 写入业务文件元数据与对象键关联
→ 读取/下载前再次校验权限和归属
→ 删除或替换时同步更新业务状态与对象
```

### 4.1 对象键规则

对象键由服务端根据业务域、租户、业务对象和随机文件名生成，不能直接使用用户提交的绝对路径或未经处理的原始文件名。建议结构如下：

```text
{业务域}/{租户标识}/{业务对象}/{随机标识}.{安全扩展名}
```

对象键不包含 token、Cookie、Secret Key、身份证号等敏感信息。原始文件名仅作为展示元数据保存，并经过长度、字符和敏感内容处理。

### 4.2 上传、读取和删除示例

下面示例只展示公共存储入口。`AttachmentRecordService`、`AttachmentObjectKeyFactory`、权限判断和业务实体由业务模块实现，不是 `aura-common-oss` 自动提供的能力。示例中的文件归属校验封装在 `requireReadable` 和 `requireDeletable` 中。

```java
@Service
@RequiredArgsConstructor
public class AttachmentStorageService {
    private final FileTemplate fileTemplate;
    private final FileProperties fileProperties;
    private final AttachmentObjectKeyFactory objectKeyFactory;
    private final AttachmentRecordService recordService;

    public AttachmentRecord save(Long ownerId, InputStream input, String contentType) throws Exception {
        // 业务层先完成当前用户、租户和 ownerId 的访问校验。
        String objectKey = objectKeyFactory.create(ownerId, contentType);
        String bucket = fileProperties.getBucketName();

        // 只通过统一入口写入，不能在这里 new MinioClient 或 S3Client。
        fileTemplate.putObject(bucket, objectKey, input, contentType);

        // 存储成功后再记录业务关联；失败时不得留下“已上传”的假记录。
        return recordService.create(ownerId, bucket, objectKey, contentType);
    }

    public void copyTo(Long attachmentId, OutputStream output) throws IOException {
        AttachmentRecord record = recordService.requireReadable(attachmentId);
        // 调用方负责响应头和输出流；此处关闭存储对象及其内容流。
        try (S3Object object = fileTemplate.getObject(record.bucketName(), record.objectKey())) {
            object.getObjectContent().transferTo(output);
        }
    }

    public void remove(Long attachmentId) throws Exception {
        AttachmentRecord record = recordService.requireDeletable(attachmentId);
        fileTemplate.removeObject(record.bucketName(), record.objectKey());
        recordService.markDeleted(attachmentId);
    }
}
```

`FileTemplate.getObject` 在上述源码版本返回 `S3Object`；其他版本须核对签名。示例没有解决“对象存储写入成功、业务记录写入失败”和“对象删除成功、业务状态更新失败”的跨系统一致性，业务实现须定义清理、重试或补偿。上述 `OssTemplate` 写入实现会先把输入流完整读入内存；大文件不能仅凭这个示例直接接入，须按文件批处理与资源规范评估。

### 4.3 签名 URL

`getObjectURL` 是 `OssTemplate` 的实现扩展，不是所有 `FileTemplate` 实现都保证提供。只有确认底层实现、签名有效期、访问权限和域名策略后才可使用：

```java
if (fileTemplate instanceof OssTemplate ossTemplate) {
    // 先完成业务权限判断；有效天数由业务契约约束。
    return ossTemplate.getObjectURL(bucketName, objectKey, validDays);
}
throw new UnsupportedOperationException("当前文件存储实现不支持签名 URL");
```

签名 URL 的有效期、下载审计、撤销策略和是否允许直接暴露给浏览器，必须由业务接口契约明确；不能把签名 URL 当成永久公开地址。

## 5. 可选 HTTP 端点

当 `file.oss.info=true` 且当前版本的自动装配条件满足时，`OssEndpoint` 会提供 `/oss/*` 管理接口。它是可选底层端点，不是业务应用可直接对外发布的统一接口：上述源码中的方法直接返回 `Bucket`、`S3Object`、`Map` 或 `void`，未通过业务 DTO 与统一响应封装，也未在端点方法中声明业务权限和租户校验。默认保持 `info: false`；业务文件接口应由应用层按接口规范封装。

| 资源 | 方法 | 路径 | 结果/风险 |
| --- | --- | --- | --- |
| Bucket | `POST` | `/oss/bucket/{bucketName}` | 创建存储桶；必须限制为受控运维或初始化权限 |
| Bucket | `GET` | `/oss/bucket` | 查询存储桶列表；不得无权限暴露租户或基础设施信息 |
| Bucket | `GET` | `/oss/bucket/{bucketName}` | 查询指定存储桶；必须校验访问边界 |
| Bucket | `DELETE` | `/oss/bucket/{bucketName}` | 删除存储桶；必须有高风险操作保护和二次确认 |
| Object | `POST` | `/oss/object/{bucketName}` | 使用原始文件名上传；必须限制文件名、大小、类型和权限 |
| Object | `POST` | `/oss/object/{bucketName}/{objectName}` | 使用指定对象名上传；对象名不能直接接受任意路径 |
| Object | `GET` | `/oss/object/{bucketName}/{objectName}` | 按前缀查询对象；需防止越权枚举 |
| Object | `GET` | `/oss/object/{bucketName}/{objectName}/{expires}` | 获取限时签名 URL；需限制有效期和访问方 |
| Object | `DELETE` | `/oss/object/{bucketName}/{objectName}/` | 删除对象；必须完成业务归属和权限校验 |

若确需启用该运维端点，必须先核对部署入口隔离、认证授权和审计；不能只通过配置开关为其补出统一业务响应或租户权限。面向业务调用方的上传、下载、删除接口应另由应用层封装统一响应、DTO、权限、错误及联调文档。

## 6. 正例与反例

### 正例：统一入口 + 业务关联

```java
fileTemplate.putObject(bucket, serverGeneratedKey, inputStream, contentType);
attachmentRecordService.create(ownerId, bucket, serverGeneratedKey, contentType);
```

条件：对象键由服务端生成；上传前后有权限、租户和失败状态处理；文件流和存储对象的生命周期有明确关闭策略。

### 反例：业务代码直接绑定厂商客户端

```java
MinioClient client = MinioClient.builder().endpoint(userInputEndpoint).build();
client.putObject(...);
```

问题：绕过 AURA 统一配置和切换入口，可能把用户输入当 endpoint，无法统一鉴权、审计、重试和资源策略。

### 反例：把原始文件名当对象路径

```java
fileTemplate.putObject(bucket, request.getParameter("path"), input, contentType);
```

问题：存在路径穿越、对象覆盖、敏感信息泄露和跨业务/租户访问风险。

## 7. 完成判断

- 项目依赖和实际版本已核对，未凭文档臆测方法签名；
- 已选择并验证本地或对象存储实现，配置来自环境或密钥管理；
- 上传、读取、删除均经过业务权限、租户和对象归属校验；
- 业务记录与对象键、内容类型、原始文件名、状态和删除策略一致；
- 输入流、对象流、超时、异常和失败补偿边界已明确；
- 若启用 `/oss/*` 或签名 URL，接口契约、鉴权、审计和有效期已有证据；
- 已完成至少一条成功、参数错误、权限拒绝、存储失败和删除失败的项目自测；
- 仍未在目标项目验证的项明确标记为“未验证”，不写成能力已上线。
