# 基础通用支撑能力包使用技能

询问如何调用本技能时，阅读[使用说明](USAGE.md)。

本技能版本为 `1.0.0`。能力事实与接入方式以链接的同版能力包正文为准；共同研发规则以基础编码规范正文为准。能力包编号只定位接入要点，不作为项目必须选用该能力的依据。

## 任务选择

先在[能力包入口](references/standards/05-能力包/01-通用工具类/03-基础通用支撑能力包/01-总入口.md)和[能力地图](references/standards/05-能力包/01-通用工具类/03-基础通用支撑能力包/02-能力清单与边界.md)确认任务确需本包，再按[研发任务导航](references/研发任务导航.md)只读取命中的接入要点和示例。数据库建模、Mapper、Service 分层及事务的共同要求以基础编码规范为准；选用 AURA 数据访问等入口时，再用 `aura-cap-common-business-use` 查接入组合。本技能只补充命中的公共能力用法。

## 开发时

文件存储接入时使用[接入检查](checklists/capability-integration.md)复核实现、权限、流与结果边界；其他能力按命中的能力文档执行，不因一个任务加载整包。

1. 核对项目的 AURA 版本、所需公共模块、配置和能力状态。依赖与启动配置先读[基础能力接入要点](references/standards/05-能力包/01-通用工具类/03-基础通用支撑能力包/04-基础能力使用规范.md)中的 `AURA-CAP-BASE-001`、`002`、`017`～`020`；使用文件存储时再读[文件存储能力说明](references/standards/05-能力包/01-通用工具类/03-基础通用支撑能力包/08-文件存储能力说明.md)中的 `AURA-CAP-BASE-021`～`027`。其共同依赖和配置要求回到文中引用的基础规范，不得因示例出现某个类就推断当前项目已具备该能力。
2. 根据命中的任务读取详细说明、接入要点及示例，沿用公开入口完成业务实现。不要复制公共包内部实现，也不要把内部 `R<T>` 契约用于公开 OpenAPI。
3. 写接口同时核对当前用户、权限、租户和审计边界。`@Idempotent` 仅在项目中确认服务端拦截实际生效并验证重复请求结果后使用；注解存在本身不是防重证明。
4. 完成后分别按适用的基础规则和命中的能力接入要点检查正常、错误与边界结果，并记录项目中实际验证过的行为。文档示例不能代替项目联调。

文件存储任务必须额外核对：对象键是否由服务端生成、文件是否绑定业务和租户、读取/删除是否再次鉴权、流是否关闭，以及 `file.oss.info` 或签名 URL 是否已有接口和审计证据。不能只因为 `FileTemplate` 可以注入就宣称文件访问已安全可用。

## 边界

项目版本与技能引用的规范不匹配、能力清单没有公开入口，或关键配置和失败行为无法确定时，停止按本技能推断实现并说明缺口。本技能不制定新规范、不决定能力发布状态，也不读取内部治理、审查或评分资料。
