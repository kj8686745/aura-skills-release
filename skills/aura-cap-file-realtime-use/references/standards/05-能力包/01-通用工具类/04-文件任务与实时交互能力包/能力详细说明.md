# 文件任务与实时交互能力详细说明

**版本**：0.1.0-draft  
**状态**：建设中  
**当前源码依据**：`aura-core-common` `dev@4a2a1f1`

## 使用前确认

按实际任务引入 `net.fxft` 下对应的 `aura-common-oss`、`aura-common-excel`、`aura-common-sse` 或 `aura-common-websocket` 模块；依赖版本由项目采用的 AURA 依赖管理确定，不应把模块全部引入。文件存储先确认 `FileTemplate` 实际注入的是本地还是对象存储实现。`aura-common-download` 当前不作为可直接照用的下载任务能力；不能为了使用本包其他入口而一并引入。文中的代码示例不能代替项目启动、权限和运行验证。

## 1. 文件存储组合说明

文件存储的公共依赖、配置、`FileTemplate` API、对象键、权限边界、正反例和完成判断统一见[基础通用支撑能力包文件存储说明](../03-基础通用支撑能力包/08-文件存储能力说明.md)。本能力包只补充它与 Excel、SSE、WebSocket 或异步文件任务的组合关系，不再维护第二套文件存储契约。

组合接入时仍需确认：

1. 文件上传或生成任务的业务权限、租户和文件元数据；
2. 文件任务的状态、失败重试、结果访问和删除策略；
3. SSE/WebSocket 通知的接收人、事件顺序、断线与重连语义；
4. 目标项目实际启用的模块和运行版本。

## 2. 下载任务模块现状（非接入说明）

### 能力作用

当前 `aura-common-download` 包含 `@ExportMonitor`、任务模型和响应封装，但 `IExportExcelService` 的实现整体被注释，模块自身没有提供完整的状态查询与授权下载入口。任务归属和结果文件可访问性也不能仅从切面执行或任务状态推断。这里记录模块现状，不提供 `@ExportMonitor` 的业务接入步骤、正反例或“完成”结论。

需要大文件导出时，按[文件批处理与性能边界](../../../01-基础编码规范/11-运行时并发与资源管理规范/04-文件批处理与性能边界.md)确定规模、内存和任务边界，按[身份上下文与权限边界](../../../01-基础编码规范/07-安全身份权限与敏感信息规范/01-身份上下文与权限边界.md)和[前端会话与文件访问](../../../01-基础编码规范/07-安全身份权限与敏感信息规范/03-前端会话与文件访问.md)处理提交与结果访问权限。目标项目若已有完整且验证过的文件任务实现，可按该项目的版本契约接入；不能仅引用本模块并宣称下载中心可用。

## 3. Excel 导入导出

### 能力作用

提供 Excel 请求解析、响应导出、字段转换、校验和多 Sheet 处理能力。

### 开发步骤

1. 定义导入 DTO 和导出 VO，不直接使用持久化实体；
2. 声明列名、类型、必填和错误信息；
3. 导入时逐行校验，并明确失败行的反馈方式；
4. 大文件导入使用任务或分批处理；
5. 导出时限制查询范围和字段，敏感字段必须脱敏；
6. 记录导入、导出操作日志。

### 正确方向

```java
@PostMapping("/import")
public R<ImportResult> importDevices(@RequestExcel List<DeviceImportRow> rows) {
    return R.ok(deviceImportService.importRows(rows));
}
```

`@RequestExcel` 修饰 `List<导入行DTO>` 参数，而不是方法；上传字段默认名为 `file`。`ImportResult` 和业务 Service 是项目业务类型，需由项目定义。导出时 `@ResponseExcel` 修饰返回 `List<导出行VO>` 的方法，不能直接把持久化实体交给响应处理器。

### 错误方向

```java
public void importData(List<DeviceEntity> rows) {
    deviceMapper.batchInsert(rows);
}
```

直接将上传内容绑定到实体并批量入库，缺少字段校验、权限和失败行处理。

### 完成判断

- 导入 DTO 与实体分离；
- 失败行和错误原因可追踪；
- 导入具备重复提交和事务边界设计；
- 导出字段符合权限和敏感数据要求。

## 4. SSE 能力

### 能力作用

SSE 适用于服务端向前端单向发送进度、通知或流式结果。它不适合需要客户端频繁反向发送消息的双向会话。

### 开发步骤

1. 定义连接身份、租户和权限；
2. 使用当前模块的 SSE 端点建立连接，并核对项目实际暴露路径；
3. 为每类事件定义事件名和数据结构；
4. 处理断开、超时、重连和多实例分发；
5. 关闭连接时清理持有器和订阅关系。

### 正确方向

```java
// 业务侧已确认接收人及其租户、事件访问权限后发送。
boolean sent = SseEmitterMessageSender.send(recipientUserId, eventPayload);
// false 表示当前发送入口没有成功投递，不能据此宣称用户已收到。
```

当前 `SseEmitterEndpoint` 在 `/sse/info` 建立连接并按用户 ID 登记；发送器提供定向发送和广播。这个入口没有替业务完成事件级租户隔离，广播也不适合发送用户私有数据。多实例时须核对所用分发器及断线后的投递语义。

### 错误方向

```java
SseEmitterMessageSender.broadcast(privateProgressPayload);
```

把某个用户的导出进度广播给所有连接，会越过接收人和租户边界。

### 完成判断

- 未授权用户不能订阅他人事件；
- 事件数据不会跨租户发送；
- 断开和重连不会遗留连接；
- 业务方知道事件顺序、重复和丢失语义。

## 5. WebSocket 能力

### 能力作用

WebSocket 适用于需要保持会话并进行双向实时通信的场景，例如协同状态、实时控制和双向消息。

### 开发步骤

1. 明确握手认证、会话身份和允许来源；
2. 定义消息类型、版本和错误格式；
3. 按消息类型实现 `JsonMessageHandler<T>`，让 `type()`、`getMessageClass()` 与实际消息一致；
4. 明确心跳、断线重连、顺序和重复消息处理；
5. 多实例部署时定义消息分发和会话路由；
6. 关闭会话时清理服务端持有状态。

当前模块默认连接路径是 `/ws/info`，并提供 `WebSocketMessageSender.send(sessionKey, message)` 和 `JsonMessageHandler<T>`。默认允许来源较宽，项目接入时应限制到实际前端来源；握手拦截器存在不等于每类业务消息都已完成鉴权。

### 正确方向

业务消息处理器实现 `JsonMessageHandler<T>` 后，先按当前会话身份核对消息类型和业务资源权限，再调用业务 Service；回复消息可使用 `WebSocketMessageSender.send(session, responseMessage)`，定向发送前应确认目标会话属于预期接收人。

### 错误方向

```java
session.sendMessage(new TextMessage(request.getParameter("message")));
```

直接转发客户端内容，缺少消息类型校验、权限校验和敏感数据处理。

### 完成判断

- 握手和每类消息都有权限边界；
- 消息格式、版本和失败语义明确；
- 断线、重连和会话清理经过设计；
- 多实例下不会把消息发送给错误会话。

## 6. 能力组合示例

```text
用户上传业务附件
→ 应用校验用户与业务资源权限
→ FileTemplate 保存对象
→ 应用保存对象键与业务记录的关系
→ 如需实时通知，向已核实的接收人定向发送 SSE 事件
→ 后续读取文件时按业务归属再次校验权限
```

这个组合只展示文件存储和 SSE 的可选协作；业务关联、权限与通知语义由应用实现。Excel 的导入导出用法见第 3 节，不能由本示例推断下载任务已可接入。若需要按周期统一调度文件生成，应另读[任务与调度能力包](../08-任务与调度能力包/总入口.md)。
