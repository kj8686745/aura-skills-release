# 审计类型与报告契约

## 端类型边界

- 综合端必须同时具备 PIGX 综合端基础配置、标准 expose 聚合、config/aura 公共包运行时绑定，以及 Vite Module Federation 配置。
- 生产端是存在对外 exposes、但不具备 PIGX 综合端运行时外壳的项目。
- 消费端是存在 remotes、运行时远程注册或远程加载行为、但不具备综合端和生产端特征的项目。
- 同时命中生产端和消费端、或证据不足时归类为 `Unknown`。

处理器按 `scripts/rules/<ProjectType>.ps1` 动态发现。首版只提供 `Integrated.ps1`；该处理器必须完整检查综合端内部的提供方 exposes、消费方 remotes、后台菜单和远程模块导入。后续新增独立生产端或消费端支持时，再增加 `Provider.ps1` 或 `Consumer.ps1`，无需修改主入口和报告模型。

## 报告约定

检查结果必须包含：项目类型、识别证据、规则编号、严重级别、文件、行号、问题和修复建议。

- `error`：可以从当前项目确定的违规，退出码为 `1`。
- `warning`：高风险候选项或缺少构建验证，不单独导致失败。
- `manual`：必须结合部署环境、后台菜单或运行时验证的事项。
- `pass`：已通过的关键检查或最终通过结论。

退出码：`0` 表示静态检查没有确定错误，仍需处理 warning/manual；不代表运行时验收完成，`1` 表示综合端存在错误，`2` 表示参数或类型无法识别，`3` 表示识别为首版未支持的生产端或消费端。

复检时对照实际消费链。例如 Vite 源码调用了 `federation()`，还要追踪其返回值是否进入生效配置的 `plugins`；包的导出文件存在时，还要确认当前 import 的具名 API 及声明确实可用。静态错误清零但这些检查缺证时，分别记录已关闭的规则和剩余缺口。

## 交付格式

1. **项目类型**：类型、识别证据和是否进入专项检查。
2. **已修复或待修复的偏差**：按规则编号给出原证据、位置及复检结果。只读模式交付发现和建议；默认检查另列实际改动。脚本严重级别和退出码用于定位，改法依据真实配置、依赖、调用方及用户范围确认。
3. **待决策与缺证**：列出已经核对过的材料。需要用户抉择时给出具体问题、可选方案及各自影响；缺运行条件时写明还需验证什么。报告标明哪些项正在等待决定，哪些已有证据关闭。
4. **验证结果**：脚本退出码、build 和运行时检查结果。
5. **剩余边界**：明确生产端、消费端、后台菜单或部署环境中未覆盖的部分。
6. **对外接入说明**：仅在综合端完成修改且复检无确定错误时，按参考列出 `remoteName`、`remoteEntryName`、待填 manifest 环境变量、业务/i18n/样式 expose、远程菜单 `componentPath` 与“带参”要求。
