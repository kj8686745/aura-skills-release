# AURA 模块联邦检查使用说明

## 适用与调用

在 AURA 综合端请求 `$aura-module-federation-check 检查当前项目模块联邦。` 时，技能会先检查，自动修复有充分依据且改法明确的偏差，再用改后配置复检。部署环境、远程身份或公共契约存在多种选择时，会说明选项与影响，请你决定。

项目编辑执行 `aura-web-develop` 的适用规范。生产端、消费端和证据不足的项目只报告类型及证据。直接运行 PowerShell 检查脚本只会采集结果，修改和复检由调用技能的代理执行。

从技能目录单独采集静态结果时，可运行 `pwsh -NoProfile -File scripts/check-module-federation.ps1 -ProjectPath <项目路径> -Json`。

## 需要提供的信息

- 项目路径；
- 是否仅审计、是否作为改前基线或改后复检；
- 需要核验远程菜单时的真实 `componentPath`；
- 指定消费方接入时的消费方项目路径与接入目标。

## 示例提示词

- `检查当前 AURA 综合端模块联邦配置，只做审计并输出问题。`
- `检查当前项目的首次菜单重载和依赖预构建。`
- `为新增 aura-order-web 远程配置做改前基线检查。`
- `模块联邦改完后复检，并输出提供方的对外接入说明。`
- `把当前提供方接入 E:\\code\\frontEnd\\company\\consumer，动态菜单只走运行时入口。`

## 边界

只读审计、改前基线和仅复检保持只读。普通检查中，代理会先处理独立的确定项；需要决定目标环境或 manifest 地址时再请你选择。
