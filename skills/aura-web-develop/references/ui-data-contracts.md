# i18n 分层与去重

- 按复用范围放置文案：全项目通用文案使用 `src/i18n/`；同一业务域内两个及以上页面/模块共用的文案使用 `src/views/<业务域>/i18n/`；仅单个页面或私有组件使用的文案才放入其业务目录 `i18n/`。
- 新增 key 前必须依次搜索全局、业务域和当前模块语言包；已存在且语义一致的 key 直接复用，禁止在相邻业务模块重复定义同义文案。发现同类文案已在多个模块出现或预期跨模块复用时，应按复用范围主动提取到全局或业务域公共语言包，并同步替换本次涉及模块的重复 key。
- 业务域共享 key 使用业务域命名空间，例如 `iot.clearFilter`；不得以页面名称承载跨页面通用语义。中英文语言包必须同步维护。
- 不为整理目录而无差别迁移历史 key；仅在本次需求涉及的模块中合并已确认重复、且不影响远程暴露和现有调用契约的文案。

## 新增文案的执行与验收

本节落实既有 FE-019，适用于功能开发中新增文案、修改文案值或新增/替换 `t()` / `$t()` 引用；纯注释整理保持原范围。修改前先从本次需求盘点文案，不以语言文件是否变更作为唯一触发条件。

1. **先查再写**：逐项在全局、业务域、当前模块语言包查中英文原文、近义表达和已有 key，并确认实际消费含义与语言注册。已有同义公共 key 直接引用；未查到时记录检索范围及新增原因，不能仅按页面命名空间创建。若任务已分给多个执行者，先共享本批公共文案与拟复用 key，避免各模块各造一份；不要求为此新建代理或单独报告。
2. **按消费者放置**：多个模块共用且已有业务域 key 时直接复用；确需新增公共 key 时按上述层级选择，并同步 zh/en 和本次涉及的引用。不凭“重试”“关闭”等短词预设一个不存在的 `common.*` key。相同字面但业务含义、插值参数或翻译语境不同的文案可保留独立 key，写明依据。
3. **稳定后逐项核对**：按 diff、未跟踪语言文件及本次新增/替换的调用列出新增/改值 key，核对公共检索和最终复用/提取/保留结论；原 key 复用也要确认双语与注册有效。提取后检查本次引用已替换、旧 key 是否仍有消费者及远程公开契约，不能为去重删除范围外仍在使用的键。

在既有开发记录或自检输入简记“本次 key/用途 → 检索目录与命中的公共 key（或未命中依据） → 最终 key 及复用层级 → 调用位置/保留原因”。同一公共文案可合并记录多个调用，不创建逐键机器矩阵。没有新增/改值/替换引用时按 diff 事实注明；未检索或未判断的项不能记通过。

`-StrictUiContracts` 还会将不同完整 key 的相同静态 zh/en 字符串对列为重复候选，涉及选中语言定义或选中源码字面量调用时才输出；全量语言包只作比对上下文。候选列出 key 与定义位置，不输出文案值，也不自动判违规或选定公共层级。动态值、导入、运行时注册/合并及文字不同的同义表达仍需人工核对；零候选不能代替上述检索。候选的语义、插值与真实使用确认后，在已有记录注明复用、提取或有据保留；脚本不承担语义判定。来源与验证边界见[维护记录](i18n-reuse-source.json)。

三字典组件的入口、Props、选项、空值和公开方法/插槽以 [aura-ui 组件库入口](../knowledge/PIGX前端开发规范/aura-ui组件库/README.md) 为按需说明；实际安装版本不同时重新核对。

## 枚举、字典、国际化与占位硬约束

- 编码前解析 API/OpenAPI、TypeScript 类型和相邻业务契约中的枚举与 `dictKey`，逐字段列出“筛选、表格、详情、表单”的渲染方式。接口类型中带字典的字段必须保留 `/** @dictKey <key> */` 注释，作为可扫描契约。
- 表格、详情及交互文案的组件选择统一按 [FE-012 字典展示规则](dictionary-table-contract.md)执行（[待绑定来源](dictionary-source.json)）：字典展示以原始 code + options 按语义选择组件；状态/结果/严重级别等独立分类标识优先 `AuraDictTag`，连续描述、规则摘要、句内枚举与行内交互提示可 `AuraDictText`，即使在表格内。触发规则摘要“离开区域 · 持续 · 时长”保留 Text 与行内排版，不强制逐片段改为 Tag。嵌套/弹窗表格、私有组件和动态列均检查同一语义边界，筛选继续按 Select 契约。真实实体/物模型事件名称先确认无字典关联，不凭 `*Name` 后缀机械整改。
- 沿“接口原始 code + `@dictKey`/真实字典关联 → 表格列/私有组件/可配置或动态列 → 最终组件渲染”取证，逐项核对传入的原始值、options 来源以及 formatter/slot/render 分支，不能只看组件名出现或零扫描命中。静态扫描不能证明动态列与交互语义均符合，未能追踪的链路保留缺证。核对实际依赖/锁定版本、已安装 exports/types、显式 import 或自动导入/Resolver 注册及真实使用；只检查公开契约，不开展 SDK 底层审计。组件或依赖缺失按证据记偏差或缺证，不自动升级，也不转为手写映射。源码仓库名 `aura-web-sdk` 的 UI 包公开名为 `@fxft/aura-ui`；不得虚构 `@fxft/aura-web-sdk` 包名或把 `DictTag` / `DictText` 当作已核实的公开导出。
- 业务 `.vue/.ts` 中用户可见文案一律使用 `t()` / `$t()`，覆盖 label、title、placeholder、按钮、列名、卡片标题与说明、Dialog/Drawer、空态、校验与消息。注释、接口/字典返回值、后端异常、mock 数据和 i18n 文件除外。
- 新文案先复用 `common`；跨两个及以上业务模块、但不属于全局 common 的文案上提到业务域公共 `i18n/`；中英文 key 同步存在。不得在页面 i18n 重复定义已有 common 或业务域文案。
- 每个可编辑或筛选的 `el-input`、`el-select`、`el-date-picker`、`el-input-number`、`el-autocomplete` 必须具备 i18n placeholder。确无占位语义时添加 `data-placeholder-exempt`，并以相邻中文注释说明原因。
- 行内查询表单中，查询、重置、导出、视图切换等每个独立操作各占一个无标签 `el-form-item`；禁止在同一无标签 `el-form-item` 内堆叠多个 `el-button` 或 `el-radio-group`。间距只由表单 `gap` 管理，不使用按钮相邻 margin 或负 `margin-bottom` 补偿。
- 功能开发在本批稳定后按[检查选择表](development-review-workflow.md#检查选择表)选择显式 `-Files` 或有依据的全量扫描，保留 `-StrictUiContracts`；纯注释按快速路径。直接中文、缺少 placeholder、i18n key 未在 zh/en 同步、或已声明 `@dictKey` 字段的 `*Name` 直出仍为错误，须在本次范围内整改后验收。

- 组件默认行为仅是公开契约事实，不意味着业务必须自行增加兜底。fallback 或未知值展示按真实需求配置；未经要求不新增转换、硬编码或覆盖值，不用自设 fallback 掩盖字典类型、选项来源或编码匹配错误。说明当前用途时写具体业务语义，不把组件默认行为描述成业务额外实现。
