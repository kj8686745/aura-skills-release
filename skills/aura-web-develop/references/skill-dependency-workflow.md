# 外部技能依赖检查与安装提示

本流程适用于 `aura-web-develop` 准备调用的任何其它技能，不限于当前已知名单。

技能依赖与工具能力分开判断：当前工具已能完成所需操作时，不因旧技能名称缺失而要求安装或判定受阻。Codex 内置浏览器按 [浏览器走查流程](codex-browser-review-workflow.md) 检查实际控制入口与连接结果；仅在确实需要调用另一个技能时，执行下述技能名检查。

## 调用前检查

1. 从当前环境提供的可用技能列表中按技能名精确检查。
2. 默认只有技能存在时才读取其 `SKILL.md` 并执行；不得以本地旧目录、历史会话或文档提及代替可用性检查。开发自检可按[开发闭环](development-review-workflow.md)明确加载当前仓库新版的绝对路径，核对模式能力及版本并记录“仓库路径调用，未安装替换”，不能称已安装旧版支持。
3. 同一任务需要多个技能时一次性列出已安装和缺失项，避免逐个打断用户。

当前常见依赖包括：

- `$frontend-design`：仅新视觉方案、显著布局重做或用户要求设计时的可选协作；缺失时按现有规范完成。
- `fmap-2d`：2D 地图专项规范；缺失时可依据随包 PIGX 地图规范及真实公开契约完成已覆盖能力，未覆盖的必需能力另记缺口。
- `fxft-video`：视频专项规范；缺失时可依据随包 PIGX 视频规范及真实公开契约完成已覆盖能力，未覆盖的必需能力另记缺口。
- `aura-module-federation-check`：模块联邦改前基线与改后复检；属于模块联邦任务的必需技能。
- `aura-web-review`：功能开发自检必需；纯注释/说明整理默认不调用，仅明确要求验证/报告或真实项目强制门禁时按范围调用，先核对实际加载版本的 `development-self-check` 能力。缺失或旧版不支持时按开发闭环处理；新版可从当前仓库明确加载时无需安装，否则记录能力阻断、继续独立工作，不生成该块最终开发报告。
- `vueuse-functions` 等参考资料按条件要求的技能：命中条件时同样检查。

## 缺失处理

- 可选协作或现有规范足以覆盖的能力：直接继续，用随包规范、项目事实和公开契约完成，在交付列出缺失技能及实际影响，不强制询问安装，不假称已调用。
- 必需能力确实缺失：只阻断受影响分支，记录具体缺口、影响和可恢复条件，继续其它独立工作。开发自检的仓库路径加载按上文处理，不得用正式六文件审查冒充自检。
- 用户要求安装或安装确为恢复必需能力的下一步时，说明具体技能、用途及本机目录写入后再取得授权。不得静默安装，也不把普通依赖安装授权视作技能安装授权；来源或作用域不明时先确认。安装后核对实际可用性与模式能力，不能仅凭安装命令成功认定已调用。
