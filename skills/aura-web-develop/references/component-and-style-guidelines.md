- [组件复用与公司 UI 规范](../knowledge/PIGX前端开发规范/组件复用与公司基础组件库规范.md)
- `../knowledge/PIGX前端开发规范/样式布局与静态资源规范.md`
- 当前项目 `src/components/index.ts` 和真实类型声明

## 组件选择顺序

1. 综合端已有全局组件和 Hooks。
2. Element Plus。
3. 当前页面目录内的业务组件。
4. 确认无法复用后再新增跨业务公共组件。

`@fxft/ui-plus` 不作为普通业务 UI 的通用优先复用层级；地图、视频等专项场景按对应专项规范处理。

远程页面不会执行提供方 `main.ts`。组件解析、样式和资源必须随 expose 正确加载，不得只依赖独立运行时的全局注册。

## 拆分原则

- 页面私有组件放在页面目录 `components/`。
- 只共享逻辑时优先抽业务 Composable。
- Props 使用明确类型，不传整个页面 state。
- 通过 Emit 表达业务动作，不直接修改父组件数据。
- 复杂弹窗、抽屉、地图和视频只调用公开 Exposes，不访问内部 DOM 或底层 SDK。

## 设计输入

截图、HTML 原型和 Figma 可用于确定业务区块、层级、间距和视觉状态，但不得覆盖最新版 PIGX 的页面高度、主题、模块联邦、静态资源和组件接入规则。
