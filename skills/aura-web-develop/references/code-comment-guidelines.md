## 1. 核心原则

### 解释具体业务步骤与原因

- 以业务阅读者能沿源码理解流程为准。每个有业务意义的执行步骤、校验分支、字段转换、异步恢复和状态副作用都需相邻中文行注释，说明做什么、为何这样做及条件不满足的结果；复杂业务写清具体状态条件、数据来源与去向和执行顺序。
- 方法总注释不能替代执行链各阶段的说明；不以“代码自解释”“只写 Why”或防噪音为由压缩必要业务解释。
- 普通赋值、循环和语法不逐行翻译；一旦承载校验、映射或状态变化等业务意义，就按业务步骤说明，不用“设置 loading”“调用接口”等空泛句代替。

### 保持同步

- 修改逻辑时同步更新相关注释。
- 删除过时、矛盾或误导性的注释。
- 废弃代码直接删除并交给 Git 保存历史，不保留大段注释代码。

### 按授权改进可读性

- 详细业务说明或补注释本身不构成重构理由；保持现有行为，覆盖本次涉及的完整业务块与必要调用链，不扩展无关模块。
- 需求确需调整结构时再按影响拆函数、优化命名或抽离 Composable；仅补注释时不自动重构。
- 注释不能替代清晰的类型、变量名和组件职责。

### 中文与编码

- 新增注释、文档、错误提示使用简体中文。
- 新增文本文件使用 UTF-8 无 BOM。
- 技术标识、类型名、函数名和标准标记保留英文。

### 业务对象覆盖表

实施与自检先阅读本次完整业务块源码，提取实际存在的语义对象清单；按下表逐项覆盖，不按截图临时挑对象，也不为不存在的对象加空注释。清单可直接写在已有检查记录中，无需新扫描器或单独审计流程。

| 对象类别 | 应说明的内容与位置 |
| --- | --- |
| 业务变量、常量、ref/reactive/computed、解构服务与业务局部变量 | 逐项中文用途；短声明尾部 //，复杂状态上方多行写取值、更新时机和影响。相关解构服务可由一处明确组注释覆盖各自职责，不能省略实际业务用途；技术 import 不逐条机械解释 |
| 模板业务区块 | 返回/标题/说明区、操作栏、业务内容区、表单、列表、状态与错误区逐项说明真实职责与关联，在区块语义所有者上方紧邻注释 |
| 模板业务语义元素 | 返回/操作按钮、业务标题、说明文字、字段、筛选项、表格列、状态/错误提示，逐项中文用途及关键条件/配置；紧邻对应语义所有者上方，不以文案或命名自解释省略。表单字段始终在 el-form-item 上方，无该容器才在最外业务控件上方，不藏入 span/t() |
| 自定义、公司或第三方业务组件实例 | 每个实例上方说明组件类型、当前业务职责、关键配置/输入、组件引用、事件绑定与显示条件，以及实际存在的生命周期边界；组件来源按真实项目取证说明。不得虚构 Props/方法；来源按真实 import、Resolver 或声明核实 |
| 事件、生命周期与复杂逻辑 | 方法多行 JSDoc 保持契约；执行链各业务步骤相邻行注释解释做什么、为何、不满足结果，含状态副作用、异步恢复和清理；不能用总注释替代 |

普通布局 div 不逐层重复注释；普通 el-input 等不必每次介绍组件库，但所属字段用途及关键配置仍须解释。相邻控件只有共享同一职责且组注释清楚覆盖各成员时才合并；不得用“操作区”三个字代替独立操作的业务含义。条件链必须合法，不为放置注释改动渲染关系。

统一验收记录使用“对象—用途/状态—注释位置—结论”；每个纳入对象都核对内容具体、位置正确且与真实实现一致；模板按层级和分支标识独立子节点及其注释归属，不以父区块注释覆盖子级。漏项、只解释技术名或放错位置均需整改；不按行数、百分比或零散有注释判通过。纯注释任务仅补注释/说明，不据本表新增组件、状态或逻辑。

## 2. SFC 结构与文件头

Vue SFC 默认按以下顺序组织：

```text
1. <script setup lang="ts">
2. <template>
3. <style scoped>
```

新增页面级组件或复杂公共组件在文件顶部添加说明：

```vue
<!--
 * @description 用户资料卡片，负责头像、基本信息和权限标签展示
 * @module 用户中心/用户资料
 * @business 支持用户查看和维护个人资料
-->
```

- `@description`、`@module`、`@business` 使用真实业务语义。
- 团队或项目明确要求作者、日期管理时，可增加 `@author`、`@date`；不得虚构作者或生成无意义日期。
- 简单、职责由文件名即可明确的内部小组件，可不写冗长文件头，但公开 Props/Emits 仍需说明。

## 3. Template 注释

大型模板按业务区块划分：

```vue
<template>
  <div class="layout-padding">
    <!-- 查询区：按名称和状态筛选设备 -->
    <section>...</section>

    <!-- 列表区：展示分页数据和行级操作 -->
    <section>...</section>

    <!-- 编辑弹窗：新增和编辑共用 -->
    <DeviceForm ref="formRef" />
  </div>
</template>
```

复杂条件渲染说明业务触发场景：

```vue
<!-- 仅在账号已认证、未停用且拥有编辑权限时显示编辑入口 -->
<el-button v-if="isAuthed && !isSuspended && canEdit" @click="handleEdit">
  {{ $t('common.editBtn') }}
</el-button>
```

- 条件超过两个、表达式包含业务组合判断或循环存在特殊过滤时补充说明。
- 本次业务表单区使用具体用途注释，例如“入港申请表单：采集申请编号和联系人信息，校验后提交入港申请”，不能只写“表单区”。
- 每个国际化表单项、筛选项和业务表格列都在语义所有者正上方紧邻补中文业务含义，例如“申请编号”“联系人”“联系电话”；不能因存在 `t(key)` 或文件头/区块注释就省略。操作分组及状态区说明真实业务用途、可用条件与结果。
- 有 `el-form-item` 时，字段注释必须紧邻该 `el-form-item` 上方；表格列紧邻 `el-table-column` 上方，筛选项同理。不得藏在内部 `span`、插槽文字或 `t()` 前；没有 FormItem 时才放实际最外业务控件上方。条件链保持合法，不为放注释改动 `v-if/v-else-if/v-else` 的渲染关系。
- 无业务语义的普通布局元素不要求逐行注释；已有中文 literal 也不能替代业务语义对象的用途说明；按覆盖表解释对象职责、关联或操作结果，不只重复文案。纯装饰及普通布局不机械注释，业务按钮逐项检查实际用途。

```vue
<!-- 设备编辑表单：维护设备编号、联系人及启用状态，校验后保存 -->
<el-form :model="form">
  <!-- 设备编号：用于识别当前维护的设备 -->
  <el-form-item :label="$t('device.code')" prop="deviceCode">...</el-form-item>
  <!-- 联系人：负责当前设备维护的业务联络人 -->
  <el-form-item :label="$t('device.contactName')" prop="contactName">...</el-form-item>
  <!-- 联系电话：用于联系设备维护人员 -->
  <el-form-item :label="$t('device.contactPhone')" prop="contactPhone">...</el-form-item>
  <!-- 启用状态：控制设备是否参与后续业务操作 -->
  <el-form-item :label="$t('device.enabled')" prop="enabled">
    <el-switch v-model="form.enabled" />
  </el-form-item>
</el-form>
```

示例说明注释粒度，字段和语言 key 在实际业务中按真实契约替换，不声明它们已存在。

### 模板子节点递归盘点

按真实 template AST 或源码树从根到子级逐层盘点语义节点，不只列顶层区块。父注释只能解释父职责，不能替代内部具有独立业务语义的子节点：动态文案、业务 v-if/else 分支、v-for 集合及每项含义、关键 v-model/事件、空态与 loading 条件均分别核对相邻说明。只有没有业务逻辑、仅承载 class 布局的容器可省略，不按层数机械重复相同职责。

表单字段说明仍紧邻所属 el-form-item 上方；子级提示、分支、循环项等注释贴其自身语义所有者上方，不能藏在标签文本或 t() 前。条件链注释需保持 Vue 语法合法，不通过修改 DOM、条件或事件实现满足注释要求。三元动态文案需说明各实际分支的业务含义，而不只写“空态”。复选组说明已选值来源和多选作用，循环项说明选项编码和显示名称各自含义。候选空态核对是否仅加载结束且无候选时展示，解释该条件为何避免加载中误报；若原实现不满足，只据实说明并记录原有功能偏差，纯注释任务不自行修条件。

以下为结构示意，变量和省略号均须对照项目已有实现，不引入新状态或事件；实际代码没有的条件不照搬：

```vue
<!-- 选择区：展示已有候选，保留本次业务选择 -->
<section ...>
  <!-- 条件提示：已有选择时解释当前选择会如何影响后续业务处理 -->
  <div v-if="hasSelection">...</div>

  <!-- 候选加载状态：说明当前尚不能据空列表判定没有可选项 -->
  <div v-if="loading">...</div>

  <!-- 候选空态：仅在加载结束且无候选时显示，分别解释两类实际空态原因 -->
  <div v-if="!loading && !options.length">{{ emptyReason ? ... : ... }}</div>

  <!-- 多选组：selectedValues 来自本次选择状态，多选决定后续参与处理的候选范围 -->
  <el-checkbox-group v-model="selectedValues" ...>
    <!-- 候选集合逐项展示；option.value 为选择编码，option.label 为当前业务显示名称 -->
    <template v-for="option in options" :key="option.value">
      <!-- 单个选择项：以当前候选编码写入多选状态，显示对应业务名称 -->
      <el-checkbox :value="option.value">{{ option.label }}</el-checkbox>
    </template>
  </el-checkbox-group>
</section>
```

该模板只说明粒度，不证明所示控件 Prop 属于项目安装版本；实际公开契约以真实声明核对。循环卡片同理分别检查集合/单项职责及内部标题、说明、操作和状态；外层循环注释不替内部独立对象说明。

### 业务区块与组件实例模板

下面是注释位置示意，省略号代表项目已有内容，不能作为可执行页面复制。业务组件以普通语义占位表示，没有假设组件名或命名 API；实际存在的配置/输入、组件引用、事件及显示条件需在实例注释中写具体含义，没有相关绑定则不虚构。

```vue
<!-- 设备编辑覆盖层：Teleport 到项目已有业务容器，沿用原挂载条件和销毁流程 -->

  <!-- 返回与标题说明区：返回设备列表，说明当前编辑对象和可执行操作 -->

    ...（项目已有组件实例，此处仅示意注释位置）
```

### 页面模式注释锚点

- 实现前从所选正式页面模式提取实际存在的主要区块，作为本页注释锚点；交付时逐项列出位置与覆盖原因。
- 查询卡片页必须为实际存在的查询/筛选区、工具栏、卡片列表、空态、分页保留中文区块注释。可合并相邻区块的说明，但不得只保留其中一项。
- 卡片整体可点击而内部存在编辑、删除、状态切换等操作时，说明事件阻断的交互边界，避免操作触发详情跳转。
- 没有查询、工具栏或分页的页面不补虚假锚点；不按注释数量或行数验收。

## 4. Script 注释

### 注释形式与可复制模板

本规范直接维护以下三种模板，不另复制一份模板文件；按声明职责选形式，不能把所有注释都写成块。

| 场景 | 默认形式与模板位置 |
| --- | --- |
| 简短类型字段、Props、Emits 事件签名 | 声明同行尾部 `// 中文业务含义`，见[字段与事件模板](#5-props-与-emits)；事件签名不是方法实现，不套方法 JSDoc 或逐参数标签 |
| 业务执行步骤 | 步骤上方相邻 `//`，详细说明可续多行，见下方步骤模板；复杂业务规则可用独立多行块解释具体条件与数据流，不能代替各阶段行注释 |
| 方法契约 | 方法上方独立多行 JSDoc，用途行与标签区空行分隔，各标签独占行，见下方方法模板 |

简短字段默认尾注释；复杂字段约束或确需 IDE 文档时允许上方独立 JSDoc，但块注释与声明不得挤在同一行。不为每个 type 属性生成冗长 `@param`，也不因字段是函数类型就当作业务方法实现。

业务步骤模板（仅示例本地数据校验与转换，无业务 API）：

```ts
// 只允许提交已选择的设备，避免空列表被当作有效分配；没有设备时保留原选择并停止转换。
if (selectedDevices.length === 0) return;

// 从当前选择提取设备标识供后续分配使用，保留选择顺序；不把显示名称作为提交标识。
const deviceIds = selectedDevices.map((device) => device.id);
```

示例变量须对应项目真实数据；注释应跟随实际业务条件、失败结果和执行顺序调整，不能直接套用未存在的业务阶段。

### 方法契约

本次业务块内的方法使用 JSDoc 说明业务用途、前置条件、每个入参和返回语义，覆盖具名函数、箭头方法、事件处理、API、Store action 与 Composable。无参方法注明无入参，不生成虚构参数；无返回值说明实际作用与重要副作用。

API 导出的箭头方法与具名函数使用同一标准：每个实际参数均有独立中文 `@param`，说明目标对象及作用，例如区分资产 ID、设备 ID 和分组 ID。对象参数继续沿类型或内联声明核对每个业务属性；仅写“data 为请求参数”不构成完整说明。返回说明依据请求实例和真实消费，不能把请求完成等同于设备执行成功。

- 方法 JSDoc 必须为多行块：用途单独成行，与标签区之间空一行；每个 `@param`、`@returns` 和实际需要的 `@throws` 各占独立行，详细说明在后续行续写。禁止把用途和多个标签挤在单行。简短字段默认声明尾部 `//`；复杂约束或 IDE 文档使用上方独立 JSDoc，不与声明挤同一行，不机械扩成长块；不为没有抛出的异常虚构 `@throws`。
- 入参说明业务含义、可选性和真实约束；异步方法说明完成、失败、取消及内部错误处理的实际含义，`Promise<void>` 不等于业务成功。
- 简短内联回调可由所属业务步骤统一解释；关键方法必须沿执行顺序，为每个业务阶段及其校验、数据映射、异步恢复、失败/取消路径和状态副作用提供相邻行注释。复杂原因可追加多行说明，但不能仅靠开头总注释或两处概括覆盖整条提交链。
- 例如提交链分别说明：校验哪些业务条件及失败为何终止 → 从哪些表单/字典/详情数据构造提交字段 → 为何按该顺序发请求 → 失败或取消如何保留/恢复状态 → 成功后哪些状态、弹窗和列表更新以及为何。只覆盖真实存在的步骤，不虚构分支。

```ts
/**
 * 按记录标识加载当前编辑对象，并完成表单回填。
 *
 * @param recordId 当前编辑记录标识；必须来自本次打开的操作上下文。
 * @returns 请求及回填流程结束；失败时保留错误态并阻止提交，不代表保存成功。
 */
const loadDetail = async (recordId: string): Promise<void> => {
  // 按真实实现完成详情加载、字段映射与错误处理。
};
```

示例只解释注释形式，不提供接口或实现。配套模块说明和流转图见[开发闭环](development-review-workflow.md)。

长 `<script setup>` 可按区域分组：

```ts
// ==================== Props 与 Emits ====================
```

#### 声明字段完整性门槛

公共继承和引用类型沿实际声明核对；本文件之外的实际声明缺注释时单列路径、字段和缺口，不能把本文件结构通过视为继承已通过，不擅改依赖或为补注释重复声明类型。中文含义须从真实文档、类型和消费取得依据，不以出现汉字代替准确性判定。

命中 TS/TSX API/类型文件时必须运行随包[只读检查器](../scripts/check-api-comments.cjs)：

```sh
node <技能目录>/scripts/check-api-comments.cjs --project <已有项目根> --files <明确文件1.ts> <明确文件2.ts> [--output <新建证据.json>]
```

`--project` 仅用于从其 package.json 解析已安装 TypeScript；相对文件按该根解析，绝对文件可指向隔离样本，不自动扩展或发现文件。必须给完整明确清单，不能挑两文件代表整批。默认仅输出 stdout；`--output` 须显式提供，必须为新文件且不能与输入同一路径。脚本不安装工具、不修改源码、不运行全项目 typecheck。

结构支持：递归 property signatures（含方法签名注释）、type literals、class properties/参数属性、index signatures、enum members；嵌套/内联/交叉和数组内声明同样递归；检查同容器重复普通属性。具名函数实现、变量箭头/函数表达式、class 方法/访问器及函数属性检查中文 JSDoc 用途、实际各参数 @param、@returns 与分行结构，匿名回调不计具名方法。多行字段结束位置的同行尾注释可归属于该字段；前一成员尾注释不能借给下一字段。

退出码：`0` 仅所请求结构检查完整且无机械缺项；`1` 有确定缺项/重复声明；`2` 输入、依赖、文件、语法或能力不完整。JSON 保留完整 scope、逐文件状态、字段/方法/参数数和缺项真实路径行号。mapped type、动态计算属性、解构方法参数标不完整；外部引用/继承只列人工追踪入口，不做类型解析。脚本不验证中文业务含义、枚举取值准确性、字符串枚举 alias 的语义、跨文件声明合并、继承链或运行行为，必须另作语义核验；不支持的结构不能标通过。

每个文件记录“声明路径/字段 → 业务含义 → 本字段注释位置 → 结构结果 → 语义结论”，所有纳入文件已检查且缺项逐一关闭，结构与语义同时满足才可声明限定范围通过；未检查、检查能力不足、外部声明缺证均保留不完整状态。只补字典字段或少量文件不能关闭整批。用户仅要求维护技能时，业务文件只读作资料，验证使用隔离副本，不直接修复业务代码；纯注释任务仍保持签名、执行行为和授权范围，不作全量格式化。


先从本次业务的请求构造、接口声明与实际消费提取字段清单，再逐项解释中文业务含义。范围同时覆盖查询条件、请求体、表单提交、详情/列表响应、导入导出参数及错误结果；包括普通字段、嵌套对象、数组项、内联类型和交叉类型中的业务属性，不能只检查字典字段、状态字段或新改动行。

- 每个纳入字段在声明旁有中文业务含义，例如哪个对象的 ID、何种名称、什么时间、按何条件筛选或导出；已有类型名、英文标识、`@dictKey` 等工具标记和接口总注释不能代替逐字段说明。普通字段与字典字段使用同一覆盖标准。

- 从方法签名追踪到字段声明：命名类型在实际类型定义逐字段说明；内联对象、解构参数和嵌套属性按真实结构核对，每个明确声明字段必须在自己声明相邻有中文含义。`@param data.<字段>` 可补充对象入参说明，不能替代明确字段自己的注释。数组须说明元素所指业务对象，枚举须说明有依据的各取值。保持现有签名和类型结构，不为补注释强制抽取新接口或调整参数。

- 自检沿“接口方法 → 每个参数 → 字段声明/公共定义 → 中文含义及注释位置”逐项核验，记录对应结论；缺方法参数说明、对象子字段说明或只有工具标记均记为需整改，不以方法总注释或标签数量代替。业务说明文档中的字段表不能代替源码字段注释；后续使用新字段时同步补说明。

## 5. Props 与 Emits

字段逐项写明业务含义、可选性、默认值或事件载荷，内容完整不等于必须使用块注释。简短 Props、Emits 及类型字段默认同行尾部 `//`：

```ts
interface Props {
  id?: string; // 当前编辑设备记录 ID；为空时进入新增模式
  appendTo?: string; // Teleport 目标选择器，由父业务页提供
  mode?: 'compact' | 'full'; // 展示模式：compact 为紧凑，full 为完整
}

const props = withDefaults(defineProps<Props>(), {
  appendTo: '.device-management',
  mode: 'compact',
});

const emit = defineEmits<{
  (event: 'refresh'): void; // 保存成功后通知父页面刷新设备列表
  (event: 'back'): void; // 返回父业务页并保留当前查询状态
}>();
```

禁止只写“ID”“模式”“回调”等没有业务上下文的说明。

## 6. 响应式状态与副作用

本次业务块的常规 `const/ref/reactive/computed` 业务变量、组件 ref、各 loading/ready 状态和默认业务常量均须逐项中文用途说明，不以命名自解释或“非显而易见才注释”省略。方法内有业务意义的局部变量同样说明数据来源、用途或去向。

简短声明默认同行尾部 `//`；复杂状态在声明上方多行解释取值含义、更新时机及对流程的影响，不翻译 ref/false/赋值等语法。同一解构服务或技术导入可用一个明确注释覆盖一组，不要求每条 import 逐行注释。

以下只示范声明与注释，类型须使用项目真实公开声明，不新增虚构组件 API：

```ts
const formRef = ref(); // 设备编辑表单实例，用于提交前校验和关闭后清理
const mapRef = ref(); // 设备地图组件实例，用于本页已有地图交互
const submitLoading = ref(false); // 当前设备保存请求处理中，控制提交按钮忙碌状态
const mapReady = ref(false); // 地图已具备本页交互条件，由真实初始化和销毁流程更新
const defaultColor = '#409eff'; // 未指定设备展示颜色时使用的业务默认色
const unsavedChangesCount = ref(0); // 未保存修改数量，用于拦截离开编辑页
```

示例不能替代项目真实类型或既有状态逻辑；纯注释任务只给已有声明补说明，不借此新增或修改变量、组件 ref、状态与控制流。

`watch`、`watchEffect`、`nextTick`、定时器、事件监听和 DOM 操作说明触发原因与清理时机：

```ts
// 用户 ID 变化时必须清空旧表单并重新加载，避免展示上一位用户的数据
watch(
  () => props.userId,
  (userId) => {
    resetForm();
    if (userId) loadUser(userId);
  },
  { immediate: true },
);

// useForm 会等待 Dialog 完成挂载，避免上一次操作的校验状态残留
await clearFormValidate(formRef);
```

地图、视频、WebSocket、Worker、轮询和模块联邦实例必须说明创建、更新、隐藏恢复和销毁时机。

## 9. 标准标记

| 标记 | 使用场景 | 示例 |
|---|---|---|
| `TODO:` | 待实现或待重构 | `// TODO(负责人): 接入组织权限接口（Issue-204）` |
| `FIXME:` | 已知缺陷或隐患 | `// FIXME: 高频切换会产生请求竞态` |
| `PERF:` | 性能取舍 | `// PERF: 使用虚拟列表避免万级数据卡顿` |
| `HACK:` | 框架或第三方组件避坑 | `// HACK: 标签页显示后重新计算图表尺寸` |
| `DEPRECATED:` | 弃用说明 | `// DEPRECATED: 请改用新的批量接口` |

- 能关联负责人、Issue 或移除条件时一并注明。
- 不用 `TODO` 代替本次任务应完成的代码。

## 10. 好坏注释对比

| 不推荐 | 推荐 |
|---|---|
| `const visible = ref(false); // visible 为 false` | 用尾部 // 说明该弹窗的业务用途和打开/关闭时机，不以 visible 命名清晰为由省略 |
| `const d = ref(7); // 延迟天数` | 改名为 `delayDays` |
| `// 调用 nextTick` | `// 等待弹窗 DOM 挂载后再初始化表格` |
| 注释掉几十行旧代码 | 删除旧代码，由 Git 保存历史 |
| `// 查询列表` | 具体说明按哪些业务条件加载哪个范围的数据、为何此时加载，以及失败后如何保持当前视图 |
