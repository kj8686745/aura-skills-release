# 查询提交与选择器规模契约

命中查询参数、查询表单、列表/导出条件或选择器选型时读取。规则正文以随包同版[请求规范](../knowledge/PIGX前端开发规范/工程与代码生成规范.md#查询条件的空值提交边界)、[公共能力](../knowledge/PIGX前端开发规范/aura-web-kit能力清单与接入规范.md)和[组件规范](../knowledge/PIGX前端开发规范/组件复用与公司基础组件库规范.md)为准；本文件说明开发执行与验收，不扩大为全项目迁移。

## 查询条件在提交边界格式化

业务 API 优先通过统一 request 的显式 queryFormat 配置格式化提交参数，避免每个模块重复导入工具：GET 使用 { params: true }，POST 查询使用 { data: true }，混合导出仅使用 { data: { paths: [['filter']] } }。默认不开启，不按 HTTP 方法推断查询；只作用于选定目标，空 filter 删除键而范围外字段保持。在 JSON 归一化与加密前执行，不能格式化路径、请求头或未选定的写入字段。配置和 preserveEmptyPaths 路径均相对 params/data 根。

- 普通对象字段值为 undefined、null、空字符串、纯空白字符串、空数组或空普通对象时不发送；普通对象递归格式化后为空也省略。
- 保留 0、false、非空字符串原值，以及 Date 等特殊实例引用；不擅自 trim 非空字符串。非空数组只复制容器，保持元素引用、内部空值和位置，不把 `[null]`、`[{}]` 等自行压缩为空数组；结果不是完整深快照。
- 不原地改查询模型。必须真正删除结果对象中的空键，不能只赋 undefined 后假定序列化一定省略；检查最终 Network/序列化结果。
- 新增、编辑、局部更新中的 null 可能表示清空，不能套用查询格式化。接口明确要求某个空值时，按真实契约显式保留并记录字段、语义及证据，不用例外放弃整个查询对象的规范。

公共算法仍由无 Vue 状态的纯函数 formatQueryParams 承担，独立入口 @fxft/aura-web-kit/utils/query 保留给非请求条件构造等用途，不因过滤字段单独创建 Hook。业务请求复用 queryFormat；必须核对消费者实际安装的公开配置声明与实现，该能力已随1.9.5发布并完成私服读回，旧1.9.3不支持，不能在业务复制实现或虚构支持。useTable默认行为不变。

路径例外仅允许该精确字段的空值保留，不表示跳过非空父对象全部子字段的格式化。保留 undefined 也不改变传输协议：GET 序列化仍可能省略，原 JSON 归一化仍可能转为 null；接口明确要求 null 时应明确传 null，不能用例外假定 undefined 一定被传输。

按影响范围验证：输入未被修改、格式化后键确实缺失、0/false 保留、嵌套空对象、非空数组结构和特殊值保留、明确空值例外，以及同一筛选下列表与导出条件一致。POST 查询须核对请求层处理后的实际请求体，不以单元测试对象或函数名出现代替提交结果。

导出参数按真实接口契约构造。分页导出或字段具有业务含义时，保留接口需要的 current、size 等参数；只有契约明确不接收列表分页时，才从筛选副本移除对应字段，不得仅凭字段名删除或把 current、size 当作完整分页字段清单。queryFormat 只处理空值，不推断分页或其他业务语义。不得修改原查询模型；导出候选列表的分页、排序及外层控制字段分别按各自接口契约处理。

### 请求配置示例

```ts
request({ url, method: 'get', params: query, queryFormat: { params: true } });
request({ url, method: 'post', data: query, queryFormat: { data: true } });
request({ url, method: 'post', data: { ids, fields, format, filter: query }, queryFormat: { data: { paths: [['filter']] } } });
```

仅示意配置，URL、字段及实例沿项目真实协议。未配置目标保持原语义，配置不传入HTTP头或body；不能假定旧下载Hook接受额外配置参数。

## 选择器按候选规模选型

候选数量较大、数量无明确上限或可能持续增长的选择器，必须采用 `el-select-v2`，或经实际公开契约与渲染行为核实具备等效虚拟化能力的公共选择组件；禁止普通 `el-select` 一次性渲染全部选项。候选数量明确且规模较小的选择器可使用普通组件。按候选规模、上限及渲染成本判断，不列业务类别，也不擅自规定缺少依据的统一数量阈值。

远程搜索、分页控制取数规模，不能替代大结果集的虚拟化渲染；filterable、collapse-tags 和滚动条本身都不证明虚拟化。先核对目标项目 Element Plus/公共组件已安装版本的 options、value/value-key、过滤、插槽及行高契约，再使用；自定义选项不能原样照搬 el-option 循环或固定单行高度。官方入口：[Virtualized Select](https://element-plus.org/en-US/component/select-v2.html)。

验证候选规模与可见窗口 DOM 数量、滚动后远端选项可选、选值类型/单多选、搜索、清空、既有值回显，以及自定义多行高度；下拉读取失败显示空选项，不能仅因辅助候选失败把整个表单替换为错误态。证据按实际影响选取，不用静态标签命中、候选少量样本或截图代替虚拟化和交互验收。
