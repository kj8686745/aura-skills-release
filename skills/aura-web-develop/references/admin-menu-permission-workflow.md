# 管理端菜单与按钮权限流程

新增正式业务页面、菜单入口或页面操作按钮时，应主动询问用户是否同步创建/更新正式菜单和按钮权限，以及是否需要配置远程菜单。只有用户在该询问后明确授权（确认同步及本次写入），并提供目标环境、可用管理端 Token、租户和父菜单定位信息，且在写入前再次确认后，才能调用管理端 API。远程菜单是管理端菜单形态选项，不等同于页面是否使用模块联邦。

当用户在同一开发任务中已明确要求同步创建，并给出目标环境、运行时 Token、租户和父菜单名称或路径时，视为本次菜单写入授权。Agent 应继续查询菜单树定位真实父级、查重、幂等写入和复核；除非写入目标、菜单内容或权限编码出现新的实质性歧义，不得重复要求确认。令牌不得写入任何文件、计划、日志或交付内容。

## 准备清单

从真实页面和路由生成以下待确认项：

- 页面菜单：名称、路径、组件路径、权限编码、图标、排序、可见性和父菜单定位；
- 按钮权限：每个唯一 `v-auth` 权限编码、名称、所属页面菜单，以及它在源码中的全部引用位置；
- 模块联邦菜单：完整 `componentPath` 与“带参”要求。

权限编码采用以下优先级：

1. 用户明确指定页面菜单或按钮权限时，原样采用指定编码，不改写为模板格式；
2. 用户未指定时，按“业务标识 + 功能动作”生成，再对齐当前项目相邻业务模块真实 `v-auth` 的大小写、分隔符和动作词。例如项目采用下划线时，设备业务的新增、编辑、删除分别为 `device_add`、`device_edit`、`device_delete`。业务标识必须来自真实业务对象、页面资源或已存在业务域，功能动作必须对应按钮实际行为；不得只生成无业务限定的 `add`、`edit`、`delete`。只有项目既有规则明确包含模块或子资源层级时才扩展为相同层级，不自行增加前缀或缩写；
3. 无法从当前项目确定命名规则时，交付候选清单并说明依据不足，不猜测框架外的权限前缀。

## 唯一性与冲突处理

权限清单以“业务身份 + 权限编码”判断语义是否冲突。业务身份由真实页面菜单、路由/组件路径和业务对象共同确定，不以源码文件名或按钮出现次数代替。同一业务内，同一编码在工具栏、表格行操作、卡片或多个组件中重复出现是合法共享场景，只对应一条后台按钮权限记录，并在清单中汇总全部引用位置；不得把这种正常复用误报为权限冲突。

查重是四阶段硬约束：生成前扫描源码并识别每个编码所属业务；生成候选清单后检查是否有两个不同业务使用同一编码；每次 API 新增或更新前查询目标租户与系统的完整菜单树，比较现有记录与候选记录的真实页面父级、路由/组件和业务语义；写入后再次查询确认没有产生跨业务同码记录。只有“同一权限编码对应不同业务身份”才属于本流程要拦截的重复；同一业务中的多处 `v-auth` 复用不属于重复。

生成候选编码后、写入前都必须在目标租户与目标系统的完整菜单树中查询权限编码，不能只查目标父菜单或当前页。按以下规则处理：

| 查询结果 | 处理方式 |
|---|---|
| 同一编码不存在 | 可以进入待创建清单 |
| 同一编码仅有一条，且类型、真实页面父级、路由/组件和业务语义一致 | 属于同一业务正常复用；复用该记录 ID，需要时只更新本次明确字段，不新增 |
| 同一编码关联两个及以上不同业务身份 | 视为跨业务重复冲突，停止该编码的写入并报告全部记录 ID、父级、路由/组件和业务对象，不再新增 |
| 同一编码存在于不同父菜单、不同菜单类型、不同路由资源或不同业务语义 | 视为跨业务占用冲突，不复用、不改挂载、不覆盖 |

用户明确指定的编码发生占用冲突时，保留用户输入但暂停该项，请用户决定复用现有授权语义还是改用新编码。自动生成的编码发生冲突时，先确认“业务标识 + 功能动作”中的业务标识是否过宽；只能依据当前项目已经存在的命名层级改为更具体、稳定的页面或子资源业务标识，并重新全量查重。不得自动追加数字、时间戳、随机串、`copy`、`new` 等后缀。若项目没有可验证的消歧规则，输出候选方案让用户选择。

同一业务动作的多个按钮可以有意共享一个编码，此时后台仍只有一条权限记录；同一业务中的多处 `v-auth` 不因出现次数而要求改名。不同业务对象或不同业务动作默认不得共享编码。若多个不同动作被用户明确设计为同一授权门槛，在清单中注明共享原因，避免后续人员误判为重复。

页面菜单按路径、组件路径和权限编码组合识别，按钮权限按唯一编码及真实页面父级识别。按钮权限的 `parentId` 必须使用查询或创建后得到的真实页面菜单 ID，不得猜测、复用历史 ID 或把按钮挂到栏目菜单。每个页面中的 `v-auth` 必须与对应后台按钮权限编码完全一致。

## 受控幂等写入

1. 只使用本次明确指定环境的管理端 REST API 基地址，令牌和租户仅通过运行时请求头传入；不得写入脚本、源码、Markdown、日志或版本库。
2. 先查询目标租户与目标系统的完整菜单树和目标详情，递归展开后定位真实父级，并建立权限编码索引；任何待写入编码必须先通过精确查重、唯一性与冲突检查。批量任务也必须逐项使用索引校验，不能因一次列表查询成功而跳过单项判断。
3. 缺失目标执行新增；唯一匹配且身份一致的目标只更新本次明确字段，并保留真实菜单 ID。不得删除、批量覆盖、静默改挂载或修改未在需求中列出的菜单。
4. 页面菜单创建或更新完成并取得真实 ID 后，对按权限编码去重后的按钮清单逐项新增或更新；同一编码一次任务最多发起一次新增请求。
5. 写入后重新查询完整菜单树和详情，逐项核验父级、名称、路径、组件、权限、菜单类型、排序、显示和带参字段，并确认本次编码没有被不同业务身份共同占用；同一业务多处前端引用不要求产生多条后台记录。以 API 成功响应和复查数据为验收依据，不以管理端页面显示为依据。

## 连续执行顺序

菜单创建是页面开发的连续步骤，不是独立终点。页面新增时按以下顺序推进：

1. 完成真实页面、私有组件、`v-auth` 和模块联邦 expose；构建失败先修复，不创建指向不可加载组件的菜单。
2. 使用已提供的环境和运行时凭据查询完整菜单树，按名称或路径定位父菜单，不能要求用户提供可由菜单树获得的父菜单 ID。
3. 对全量菜单树完成路径、组件和权限查重后幂等创建或更新页面菜单，再按真实页面菜单 ID 写入唯一按钮权限。
4. 重新查询菜单树和详情复核，然后继续构建、浏览器验收和其余交付项；状态问答或菜单查询结果不结束原开发任务。

管理端 REST API 路径和请求体必须从当前项目提供的接口契约、管理端 SDK 或可访问的 API 文档确认；不得仅因本技能未列出字段而停止，也不得凭猜测写入。

## 条件不足时的交付

不得发起外部写入。交付需给出页面菜单和按钮权限清单，并明确用户是否选择同步、是否配置远程菜单，以及缺少以下哪项：目标环境、同步写入确认、管理端 Token、租户、父菜单名称/路径/ID 或接口字段约定。

## 模块联邦菜单

管理端写入请求通常使用 `component` 字段，菜单树可能返回为 `componentPath`；以目标管理端实际响应为准。组件路径标准如下：

- 本地自定义组件：不带 `views` 和 `.vue`，例如 `iot/asset-change-record/index`。
- 远程模块联邦组件：必须使用 `/remoteName/views/.../index.vue?type=moduleFederation`，例如 `/aura-iot-bus/views/iot/asset-change-record/index.vue?type=moduleFederation`，并开启“带参”。

本地路径不得写 `views/` 前缀；远程路径必须包含 `remoteName`、`views`、`.vue` 和 `?type=moduleFederation`。动态菜单只依赖运行时远程配置；不因菜单配置而新增编译期 remote。写入后从菜单树复核返回的组件路径是否符合对应模式。

当用户选择不配置远程菜单时，应撤销本次业务页面为该菜单新增的远程暴露项，例如删除 `src/hooks/moduleFederation.ts` 中对应的业务 expose 配置及其菜单字段；框架标准的 runtime、i18n、Tailwind 等 expose 不得删除。若页面仍被其他远程消费者使用，则按实际依赖保留必要 expose，并在交付中说明。
