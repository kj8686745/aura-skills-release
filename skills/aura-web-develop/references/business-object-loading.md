# 已有业务对象的数据加载约束

- 进入需要已有业务对象完整信息或当前状态的场景时，必须按业务标识调用真实详情或场景初始化接口后再展示、回填和执行依赖该数据的操作。此规则适用于独立页面、路由子页、Tab、内嵌面板、抽屉和弹窗，覆盖查看、编辑、复制、分配、审批、配置等操作，不以容器形态或是否编辑为判断条件。
- 表格行、卡片、树节点、地图点位、父组件 Props、路由 state 和本地缓存均属于入口上下文，不能替代详情接口响应。入口只传业务 ID、操作类型及必要限制条件；接收方负责加载数据，禁止直接将入口对象展开或 `Object.assign` 到详情状态、表单或提交对象。
- 操作类型与对象标识分别表达，例如 `{ id, action }`；有 ID 不等于编辑，复制、查看和处理也可能有 ID。简单新增/编辑组件可以保留 `open(id?)`，但不得将这一约定推广到其他场景。
- 在进入场景、重新打开或目标 ID 改变时加载；复用组件和 keep-alive 页面必须处理目标变化。加载前清理上一对象的数据，加载成功前禁止依赖详情的提交；失败或无数据时展示局部错误/空态并允许重试，不回退使用入口快照。快速切换目标或离开场景后，旧请求不得覆盖当前状态。
- 回填和提交按接口契约显式映射字段，避免把详情响应的关联集合、展示字段和只读元数据整体提交。新增、尚未保存的本地草稿、明确要求查看固定历史快照的场景按其真实数据契约处理；不需要详情数据的轻量操作无需额外查询。后端没有所需详情接口时先确认已有接口契约并说明缺口，不虚构接口，也不静默用入口数据代替。
- 验收必须覆盖：从实际入口进入时发出对应 ID 的请求、详情回填、切换对象、加载失败和提交阻断；不能只以弹窗打开或字段非空作为通过依据。
