# 验证与交付清单

本清单用于功能开发，或用户明确要求验证/报告、真实项目强制门禁命中的整理任务，并只采用所请求范围。普通纯注释/说明整理不运行本清单及其扫描、自检、测试、构建和报告门槛，按[快速路径](../references/development-review-workflow.md)人工核对含义与差异范围、项目格式化后直接交付；完整注释和业务说明标准不减。

检查触发、范围和时机仅按[检查选择表](../references/development-review-workflow.md#检查选择表)选择；下列条目用于核对命中结果，不要求每个局部任务执行全部项目。

## 命令验证

- [ ] 已复核外部技能依赖检查结果；可选能力缺失已按现有规范完成并披露，必需能力缺失已记对应阻断，未静默安装
- [ ] 使用当前项目规定的 Node.js 和 pnpm 版本
- [ ] 编程完成后已自动执行项目本地 Prettier，并已执行 `git diff --check`
- [ ] 已按检查选择表完成命中的规则扫描、只读 lint、类型检查/构建及证据复用；未执行、不适用或全量触发有事实依据
- [ ] 严格 UI 契约扫描无错误：无直接中文、缺失 placeholder、zh/en i18n key 缺失、已声明 `@dictKey` 字段 `*Name` 直出或硬编码枚举
- [ ] 无业务代码直接导入 Element Plus Message/MessageBox
- [ ] 无错误 `@/` 别名、业务 axios 实例、凭证或部署前缀硬编码
- [ ] 已人工确认本次完整注释语义；结构扫描仅按明确请求或项目门禁选择，告警按上下文判定
- [ ] 需要撑满剩余高度的表格已人工确认 Flex 高度链路、`min-height: 0`、`el-table--fit` 和 `flex: 1` 生效，且未使用 `100vh` 或固定像素表格高度
- [ ] 新增或修改的普通 `el-select` 可按关键字筛选；不适用项有明确原因

## 页面与交互

- [ ] 可见交互稳定后已集中完成核心流程及相关失败/取消/权限边界走查；无可见影响或纯 API 记录不适用
- [ ] 已检查浏览器控制台和 Network；未验证项有明确原因，未假称通过
- [ ] 有可访问原型时已同步打开原型与实现页对照；用户明确意见已逐条验证并优先采用
- [ ] 用户无明确取舍时，已输出一致项、差异项、风险和待用户决策项
- [ ] 已在 Codex 内置浏览器中检查左侧强调条：每处均有信息语义，且同页及同业务模块未形成重复模板感
- [ ] 页面结构符合所选最新版页面模式
- [ ] 已人工复核路由入口职责；不存在两个及以上业务 Dialog/Drawer 内联在入口页，轻量单弹窗内联有明确理由
- [ ] 已验证弹窗关闭时不请求专属数据，每次打开时加载并正确呈现 loading、错误、空态和重试
- [ ] 已检查空态与顶部/摘要工具栏，不存在重复的新增等主操作入口
- [ ] 加载态、空态、错误态或明确不适用说明完整
- [ ] 查询、重置、分页、排序、刷新和导出行为正确
- [ ] 权限、`useForm.validateForm` 校验、防重复提交、成功和失败反馈正确
- [ ] 无权限账号下表格没有空操作列，卡片、工具栏、下拉菜单和批量操作区没有空白容器；具备任一子操作权限时容器恢复且按钮仍按各自权限精确显示
- [ ] 业务页面未绕过 `useForm` 直接调用表单实例的 `validate/resetFields/clearValidate`
- [ ] 父子组件自定义事件及访问组件 ref 的事件绑定具名方法，组件公开方法只在脚本中通过可选链访问
- [ ] 新业务菜单权限流程命中时，页面菜单和去重后的唯一 `v-auth` 按钮权限已按路径、组件和权限编码精确复核；按钮父级为真实页面菜单 ID
- [ ] 条件齐全时已重新查询完整菜单树，确认没有两个不同业务身份使用同一权限编码；同一业务多处前端引用仍复用一条后台权限
- [ ] 同一权限编码一次任务最多执行一次新增请求；条件不足时已交付待补环境、授权、凭据、租户或父菜单信息，且没有外部写入
- [ ] 消息提示和确认框样式、i18n、取消分支正确
- [ ] 仅变更操作的失败分支使用 `useMessage().error(...)`；字典、下拉、列表、详情等只读加载失败不弹消息
- [ ] 页面卸载后无残留定时器、监听器、地图或播放器实例
- [ ] 浏览器控制台无新增错误，Network 无关键 404

## 模块联邦与资源

- [ ] 独立运行正常
- [ ] 作为远程页面运行正常
- [ ] expose、i18n、Tailwind、页面 CSS 和组件样式正确加载
- [ ] 图片、字体、Worker、decoder 和视频资源指向资源提供方
- [ ] 首次加载、刷新、失败重试和版本更新符合任务范围
- [ ] 模块联邦配置已提供检查技能改前基线与改后复检结果

## 接口联调

- [ ] 分页仅核对前端发送 current/size、消费 records/total 并映射 useTable/AuraPagination；有排序才核对 orders 的 column/asc；pages 缺省不误判，前端参数/消费代码或必要 Mock 测试提供证据，不要求验证后端分页算法或接口实现
- [ ] 需要已有对象详情的场景已验证进入/重开/目标切换时的请求 ID、详情回填、错误/空态、提交阻断及旧响应隔离；验证覆盖实际入口和容器形态，不局限于表格编辑弹窗
- [ ] URL、Method、入参和响应结构与接口定义一致
- [ ] 分页列表和总数字段与 `useTable` 配置一致
- [ ] Apifox/真实请求成功；无法联调的接口已注明原因
- [ ] 未把真实 Token、Cookie 或密码写入代码和交付文档

## 注释与编码

- [ ] 已按[注释覆盖表及评审清单](../references/code-comment-guidelines.md)逐项核对完整授权业务块的中文含义、相邻归属与真实语义；方法/变量/模板/组件实例/执行阶段不漏项，格式和编码符合 canonical 要求
- [ ] API/类型已按[声明字段门槛](../references/code-comment-guidelines.md#声明字段完整性门槛)核对完整文件，每字段自己的相邻中文和方法各入参与返回分别检查；未以少量文件、仅字典字段、结构 0 或未检查结果冒充通过

## 开发自检与报告准入

- [ ] 已确认实际加载的 aura-web-review 支持 development-self-check，记录精确路径与版本；旧版能力缺口没有伪装成功或改走六文件流程
- [ ] 已按[开发闭环](../references/development-review-workflow.md)完成语义自检，保留原规则与可读性补充来源、范围、证据、问题/修复/复查及测试记录
- [ ] 审查侧已核对 AuraDictTag / AuraDictText / AuraDictSelect 的依赖、公开契约、注册/import 和实际展示全链；其余 aura-ui 范围排除与开发侧既有检查分开记录
- [ ] 全部适用必需检查和测试通过后才写本批最终交付结论；局部功能合并为简短开发记录，完整新功能或要求独立报告时保留报告/过程记录，未把失败或缺证写成通过
- [ ] 失败历史保留，修改后受影响证据已重新获取；存在阻断时仅交付过程记录和待补条件，并继续独立工作
- [ ] 已更新必要的既有业务说明和真实代码阅读入口；独立新流程或实质改变主路径时维护对应图，无新流程不机械新增总览/图/索引
- [ ] 本次功能/交付批次集中验收与报告，用户要求独立分批时才按批次；整体仅核对受影响跨块衔接，复用仍有效证据

## 通过后的开发记录或报告

按[开发闭环交付要求](../references/development-review-workflow.md#5-通过后供开发人员审阅)选择合并开发记录或独立报告。局部功能记录需求、修改、说明位置、实际证据、未执行原因与版本范围；完整新功能或要求独立报告时在既有目录或 `docs/development-reviews/<任务>/` 保存报告，摘要结论并引用过程记录。标记“自检通过，待人工审查”，未通过的必需项不能以剩余风险代替准入条件。

- [ ] 注释验收已逐对象核对方法契约、业务步骤、模板字段与操作语义；报告引用检查记录，不复制完整过程。
- [ ] 当前有效、受后续变更影响待复查及历史状态清楚；旧报告保留原范围、版本与证据并链接后续记录，不显示为当前通过。
- [ ] 纯整理按快速路径完成，差异仅注释/文档且行为保持，既有 FE 功能偏差只记录；仅用户要求报告时陈述所请求范围，不宣称整体 FE 合规
