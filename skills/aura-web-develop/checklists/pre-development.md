# 开发前检查清单

功能开发按[检查选择表](../references/development-review-workflow.md#检查选择表)确定本次功能/交付批次的必要验收，不为每个子块重复执行。

普通纯注释/说明整理按[快速路径](../references/development-review-workflow.md)直接处理，不自动执行本清单的功能开发检查或调用审查；明确要求验证时仅采用对应范围。

## 最新规范

- [ ] 已读取 `knowledge/PIGX前端开发规范/README.md`
- [ ] 已按本次任务读取命中的总览、工程与代码生成规范、开发检查清单章节；已读且未变化资料直接复用
- [ ] 已按任务读取路由、模块联邦、样式资源、组件复用或对应页面模式
- [ ] 未使用旧技能模板覆盖最新版正式规范

## 当前项目事实

- [ ] 指定页面/模块的结构优化已按[结构任务覆盖](../references/development-review-workflow.md#结构任务覆盖与收尾)识别完整授权职责，未自行缩成少数候选文件；普通局部修改不扩大为整模块整改

- [ ] 已记录本次业务块、需求/原型、提交及工作区状态或摘要，确定全部适用必需检查与项目强制门禁
- [ ] 已确认实际可加载的 aura-web-review 路径/版本支持 development-self-check；缺口如实记录，未静默安装替换
- [ ] 已列出本任务需要调用的所有外部技能，并按当前可用技能列表逐项检查
- [ ] 缺失技能已按依赖流程处理：可选技能按现有规范完成并披露，必需能力缺失明确对应阻断；仓库源码自检记录真实路径/版本/模式与未安装状态，未静默安装
- [ ] 用户可见页面已确认开发服务、实现页路由和 Codex 内置浏览器验证条件
- [ ] 用户提供可访问原型时，已记录原型 URL、访问权限、目标状态和用户明确验收意见
- [ ] 已检查 `package.json`、锁文件和实际 Node.js/pnpm 要求
- [ ] 已检查 `vite.config.*`、Module Federation 配置和当前 `remoteName`
- [ ] 已检查 web-kit 公开能力、`src/config/aura/`、aura-ui 导出、相邻页面和 API
- [ ] 新增或功能修改表单已读取 [useForm 契约](../recipes/hooks-standards.md#useform)，核对项目实际 `hooks/form` 导出/类型，并定位本次表单 ref、模型及生命周期入口；没有把相邻旧写法当作接入依据
- [ ] 已确认路径别名为 `/@/`
- [ ] 已确认独立运行、远程运行或两者都需要验收

## 需求与页面模式

- [ ] 已列出页面、字段、接口、权限、状态、路由/菜单和验收项
- [ ] 新建正式业务页面、菜单入口或操作按钮时，已从路由/组件路径和 `v-auth` 生成页面菜单与按钮权限清单；清单按权限编码去重并记录每个编码的全部源码引用位置
- [ ] 用户明确指定的权限编码已原样纳入清单；未指定项已按“业务标识 + 功能动作”生成并对齐相邻模块的大小写、分隔符和动作词，未使用缺少业务限定的通用动作编码
- [ ] 已扫描本次修改文件和当前业务域的已有 `v-auth`；同一业务内多处按钮共享编码视为合法复用，只规划一条后台权限
- [ ] 候选权限清单已按真实页面菜单、路由/组件和业务对象区分业务身份，不存在两个不同业务使用同一权限标识
- [ ] 菜单权限流程命中时，已读取 `references/admin-menu-permission-workflow.md`；已确认是否具备明确授权、环境、Token、租户和父菜单定位信息
- [ ] 已选择查询表格、查询卡片、左树右表、弹窗表单、详情/抽屉、看板或 Teleport 页面模式
- [ ] 已按[职责决策表](../knowledge/PIGX前端开发规范/文件组织与职责拆分.md)确定命中职责与所有权；独立业务区域及复杂弹窗按需拆分，简单页面保留 SFC，不强制生成 Hook/类型/样式文件或额外报告
- [ ] 已划分弹窗数据所有权：详情、候选项和业务列表在弹窗 `open` 流程加载，父页面只准备本次操作上下文
- [ ] 截图、HTML 原型或 Figma 只作为业务内容和视觉输入，未覆盖 PIGX 工程规范
- [ ] 地图任务已读取 2D 地图规范；视频任务已读取视频规范
- [ ] 新视觉方案、显著布局重做或用户要求设计时才检查 `$frontend-design`；地图、视频和模块联邦任务分别检查对应能力，可选技能缺失不强制询问安装

## 接口与反馈

- [ ] 已从用户资料、Apifox 或后端定义确认 URL、Method、字段和响应结构
- [ ] 已检查当前业务域 API 命名，不强行套用历史五段式
- [ ] 已确认业务消息统一导入：
  `import { useMessage, useMessageBox } from '/@/config/aura/index';`
- [ ] 已确认不会直接引入 Element Plus Message/MessageBox，也不会自行实现消息组件

## 表格与下拉

- [ ] 明确要求表格撑满剩余高度时，已规划纵向 Flex 高度链路、`min-height: 0`、`el-table--fit` 和 `flex: 1`，未计划使用 `100vh` 或固定像素表格高度
- [ ] 新增或修改的普通 `el-select` 已添加 `filterable`；不适用时已记录用户要求或组件不兼容原因

## 注释

- [ ] 已读取 `references/code-comment-guidelines.md`
- [ ] 已识别需要说明的文件头、Props/Emits、API 契约、副作用、兼容和生命周期位置
- [ ] 已确认新增文本使用 UTF-8 无 BOM
