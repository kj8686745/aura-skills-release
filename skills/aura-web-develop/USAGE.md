# PIGX 综合端业务开发使用说明

版本更新记录见[CHANGELOG.md](CHANGELOG.md)。

## 适用与调用

用于已识别的 PIGX 综合端业务页面、CRUD、接口、正式菜单/按钮权限、样式资源和模块联邦实现。可直接描述需求自动触发，也可显式调用：`$aura-web-develop <需求>`。

地图和视频需求会在当前环境存在对应技能时串联 `fmap-2d` 或 `fxft-video`；专项功能先检查项目的 `@fxft/ui-plus` 实际版本，不足时只提出升级建议，取得用户授权后才升级依赖。

新视觉方案、显著布局重做或明确要求设计时，协作使用可用的 `$frontend-design`；沿既有模式增字段、校验或局部 CRUD 不触发。详细流程见[视觉协作](references/frontend-design-workflow.md)。

调用其它技能前检查实际可用性。缺少可选协作技能时，直接按现有规范和真实契约完成并披露影响；必需能力确实缺失才阻断对应分支，继续独立工作。技能安装需另有明确授权，不静默安装，也不为可选技能强制询问安装。

功能开发或明确要求自检时，另核对 `aura-web-review` 的模式能力；安装旧版不支持时如实说明。当前仓库新版可取得时，可明确按绝对源码路径加载，记录版本和“未安装替换”，否则记为阻断，不用正式六文件流程代替。

前端页面业务完成后会明确调用 Codex 内置浏览器检查实际页面、核心交互、控制台和 Network。有可访问原型链接时，用 Codex 内置浏览器保留实现页与原型页同步对照；用户明确提出的验收意见优先。用户未明确取舍时，交付一致项、差异项、风险和待决策选项，不替用户做主观确认。

新开发和功能修改补齐完整注释，按真实场景维护业务说明。局部变更优先更新现有说明，无独立新流程不机械新建总览、图或索引。检查节奏统一见[检查选择表](references/development-review-workflow.md#检查选择表)；全部必需项通过后标记“自检通过，待人工审查”。局部功能可用一份简短开发记录合并检查与交付，保留需求、实际证据和未执行原因；完整新功能或要求独立报告时保留开发报告与过程记录。阻断时如实记录并继续独立工作。

## 需要提供的信息

- 页面、字段、接口或 PRD/截图；
- 正式菜单时的名称、父级和排序；按钮权限已指定时原样采用，未指定时按“业务标识 + 功能动作”生成并对齐相邻模块格式。相同 `v-auth` 的多处按钮引用会合并成一条后台权限，写入前在目标租户和系统完整菜单树查重；
- 新增正式页面命中菜单权限流程时会主动询问是否同步创建/更新；管理端真实写入还需要用户确认同步与写入、目标环境、运行时 Token、租户和父菜单定位；
- 页面开发开始时会询问是否配置远程菜单；不配置时会撤销本次新增的业务远程暴露配置（包括 `src/hooks/moduleFederation.ts` 对应 expose），但保留框架标准 expose 及其他实际依赖所需的模块联邦配置；
- 模块联邦时的提供方/消费方、远程名称和部署信息；地图/视频时的组件库版本、数据或流地址。

## 示例提示词

- `新增设备 CRUD 页面，表格占满剩余高度；创建正式菜单和新增、编辑、删除按钮权限。`
- `新增设备地图页，展示点位聚合、轨迹回放和热力图；先检查 @fxft/ui-plus 是否满足所用功能版本。`
- `接入四路监控视频，支持全屏、PTZ 和拖拽换位；不安装依赖前先告知我。`
- `新增 aura-order-web 运行时远程配置，先做模块联邦基线检查，修改后复检。`
- `根据附件 PRD 开发订单详情页，只改前端，不创建正式菜单。`
- `新增订单看板页面，先调用 frontend-design 统一视觉方向，再按 PIGX 页面模式实现。`
- `开发完成后使用 Codex 内置浏览器自查；这个原型链接可访问，请逐项对照并列出差异。`

## 边界

截图、PRD、HTML 原型和 Figma 仅提供业务与设计输入，不能覆盖 PIGX 工程规范。管理端 API、依赖升级和外部环境写入均遵循用户授权边界。

## 已有业务提示词

整体结构优化：

```text
用 $aura-web-develop 按最新规范优化【项目/模块】整体结构，合理拆分组件、Hook 和工具，保持功能不变，补齐注释和业务说明，完成回归；无数据或异常接口用 Mock 测试。
```

修改功能：

```text
用 $aura-web-develop 修改【项目/模块】的【功能】，按规范调整受影响结构，更新注释和说明并验证。
```

只补注释和说明：

```text
用 $aura-web-develop 补齐【项目/模块】中文注释和业务说明，保持功能与结构不变。
```

仅第三种属于纯整理：人工核对真实语义和差异、按项目约定格式化后直接交付，默认不运行扫描、审查、lint、typecheck、build、测试、浏览器或 AST 对比。明确要求验证或真实项目强制门禁时按范围追加。前两种按[开发闭环](references/development-review-workflow.md)执行，局部修改不扩大为整个模块重构。

业务枚举/字典的标签与文本展示必须使用 `AuraDictTag` / `AuraDictText`，功能开发自检会核对实际公开接入与全部展示消费；纯注释不据此改造已有组件；筛选/表单保持现有字典选项流程。

业务说明优先更新既有目录；需要新建独立流程说明时可采用 `docs/业务说明/<中文模块>/<中文功能>.md`，完整新模块按需补总览，按真实场景说明操作、条件与结果。结构与交付选择见[开发闭环](references/development-review-workflow.md)。明确要求中文时迁移本次涉及说明并修链接；不因此强制迁移过程记录目录。

## API/类型注释范围

请提供明确的完整文件清单。按[声明字段门槛](references/code-comment-guidelines.md#声明字段完整性门槛)人工核对每个声明字段自己的相邻中文含义，保留完整覆盖标准。随包只读检查器为可选结构诊断，仅用户要求结构检查或真实项目强制门禁时运行；检查部分文件不能宣称整批通过。仅维护技能时，业务源码只读。当前版本以 `VERSION` 为准。

涉及业务表单的开发/功能修改/重构会主动接入 web-kit `useForm`；审查及开发自检逐表单核对真实调用，未接入或直接绕过不能通过，无需在提示词中另写“使用表单 Hook”。只读排版、纯注释与动态表单协议按技能执行边界处理。
