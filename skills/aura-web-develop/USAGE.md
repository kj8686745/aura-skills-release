# PIGX 综合端业务开发使用说明

## 适用与调用

用于已识别的 PIGX 综合端业务页面、CRUD、接口、正式菜单/按钮权限、样式资源和模块联邦实现。可直接描述需求自动触发，也可显式调用：`$aura-web-develop <需求>`。

地图和视频需求会在当前环境存在对应技能时串联 `fmap-2d` 或 `fxft-video`；专项功能先检查项目的 `@fxft/ui-plus` 实际版本，不足时只提出升级建议，取得用户授权后才升级依赖。

新增或改造用户可见页面时会自动协作调用 `$frontend-design`，先确定与业务对象匹配的视觉方向和令牌，完成后做一致性、自适应、键盘焦点和 reduced-motion 自评；纯后端、隐藏页和组件修复不触发。详细流程见 [`references/frontend-design-workflow.md`](references/frontend-design-workflow.md)。

调用任何其它技能前都会检查当前环境是否已安装。若缺少 `$frontend-design`、`fmap-2d`、`fxft-video`、`aura-module-federation-check` 或其它条件依赖，会先提示技能用途、任务影响并询问是否安装；未经明确授权不会安装。用户拒绝时，可降级项继续按 PIGX 本地规范完成，必需项只暂停受影响分支。

开发自检另核对 `aura-web-review` 的模式能力；安装旧版不支持时如实说明。当前仓库新版可取得时，可明确按绝对源码路径加载，记录版本和“未安装替换”，否则记为阻断，不用正式六文件流程代替。

前端页面业务完成后会明确调用 Codex 内置浏览器检查实际页面、核心交互、控制台和 Network。有可访问原型链接时，用 Codex 内置浏览器保留实现页与原型页同步对照；用户明确提出的验收意见优先。用户未明确取舍时，交付一致项、差异项、风险和待决策选项，不替用户做主观确认。

正常开发和修改会自动补齐代码注释、按场景组织的模块业务说明、真实流转图与简洁代码阅读入口，执行开发自检、整改和必要测试；全部必需项通过后保存开发审查报告，状态为“自检通过，待人工审查”。每块通过后继续开发，整体再检查衔接；阻断时保留过程记录并继续独立工作。

## 需要提供的信息

- 页面、字段、接口或 PRD/截图；
- 正式菜单时的名称、父级和排序；按钮权限已指定时原样采用，未指定时按“业务标识 + 功能动作”生成并对齐相邻模块格式。相同 `v-auth` 的多处按钮引用会合并成一条后台权限，写入前在目标租户和系统完整菜单树查重；
- 新增正式页面命中菜单权限流程时会主动询问是否同步创建/更新；管理端真实写入还需要用户确认同步与写入、目标环境、运行时 Token、租户和父菜单定位；
- 页面开发开始时会询问是否配置远程菜单；不配置时会撤销本次新增的业务远程暴露配置（包括 `src/hooks/moduleFederation.ts` 对应 expose），但保留框架标准 expose 及其他实际依赖所需的模块联邦配置；
- 模块联邦时的提供方/消费方、远程名称和部署信息；地图/视频时的组件库版本、数据或流地址。

## 示例提示词

- `新增设备 CRUD 页面，表格占满剩余高度；创建正式菜单和新增、编辑、删除按钮权限。`
- `新增设备地图页，展示点位聚合、轨迹回放和热力图；先检查 @fxft/ui-plus 是否满足所用功能版本。`
- `接入四路监控视频，支持全屏、PTZ 和拖拽换位；不安装依赖前先告知我。`
- `新增 aura-order-web 运行时远程配置，先做模块联邦基线检查，修改后复检。`
- `根据附件 PRD 开发订单详情页，只改前端，不创建正式菜单。`
- `新增订单看板页面，先调用 frontend-design 统一视觉方向，再按 PIGX 页面模式实现。`
- `开发完成后使用 Codex 内置浏览器自查；这个原型链接可访问，请逐项对照并列出差异。`

## 边界

截图、PRD、HTML 原型和 Figma 仅提供业务与设计输入，不能覆盖 PIGX 工程规范。管理端 API、依赖升级和外部环境写入均遵循用户授权边界。

## 旧代码专项提示词

```text
$aura-web-develop 为 <项目路径> 的围栏注册业务补齐注释和业务逻辑说明，保持现有功能。
```

```text
$aura-web-develop 梳理 <模块路径>，逐块补齐注释和业务逻辑说明，再形成整体概览。
```

这两种纯整理调用只改注释与说明，保持组件、DOM 属性、导入、状态、接口和执行流程不变。自检发现既有功能偏差只记录证据与建议，完成可读性和行为保持验收后交限定范围的“注释/说明整理审阅报告”，不宣称整体规范通过。新开发和功能修改按原授权执行开发整改闭环。

业务枚举/字典的标签与文本展示必须使用 `AuraDictTag` / `AuraDictText`，开发自检会核对实际公开接入与全部展示消费；筛选/表单保持现有字典选项流程。

业务说明默认保存为 `docs/业务说明/<中文模块>/业务总览.md` 和 `<中文功能>.md`，按真实场景阅读操作、条件与结果；可裁剪结构及文档职责见[开发闭环](references/development-review-workflow.md)。已有约定优先，明确要求中文时迁移本次涉及说明并修链接。开发报告默认中文功能名，过程记录目录不随此要求强制迁移。

## API/类型注释范围

请提供明确的完整文件清单。当前源码版 1.4.5 按[声明字段门槛](references/code-comment-guidelines.md#声明字段完整性门槛)逐文件核验每个声明字段自己的相邻中文，运行随包只读检查器并另查语义；部分文件通过不代表整批。仅请求维护技能时，业务源码只读，验证使用隔离样本。源码更新未安装或发布。
