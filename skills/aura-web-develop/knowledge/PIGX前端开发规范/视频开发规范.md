## 一、组件与依据

视频统一使用 `@fxft/ui-plus` 当前源码中的 `FxftWebVideo`（单路）和 `FxftWebMultiVideo`（多路）。核对基线为 `fxft-public/packages/ui-plus` 的 `1.1.3` 源码、根 `index.d.ts`、两个组件的 `types.ts` 与 `defineExpose`；发布包消费前核对实际安装的导出。

组件名不是 `webVideoPlayer`。本规范使用 Web 视频的 `source / channels / layout` 契约，不沿用 Jessibuca 组件的 `url / videos / split / decoderPath`、`playWindow` 或 `setPlayProgress`。

- 单路按协议动态创建引擎，统一使用浏览器 video 渲染。
- HLS 使用原生能力或 hls.js，FLV/MPEG-TS 使用 mpegts.js，WebRTC 使用 WHEP 信令。
- 业务只调用公开 Props、Events、Slots 和 Exposes，不访问底层播放引擎实例。
- 通过 `FxftUiPlusResolver` 同时引入组件和样式；合并已有 Resolver，接入方式见[公共 UI](组件复用与公司基础组件库规范.md)。

## 二、视频源模型

| source.protocol | 必要字段 | 内容类型与说明 |
| --- | --- | --- |
| `native` | `url` 或浏览器选择的 `file: File` | `kind: live / playback / vod`；网络地址与本地文件二选一 |
| `hls` | `url` | 支持 `request`、`lowLatency`；类型按真实视频源设置 |
| `flv`、`mpegts` | `url` | `transport: http / websocket`，按需配置 `hasAudio / hasVideo / lowLatency` |
| `webrtc` | `endpoint`、`signaling: whep` | 仅 `kind: live`；鉴权通过运行时 `request` 注入 |

`kind: playback` 表示录像回放，`kind: vod` 表示点播；播放器的本地录像功能由 `features.record` 控制，两者职责不同。空源传 `null`，不使用无效 URL 制造空态。

FLV/MPEG-TS 的 `hasAudio` 不传时自动识别；明确关闭音频才传 false。媒体流地址使用业务接口返回的真实地址；项目内 public 视频使用 `getPublicResourceUrl`，import 海报使用 `getStaticResourceUrl`。新组件不需要业务配置 Jessibuca 脚本或 decoder。

## 三、单路示例

示例使用 `camera` 页面命名空间，提供方须把其语言目录加入 i18n 扫描；如果已有等价公共 key，应复用。组件标签由 Resolver 注入，类型从根公开入口导入。

```vue
<script setup lang="ts">
import { computed, ref } from 'vue';
import { useI18n } from 'vue-i18n';
import type { WebVideoExpose, WebVideoSource, WebVideoState, WebVideoPtzEvent } from '@fxft/ui-plus';

const props = defineProps<{ source: WebVideoSource | null; title: string }>();
const emit = defineEmits<{ ptz: [command: WebVideoPtzEvent] }>();
const { t, locale } = useI18n();
const playerLocale = computed(() => locale.value === 'en' ? 'en-US' : 'zh-CN');
const playerRef = ref<WebVideoExpose>();
const state = ref<WebVideoState>();
const failed = ref(false);
function handleState(value: WebVideoState) {
  state.value = value;
  failed.value = value.status === 'error';
}
function handleError(error: { fatal: boolean; message: string }) {
  failed.value = error.fatal;
}
function handlePtz(command: WebVideoPtzEvent) { emit('ptz', command); }
function retry() { return playerRef.value?.reload(); }
</script>

<template>
  <section class="camera-player">
    <FxftWebVideo
      ref="playerRef"
      :source="props.source"
      :title="props.title"
      :locale="playerLocale"
      :empty-text="t('camera.empty')"
      :loading-text="t('camera.loading')"
      :features="{ ptz: true, snapshot: true }"
      :muted="true"
      @state-change="handleState"
      @error="handleError"
      @ptz-command="handlePtz"
    />
    <el-button v-if="failed" @click="retry">{{ t('camera.retry') }}</el-button>
  </section>
</template>

<style scoped>
.camera-player { height: 400px; min-height: 0; }
</style>
```

PTZ 命令含 `command / direction / phase / speed`。`phase` 为 start 或 stop，松开时 `direction` 为 stop；业务父组件按设备接口转发并处理停止，不直接把播放器事件当设备 API 参数。失败采用播放器或所属区域的错误反馈。

当前根类型入口未导出 `WebVideoError`，组件源码的同名类型用于描述事件结构；示例只声明实际使用的结构字段，不从未公开的内部路径导入该类型。

```ts
// 页面 i18n/zh-cn.ts
export default { camera: { empty: '暂无视频源', loading: '正在加载', retry: '重试' } };
```

```ts
// 页面 i18n/en.ts
export default { camera: { empty: 'No video source', loading: 'Loading', retry: 'Retry' } };
```

## 四、进度、控制与生命周期

| 场景 | 当前公开接口 |
| --- | --- |
| 播放、暂停、停止和重连 | `play()`、`pause()`、`stop()`、`reload()` |
| 回放定位与倍速 | `seek(seconds)`、`setPlaybackRate(rate)`；直播不套用回放操作 |
| 进度 | `time-update` 的 `currentTime / duration / buffered`，单位秒 |
| 状态与错误 | `state-change: WebVideoState`、`error: WebVideoError` |
| 缓冲策略 | `buffer`、`setBuffer(policy)`；变更可重建引擎 |
| 截图与本地录像 | `capture()`、`startRecording()`、`stopRecording()`；核对返回 Blob/null 和浏览器支持 |
| 缩放 | `zoomIn()`、`zoomOut()`、`resetZoom()` |
| 单路全屏 | `enterFullscreen()`、`exitFullscreen()`、`fullscreen-change` |

`active=false`、默认启用的 `suspendWhenHidden` 和组件卸载参与引擎释放。页面负责提供有效尺寸和实际显示状态，不在显隐后调用未公开的 resize/getInstance/destroy 方法。`autoplay` 默认开启且静音，浏览器拒绝自动播放时仍需提供用户播放入口。

## 五、多路示例

`channel.id` 是稳定业务身份，布局位置不能代替通道标识。`layout` 支持 grid 的 columns/maxVisible 与 focus 的 focusId/thumbnails/thumbnailCount。示例中的视频源由调用方提供，按钮权限按业务页面实际操作配置。

```vue
<script setup lang="ts">
import { ref } from 'vue';
import type { WebVideoChannel, WebVideoWallLayout, WebMultiVideoExpose, WebVideoChannelRemoveEvent } from '@fxft/ui-plus';

const wallRef = ref<WebMultiVideoExpose>();
const channels = ref<WebVideoChannel[]>([]);
const selectedId = ref('');
const selectedIds = ref<string[]>([]);
const layout = ref<WebVideoWallLayout>({ mode: 'grid', columns: 2, maxVisible: 4 });
function handleReorder(payload: { ids: string[]; channels: WebVideoChannel[] }) {
  channels.value = payload.channels;
}
function handleLayout(value: WebVideoWallLayout) { layout.value = value; }
function handleRemove(payload: WebVideoChannelRemoveEvent) {
  const removed = new Set(payload.ids);
  channels.value = channels.value.filter(channel => !removed.has(channel.id));
  selectedIds.value = selectedIds.value.filter(id => !removed.has(id));
  if (removed.has(selectedId.value)) selectedId.value = selectedIds.value[0] ?? '';
}
</script>

<template>
  <FxftWebMultiVideo
    ref="wallRef"
    v-model:selected-id="selectedId"
    v-model:selected-ids="selectedIds"
    :channels="channels"
    :layout="layout"
    :features="{ removeChannel: true, focusMode: true, wallFullscreen: true }"
    :max-concurrent-starts="2"
    @reorder="handleReorder"
    @layout-change="handleLayout"
    @remove-channel="handleRemove"
  />
</template>
```

- 拖拽使用 `reorder` 载荷的 ids/channels，同步业务顺序；不读取旧组件的 getWindowStates。
- `removeChannel(id)`、`removeSelectedChannels()` 只是发出 remove-channel 请求；调用方处理事件并更新 channels 后才移除通道。
- `play(id?) / pause(id?) / reload(id?)` 默认作用于主选中通道，不表示全部通道；批量动作遍历已选 IDs。
- `focus(id)` 切换聚焦布局；整体全屏使用多路组件的 enterFullscreen/exitFullscreen。单窗操作由内部单路组件处理。
- 单窗状态、错误、进度、指标对应 `channel-state-change / channel-error / channel-time-update / channel-metrics`，载荷带 channel；一路错误不清空其他通道。
- 多路 PTZ 载荷为 `{ channel, command }`，command 是结构化 WebVideoPtzEvent。
- 当前多路 Props 未公开 locale；可配置 title/emptyText/loadingText，但内置多路文案的完整语言切换需由组件库支持，不凭单路接口推断多路支持。

## 六、接入验证

1. 独立和宿主模式均能解析 FxftWebVideo/FxftWebMultiVideo 与样式；协议引擎 chunk 无 404。
2. 验证空源、播放成功、失败、自动播放拒绝、重试、换源和卸载；不遗留旧引擎。
3. HLS、FLV/MPEG-TS、native 和 WHEP 按实际需求分别验证；协议可编译不代表流地址和浏览器编码可用。
4. 录像/点播验证 seek、倍速和 time-update；PTZ 验证按下、松开、失焦后的停止业务。
5. 多路验证稳定 ID、拖拽 reorder、多选、remove-channel 回写、聚焦与全屏；隐藏后恢复和连续换源不串窗。
6. 截图与录像验证浏览器能力、跨域媒体和 Blob 结果；需要下载时由业务复用文件能力并释放临时 URL。

本规范依据当前源码核对 API；真实流、浏览器和发布包消费须在目标环境完成验证。
