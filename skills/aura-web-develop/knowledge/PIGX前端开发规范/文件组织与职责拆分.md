# 前端文件组织与职责拆分

本文是 FE-001～004、FE-019、FE-024 共用的职责判断正文，适用于所有手写 Vue、TypeScript、CSS/SCSS，包括页面、私有与共用组件、Hook、纯工具、普通业务模块、API、Store、类型、常量、配置和 Node 工具脚本。生成文件、第三方代码和构建产物不参与结构整改。

## 判断顺序与任务范围

新增文件、功能改造、明确授权的重构，以及只读结构评估或拆分建议，均依次确定职责、状态与资源所有者、实际消费者、拆分收益，再选择最小适用结构。按职责边界和实际收益决定保留、内部整理或提取；业务场景、容器类型、数量与行数均不能直接决定拆分。多个函数共同完成同一能力可以同文件；短文件混入无关职责仍需调整。

局部任务只评估本次相关职责；纯注释和业务说明整理保持行为与结构，发现组织问题仅记录建议，不自动重构。文件长、注释多、函数多、未使用 Hook 或 CSS 未外置均不能单独作为偏差依据。不新增全仓复杂度扫描、固定拆分报告或额外构建门槛。

## 拆分收益与停止条件

先判断当前组织是否存在实际问题，再选择处理方式：职责是否混杂、状态或资源所有权是否冲突、修改一项能力是否需要理解和联动无关实现。能独立命名、有多个请求或多个状态，不等于必须拆分。

提取应能使所属状态、行为、样式或资源生命周期内聚，通过明确的业务输入、输出与外部协作，并减少理解和修改成本。只有独立职责确有混杂问题且提取能改善边界时要求拆分；同一流程的多个步骤、请求或状态允许一起保留。职责已内聚、所有权清楚、接口合理且无具体结构缺口时即可停止，不追求最小文件或将页面变成空壳，不要求每个组件配一个 Hook。

完整页面或模块结构任务应评估完整授权范围，对各职责决定保留、内部整理或提取，完成后复核入口及相关私有实现。合理保留是有效完成结果，未检查与合理保留必须区分；不能只提取少数函数就宣称整体完成，也不能以“还能继续拆”阻断交付。局部任务不扩大为整模块整改。

## 入口内部职责与展示组件

结构评估同时检查入口中尚未提取的职责和已有子组件，不能以“已经有表单、详情组件”推断入口组织合理。对用户范围内的主要职责说明保留、内部整理或提取的依据；尚未核对的部分保留检查缺口，不提前给整体合理结论。只读咨询只交付建议及证据，不因此修改代码或进入开发实施验收。

纯展示区域也可提取组件，不以拥有私有状态、请求或多个消费者为前提。若其模板、交互与样式已形成独立维护单元，提取可隔离变化、明确输入输出或便于独立验证，应提出有依据的拆分建议；“不按行数机械拆分”不能代替收益评估。例如表格和卡片共享一份查询结果，但各自有列定义或布局、操作事件及加载/空态时，可分别提取展示组件，由父页保留查询、分页与业务操作，子组件接收只读业务 Props 并发出操作意图。若两种视图都很轻且提取只增加转发，则可保留并说明实际依据。

展示组件允许无私有状态。区域独占的状态、行为、样式与资源清理随职责迁移；父页的共享状态和协调仍留在父页。“只搬模板”的问题指区域私有实现仍散落父页、通过整页 state 或大量实现回调继续耦合，不将合理的纯展示拆分判为偏差。

评估测试合理性时，将已有证据对应到上述职责与用户行为，指出已覆盖和缺失的成功、失败、取消、权限或异步边界；未发现可重复测试时如实说明。静态检查、构建和历史验收只能支持各自范围，不代替当前行为测试，也不要求每提取一个展示组件就机械新增镜像测试。

## 职责决策表

| 对象 | 保留或拆分条件 | 接口与所有权 |
| --- | --- | --- |
| Vue SFC | 默认 template、script、scoped style 同文件；简单状态、computed 和事件编排可以留在页面 | 不要求页面成为空壳；不把整个 script 原样外搬当作职责拆分；默认不外置 HTML 模板，既有工具链约定另行核对 |
| 业务子组件 | 按上文收益判断提取独立职责；仅用一次也可拆，视觉分区或可独立命名本身不构成必须拆分的理由 | 模板、私有状态、行为和样式随职责迁移；父页保留共享状态与协调，不传整页 state 和大量实现回调 |
| Dialog / Drawer | 与普通页面区域使用同一判断原则；不按容器类型、数量或是否请求直接要求拆分 | 可内聚管理的独立职责按收益提取；轻量交互、展示或同一流程中拆分无收益的内容允许内联 |
| Composable / Hook | 围绕一个能力封装响应式状态、操作及资源清理；存在独立流程混杂且提取能改善所有权与生命周期管理时拆分 | 使用 useXxx；输入、返回状态与操作、初始化和清理责任明确；不采用包办整页的巨大 usePage，也不一函数一 Hook；组合层只协调多个能力 |
| utils | 按计算、转换、校验等语义组织纯函数，相关函数可同文件 | 输入输出明确，不隐式读写 Vue 状态、Store、路由、DOM、网络或存储；公共工具不反向依赖 Hook、页面或组件 |
| 普通业务 TS | 不依赖 Vue 的流程、策略或算法按业务能力组织；单一内聚能力可保留多个私有辅助函数 | 使用具名文件，带副作用的编排不伪装成纯工具，不强制 use 前缀，也不统一塞入 utils |
| API | 同一业务资源的请求与契约可同文件，独立资源混杂才拆分 | 仍放 src/api/<业务域>/，不按 GET/POST 分文件；复用统一请求入口，不把请求实现搬入页面 |
| Store | 按共享状态的生命周期与所有权组织 | 页面自用状态不因拆文件进入 Store，不按每个字段机械拆 Store |
| 类型 | 默认靠近 API 或所属实现；真实共用或契约独立时提取 | 页面 types.ts 仅放页面独有类型，不复制请求响应契约、不建只有转发作用的空壳；适当使用类型导入 |
| 常量 | 与所属能力就近，真实共用再集中 | 不建立杂物式全局 constants.ts，不为单个常量建立无收益文件 |
| 配置 | 入口表达配置与组合，独立且复杂的生成逻辑可提取 | 保持加载顺序、运行环境与副作用 |
| Node 脚本 | 单一小任务可保留，独立处理步骤或真实复用再拆具名模块 | 使用既有 scripts/ 或构建工具目录，与浏览器模块分开 |

每份可变状态只有一个所有者，子组件通过明确的 Props/Emits 接收输入和表达业务事件，必要命令式操作使用公开 Exposes；子组件不反向导入父页面实现。拆分不能改变公开导出、请求顺序、初始化、取消或清理行为；确需改变时作为功能调整处理。

弹窗专属数据在实际打开时加载，不在页面或组件挂载阶段提前请求。已提取组件持有其私有状态，通过公开打开流程加载，父页面只传 ID、已选 ID 和操作约束；合理内联时由所属页面持有该交互状态并在具名打开处理中加载，不为公开方法而强制拆组件。

共享 Hook 默认每次调用创建独立状态；确需共享实例时使用明确的既有 Store 或缓存机制，不通过模块级可变变量无意共享。Hook 可调用领域 API 和纯工具。

## 文件放置与复用层级

| 实际消费者 | Vue 组件 | Hook / Composable | 纯工具与样式 |
| --- | --- | --- | --- |
| 当前页面及其私有组件 | 页面 components/ | 少量私有 TS 可与 index.vue 同级；形成多组职责后按需放页面 composables/ | 少量私有 TS/SCSS 同级；需要分组时放页面 utils/、styles/ |
| 同一业务模块多个页面 | 模块 components/ | 模块 composables/ | 模块 utils/、styles/ |
| 项目多个业务模块 | src/components/<职责>/ | src/hooks/<职责>/ | src/utils/<职责>/、既有 src/styles/ |
| 跨项目通用能力 | 核对 aura-ui 归属 | 先查 web-kit 公开能力，适合时补充公共包 | 按公共包和既有主题系统归属维护 |

页面私有 Vue 组件仍必须放 components/，允许同级的是少量职责明确的私有 TS/SCSS。私有文件形成多组能力、同级难以区分时才建 composables/、utils/、styles/，不设固定数量门槛，不建空目录或并存同义目录。Hook 与 Composable 表达同类能力，项目层沿用 src/hooks/，不并建 src/composables/；已有目录不因名称差异批量迁移。

普通业务 TS 按职责具名，留在所属页面或模块；组件独占的复杂辅助逻辑可与组件就近组织，不把所有实现挂在路由入口。跨页面共用不等于跨项目通用；带项目业务规则的能力留项目，跨项目能力明确通过参数或回调接收依赖，先查公开能力，避免重复分页、表单和日期工具。

依赖方向是私有实现 → 模块共用 → 项目公共 → 公共包公开入口。两个页面共用时提升到最小共同范围，不互相导入对方私有实现；类型、样式和工具同样遵守，不产生循环依赖或跨层实现回调泄露。

```text
src/views/order/list/
├─ index.vue                  # 默认完整 SFC，保留简单状态与页面编排
├─ useOrderQuery.ts           # 按需：页面私有查询能力
├─ orderTransform.ts          # 按需：页面私有纯转换
├─ orderExport.ts             # 按需：有副作用的业务流程，不归纯工具
├─ types.ts                   # 按需：仅页面独有类型
├─ index.scss                 # 按需：仍是页面私有样式
└─ components/
   └─ order-form.vue          # 独立表单职责及其状态、行为、样式
```

目录示意表达可选职责，不要求同时生成全部文件。简单页面保留一个 SFC；多组能力才按需分目录。同模块第二个页面需要查询能力时提升到模块 composables/，多个业务模块实际共用才放 src/hooks/。

## CSS/SCSS 规模与归属

| 场景 | 判断与处理 |
| --- | --- |
| 单一内聚职责 | 默认保留 SFC scoped style；不因长度要求外置或另写保留理由 |
| 职责混杂或选择器相互影响 | 评估组件边界与样式归属；先解决具体耦合，不只搬动样式文件 |
| 多组件实际共享 | 提取到最小共同范围，避免复制与重复输出 |
| 全局主题与颜色变量 | 使用既有主题系统和独立主题文件，业务优先消费现有变量 |
| Element Plus 覆盖 | 项目统一覆盖集中管理，组件专属覆盖保持局部范围；既有授权边界继续适用 |

不设置样式行数分档或额外扫描门槛；按职责、实际共享、选择器耦合和作用域判断。

先判断是否属于独立业务区域，能拆组件时样式随职责迁移；真实共享再抽共用样式。职责单一但样式较长时，可保留 SFC 或外置专属 CSS/SCSS，并保持 scoped 编译效果、选择器语义、加载顺序、资源路径及远程样式随组件加载和既有隔离机制。外置 index.scss 不从项目全局入口加载。

优先组件公开 Props、Slots 和主题变量。业务不得随意新增或修改 Element Plus 覆盖，集中管理不构成新增授权；有授权的统一覆盖走既有入口，专属覆盖限定局部作用域和业务根类，不无约束覆盖全局 .el-*。说明原因、影响范围与必要版本约束，避免互相覆盖和优先级堆叠。Aura 核心主题仍归既有主题系统，业务不复制主题运行时或建立第二套公共颜色体系。

## 正反例与审查依据

下列示例解释判断边界，不是业务场景清单，也不新增按名称或数量触发的规则。

| 判断边界 | 正例 | 反例 |
| --- | --- | --- |
| 保留内聚流程 | 查询、分页与选择围绕同一列表，状态归属清楚，保留页面实现 | 仅因有多个状态或请求，将每个步骤拆成 Hook，增加交叉回调 |
| 提取独立职责 | 某区域的编辑、校验与提交细节混入主查询；提取后自行管理私有状态，只接收操作上下文并发出完成事件 | 只搬模板，区域独占字段和提交细节仍散落父页面，向子组件传整页 state |
| 展示组件边界 | 表格列与卡片布局各有独立变化和验证需要时，分别接收当前页数据并发出业务事件，共享查询分页仍由父页管理 | 仅因没有私有状态/请求而否定提取收益，或只因存在表格/卡片就强制拆分 |
| 容器不决定拆分 | 多个轻量 Dialog/Drawer 无独立职责混杂，可内联；一个存在独立复杂流程且提取有收益的弹窗也应拆 | 见到两个弹窗就判违规；只有一个弹窗就免查职责 |
| 不要求真实复用才拆 | 只使用一次的区域，提取能明确资源所有者和释放责任，放页面私有组件 | 为假想复用将一次性业务组件提升到项目公共目录 |
| 选择合适边界 | 同一流程的多个请求、转换与提交保持在一起；纯转换确有独立契约时再提取 | 因文件同时包含转换和请求便按技术动作拆散同一流程 |
| 停止提取 | 职责内聚、所有权明确、接口合理，评估后保留，计为完成 | 页面已合理仍要求继续抽文件、每组件配 Hook 或清空入口脚本 |
| 覆盖完整任务 | 整模块任务检查入口、新模块及保留部分，记录实际调整与保留依据 | 只审新增 Hook/diff，以文件变短宣称整个模块完成 |
| 复用范围 | 两个页面实际共用能力提升到最小共同范围；少量私有 TS/SCSS 可同级 | 页面互相导入对方私有 Hook，或公共工具反向导入页面 |
| 样式归属 | 长但内聚的 scoped style 可保留；真实共享的短样式也可提取 | 达到某行数就外置，或将页面私有样式挂到全局入口 |

审查按同一正文给出结论：确定偏差须指出具体职责/所有权/依赖/作用域问题、影响及关闭条件；当前结构合理而另一种组织方式也可行时只列可选建议，不阻断完成；尚未查清调用关系或生命周期时记未证实及缺少证据，不直接判应拆。代码长度、组件数量、未抽 Hook 或 CSS 未外置均不能单独证明偏差。
