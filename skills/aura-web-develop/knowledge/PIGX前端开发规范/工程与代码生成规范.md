# 工程与代码生成规范

## 一、基础写法

- Vue 页面统一使用 `<script setup lang="ts">`。
- 项目内部路径使用 `/@/`，不使用层层 `../../../`。
- Vue、Vue Router、Pinia 常用 API 已由 Vite 自动导入；以生成的 `auto-imports.d.ts` 为准。
- 父子组件自定义事件及任何需要访问组件 ref 的模板事件必须绑定脚本中已定义的具名方法，例如 `@edit="handleEdit"`；不得写成 `@edit="formRef.open"`、`@click="formRef.open()"` 或访问 ref 的内联箭头函数。需要向普通业务方法传递当前行等上下文时允许 `@click="handleEdit(scope.row)"`；组件 ref 只能由脚本中的具名方法通过 `ref.value?.openDialog(...)` 等安全访问，避免子组件尚未挂载时在渲染阶段读取 `undefined`。
- 新增类型、函数和文件使用有业务含义的英文名称；注释、错误提示和文档使用简体中文。
- 页面内组件按需异步加载，避免把非首屏大组件放入主图。
- 路由页面模板必须保持一个真实元素根节点，根元素统一使用 `class="layout-padding"`；业务区域置于 `class="layout-padding-auto layout-padding-view"`，Dialog、Drawer 等弹窗可与业务区域并列置于根节点下；复用列表页组件时，该组件的真实根元素同样遵循此结构。

```ts
const OrderForm = defineAsyncComponent(() => import('./components/order-form.vue'));
```

## 二、目录和命名

文件职责、SFC、TS 类型边界、复用层级和依赖方向统一按[文件组织与职责拆分](文件组织与职责拆分.md)决策表执行。下例仅示意可选职责，不要求每页生成所有文件；多组能力才建立职责子目录。

```text
src/views/order/list/
├── index.vue
├── useOrderQuery.ts          # 按需：页面私有查询能力
├── orderTransform.ts         # 按需：页面私有纯转换
├── index.scss                # 按需：保持页面局部作用域
├── components/
│   ├── order-form.vue
│   └── order-detail.vue
└── i18n/
    ├── zh-cn.ts
    └── en.ts

src/api/order/index.ts
```

- Vue 页面和组件文件使用小写 `kebab-case`；普通 JavaScript/TypeScript 工具、配置和模块文件使用 `camelCase`，例如 `mapConfig.ts`。
- 组合式 Hook 文件使用 `useXxx.ts`，导出函数使用 `useXxx`，例如 `useDeviceQuery.ts` / `useDeviceQuery`。
- 代码中的函数、方法、变量和参数使用 lowerCamelCase，固定业务常量使用 UPPER_SNAKE_CASE，类型、接口、枚举和类使用 PascalCase。
- CSS/SCSS 类名使用小写 `kebab-case`，组件样式优先采用 BEM；新增文件按此规则命名，已有文件不要求批量重命名。
- API 函数使用 `get/list/create/update/delete` 加业务名。
- 不以 `common`、`temp`、`new`、`test` 命名正式业务模块。
- 业务路由入口保留在业务目录的 `index.vue`。凡由该页面引入的私有页面组件，包括表单、详情、弹窗、抽屉、面板和嵌套业务视图，必须放入同路径的 `components/` 目录，禁止与 `index.vue` 并列；共用组件先提升到模块 `components/`，项目跨模块实际复用才放入 `src/components`。
- 路由页及 Dialog/Drawer 的保留、内部整理与提取统一按[职责决策表](文件组织与职责拆分.md)；合理保留也是完成，不按类型、数量和行数判拆分。提取时私有状态、行为和样式随职责迁移，父页保留共享状态与协调。
- 仅供弹窗使用的数据在实际打开时加载，禁止页面 `onMounted`、组件挂载或 `immediate` 监听提前请求。已提取组件持有私有状态并在公开 `openDialog/openDrawer` 流程加载，父页只传记录 ID、已选 ID 和业务约束；合理内联时由所属页面持有该交互状态并在具名打开处理中加载，保持单一来源，不为加载入口强制拆组件。
- 主页面本身也需要的数据仍由主页面按页面生命周期加载，但不能以此替代弹窗打开时对时效性数据的初始化；保存成功后仅刷新仍处于打开状态且确有需要的关联弹窗。

### 前端常量归属与定义

以下约定仅适用于前端 Vue/TypeScript 业务常量，属于本节目录与命名约定，不扩展为后端常量规范。定义与消费示例见[样例 9：前端常量定义与复用](参考页面样例.md#样例-9前端常量定义与复用)。

#### 归属与拆分

先确定语义所有者与实际消费者，选择最小共同归属，不按常量个数或文件长度机械拆分。

| 实际消费者 | 默认位置 | 判断边界 |
| --- | --- | --- |
| 单个文件 | 所属 Vue/TS 文件内 | 少量私有固定值可就地保留，无需为了目录齐全提取 |
| 当前页面及其私有组件 | 页面目录 `constant/<职责>.ts` | 页面私有实现不被其他页面反向导入 |
| 同一业务模块多个页面 | 业务模块目录 `constant/<职责>.ts` | 共享业务状态、权限码等归所属模块 |
| 项目多个业务模块 | `src/constant/<职责>.ts` | 仅提升真实项目共用语义，项目公共不依赖业务私有模块 |

新项目默认使用 `constant/`；已有 `constants/` 等明确约定时沿用，不并建同义目录、不批量迁移。具名文件表达上传限制、设备状态等职责，不建立杂物式全局 `constants.ts`。缺少目录不直接构成偏差；共享语义重复、跨页面私有依赖或公共层反向依赖才须结合源码判断。同一语义复用同一定义；数值相同而业务语义不同，不机械合并。

#### 定义与注释

- 固定业务值及固定编码映射的键（如 `DEVICE_STATUS.ONLINE`）使用 `UPPER_SNAKE_CASE`；普通业务对象成员仍用 `lowerCamelCase`；普通 `const` 局部变量、`ref`、`computed` 和工厂函数仍按正常变量/函数命名，不因使用 `const` 就全部大写。
- 名称、类型及相邻中文注释共同表达用途、单位、范围和必要约束。阈值说明边界是否包含，时长说明毫秒/秒，大小说明字节或 MiB，约定编码说明来源；不凭空补来源或重复解释显然的赋值语法。
- 固定状态映射可用 `as const` 保留字面量并派生联合类型；它是类型约束，不是运行时冻结。需要运行时冻结时按真实需求另行设计，不把它当作常量模板的默认机制。
- 可变表单默认值使用工厂，每次返回独立对象/数组；不能复用模块级对象造成跨弹窗、跨实例污染。
- 后端动态字典不改成本地固定枚举；可见标签在消费时走 i18n，不将翻译结果固化为模块级常量。环境值从现有配置读取，运行状态由所属组件/Hook/Store 持有；不为了集中存放将请求、权限判断或副作用塞入常量文件。

开发与审查按本次范围沿“定义 → 实际消费者 → 真实契约 → 导入方向”核验；确认偏差须给出定义、调用位置及具体影响。缺少真实契约记未证实，尚未读取调用链记未检查。调整影响行为时验证相应边界值、重置或权限入口；纯注释不扩大为结构整改。

## 三、API 封装

业务请求统一使用懒加载请求入口。下列查询示例以消费者已安装并核实支持 `queryFormat` 的请求层为前提；本轮已随 web-kit 1.9.5 发布并完成私服读回，旧包缺口按公共能力流程处理，不能虚构配置。新增、编辑及删除的数据保持各自写入协议，不套用查询格式化：

```ts
import request from '/@/config/aura/request';

export const getOrderPage = (params: OrderPageQuery) =>
  request({ url: '/order/page', method: 'get', params, queryFormat: { params: true } });

export const createOrder = (data: OrderForm) => request({ url: '/order', method: 'post', data });

export const updateOrder = (data: OrderForm) => request({ url: '/order', method: 'put', data });

export const deleteOrders = (ids: Array<string | number>) => request({ url: '/order', method: 'delete', data: ids });
```

禁止：

- 页面直接 `import axios from 'axios'`。
- 业务代码重复创建请求实例、重复拼接 Token 或租户头。
- 捕获认证异常后自行清 Token、刷新页面或跳登录。
- 在源码中写死域名、IP、Token、Cookie 或密码。
- 字典、候选项、列表、详情、初始化和刷新等只读请求失败时弹出全局错误消息；应维护所属区域的加载、错误、空态和重试状态，或交给上层统一错误策略。

`request.ts` 的懒加载入口以及 `requestService.ts`、认证异常、公共请求头、参数序列化等处理链属于框架保护区。业务只在 `src/api/<业务域>` 中调用统一请求入口，不直接修改请求内核；框架能力不满足时按[开发边界说明](./开发边界说明.md)提出需求。

### 查询条件的空值提交边界

导出参数按真实接口契约构造。分页导出或字段具有业务含义时，保留接口需要的 current、size 等参数；只有契约明确不接收列表分页时，才从筛选副本移除对应字段，不得仅凭字段名删除或把 current、size 当作完整分页字段清单。queryFormat 只处理空值，不推断分页或其他业务语义。不得修改原查询模型；导出候选列表的分页、排序及外层控制字段分别按各自接口契约处理。

查询条件在提交时统一省略未输入字段：`undefined`、`null`、空字符串、纯空白字符串、空数组和空普通对象不传。普通对象递归清理，清理后为空的字段也省略；`0`、`false`、非空字符串及其原始内容、日期等非普通对象必须保留。数组不随意删除元素、移动索引或改写元素语义，不能把对象字段清理规则机械套到数组项。处理生成新对象，不修改界面表单或调用方数据。

清理只用于 GET 的查询参数、POST 的查询条件对象及导出的 `filter`，在共享查询构造或查询 API 提交边界复用同一能力。POST 外层协议字段、手选标识与操作控制字段不属于可随意清理的查询条件；列表、统计、候选和导出在使用相同查询条件时应复用同一构造结果，不能各写一套过滤。既有 HTTP 层的写入序列化与查询清理语义不同，不得对所有请求无差别删除空值，统一请求内核只处理显式 queryFormat 配置的目标范围，不把待省略字段赋 `undefined` 后当成已经删除。

新增、编辑、清空字段等写入请求不进入默认清理范围。真实查询契约明确要求传 `null`、空字符串、空数组或空对象时，在 API 适配边界保留该字段，并记录契约来源及验证结果；不得为了通过通用规则改变接口语义。

**公共能力归属**：格式化算法放在 `aura-web-kit` 纯工具中，不为字段过滤另造查询 Hook；业务 API 优先使用统一请求层的显式 `queryFormat` 配置，不需要逐模块重复导入纯函数。GET 查询配置 `{ params: true }`，POST 查询配置 `{ data: true }`，导出仅配置 `{ data: { paths: [['filter']] } }`。默认不开启，不按 HTTP method 推断是否为查询；在 JSON 归一化和加密之前处理，仅作用于选定目标或字段路径。`filter` 清理后为空时省略该键，外层 `ids/fields/format` 等协议字段保持。仅独立条件构造等非请求场景按需直接调用 `formatQueryParams`。使用前核对已安装包的公开配置声明、实现和版本；待发布能力不等于消费者已可用，不在项目 request 或业务目录复制公共实现。

**正例**：查询 `{ keyword: '  ', status: 0, enabled: false, ids: [], filter: { text: '' } }` 提交为 `{ status: 0, enabled: false }`；写入请求中明确表达清空的 `null` 保持原样。

**反例**：用 `Boolean(value)` 过滤导致 `0/false` 丢失；把查询表单原对象的键删除；对所有 POST/PATCH 请求统一删除 `null`；删掉导出外层协议控制字段；列表与导出分别拼条件。

**判断要点 / 验证方式**：沿模型、查询构造、API 和最终请求取证，验证嵌套清空、有效假值、日期、数组位置与源数据不变；对照 GET 参数、POST 查询及导出 filter 的实参；写入清空与契约例外须保持原语义。没有拿到有效请求或契约证据时保留未验证，不用代码里出现函数名代替验收。

## 四、列表页和 useTable

标准分页列表使用 `/@/config/aura/index`：

```ts
import { BasicTableProps, useTable } from '/@/config/aura/index';
import { getOrderPage } from '/@/api/order';

const state = reactive<BasicTableProps>({
  pageList: getOrderPage,
  queryForm: {
    keyword: '',
  },
  tableAlign: {
    name: 'left',
    amount: 'right',
  },
});

const { getDataList, currentChangeHandle, sizeChangeHandle, sortChangeHandle, tableStyle } = useTable(state);
```

```vue
<el-table
  :data="state.dataList"
  v-loading="state.loading"
  :cell-style="tableStyle.cellStyle"
  :header-cell-style="tableStyle.headerCellStyle"
  @sort-change="sortChangeHandle">
	<el-table-column prop="name" label="订单名称" />
	<el-table-column prop="amount" label="金额" sortable="custom" />
</el-table>

<AuraPagination v-bind="state.pagination" @size-change="sizeChangeHandle" @current-change="currentChangeHandle" />
```

- 未配置的列默认居中；文本列可左对齐，数字列可右对齐。
- 不手写与 `useTable` 重复的分页、排序、下载逻辑。
- 搜索通常调用 `getDataList()` 回第一页；保留当前页刷新使用 `getDataList(false)`。覆盖层仍可见的操作成功同步按[静默刷新契约](aura-web-kit能力清单与接入规范.md#已加载列表的静默刷新196-已发布)选择本次参数，保持原分页与选择语义。

## 五、权限、表单和国际化

```vue
<el-button v-auth="'order_add'" type="primary" @click="openCreate">新增</el-button>
```

- 受限按钮、入口和操作使用项目既有 `v-auth` 及已注册变体，模板不直接调用 `permissions.has/any/all`；权限码定义为常量，同一业务多入口共用。
- 脚本通过公开 `usePermissions` 在受限打开、查询、保存、重置入口兜底，校验先于初始化、状态变更和请求。并集用于只含受限操作的容器；普通 DOM 使用实际支持的权限指令，组件注册/插槽结构使用脚本派生状态，避免空列、空菜单与空 footer；混合容器保留不受限操作。
- `v-auth` 只控制 DOM 呈现，不能阻止 `setup` 或请求。Tab/Drawer 等先在脚本筛选可挂载项、校正激活项或约束打开状态，模板使用派生结构/状态和入口指令；不得简单把 `ElTabPane` 的 `v-if` 换为 `v-auth`。未就绪与撤权时不初始化、不请求。
- 保留原有行状态、流程阶段等业务条件；不全项目机械替换，不要求所有只读展示添加权限指令。权限实现及无权/恢复/撤回验收按 [权限实现边界](../../references/admin-menu-permission-workflow.md#权限实现边界) 执行。

- 所有业务表单必须从 `@fxft/aura-web-kit/hooks/form` 使用 `useForm`；提交校验使用 `validateForm`，表单重置使用 `resetForm`，弹窗复用时使用 `clearFormValidate` 清除历史校验。业务页面不得直接调用表单实例的 `validate/resetFields/clearValidate`，也不得重复编写对应的 `nextTick` 清理逻辑。
- 表单提交前通过 `validateForm` 校验，校验成功后才进入提交状态；提交期间禁用按钮，成功后再关闭弹窗和刷新列表。
- 所有用户可见业务文案必须走 `t()` / `$t()`：包括 `label`、`title`、`placeholder`、按钮文字、表格列名、卡片标题与说明、Dialog/Drawer 文案、空态、校验与消息提示。业务 `.vue/.ts` 中禁止直接写中文；注释、接口/字典返回值、后端异常、mock 数据和 i18n 文件除外。
- 文案按复用范围放置：已有 `common` key 必须复用；跨两个及以上业务模块、但不属于全局 `common` 的文案上提到 `src/views/<业务域>/i18n/`；仅单页面或私有组件使用的文案才放入页面 i18n。中英文 key 必须同步存在。
- 每个可编辑或筛选的 `el-input`、`el-select`、`el-date-picker`、`el-input-number` 和 `el-autocomplete` 必须配置 i18n placeholder；无占位语义时以 `data-placeholder-exempt` 标记并在相邻注释说明原因。
- 行内查询表单的查询、重置、导出、视图切换等每个独立操作必须各占一个无标签 `el-form-item`；禁止在同一无标签 `el-form-item` 内堆叠多个 `el-button` 或 `el-radio-group`。行列间距统一由 form 的 `gap` 管理，禁止用按钮相邻 margin 或负 `margin-bottom` 补偿。
- API/OpenAPI 或 TypeScript 类型声明为枚举、带 `dictKey` 的字段，先保留 `/** @dictKey <key> */`，再按 [FE-012 字典展示规则](../../references/dictionary-table-contract.md)建立筛选/表格/详情/表单映射；字典展示以原始 code 和 options 按语义选择 `AuraDictTag` / `AuraDictText`，不以表格位置作为唯一依据。动态列、真实名称和交互开关边界按该规则核验，禁止名称快照或手写展示映射替代。
- 构建前必须执行 `check-project-rules.ps1 -StrictUiContracts`；脚本对直接中文、缺少 placeholder、i18n key 不完整和已声明 `@dictKey` 的 `*Name` 直出以错误退出。
- `src/components` 是框架默认语言包扫描目录，业务不得从 `i18nScanDirs` 中移除。
- 对外提供模块时，在默认扫描目录基础上追加业务目录；生成的 `src/i18n/moduleFederation.ts` 禁止手工修改。

## 六、系统配置与 Iconfont

模块联邦（综合端）启动时会先恢复缓存的 `systemId`、主题和 `iconfontUrl`，再通过 `aura-core` 的系统全局配置接口校准最新值。`setIconfontUrl()` 使用固定的 `data-system-iconfont` 标识替换旧样式表，避免重复加载多套图标字体。

业务开发遵守以下边界：

- 菜单和页面按现有 `pigx-iconfont` 类名使用图标。
- 不在业务页面硬编码阿里 Iconfont CSS 地址，也不重复插入 `<link>`。
- 不修改启动缓存键、系统全局配置读取顺序或 `setIconfontUrl()` 的替换机制。
- 需要新增或更新系统图标库地址时，通过系统平台配置统一维护。

## 七、静态资源

```ts
import orderIconSource from '/@/assets/images/order/icon.png';
import { getPublicResourceUrl, getStaticResourceUrl } from '/@/hooks/moduleFederation';
```

```ts
import { getFileFullUrl } from '/@/utils/file';

const imageUrl = getFileFullUrl(record.icon);
```

例如后端返回 `/admin/sys-file/oas/file?fileName=order.png` 时，会按当前 `VITE_API_URL` 转换为 `/api/admin/sys-file/oas/file?fileName=order.png`。完整 URL、协议相对地址、`blob:` 和 `data:` 地址保持原样。业务页面不得直接拼接 `baseURL` 或 `VITE_API_URL`。
