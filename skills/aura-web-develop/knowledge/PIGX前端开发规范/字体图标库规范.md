# 字体图标库规范

## 一、适用范围

本规范适用于 Aura/PIGX 综合端中的阿里 Iconfont 字体库、框架图标和业务图标。字体图标库统一由 `aura-core` 的系统全局配置管理；业务综合端只消费核心加载结果。

## 二、配置模型

全局配置接口使用 `iconfontSources` 数组；每项只保存业务信息：

```ts
interface IconfontSource {
	id: string;
	name: string;
	url: string;
	priority?: number;
}
```

| 字段 | 要求 |
| --- | --- |
| `id` | 字体库唯一标识；用于管理、更新和删除配置。 |
| `name` | 用户可读的字体库名称。 |
| `url` | 原始 Iconfont CSS 地址；支持 `https://`、`//` 与站内绝对路径。 |
| `priority` | 无冲突样式的注入顺序，数值越大越靠后；不用于规避冲突。 |

不得保存或要求业务填写 `iconfontUrl`、`enabled`、`fontFamily`、`className`、`iconPrefix`。其中后三项由核心从 CSS 自动解析，仅用于展示、校验和图标选择。

## 三、原始类名保持不变

核心加载器会读取 CSS、补全其中相对字体资源地址，并原样注入样式；不会改写业务既有的字体族、基础类名或图标类名。

因此业务已使用的写法继续有效：

```vue
<i class="pigx-iconfont pigx-icon-home" aria-hidden="true" />
<i class="iot-iconfont iot-icon-device" aria-hidden="true" />
```

禁止为了接入多个字体库而在业务页面中拼接命名空间、动态替换 class，或重命名既有 `pigx-iconfont` 图标。

## 四、冲突校验

同一页面加载多套 Iconfont 时，后端保存配置前必须拉取并解析每个 CSS，比较以下三个值：

| 解析项 | CSS 示例 | 冲突影响 |
| --- | --- | --- |
| 字体族 | `font-family: "pigx-iconfont"` | 相同字体族会覆盖字形映射。 |
| 基础类 | `.pigx-iconfont` | 相同基础类会覆盖实际采用的字体族。 |
| 图标前缀 | `.pigx-icon-home::before` 中的 `pigx-icon-` | 同前缀库可能定义相同图标类，导致 Unicode 编码覆盖。 |

任意两套库的任一解析项重复，都必须拒绝保存；`priority` 不能解决这类冲突。

例如以下两套 CSS 即使基础类和字体族不同，也不得同时配置：

```css
.a-iconfont { font-family: "font-a"; }
.icon-home::before { content: "\e001"; }

.b-iconfont { font-family: "font-b"; }
.icon-home::before { content: "\e002"; }
```

因为后加载的 `.icon-home::before` 会覆盖前者的 `content`，但页面元素可能仍使用 `font-a`，从而显示错误图标或空白。

后端应限制可请求的 CSS 域名、下载体积和超时，并缓存解析结果，避免开放 URL 带来 SSRF 风险。

## 五、消费项目接入

1.2.0 业务综合端从公共包使用加载器；系统全局配置仍由核心服务管理：

```ts
import { applyIconfontSources, setCssCdn } from '@fxft/aura-web-kit/browser/iconfont';
import type { IconfontSource } from '@fxft/aura-web-kit/browser/iconfont';
```

启动时从核心全局配置读取 `iconfontSources` 后调用：

```ts
await applyIconfontSources(iconfontSources);
setCssCdn();
```

图标选择使用 `@fxft/aura-ui` 的 `AuraIconSelector` / `AuraBusinessIconPicker`；需要字体类名读取时核对 `@fxft/aura-web-kit/browser/iconfont-list`。不得在业务项目中复制加载器或扫描器。

禁止以下写法：

```ts
// 禁止：业务项目自行加载原始阿里 CSS
const link = document.createElement('link');
link.href = '//at.alicdn.com/t/c/font_xxx.css';
document.head.appendChild(link);
```

业务自行加载会绕过核心冲突检查，与全局配置重复注入，最终导致图标覆盖不可控。

## 六、验证

完成配置后至少验证：

- 字体库管理页能解析并展示字体族、基础类和图标前缀。
- 重复字体族、基础类或图标前缀时，保存接口返回明确错误。
- 独立运行和模块联邦消费两种模式下，框架图标与业务图标均正常显示。
- 浏览器 Network 中同一 CSS 未被业务与核心重复加载；控制台没有字体库冲突或字体资源 404。
