# 样式、布局与静态资源规范

## 一、页面高度链路

业务页面处于 `aura-core` 布局内容区，禁止直接使用 `height: 100vh` 抢占整个浏览器高度。标准页面使用 Flex 占满路由内容区：

```vue
<template>
	<div class="layout-padding">
		<div class="layout-padding-auto layout-padding-view page-content">
			<section class="query-panel">...</section>
			<section class="content-panel">
				<div class="toolbar">...</div>
				<div class="table-wrap">...</div>
				<Pagination v-bind="state.pagination" />
			</section>
		</div>
	</div>
</template>

<style scoped lang="scss">
.page-content {
	display: flex;
	flex-direction: column;
	gap: 16px;
	min-height: 0;
}

.content-panel,
.table-wrap {
	display: flex;
	flex: 1;
	min-height: 0;
}

.content-panel {
	flex-direction: column;
}

.table-wrap :deep(.el-table) {
	flex: 1;
}
</style>
```

`layout-padding` 与 `layout-padding-auto layout-padding-view` 是框架统一的父级和次级容器；业务页面不得重新定义这些类。页面自身的 Flex、间距和滚动约束应添加到业务类（如 `page-content`）上。

Flex 子项需要滚动时通常必须设置 `min-height: 0`；不要通过固定像素高度适配不同分辨率。

## 二、滚动区域

- 普通内容区域需要滚动时统一使用 Element Plus `el-scrollbar`，不得使用 `overflow: auto`、`overflow: scroll`、`overflow-y-auto`、`overflow-auto` 等原生 CSS 或 Tailwind 滚动实现。
- 查询区、工具栏和分页应放在 `el-scrollbar` 外保持固定；滚动容器及其 Flex 父级设置 `min-height: 0`。
- `el-table`、`el-tree`、`el-select` 等已有内置滚动能力的 Element Plus 组件，优先使用组件公开的 `height`、`max-height` 或自身滚动能力，不额外套 `el-scrollbar`。
- 第三方组件内部滚动、虚拟列表、地图或视频 SDK 容器确实无法使用 `el-scrollbar` 时，可以保留原生滚动，但必须在代码附近用中文注释说明组件限制和作用边界，并在交付中列出。

```vue
<section class="content-panel">
	<header class="toolbar">...</header>
	<el-scrollbar class="content-scrollbar">
		<div class="content-list">...</div>
	</el-scrollbar>
	<Pagination v-bind="state.pagination" />
</section>
```

```scss
.content-panel,
.content-scrollbar {
	min-height: 0;
}

.content-scrollbar {
	flex: 1;
}
```

## 三、主题和颜色

后台主布局和主题运行时由 `aura-core/theme-core` 提供。模块联邦（综合端）启动时通过 `ensureAuraCoreFrameworkStyles()` 从 `aura-core` 的 manifest 精确加载标准主题 expose，业务项目不维护本地 `src/theme-core`，也不手工插入核心主题样式链接。

### 主题变量目录与选型顺序

主题运行时已有颜色变量按以下顺序选用：先使用 `--el-*`；其语义无法满足布局主题时使用 `--next-*`；前两者均无对应语义时使用 `--fxft-*`。不得因方便而重复硬编码主题、文字、背景或边框颜色。

| 分组 | 现有变量 | 含义与使用场景 |
| --- | --- | --- |
| Element Plus 品牌与状态色 | `--el-color-primary`、`--el-color-success`、`--el-color-warning`、`--el-color-danger`、`--el-color-error`、`--el-color-info` | 通用主操作、成功、警告、危险/错误、信息状态的文字、图标、边框和按钮颜色。 |
| Element Plus 明暗阶 | `--el-color-{type}-light-1` ～ `--el-color-{type}-light-9`、`--el-color-{type}-dark-2`、`--el-color-{type}-rgb` | 弱强调背景、悬浮态、选中态、深色态和需要 RGB 通道的透明叠加；`type` 为上述状态色名称。 |
| Element Plus 文本 | `--el-text-color-primary`、`--el-text-color-regular`、`--el-text-color-secondary`、`--el-text-color-placeholder`、`--el-text-color-disabled` | 标题和关键内容、常规正文、辅助说明、输入占位、不可用内容。 |
| Element Plus 表面与填充 | `--el-bg-color`、`--el-bg-color-page`、`--el-bg-color-overlay`、`--el-fill-color`、`--el-fill-color-light`、`--el-fill-color-lighter`、`--el-fill-color-blank` | 卡片、页面、浮层、控件底色与弱填充；优先用于业务页面的通用表面颜色。 |
| Element Plus 边框与组件语义 | `--el-border-color`、`--el-border-color-light`、`--el-border-color-lighter`、`--el-border-color-extra-light`、`--el-border-color-hover`、`--el-input-*-color`、`--el-table-*-color`、`--el-mask-color` | 分隔线、卡片/表格边框、控件交互边框、输入框、表格和遮罩的已有组件语义。 |
| aura-core 布局变量 | `--next-color-white`、`--next-color-black`、`--next-color-{success|warning|danger|info}`、`--next-color-*-lighter`、`--next-color-dark-hover` | 核心布局中的基础色、状态色、弱强调色和深色悬浮态。 |
| aura-core 布局表面与文字 | `--next-bg-main-color`、`--next-bg-color`、`--next-border-color`、`--next-border-color-light`、`--next-text-color`、`--next-text-color-regular`、`--next-text-color-placeholder` | 页面主背景、布局区域、旧布局边框及旧布局文本；当 Element Plus 通用语义无法表达布局主题时使用。 |
| aura-core 菜单与设置面板 | `--next-color-menu-hover`、`--next-color-user-hover`、`--next-color-seting-main`、`--next-color-seting-aside`、`--next-color-seting-header` | 菜单/用户区悬浮态和主题设置面板的现有布局语义。 |
| FXFT 公司 UI 规范语义 | `--fxft-text-disabled`、`--fxft-text-inverse`、`--fxft-fill-strong`、`--fxft-bg-page`、`--fxft-bg-input`、`--fxft-bg-input-disabled`、`--fxft-bg-table-header`、`--fxft-border-short`、`--fxft-border-long` | 公司 UI 规范中的禁用/反白文字、强填充、页面/输入/表头背景及短/长边框语义。 |
| FXFT 扩展交互与兼容色板 | `--fxft-color-accent`、`--fxft-color-accent-positive`、`--fxft-color-interactive-hover`、`--fxft-color-interactive-highlight`、`--fxft-color-{type}`、`--fxft-color-{type}-rgb`、`--fxft-color-{type}-light-1` ～ `--fxft-color-{type}-light-9`、`--fxft-color-{type}-dark-2`、`--fxft-menu-active-color`、`--fxft-menu-hover-text-color` | 公司 UI 规范的强调、正向点缀、交互态，以及 Element Plus 色板和菜单状态的 FXFT 兼容别名。 |

透明主题背景基于已有背景变量派生，不写死白色或固定主题色：

```scss
.transparent-card {
	background: color-mix(in srgb, var(--el-bg-color) 70%, transparent);
	border-color: var(--el-border-color-light);
}
```

业务页面正常使用 Element Plus 组件公开的 props。未获用户明确要求时，不得新增或修改 `.el-*`、`:deep(.el-*)`、`--el-*` 重写及全局 Element Plus 样式覆盖。

使用 Element Plus 和模块联邦（综合端）主题变量：

```scss
.order-card {
	color: var(--el-text-color-primary);
	background: var(--el-bg-color);
	border: 1px solid var(--el-border-color-light);
}

.order-card:hover {
	border-color: var(--el-color-primary);
}
```

禁止把主题色、正文色、边框色大面积硬编码为 `#409eff`、`#333`、`#ddd`。业务状态色可按设计使用，但应集中定义并同时适配暗色背景。

### 视觉层级、焦点与动效

- 用户可见页面在实现前先明确业务对象、目标用户和页面单一目标，再将颜色、文字层级、间距、圆角、边框/阴影、状态色和动效映射到已有主题变量；不要用随机装饰制造“高级感”。
- 左侧强调条只用于表达真实的选中、状态、分类或项目既有设计语义，不得批量套在页面标题、筛选区、卡片、内容分组和弹窗标题上。同页已有一处时，新增前必须确认它增加了新的信息含义。
- 普通信息层级优先通过字号与字重、留白、网格与对齐、分隔、局部背景和克制图标建立；去掉装饰后不影响理解的视觉元素应删除。
- 自定义按钮、卡片和可点击区域必须提供清晰的 `:focus-visible` 状态，不能只依赖鼠标 hover；键盘操作顺序应与视觉顺序一致。
- 非必要动效必须尊重 `prefers-reduced-motion: reduce`。动效用于说明状态变化和空间关系，不使用持续晃动、夸张位移或大面积阴影作为默认 hover 效果。
- 页面完成后在真实浏览器中检查明暗主题、响应式、键盘焦点、错误/空态、重复模板感和低动效表现。

## 四、表格统一样式

```ts
const state = reactive<BasicTableProps>({
	pageList: getOrderPage,
	tableAlign: {
		name: 'left',
		amount: 'right',
	},
});

const { tableStyle } = useTable(state);
```

```vue
<el-table
	:cell-style="tableStyle.cellStyle"
	:header-cell-style="tableStyle.headerCellStyle"
>
</el-table>
```

`useTable` 默认居中，`tableAlign` 以 `el-table-column` 的 `prop` 为键覆盖单列。不要在每个页面重复实现表头背景和对齐回调。

## 五、模块联邦样式

远程运行不会加载提供方 `index.html`，因此：

- 页面自身 CSS 必须随 expose 出现在 `mf-manifest.json`。
- Tailwind 通过标准 `./styles/moduleFederationTailwind.ts` expose 加载。
- PostCSS 和 Tailwind 根节点必须使用当前 `remoteName` 对应 scope。
- 远程 Tailwind 样式入口不引入完整 Preflight，避免重置宿主和 Element Plus 控件。
- 框架 PostCSS 插件会为只有边框宽度或颜色的 Tailwind 规则补充 `border-style: solid`，业务不再手写全局边框基础规则。
- 宿主不扫描远程源码生成 Tailwind。
- 业务全局选择器必须谨慎，禁止无 scope 重置 `body`、`html`、`.el-*`。

订单综合端示例：

```js
const REMOTE_SCOPE = '.aura-mf-remote-scope.aura-mf-remote-aura-order-web';
```

```css
.aura-mf-remote-scope.aura-mf-remote-aura-order-web {
	width: 100%;
	height: 100%;
	min-height: 100%;
}
```

`postcss.config.js` 中的远程 scope、选择器转换和边框兼容插件属于框架保护区。业务只同步项目身份对应的 scope 值，不删除插件、不改变处理顺序，也不绕过 scope 输出全局 Tailwind 样式。

## 六、import 静态资源

图片、SVG、视频等 import 结果在用于模板、配置或动态样式前必须转换：

```ts
import orderBannerSource from '/@/assets/images/order/banner.png';
import { getStaticResourceUrl } from '/@/hooks/moduleFederation';

const orderBanner = getStaticResourceUrl(orderBannerSource);
```

```vue
<img :src="orderBanner" alt="订单中心" />
```

动态背景：

```ts
const bannerStyle = {
	backgroundImage: `url(${getStaticResourceUrl(orderBannerSource)})`,
};
```

错误：

```vue
<img src="/assets/images/order/banner.png" alt="订单中心" />
```

远程运行时错误写法会请求宿主 `/assets`，造成 404 或加载到同名错误资源。

## 七、public 资源

Worker、播放器脚本、decoder、独立字体等 public 根路径资源使用：

```ts
import { getPublicResourceUrl } from '/@/hooks/moduleFederation';

const workerUrl = getPublicResourceUrl('/workers/order-worker.js');
const decoderPath = getPublicResourceUrl('/jessibucaPro/decoder-pro-simd.js');
```

外部绝对 URL、`data:`、`blob:` 等特殊协议不会补远程前缀，但生产代码仍不得写死临时域名、IP或凭证。

CSS `url()` 优先使用可由 Vite 重写的相对资源；需要运行时远程前缀时改用组件动态样式。

## 八、常见容器

- 查询表格页：查询区固定、表格区 `flex: 1`、分页置底。
- 左树右表页：左右面板自身 `min-width: 0; min-height: 0`，避免内容撑破。
- 弹窗和抽屉：普通内容区使用 `el-scrollbar`，底部操作区固定；不让整个页面背景滚动。
- 看板页：使用网格和比例布局，图表在容器尺寸变化后调用组件公开的 resize 能力。
- 地图和视频：父容器必须有明确可用高度，隐藏后显示的多路视频另见视频专项。

## 九、检查命令

```bash
rg "from '/@/assets|/assets/|url\('/" src
rg "pigxNexus|auraIotbusWeb|https?://[0-9]" src
rg "@tailwind base|appendTailwindBorderStyle|REMOTE_SCOPE" src/styles postcss.config.js
rg -n "overflow(-[xy])?\\s*:\\s*(auto|scroll)|overflow-(auto|scroll)|overflow-[xy]-(auto|scroll)" src
```

第一条用于发现候选项；资源 import 本身允许存在，但展示位置必须经过转换。
