# aura-web-develop

PIGX 模块联邦（综合端）业务开发规范技能。

当前版本：`1.2.18`（2026-09-03）。

`1.2.18` 补充正式业务页面的主动确认流程：主动询问是否同步创建菜单/按钮权限及是否配置远程菜单；不配置远程菜单时撤销本次新增业务 expose，同时保留框架标准 expose 和其他实际依赖。

## 权威入口

- 技能执行入口：`SKILL.md`
- 版本标识：`VERSION`
- 最新版正式规范：`knowledge/PIGX前端开发规范/README.md`
- 消息反馈硬约束：`references/message-feedback-guidelines.md`
- 代码注释规范：`references/code-comment-guidelines.md`
- 三阶段检查：`checklists/`

最新版正式规范来自 `aura-pigx-cli/src/template/nexus/docs/PIGX前端开发规范`。技能中的历史模板不得覆盖该规范。

## 使用说明

可以直接描述业务需求触发技能，也可以显式使用：

```text
$aura-web-develop <你的业务需求>
```

建议在提示词中说明页面类型、业务字段、接口范围、权限要求、菜单策略和验收方式。新增正式业务页面时，技能会主动询问两项决策：

- 是否同步创建/更新正式菜单和按钮权限；
- 是否配置远程菜单。若不配置远程菜单，会撤销本次新增的业务 expose（例如 `src/hooks/moduleFederation.ts` 对应项），但保留框架标准 expose 和其他实际依赖。

### 提示词示例

- `新增设备 CRUD 页面，包含设备名称、类型、状态查询，创建正式菜单和新增、编辑、删除按钮权限。`
- `新增订单详情页，只改前端，不同步创建后台菜单和按钮权限。`
- `新增告警列表页，菜单和按钮权限请先生成清单，等我确认后再写入管理端。`
- `新增库存页面，不配置远程菜单；如果已有业务 expose，请同步撤销本次新增的对应配置。`
- `新增 aura-order-web 远程页面，配置远程菜单，先完成模块联邦基线检查，修改后复检。`
- `新增设备地图页，使用 2D 地图能力，完成后用 Codex 内置浏览器自查。`
- `新增四路监控视频页面，支持全屏、PTZ 和拖拽换位；先检查当前组件库版本。`

管理端实际写入仍需在主动询问后获得用户确认，并提供目标环境、运行时 Token、租户和父菜单定位信息；凭据仅在运行时使用，不写入文件或日志。

## 补充硬约束

1. 业务消息只能使用 `import { useMessage, useMessageBox } from '/@/hooks/message';`，不得直接引入 Element Plus Message/MessageBox 或自行实现消息组件。
2. 新增和修改代码必须同步遵循中文注释规范，重点说明 Why、契约、边界、副作用和生命周期。
3. 页面涉及模块联邦时，其配置由本技能主导实现，并在修改前后调用 `aura-module-federation-check` 做基线和复检；是否配置远程菜单需单独确认。不配置远程菜单时撤销本次新增的业务 expose（如 `src/hooks/moduleFederation.ts` 对应项），保留框架标准 expose 和其他实际依赖。
4. 新业务正式页面、菜单入口或操作按钮需要按 `references/admin-menu-permission-workflow.md` 生成菜单权限清单；命中时主动询问是否同步创建/更新菜单和按钮权限，以及是否配置远程菜单。未指定权限编码时按“业务标识 + 功能动作”生成，并检查不同业务是否占用同一编码。同一业务多处 `v-auth` 属于正常复用；仅在用户确认同步、再次确认写入且具备运行时凭据时写入管理端。
5. 使用方式与提示词示例见 [`USAGE.md`](USAGE.md)。
6. 所有业务表单必须使用 `/@/hooks/form` 的 `validateForm/resetForm/clearFormValidate`，不得在页面中重复实现校验、重置和历史校验清理。
7. 用户可见业务页面统一调用 `$frontend-design` 做视觉方向、令牌和实现后自评；纯后端、隐藏页和组件修复不触发。
8. 调用任意其它技能前检查当前可用技能列表；缺失时提示用途、影响和安装选择，未经明确授权不得安装。
9. 前端页面开发完成后明确使用 Codex 内置浏览器验证真实页面；可访问原型同步走查，用户明确意见优先，未明确项输出走查结果供用户决策。
10. 仅供弹窗使用的远程数据在公开 `open` 流程中加载；父页只传操作上下文，空态不重复顶部已有主操作。
11. 普通业务 UI 按“综合端全局组件/Hooks → Element Plus → 页面私有组件”选型，不把 `@fxft/ui-plus` 作为通用优先复用层级；进入 Element Plus 选型阶段时先通过 Codex 内置浏览器查阅官方组件总览和候选组件文档，确无合适组件或组合方案时才自行实现，并记录不适用原因。
