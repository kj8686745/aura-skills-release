# aura-base-backend-development 任务路由与执行指南

仅在当前任务需要选择规范章节、交付格式或执行步骤时读取本文件。先按任务命中条目，再打开对应正文、正反例或清单；不要把本文件的路由表当成规范正文。

大文档按规则标题定位正文和正反例；输出被截断时，用行区间补读命中段，不通过全文重读或扩大输出预算补齐无关内容。

数据库、Entity、Mapper、SQL、迁移和事务属于本后端开发技能的数据库模块；本仓库不提供独立数据库安装技能，使用者统一从 `aura-base-backend-development` 进入。

## 执行与交付

开发前按[前置检查](../checklists/pre-development.md)确认范围；实现时按[实现检查](../checklists/implementation.md)核对分层与能力接入；交付前按[验证检查](../checklists/validation.md)记录实际证据。这些清单是任务提示，具体规则和正反例仍以命中的规范正文为准。

选路以本次实际变更为准，不以类名或脚本零候选结束：改父 POM/BOM 时读取上表依赖管理条款并核对受影响消费者；改缓存、连接、线程或销毁行为时读取共享资源及服务生命周期条款，检查复合操作和正在使用/创建的资源；改错误传播或流式行为时读取失败恢复与相关契约。工具的 `reviewFocus` 仅提供这些方向的范围线索。每类命中至少能说明采用的规则、实际改动及对应测试/未验证边界；已经读过且仍适用的正文不重复加载。

先从需求确定接口入口、业务处理、数据访问及外部副作用中实际涉及的环节，再核对项目现有实现、依赖和 AURA 版本。按命中的规范章节与正反例实现；公共能力从[能力使用索引](能力使用索引.md)选本包模块，不另外安装或调用能力技能。接口契约变化默认同步已有模块文档，缺少时创建并纳入项目文档入口；可用时组合接口技能，不另外生成一份文档。存量项目只盘点当前改动影响范围，不强制先进行整项目审查。

存量接口改造必须先建立可追溯的现状清单：至少识别受影响的 Controller、DTO、响应封装、分页类型、异常映射、认证/租户上下文、网关路径、调用方及文档。在明确影响范围和兼容策略后，按授权范围调整 DTO、适配层、分页转换、错误映射及后端实现；已有审查报告可作为输入，但不是必备前置步骤。静态搜索不能证明运行时契约已一致。

对外 API 的实现与内部 API 一样核对 `R<T>` 的 `code/msg/data`、`CommonConstants.SUCCESS=200` 和统一分页对象；调用方身份、签名、数据裁剪可以不同，响应包络和分页类型不能因此分叉。接入外部服务时，先核实被调用方契约，再检查适配层与 Controller 实际返回；不根据历史样例推断其响应码。涉及现有调用方的契约变更按已识别的兼容范围实施，不直接修改未知调用方正在使用的接口。

代码层次应有真实职责。按 `AURA-BASE-STRUCT-002/003/004` 与 `AURA-BASE-BE-001/002` 复核新增的 DTO、Service、Mapper、端口和包：没有当前契约、调用方或明确扩展职责的占位类型不应生成；任务要求保留的未接线端口应说明状态，不得写成已接入能力。

完成后针对改动路径检查正常、错误及适用的权限、事务和并发边界；按项目实际运行静态检查、构建与研发自测。交付说明分别写清代码完成、构建、自测和联调的真实状态，不以其中一种结果替代另一种。

本技能不定义框架公共包内部实现，也不加载内部治理、评分或旧 `BASE-xx` 生成产物。规范与项目版本不匹配，或关键接口、权限、租户与事务边界无法确定时，列出待确认点，不猜测实现。
