# 数据库操作模板

本模板用于数据库层的重复工程结构生成。脚本只根据明确的字段清单生成文件，不推断业务字段、索引、租户范围或迁移策略；业务规则、权限、事务和复杂 SQL 仍由开发者按数据库操作与事务路由确认。

## 字段清单

自增主键在字段清单中使用 autoIncrement:true，脚本会生成 IdType.AUTO；数据库下划线字段默认转换为 Java 小驼峰，并生成 TableField 映射。项目已核实使用 AURA BaseEntity 时，使用 EntityMode AuraBaseEntity 并明确提供基础实体字段，脚本会继承而不是重复生成。

将字段写成 JSON 文件，每个字段至少包含：

```json
[
  {"name":"id","javaType":"Long","sqlType":"BIGINT","nullable":false,"primaryKey":true,"autoIncrement":true},
  {"name":"name","javaType":"String","sqlType":"VARCHAR(100)","nullable":false},
  {"name":"device_status","javaName":"deviceStatus","javaType":"String","sqlType":"VARCHAR(32)","nullable":false}
]
```

允许的 `javaType`：`Long`、`Integer`、`String`、`Boolean`、`BigDecimal`、`LocalDate`、`LocalDateTime`、`Instant`。数据库字段名只能使用小写字母、数字和下划线；`javaName` 可选，省略时按下划线转小驼峰生成；必须有且只有一个主键字段。

## 生成内容

```text
src/main/java/<package>/entity/<Entity>.java
src/main/java/<package>/mapper/<Entity>Mapper.java
src/main/resources/db/migration/<MigrationVersion>__create_<table>.sql
```

脚本默认不生成 Service、Controller、DTO 或空 XML。需要复杂查询时，开发者再按实际 Mapper 方法和 SQL 结果映射增加 XML，并沿调用链补齐事务、数据范围和接口文档。

## 命令

```powershell
./scripts/prepare-database-module.ps1 `
  -ProjectPath '<项目根>' `
  -ModulePath 'demo-service' `
  -PackageName 'com.example.device' `
  -EntityName 'Device' `
  -TableName 'device' `
  -FieldJson '<临时目录>/device-fields.json' `
  -MigrationVersion 'V1' `
  -Mode Plan
```

当需求已经明确为简单等值查询时，可额外提供查询定义；脚本只支持受控字段、等值条件、固定排序和可选限制，不根据字段名称猜测业务查询：

```json
[
  {
    "name":"selectByTenantAndDevice",
    "conditions":[
      {"field":"tenant_id","parameterName":"tenantId"},
      {"field":"device_id","parameterName":"deviceId"}
    ],
    "orderBy":"updated_at",
    "direction":"DESC"
  }
]
```

执行时增加 `-QueryJson '<临时目录>/queries.json'`。脚本会在 Mapper 中生成带参数绑定的 `@Select` 方法；`conditions` 用于表达多个等值条件，必须覆盖租户、组织等数据范围字段。多表关联、复杂条件、聚合和动态查询必须人工编写 Mapper/XML，并按数据访问规范复核。

确认字段、表约束和迁移策略后，将 `Plan` 改为 `Apply`。脚本不会覆盖已有文件；已有文件内容不一致时返回 `blocked`，必须由开发者人工合并。脚本只生成确定的持久化骨架，不猜测项目的基础实体、逻辑删除、租户字段或索引策略。

脚本默认生成独立 Entity。项目已核实使用 `net.fxft.aura.common.data.model.BaseEntity` 时，再传入 `-EntityMode AuraBaseEntity`；字段清单必须包含 `id`、`createBy`、`updateBy`、`createTime`、`updateTime`、`delFlag`，脚本会继承基础实体且不重复声明这些字段。没有核实公共实体版本时不能使用该模式。

生成后必须继续核对：

- Entity 是否使用项目真实的基础实体、主键和逻辑删除能力；
- Mapper 是否使用项目公共数据入口；
- SQL 是否包含必要的租户、组织、唯一约束和索引；
- Service 是否负责事务和业务规则，未把 SQL 写入 Service；
- 迁移是否能回滚或明确不可逆边界；
- 正常读写、约束失败和事务回滚是否真实验证。

存量模块或生成后复核可先执行 `check-database-module.ps1`。该脚本只检查 Entity、Mapper/Repository、迁移文件、命名映射和 Service 直连数据库的静态线索；输出 `review_required` 只表示需要人工复核，不代表已经确认违规。详细 JSON 写入临时目录后只提取 `scanned` 和 `findings` 摘要，不将完整结果带入会话。

## 查询开发

Agent 从需求和现有实现确认事实，不要求研发另填一套表单：

- 结果单位是主记录、子明细还是聚合结果，使用哪个查询模型与响应契约。
- 条件来自请求还是可信租户/组织上下文，空授权集合不得扩大为全部数据。
- 页大小、深页、固定排序白名单及唯一键兜底；ORM 分页与显式 SQL 不重复叠加。
- count 与列表是否共用范围与过滤口径，一对多是否应使用 EXISTS 过滤，或先分页主记录再批量读取子表，避免 N+1。
- 数据库版本、代表性数据及参数、已有索引与执行计划；没有实测不宣称性能已优化。

实现仍沿查询 DTO/可信上下文 → Service → Mapper/XML → 响应转换，不将 SQL 放入 Service。参数值绑定，动态标识符只允许受控映射；代码示例与正反例读取[数据规范第四节](standards/01-基础编码规范/08-数据访问事务数据表达与生命周期规范/01-数据访问事务与生命周期.md#四查询与结构演进开发示例)，此处不复制另一份规范。

验证同主记录多子项、相同排序值、跨租户数据、空授权、最后一页及适用的并发变化。契约变化时同步已有模块接口文档，不按每条 SQL 拆文档。

## 结构演进

沿用项目迁移工具、目录和版本。新增表可复用字段生成器；存量改造不覆盖 Entity/Mapper 或修改已应用迁移。围绕已有模块主文档核对：

1. **扩展**：真实方言、类型、可空策略及新旧实例兼容。
2. **回填**：转换来源、不可转换值、有界批次、幂等、提交后的检查点和失败续接。
3. **切换**：数量、关键值、空值/重复、关联约束和消费者读写，不仅验证 SQL 返回成功。
4. **收紧与清理**：数据满足要求、旧写入退出后才收紧约束；先核实锁、表重写和恢复，不用 DROP 或重部署旧代码冒充数据回滚。

这是思考顺序，不强制拆成四份文件或四次发布。结构演进与回填正反例统一读取[数据规范第四节](standards/01-基础编码规范/08-数据访问事务数据表达与生命周期规范/01-数据访问事务与生命周期.md#四查询与结构演进开发示例)。本工具不连接或修改真实数据库。

## 查询与迁移候选检查

在 PowerShell 中直接调用，只传本次文件，结果归入项目现有过程目录：

```powershell
./scripts/inspect-database-changes.ps1 `
  -ProjectPath '<项目根>' `
  -FilePath @('device/src/main/resources/mapper/DeviceMapper.xml',
              'device/src/main/resources/db/migration/V12__add_location.sql') `
  -Dialect PostgreSQL `
  -OutputPath 'docs/临时验证物料/数据库开发/查询迁移候选.json' -Json
```

脚本不执行 SQL、不读取配置凭据、不展开 include/动态分支，也不解析 Java 查询构造器。输出只有路径、摘要和候选说明，不回显 SQL 正文；XML 行号定位 SQL 节点起始行。`0` 表示未发现支持的确定模式，`2` 为候选/未解析待核对，`1` 为输入或解析错误，都不能替代业务合规或迁移运行验证。完整 JSON 留作证据，只把 summary 和当前命中项带回会话。
