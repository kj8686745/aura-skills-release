# 网关与流量治理能力包

**能力包编号**：AURA-CAP-COMMON-TRAFFIC  
**所属能力域**：通用工具类  
**当前源码依据**：`aura-core-common` `dev@4a2a1f1`；网关工程示例为 `aura-core-gateway` `dev@5ef887d`。接入项目须核对实际依赖与部署版本。

## 1. 能力定位

本能力包帮助接入方识别 AURA 已提供的路由加载、版本流量选择和服务调用保护能力，并据此完成网关或业务服务的接入。它解决“请求去哪里、版本流量落到哪类实例、过载或下游故障如何返回”的问题，不代替认证、授权、租户校验和业务异常处理。

## 2. 可以使用的能力

| 场景 | 已有能力 | 使用后可得到的结果 |
| --- | --- | --- |
| 网关路由变更 | `aura-common-gateway` 提供 Redis 路由定义读取、缓存刷新监听和路由健康检查 | 具备路由重载机制；保存或删除后的实际生效结果须由接入网关核对，健康检查只判断路由键是否存在 |
| 网关灰度 | `aura-common-gateway` 按 `VERSION` 请求头与服务实例元数据选择实例 | 命中版本时选择同版本实例；无匹配版本时按现有实现回退到可用实例 |
| 服务间灰度 | `aura-common-gray` 传播 Web 请求或非 Web 上下文中的 `VERSION`，并提供负载均衡选择 | Feign 调用可继续携带已确定的版本标识；当前匹配实现依赖 Nacos 实例类型，无匹配版本时回退到普通选择 |
| Servlet 接口与 Feign 保护 | `aura-common-sentinel` 提供阻断处理、请求来源解析和 Feign 构建扩展 | 配好保护规则后，Servlet 阻断可返回 HTTP 429 和统一失败体；Feign 保护按项目启用条件生效 |
| 网关限流键 | 网关工程已有按客户端 IP 提取 Key 的 `KeyResolver` 示例 | 可作为网关限流规则的一个输入，但仅存在该 Bean 不等于已启用限流 |

路由管理入口、灰度标识来源、保护规则和回退结果由实际接入项目确定。当前网关工程有自身的路由与灰度实现，不能仅凭公共模块存在就判定网关已使用该模块。本包只说明已实现的组件能力；不能把示例直接解释成项目已经发布了路由管理接口、灰度控制台或限流规则。
