# 基础通用支撑能力包工具使用说明

本文件补充[通用工具目录](./06-通用工具目录.md)中的高频工具用法。工具只解决通用技术问题，业务规则、权限判断和事务边界仍由基础业务开发能力包负责。

## 1. Web 请求工具

### 适用场景

在过滤器、异常处理器或基础适配层读取当前请求、响应、Cookie、客户端地址或输出统一 JSON。

### 推荐用法

```java
HttpServletRequest request = WebUtils.getRequest();
String clientIp = WebUtils.getIP(request);
String traceCookie = WebUtils.getCookieVal(request, "traceId");
```

### 使用边界

- Service 不通过请求上下文获取业务参数；
- 当前用户使用安全上下文工具获取，不使用请求参数冒充；
- 代理地址只在可信代理链配置下使用；
- Cookie、Header 和 IP 不能直接作为权限依据；
- `renderJson` 仅用于异常处理器或特殊响应边界，Controller 正常返回使用 `R<T>`。

## 2. 参数与消息工具

### 参数判断

`ParamUtil` 提供字符串、集合、数组、数字和 Map 的基础空值判断、UUID 和格式处理。其数字版 `isBlank(Number)` 将 `0` 视为空值；当 `0` 是合法业务值时，应显式判断 `null`，不能直接使用该方法。

```java
if (ParamUtil.isBlank(command.getDeviceCode())) {
    throw new BusinessException("设备编码不能为空");
}
```

字段必填、长度、格式和范围优先使用 DTO 校验注解；`ParamUtil` 用于通用适配和复杂条件判断，不能替代完整参数校验。

### 消息读取

`MsgUtils` 用于从统一消息源读取业务提示和安全提示：

```java
String message = MsgUtils.getMessage("device.config.notFound");
```

消息 code 应集中维护，不能在业务中散落重复文本；消息工具不能用于拼接 SQL、权限编码或缓存 key。

### 校验分组

`ValidGroup.Insert` 与 `ValidGroup.Update` 适用于同一字段在新增、修改时存在不同校验要求的 DTO：

```java
@NotNull(groups = ValidGroup.Update.class)
private Long id;
```

Controller 必须启用对应分组校验；仅在 DTO 上声明分组并不会自动执行校验。新增、修改对象差异明显时，优先使用独立 DTO，避免分组过多。

## 3. 树形数据工具

### 适用场景

菜单、组织、区域、目录等数据已按平面列表查询完成，需要构建树形返回结构时使用 `BuildTreeUtils`。

```java
List<Tree<Long>> tree = BuildTreeUtils.buildTree(
        rows,
        row -> row.getId(),
        row -> row.getParentId(),
        row -> row.getName(),
        row -> row.getSort(),
        List.of("code", "type"));
```

### 使用边界

- `id` 和 `parentId` 类型必须一致；
- 根节点、孤儿节点、重复 ID 和循环父子关系应在 Service 中先校验；
- 大数据量树应评估内存和返回大小；
- 树工具只负责结构转换，不负责查询权限和租户过滤；
- 扩展字段名称必须来自后端固定清单，不能由前端随意读取内部字段。

## 4. 数据范围工具

### 适用场景

需要按照部门、用户或自定义范围限制查询结果时，使用统一数据范围能力。

```java
DataScope scope = DataScope.of()
        .deptIds(authorizedDeptIds)
        .only(false);
```

`DataScope` 是当前框架提供的数据范围查询参数对象，不是注解。Mapper 如何消费它必须按对应项目的数据权限 Mapper 契约接入；业务代码不得自行把 `dept_id`、`create_by` 或用户输入拼接成 SQL。

### 使用边界

- 数据范围必须与租户边界同时成立；
- 列表、详情、统计和导出必须使用一致的数据范围；
- `skip` 或忽略数据范围只能用于受控的系统管理场景，并记录原因；
- 数据范围工具不能代替接口权限，权限和数据范围是两层判断；
- Mapper 查询必须保留逻辑删除和必要业务条件。

## 5. 租户键解析

`TenantKeyStrResolver` 为缓存、审计和其他公共键增加当前租户标识：

```java
String tenantKey = tenantKeyResolver.extract("device:detail:" + deviceId, ":");
```

使用时必须确认当前租户已经建立；后台跨租户任务应通过受控租户上下文逐租户执行，不能使用空租户值生成全局 key。

后台任务需要临时切换租户时，优先使用 `TenantBroker.runAs`：

```java
TenantBroker.runAs(tenantId, currentTenant -> {
    deviceService.refreshForTenant(currentTenant);
});
```

该方法结束时恢复先前租户上下文；调用方仍须明确任务自己的权限和租户来源，不能把请求中的租户 ID 直接当成授权结果。

## 6. 公共对象转换

### 转换规则

- DTO 转 Entity：只复制允许写入的业务字段；
- Entity 转 VO：只输出接口需要字段；
- 列表和分页转换使用统一转换器；
- 转换器不访问数据库、不获取当前用户、不发送消息；
- 敏感字段在转换阶段过滤，不能依赖前端隐藏。

```java
DeviceConfig entity = deviceConvert.toEntity(command);
DeviceView view = deviceConvert.toView(entity);
```

## 7. 分页对象与序列化

分页接口使用项目统一分页对象。分页序列化由公共配置处理，业务代码不自行改变外层字段或创建第二套分页结构。

```java
Page<DeviceEntity> page = new Page<>(query.getCurrent(), query.getSize());
Page<DeviceEntity> result = mapper.selectPage(page, wrapper);
return result.convert(deviceConvert::toView);
```

分页大小上限、排序白名单、租户和数据范围必须在 Service/数据访问边界明确。

## 8. Spring 上下文工具

`SpringContextHolder` 只用于框架无法通过构造器注入的扩展边界，例如公共审计、序列化或自动配置适配。普通业务类必须使用构造器注入：

```java
@Service
@RequiredArgsConstructor
public class DeviceService {
    private final DeviceConfigMapper mapper;
}
```

禁止用上下文工具隐藏依赖、绕过模块边界或在静态方法中编排业务。

## 9. 公共常量与错误语义

`CommonConstants`、`SecurityConstants`、`PaginationConstants`、`CacheConstants` 和 `ServiceNameConstants` 提供公共值。使用前先核对常量的适用范围：服务名用于服务调用，安全常量用于认证边界，分页常量用于分页默认值，不能把不同用途的常量混作业务枚举。

`ErrorCodes` 与统一异常类型用于返回可识别的失败语义。业务模块新增错误码时，应按接口规范登记并保持稳定；数据库异常、栈信息和配置值不得原样返回客户端。

## 10. 工具选型顺序

```text
识别业务问题
→ 查找通用工具目录
→ 判断工具是否属于业务直接入口
→ 阅读所属能力的使用规范
→ 在 Controller/Service/数据访问边界使用
→ 处理权限、租户、事务和异常
→ 补充正反例和自测
```

工具目录中的类名不等于全部可调用 API。自动配置、过滤器、拦截器、序列化器和上下文持有器，必须按对应能力包的公开用法接入。文件存储不在本文件展开，按任务读取[文件存储能力说明](./08-文件存储能力说明.md)。
