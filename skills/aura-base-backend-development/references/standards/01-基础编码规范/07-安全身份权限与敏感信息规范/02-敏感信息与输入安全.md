# AURA（天玑）基础编码规范：敏感信息与输入安全

<!-- 规范编号：BASE-07 -->
<!-- 规范版本：0.3.0-draft -->
<!-- 模板版本：基础编码规范模板 v3 -->

**适用对象**：使用 AURA 开展业务应用、服务、工具和平台工程开发的团队和开发人员

**规范目标**：限制敏感信息的使用与传播，并在外部输入进入业务边界前完成校验。

**边界说明**：本规范规定业务项目的使用方式，不描述密钥系统或内部安全组件的实现细节。接口字段和错误响应遵循 BASE-05。

## 一、敏感信息

### AURA-BASE-SEC-008：敏感信息不得进入日志和普通响应

**必要性**：禁止

**为什么需要**：日志和普通响应通常会被更多人员、系统和环境保存，限制敏感信息可以降低泄露和扩散影响。

Token、密码、私钥、密钥材料和完整认证载荷不得写入日志、错误信息、普通业务响应或调试输出。业务确需返回身份证件等敏感字段时，只能通过有明确权限和用途的专用响应返回所需最小字段；列表、事件和普通展示优先脱敏。统一认证接口按其公开契约返回令牌，不属于业务接口自行回传凭据的理由。


**正确写法**：日志记录脱敏用户标识、业务对象和结果；普通业务响应只返回必要字段，受控的专用响应按权限和用途返回敏感字段。

**错误写法**：把完整 Token、密码或认证载荷写入日志和业务响应，或在普通列表中无条件返回完整证件信息。

**判断要点 / 验证方式**：执行认证、异常和调试路径并扫描日志及响应内容。

### AURA-BASE-SEC-009：敏感数据必须遵循最小使用范围

**必要性**：必须

**为什么需要**：只在必要的业务边界使用敏感数据，可以减少暴露面、降低误用风险并简化脱敏和审计。

代码只读取完成当前业务所需的敏感字段，数据传递、缓存、事件和导出不得无条件携带完整敏感对象。


**正确写法**：查询只读取当前业务需要的敏感字段，事件只传递必要摘要。

**错误写法**：把完整用户对象、证件字段和密钥信息复制到缓存、事件和导出文件。

**判断要点 / 验证方式**：对字段访问、序列化、缓存和事件载荷进行最小字段检查。

### AURA-BASE-SEC-010：敏感数据的存储、传输和删除边界必须明确

**必要性**：必须

**为什么需要**：明确生命周期可以避免敏感数据在缓存、临时文件、消息和备份中无限留存或被无保护传输。

保存敏感数据前必须明确用途、保存位置、访问范围、保留期限和删除方式。业务模块不得把凭据写入 HTTP 业务 URL、页面跳转链接、前端源码或无保护的临时文件。既有实时连接若由框架握手协议使用查询参数传递凭据，只能调用框架封装入口，业务模块不得复制该做法或将完整连接地址写入日志、分享链接。

**正确写法**：敏感数据只按必要用途保存；普通 HTTP 请求通过公共请求层传递认证，实时连接通过框架既有封装接入，不记录包含凭据的连接地址。

**错误写法**：把 Token 拼在业务 HTTP URL 或页面跳转链接上，或在业务组件里自行拼装实时握手凭据。

**判断要点 / 验证方式**：检查存储、传输、缓存和到期删除路径。

## 二、输入与安全边界

### AURA-BASE-SEC-011：外部输入必须先验证再使用

**必要性**：必须

**为什么需要**：输入校验是阻断非法参数、注入内容和越权条件进入业务、数据及外部调用边界的第一道控制。

请求参数、文件名、排序字段、过滤条件、回调地址和外部消息都属于不可信输入，必须经过类型、格式、范围和业务边界校验后才能进入查询、命令或外部调用。输入校验不能替代参数化查询、排序字段白名单和服务端授权。


**正确写法**：排序字段映射到白名单，查询值使用参数绑定；回调地址、文件名和外部消息按业务允许范围校验后再使用。

**错误写法**：把请求中的 `sort`、SQL 片段或回调 URL 直接拼接使用。

**判断要点 / 验证方式**：使用非法类型、越界值和恶意字符串测试输入边界。

### AURA-BASE-SEC-012：权限、租户和业务校验不得被批量入口绕过

**必要性**：禁止

**为什么需要**：批量、导入、导出和异步入口往往绕开页面交互，必须复用同等校验才能保持安全边界一致。

用户触发的批量、导入、导出和异步任务，必须在提交及结果访问时遵守与单条操作一致的身份、权限和数据范围。定时任务和消息消费若由系统触发，应明确受控执行主体及允许的租户、资源范围，不得借用任意用户或跳过数据隔离。

**正确写法**：用户发起导出时校验其数据范围，下载结果时再次校验；系统定时任务使用明确的执行主体和处理范围。

**错误写法**：批量入口为了效率跳过权限或数据范围判断。

**判断要点 / 验证方式**：使用跨租户数据验证批量和结果访问；对系统任务核对服务身份、目标租户和处理范围。

### AURA-BASE-SEC-017：SQL数据值必须绑定且动态结构必须白名单映射

**必要性**：必须

请求、消息、文件、数据库已有文本及外部系统返回的值进入 SQL 时必须使用参数绑定，不能因先前经过校验或已入库就拼接。MyBatis 值使用 `#{value}` 或受控 Wrapper 值参数，JDBC 使用 PreparedStatement/命名参数。动态表名、列名、排序方向不能作为普通值占位绑定，应由服务端固定映射选择，未知选项拒绝；禁止业务客户端提供完整 SQL、WHERE、ORDER BY 或可执行表达式。

`${}`、Wrapper 的 `last/apply/inSql/exists` 等可携带 SQL 结构的入口和存储过程内部动态 SQL 必须沿来源核对；仅模板固定或已证明为服务端允许的结构时才使用。`apply` 等入口支持的真实参数占位按所用版本核实，不能把字符串插值冒充绑定。转义引号、关键词黑名单、WAF和仅使用ORM均不能替代参数化。运行账号使用业务必要权限，不因防注入就赋予数据库管理员、任意文件或命令执行权限。

**为什么需要**：输入即使合法格式、来自内部调用或数据库，也可能在字符串拼接时改变查询语义。

**正确写法**：`WHERE tenant_id = #{tenantId} AND id = #{id}`；排序由 `createdAt → t.create_time` 等固定映射产生，方向仅选择ASC/DESC；查询值始终绑定。

**错误写法**：`"WHERE name='" + name + "'"`、`${request.sort}`、`wrapper.last(request.sql)`；先替换单引号再拼接用户条件；认为 `ORDER BY #{column}` 等价于安全的动态列选择。

**判断要点 / 验证方式**：从输入沿Service、Mapper/XML和实际SQL核对值与结构。以字面引号、注释标记、非法排序和空范围验证结果不扩大、非法结构被拒、写入无副作用；不连接生产执行破坏性载荷。候选扫描不能证明注入存在或不存在。

### AURA-BASE-SEC-018：业务文件功能禁止暴露服务器目录管理能力

**必要性**：禁止

业务界面及配套 API 只能管理已授权的业务文件、附件及虚拟业务目录，不得提供服务器文件系统目录浏览、任意路径读取/下载、上传覆盖、创建目录、移动、删除、权限修改或文件执行能力。管理员按钮、登录校验和传入根目录白名单不能把这类主机文件管理变成普通业务能力；该禁令也适用于隐藏接口、对外API和AI工具。

使用不透明业务文件ID关联已登记存储对象及租户/资源权限；原名仅作安全展示，不直接当目标路径，bucket、对象键和存储根由服务端决定。虚拟业务文件夹是业务元数据，不映射为任意主机目录。确需主机维护时走独立运维体系，不借业务附件页面扩展；文件存储的底层运维端点不得直接接入业务页面。

服务内部必须使用本地暂存时，由服务端生成名称、固定允许根并验证真实目标处于该根；对路径解码、绝对/相对路径、盘符/UNC、符号链接/junction及归档条目实施边界控制。单纯 `normalize()` 或字符串前缀检查不足以证明实际文件操作未越界；同时限制底层进程的文件权限。不得回传服务器真实路径、配置、密钥或日志目录。

**为什么需要**：目录管理会把业务文件功能扩大成主机读写入口，可能泄露配置、覆盖程序或为恶意文件执行提供条件。

**正确写法**：页面提交附件ID，服务端校验业务对象与租户后从登记对象键读取；业务目录树只表示用户获准的文档分类。生成导出使用受控临时目录，页面只见任务和文件标识。

**错误写法**：`GET /files?path=/` 返回服务器目录；`download(path)`、`delete(path)`直接操作请求路径；后台管理员可上传替换jar、脚本或配置；把本地文件浏览器或 `OssEndpoint` 直接挂到业务菜单。

**判断要点 / 验证方式**：核对前端入口及所有文件API参数、ID到对象映射和底层读写；隔离样本验证目录穿越、绝对路径、链接越界、越租户ID及伪造对象键被拒，固定根外的哨兵文件不被读取/改变。只有业务ID或路径校验代码存在不代表已生效。

### AURA-BASE-SEC-019：上传与预览必须限制恶意内容和执行能力

**必要性**：必须

上传只允许业务必要的类型、大小和数量，结合扩展名、内容特征及适用解析器核验，不信任客户端Content-Type、双重后缀或原文件名。普通附件功能拒绝服务端可执行脚本、启动文件及可改变解释器行为的配置；上传内容不得被当作命令、类、插件或模板代码执行。

文件存储与应用程序、配置、凭据及可执行Web根隔离；上传区不具备执行/解释权限，应用进程仅取得必要读写权限。文档、图片等解析或转换在受限环境中完成；压缩包先校验条目路径、文件数、展开体积、嵌套和资源预算，不自动解压到程序或任意目录。

对外公开、预览或自动解析的外部文件，技术方案必须明确恶意文件检测及适用的隔离/内容净化方式和失败策略。已决定需扫描的文件在检测通过前保持隔离，不可因扫描超时或服务不可用自动发布；检测失败/未知与明确发现恶意分别处理。没有扫描能力时记录接入缺口与可安全实施范围，不假称框架自带杀毒，不将涉密文件送往未经允许的公共扫描服务。仅私有保存且不解析/预览的场景可按风险明确采用的控制，不把某个杀毒产品设为所有项目强制依赖。

下载设置安全文件名和准确类型；不适合内联的内容按附件交付。HTML/SVG等主动内容预览按隔离来源、沙箱及最小权限设计，不能以应用同源高权限直接呈现上传脚本。杀毒通过不保证绝对安全，不能替代授权、隔离或禁止执行。

**为什么需要**：恶意文件可利用解析器、主动内容、路径覆盖或资源消耗影响服务器和其他使用者，问题不只是不正确的后缀。

**正确写法**：外部文档先入隔离存储，完成规定检测后才能进入受控预览；类型不符、超量或路径越界直接拒绝，解析超时终止并保留受控清理记录。

**错误写法**：允许任意格式上传到静态Web根并直接访问；把 `.jsp/.sh/.exe` 改名后认为安全；解压条目能覆盖配置；扫描失败时仍签发公开下载地址；声称对象存储写入成功就完成了恶意文件检测。

**判断要点 / 验证方式**：隔离环境使用无害的类型不符、双后缀、路径穿越和超预算归档样本，验证拒绝、扫描失败/未知、预览隔离、下载头及零执行；不引入真实病毒执行。无安全检测服务的集成证据时保留未验证。

### AURA-BASE-SEC-020：禁止爬取第三方网站数据，外部数据必须通过授权渠道获取

**必要性**：禁止

**适用范围**：前后端、服务、脚本、定时任务、数据导入与 AI 工具中的第三方业务数据获取，包括地图、瓦片、POI、地址、轨迹、内容和业务记录等。

严禁使用自动化脚本、爬虫程序、浏览器自动化、未公开接口或其他技术手段爬取第三方网站数据。不得将抓取逻辑包装为同步任务、缓存预热、数据补全、导入工具、代理服务或 AI Agent 来绕过此限制，也不得以登录账号、页面公开可见、robots 允许或技术上能够访问作为数据使用授权。

业务需要外部数据时，必须通过向数据持有方正式购买、使用其官方 API/SDK 等合规途径获取，并遵守服务条款与实际授权范围。正式购买后由持有方交付的数据文件可按约定导入；使用官方 SDK 渲染地图或在授权范围内调用数据接口不属于禁止的爬取行为。不得因使用了官方 API、持有 Key 或已经付款，就默认可以任意批量获取、长期缓存、离线打包、训练模型或再次分发。

接入前在已有技术设计或模块说明中写明数据提供方、官方获取渠道及授权依据、业务用途和影响实现的使用限制；涉及限流配额、缓存期限、存储、导出或转供时，按实际条款落实，不另建重复登记表。不能确认渠道或授权范围时，停止受影响的数据获取和相关实现，说明缺口，转为官方接入、正式采购或自有测试数据；其他独立工作可继续。

**为什么需要**：第三方数据的可访问性不等于可使用、复制或转供；把非法获取的数据纳入系统、缓存或模型会使风险沿后续交付扩散。

**正确写法**：设备选址使用已授权的地图组件和官方地理编码 API，按配额和允许的缓存期限调用；将正式购买并交付的 POI 文件按许可范围导入。开发自测使用自有或获准的样本，不为补测试数据执行真实抓取。

**错误写法**：用 Playwright/Selenium 自动翻页提取地图网站 POI；分析浏览器网络请求后循环调用未公开接口；枚举瓦片地址制作离线包；让 AI、代理服务或第三方代采执行相同抓取；持有地图 Key 就将数据长期存库并向其他客户分发。

**判断要点 / 验证方式**：在当前项目范围内沿需求/设计 → 数据来源与授权依据 → 页面、任务、脚本或 Client/Adapter 的调用 → 存储、缓存与导出路径核对。确认第三方网站抓取实现及用途时记录具体偏差；只有爬虫库、HTTP 请求、分页循环或浏览器依赖时不能直接判违规，须区分官方 API、授权 SDK、自有系统及本地自测。授权材料缺失记为未证实并指出待补项，不据此宣称合规；审查不执行真实抓取，不扩大到外部 SDK 内部或第三方网站探测。

## 三、典型使用示例：受控导出与文件访问

**场景目标**：用户发起数据导出时只读取必要字段，校验输入和数据范围，不把敏感信息写入日志；生成文件后在下载入口再次校验权限。

**输入条件**：请求包含时间范围、排序字段和导出过滤条件；导出结果包含部分敏感字段；导出可能异步执行并生成临时文件。

**正确结构**：

```text
提交导出
  → 校验时间范围、排序字段和过滤值
  → 从可信身份取得租户与数据范围
  → 查询最小字段集合并脱敏
  → 创建有期限的导出任务
  → 下载入口重新校验身份、租户、资源归属和权限
  → 到期清理临时文件与任务结果
```

日志只记录任务标识、脱敏主体、范围摘要和处理结果，不记录 Token、完整用户对象、文件内容或完整查询条件。排序字段通过白名单映射，查询值使用参数绑定，回调地址和文件名不得直接来自未校验输入。

**错误结构**：把请求中的 SQL 片段直接拼接到查询中，将完整用户对象写入导出文件和日志，或只在页面按钮上校验权限后允许通过任务 ID 下载。

**验证步骤与预期结果**：

1. 提交非法排序字段、越界时间范围、恶意文件名和超出范围的过滤值，预期在进入查询或外部调用前失败。
2. 使用跨租户用户访问导出任务和下载地址，预期提交、查询和下载均被拒绝。
3. 扫描应用日志、普通响应和导出文件，预期不出现完整 Token、密码、私钥或无用途敏感字段。
4. 等待任务结果过期并检查清理行为，预期临时文件和敏感结果按保留期限删除。

## 四、开发者自检

- 敏感字段是否只在必要边界读取、传递和保存；
- 日志、响应、URL、缓存、事件和临时文件是否完成脱敏或最小化；
- 所有外部输入是否有类型、范围、白名单和业务校验；
- 批量、导出、异步提交和结果访问是否复用身份、权限和租户校验；
- 敏感结果是否有明确的保留、过期和删除方式。
