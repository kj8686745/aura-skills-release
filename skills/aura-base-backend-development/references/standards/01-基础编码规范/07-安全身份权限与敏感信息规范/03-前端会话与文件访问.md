# AURA（天玑）基础编码规范：前端会话与文件访问

<!-- 规范编号：BASE-07 -->
<!-- 规范版本：0.1.0-draft -->

**适用对象**：使用 AURA 开展业务应用、服务、工具和平台工程开发的团队和开发人员

**规范目标**：约束前端会话使用、文件与导出访问，以及会话失效后的服务端阻断。

**边界说明**：本规范规定业务项目的使用方式，不描述统一认证平台或文件服务的内部实现。接口字段和错误响应遵循 BASE-05。

## 一、前端与会话使用

### AURA-BASE-SEC-013：前端只保存完成会话所需的最小信息

**必要性**：必须

**为什么需要**：减少前端保存的身份和敏感数据，可以降低浏览器泄露、跨页面暴露和终端被接管后的影响。

业务页面和组件必须使用框架提供的登录、刷新、会话存储和退出能力，不得另建一套 Token 缓存，也不得将令牌、私钥或完整敏感对象复制到页面状态、业务 `localStorage`、URL 或日志。会话失效、退出和刷新时，应由框架会话入口清理或更新本地状态；业务数据缓存须同步失效。


**正确写法**：页面通过公共请求层和框架会话入口访问认证状态；退出或令牌失效后清理业务缓存并返回登录流程。

**错误写法**：业务组件把框架 Token 另存一份到 `localStorage`，刷新令牌后旧副本仍能被读取。

**判断要点 / 验证方式**：检查业务代码是否另存令牌；验证退出、过期和刷新后公共会话及业务缓存的状态。

### AURA-BASE-SEC-014：前端权限状态不得伪造授权结果

**必要性**：禁止

**为什么需要**：前端权限状态只能反映服务端结果，不能被当作授权事实，否则会造成界面可见性与真实权限不一致。

前端可以隐藏不可用操作，但不能通过修改本地状态、路由参数或按钮状态获得服务端未授予的权限。失败结果必须按接口真实结果展示。

**正确写法**：前端根据服务端返回的权限状态控制按钮展示，调用接口后以服务端的未授权结果为准。

**错误写法**：修改浏览器本地权限状态或路由参数后直接认为用户已获得管理员权限。

**判断要点 / 验证方式**：篡改本地状态、路由参数和按钮状态，直接调用受保护接口，确认服务端仍执行真实授权判断。

## 二、文件访问与会话失效

### AURA-BASE-SEC-015：文件访问和导出必须重新校验权限

**必要性**：必须

**为什么需要**：文件地址和任务标识可能被复制、猜测或跨用户使用。

文件下载、预览、导出和异步结果查询必须在实际访问入口重新确认访问权，不得因为生成过文件或前端隐藏入口就视为已授权。直接访问时校验当前身份、租户、资源归属和操作权限；使用临时授权地址时，必须在签发时校验相同范围，并在访问时验证地址的资源、有效期及适用对象等已登记约束。

**正确写法**：下载入口根据当前身份核对资源归属和权限；若签发临时地址，先校验请求者权限，访问时再验证地址对应的资源、有效期和适用对象。

**错误写法**：文件名或任务 ID 能够直接换取下载内容，或只在页面按钮上做权限控制。

**判断要点 / 验证方式**：分别检查直接访问与临时地址的授权；使用其他用户、其他租户、错误资源和已过期地址访问，确认按契约拒绝并记录必要审计信息。

### AURA-BASE-SEC-016：会话失效必须阻断后续业务请求

**必要性**：必须

**为什么需要**：仅清理浏览器状态无法阻止已获取凭据继续调用接口。

令牌过期或统一认证系统已判定会话失效后，服务端必须拒绝后续受保护请求；前端清理本地状态不能替代服务端校验。主动退出、账号禁用和权限撤销的生效方式应遵循框架现行认证契约；业务要求即时撤销时，必须使用已支持的统一撤销能力，并验证服务端拒绝旧凭据，不得仅靠删除本地 Token 宣称即时失效。

**正确写法**：退出调用框架统一退出入口并清理本地状态；需要即时撤销的场景验证原凭据对受保护接口已失效，并按接口契约区分未认证与无权限。

**错误写法**：令牌已过期或已由统一认证系统撤销，后端仍接受旧凭据；要求即时撤销的业务只清理前端状态而不验证服务端行为。

**判断要点 / 验证方式**：分别测试过期、退出、禁用和权限变更后的接口、任务查询与文件访问；若场景要求即时撤销，重放原凭据核对实际生效时间，不能只看前端跳转。

## 三、典型使用示例：导出任务的前端会话与下载

**场景目标**：前端通过公共会话和请求入口发起导出，正确表达受理与完成状态；会话失效或下载权限变化时，不能仅依赖页面状态继续访问文件。

**输入条件**：页面提供导出按钮，后端返回异步任务标识；文件生成后通过受保护的下载入口或短期授权地址访问。

**正确交互**：

```text
点击导出
  → 公共请求层发送当前会话
  → 页面显示“已受理”，保存任务标识而不是 Token
  → 查询任务状态并区分处理中、成功、失败
  → 下载入口重新确认当前身份、租户和资源权限
  → 会话失效时清理业务缓存并停止轮询，回到统一登录流程
```

页面不得把 Token 复制到业务 `localStorage`、URL 或组件状态；下载地址不能因为按钮可见或任务曾经创建就视为永久授权。使用短期授权地址时，前端只按接口契约使用，不能自行延长有效期或拼接资源标识。

**错误交互**：前端把完整 Token 放入下载 URL，任务 ID 可以直接换取任意文件，或会话失效后仍继续轮询和下载，只通过跳转登录页表现“已退出”。

**验证步骤与预期结果**：

1. 正常提交导出，预期页面区分受理、处理中、成功和失败状态，并只保存任务标识。
2. 清除或撤销会话后继续轮询、查询任务和访问文件，预期服务端拒绝受保护请求，前端清理业务缓存并停止后续请求。
3. 使用其他用户、其他租户、错误任务 ID 和过期授权地址访问文件，预期下载入口拒绝访问。
4. 检查浏览器存储、URL、日志和网络请求，预期不出现业务代码复制的 Token 或完整敏感对象。

## 四、开发者自检

- 身份是否来自受信任上下文；
- 权限是否在服务端真实入口执行；
- 租户和数据范围是否覆盖查询、写入、批量、导出和异步路径；
- 敏感信息是否未进入日志、响应、URL 和普通前端存储；
- 外部输入是否经过类型、范围和业务校验；
- 服务间调用是否使用匹配的身份和最小权限；
- 会话失效和退出是否清理本地状态。
