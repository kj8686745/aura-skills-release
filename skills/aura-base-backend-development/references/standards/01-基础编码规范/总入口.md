### 工程结构、命名与项目文档分类

本类规范适用于使用 AURA 开展业务应用、服务、工具和平台工程开发的团队和开发人员，统一项目工程结构、代码命名和项目文档组织。后端、前端、接口及能力包的专项要求由对应规范补充。每条规则只在一份分类文件中定义：

| 分类 | 适用任务 |
| --- | --- |
| [工程结构与代码组织](./01-工程结构命名与项目文档规范/01-工程结构与代码组织.md) | 新建工程或模块、确定职责目录、拆分文件、抽取公共能力 |
| [命名与代码表达](./01-工程结构命名与项目文档规范/02-命名与代码表达.md) | 命名文件和代码对象、统一格式、类型、常量、注释与导入导出 |
| [项目文档与资料组织](./01-工程结构命名与项目文档规范/03-项目文档与资料组织.md) | 建立项目和模块文档入口、确定资料归属、编号、模板、链接与过程资料隔离 |

开发者应自行核对工程目录、模块边界和文件归属是否清晰；名称和代码表达是否统一；项目与模块文档入口是否唯一；正式资料、示例和过程文件是否分离；是否出现重复文件、无意义拆分或无法判断来源的临时文件。具体正反例和验证方式以命中的分类正文为准。

## 二、推荐阅读和使用顺序

```text
总则
→ 工程结构、命名与项目文档
→ 架构分层与模块边界
→ 后端或前端基础编码
→ 接口规范体系
→ 配置与构建
→ 安全权限
→ 数据处理
→ 异常与可观测性
→ 异步与外部集成
→ 运行时与资源
→ 研发自测
→ 版本变更与交付
```

业务开发任务按实际涉及的模块组合使用，不要求一次性加载全部规范正文。专项设备、消息、视频、模型和地图能力由对应能力包补充。

规范要求以本目录正文为准；按当前研发任务选读，不需通读全部模块。
