# 文件上传下载、导入导出与批处理

本模块承接后端开发任务：先选择业务场景，再复用框架入口，最后验证文件、数据和结果的完整路径。只读取当前行命中的资料；不额外安装文件技能，不把所有文件请求改成异步任务。

## 一、从需求选择实现

| 场景 | 首选路径 | 实现前核对 |
| --- | --- | --- |
| 附件上传、受控下载、删除 | 项目已接入的文件服务；本应用承担存储时复用 `FileTemplate` | 文件与业务对象/租户的关联、大小/类型、谁有权操作、输入和输出流由谁关闭 |
| 数量明确、内存与请求时长可控的Excel | `aura-common-excel` 的参数级 `@RequestExcel`、方法级 `@ResponseExcel` | 行DTO/VO、模板版本、解析错误、行数/列数上限、批量结果；不是所有表格都需要任务中心 |
| 大文件或数量不可预测的导入导出 | 复用项目已验证的任务入口、监听读取/分页写出和对象存储 | 受理与最终状态、批次提交、失败明细、取消/恢复、结果权限和清理；没有任务能力不能假称已接入 |
| 后台同步、批量修正、批量删除 | 业务用例 + 有界批次 + 现有数据库模块 | 授权范围、幂等/冲突、提交粒度、进度和可重入性；不因名为批处理而强制引入新框架 |

## 二、上传与下载：围绕业务文件操作

1. 按项目实际依赖选择远程文件服务或本地注入的 `FileTemplate`，核对公开签名、响应和错误，不在业务中另建厂商客户端。文件存储本身不替业务做资源授权。
2. 上传前校验当前身份、租户和业务对象；验证大小、允许格式及实际内容，原始文件名和Content-Type是外部输入。只改后缀或只读请求头不能证明内容可信；压缩格式还要限制展开规模。需要扫描/隔离时使用已有服务，不凭后缀宣称已扫描。
3. 服务端生成对象键，原名只作处理后的展示信息；bucket/key、磁盘路径不由请求直接决定。对象键不能代替文件ID授权，不能把任意URL当下载来源。
4. 对象写入后记录业务元数据。对象存储与数据库不是同一个本地事务：元数据失败时应按已有约定补偿对象或保留可追踪的待清理记录；补偿失败保留定位信息，不能返回已完成。
5. 下载/删除/签发临时地址前重新核对当前访问者、租户和资源。签名URL按已有能力设置用途和有效期，不当永久公共地址，不记录完整签名到日志。
6. 流式复制并明确资源归属：关闭本方法取得的输入流/对象，HTTP输出流由响应生命周期管理；输出已提交后发生异常，不再追加一份JSON成功/错误包。授权失败必须在打开/发送文件之前处理。

**可照用的控制顺序（业务伪代码，不是框架新增API）**：

```text
上传：授权 → 大小/格式/内容校验 → 受控对象键 → 公共存储写入
    → 元数据关联 → 返回现有文件契约；失败 → 补偿或可追踪清理
下载：按业务文件ID查询 → 当前身份/资源授权 → 打开公共存储流
    → 设置安全下载文件名和内容类型 → 流式输出 → 释放输入资源
```

**反例**：直接接受`../../...`路径；把上传内容整体变成byte[]后通过Feign传输不设上限；存储成功就无条件返回业务成功；任务曾经创建便永久允许下载；输出二进制后又写入`R.ok`。

## 三、导入：解析、校验与写入分别表达结果

### 受控小表格

当前已核对的参考源码为 `aura-core-common dev@e311702`：`RequestExcelArgumentResolver`返回监听器的List，并将错误列表绑定至`BindingResult`；默认监听器累积有效行与校验错误，不是有界批次写入器。目标项目仍核对自身版本，不凭注解推断大小、授权或事务已处理。

默认监听器按invoke次数计算行号，不能保证多行表头或空行策略下仍是实际文件行。使用多行表头/自定义监听器时核对解析上下文中的原始行位置并验证；默认能力不能满足时明确采用已支持的适配方式，不给现有行号字段作超出实现的保证。

下面只展示现有注解位置和错误处理分支。`DeviceImportRow`、`ImportResult`、`currentScope`和业务服务是项目自己的类型，不是框架现成API；错误映射按项目统一异常约定实现。

```java
@PostMapping("/import")
public R<ImportResult> importRows(
        @RequestExcel List<DeviceImportRow> rows, BindingResult bindingResult) {
    // 若本模块约定整单拒绝，解析错误必须在任何业务写入前处理。
    // 当前框架把错误列表作为BindingResult的target；不能只检查hasErrors()。
    // 先核对本版ErrorMessage/target契约，再通过项目错误适配器提取错误。
    var parseFailures = importErrorAdapter.from(bindingResult);
    if (!parseFailures.isEmpty()) {
        throw importErrorAdapter.toBusinessException(parseFailures);
    }
    // 服务校验行数、批内重复、数据范围与业务约束，再在明确事务边界内写入。
    return R.ok(deviceImportService.importRows(currentScope(), rows));
}
```

**正例**：原始文件有10行，2行解析失败，整单模式下返回可定位错误且零写入；部分成功模式明确返回8行成功、2行失败，不把收到的8个有效DTO当成“总共8行全部成功”。行号使用解析器的真实行号，不能拿过滤后的List索引冒充原文件行号。

**反例**：忽略BindingResult直接保存有效行；只检查`hasErrors()`而实际错误留在target中；Service逐行查库；将行DTO直接作为Entity写入；业务全部回滚后仍累加成功数。

### 大批量与提交策略

读取按批次交给业务用例，每批先做格式/重复键和权限校验、批量查关联，再执行限定范围的写入。输入流、解析器、队列、待写入列表和失败明细均有边界；不要用“分批提交”掩盖前面已经把全文件读入List。

| 业务约定 | 实现与反馈 |
| --- | --- |
| 整单成功或失败 | 小且有界时可采用单事务；任何失败后成功数为0。大文件需要整单语义时，按项目已有暂存/确认方案设计，不伪装成多个批次独立提交后还能整体回滚 |
| 允许部分成功 | 明确批次/逐行提交粒度。失败批次回滚后其中记录不得计成功；已提交批次保留，重试依据业务键/检查点，失败明细单独返回或生成受保护文件 |

恢复状态必须与实际已提交结果一致；取消/超时应停止后续批次并说明已提交部分。仅在业务已有重启恢复要求时建设持久检查点，不为有限小导入强制增加分布式协调。

## 四、导出与结果交付

小结果可用`@ResponseExcel`返回有界`List<导出VO>`；该处理器需要List，不是将全表自动变成流式分页的能力。大结果使用既有任务和可分页写入器，按稳定排序读取，不一次性组装全量List。目标项目无完整文件任务契约时先列缺口，不仅凭`@ExportMonitor`宣称下载中心可用。

下表为本轮候选公共下载入口，完整签名与适用边界见[下载任务候选入口](standards/05-能力包/01-通用工具类/04-文件任务与实时交互能力包/能力详细说明.md#2-下载任务模块与导出候选入口)。使用前先核对目标依赖确实含有相同签名；旧发布包没有这些类时，报告版本缺口，不能复制源码到业务或自动升级整个框架。

| 结果规模/列形态 | 公共入口 | 交付结果 |
| --- | --- | --- |
| 有界小结果 | `@ResponseExcel` 或项目已有文件接口 | 单个文件；必须有明确行数和内存边界 |
| 大结果但可放入一个受控 Excel | `StreamingExcelExport.job` 或 `DynamicStreamingExcelExport.job` + `@ExportMonitor` | 一个 XLSX；分页写入，批次和总行数受限 |
| 超过单个 Excel 的可读规模或需要多文件交付 | `PartitionedStreamingExcelExport.job` / `dynamicJob` + `@ExportMonitor` | 多个 XLSX 压入一个 ZIP；下载中心只创建一个任务 |

分片 ZIP 必须同时设置单文件行数、总行数和分片数量上限。ZIP 内分片使用公共方法生成的连续文件名；业务不能自行创建多个下载任务、多个对象上传流程或第二套清理逻辑。单个 Excel 的最大行数、ZIP 总大小和查询批次应按目标项目容量与接口契约确认，不能把技能示例默认值当成全公司固定值。

接入前记录公共模块坐标和来源版本：`net.fxft:aura-common-download` 的版本以目标项目 BOM/依赖管理和已发布能力包为准，不能直接复制本地 `target/classes` 或把候选版本写成正式版本。隔离验证时优先使用公司 Maven 仓库和项目实际 JDK；若 Maven 依赖或插件无法解析，可以把公共模块已编译类与其同版依赖放入隔离验证 classpath，用 `javac/java` 验证 `ExportJob`、ZIP 条目、批次和上限，但必须把这种验证标为“公共实现隔离验证”，不能替代 Maven 构建、Spring 启动或真实项目联调。

导出行模型必须使用本版FastExcel可实际读取的字段/访问方式及注解；不要仅凭Java record编译成功认定单元格已写出。验证时打开每个XLSX，核对表头、行数、字段值及跨分片连续性；只数ZIP条目不证明导出数据正确，也不证明一个ExportJob已经经过注解进入下载中心。

候选公共组件验证前，检查业务源码是否存在同包同名副本；删除副本后还须清理其旧编译产物。通过类的CodeSource或等价构建证据确认实际加载来源；使用源码联编时说明其验证范围，不能据此宣称已发布构件可用。不为使样本通过而复制公共实现到业务源码。

容量按[RUNTIME-019](standards/01-基础编码规范/11-运行时并发与资源管理规范/04-文件批处理与性能边界.md#aura-base-runtime-019接口和任务输出必须限制数据规模)计算：单文件实际数据行上限须扣除真实表头/标题占用，不能把总导出上限直接写入单工作表。当前候选已收紧单文件配置并检查实际多行表头，见[能力版本限制](standards/05-能力包/01-通用工具类/04-文件任务与实时交互能力包/能力详细说明.md#容量目标与当前候选实现的差距)；仍须核对项目真实依赖包含修正，不能在业务复制公共实现或解除限制。固定入口现阶段仅接受公开getter可读的JavaBean导出DTO，不接受record；动态表头由job创建时复制，不能依赖创建后的表头修改。

首次接入只按[配套接入顺序](standards/05-能力包/01-通用工具类/04-文件任务与实时交互能力包/能力详细说明.md#配套接入顺序)核对目标公共版本、UPMS模型/SQL、同一任务表与存储。维护扫描默认关闭，实际自动装配、唯一切面、数据源与事务生效需有宿主证据；不要把手动代理隔离测试当作完整启动或部署通过。

分页结束依赖当前reader的空页/短页约定；过滤后短页不是天然末页。动态列在请求准备阶段固定表头和字段顺序，空单元格策略与模型注解均核对实际表格库。自测至少区分空结果、批次跨分片、恰好满片、超限和写入中断，并检查资源释放；既有小样本不扩写成容量压测已通过。

`@ExportMonitor` 只负责同步/异步分流、任务、对象上传和下载中心交付；它不会把一个全量 `List` 自动变成流式分页，也不会替业务冻结查询条件和数据权限。业务必须通过稳定排序分页或 keyset 读取；结果成功前必须完成文件关闭、ZIP结束、对象上传和任务元数据关联。

1. 导出创建、执行、状态查询及下载使用明确的数据范围；异步身份来自可信提交上下文，并按项目约定处理执行/下载时权限变化，不能退为默认管理员。
2. 查询沿用数据库模块的同范围筛选与唯一排序。需要一致快照时采用目标数据库/项目已支持的方案；分页不等于天然一致快照。
3. 导出VO仅含允许公开的字段；长编号按文本表达，日期与空值按接口/模板契约。CSV/表格单元格中不可信文本可能被解释为公式，应按已选格式与库采用文本写入/安全转换并验证，不把所有数字或业务公式盲目改写。
4. 写入、flush/finish和对象存储成功、元数据关联完成后再标成功。失败生成物、过期结果、临时分片按原有生命周期清理；清理重试不能误删仍有效的业务文件。
5. 有界错误明细保留真实行号、业务标识和可处理原因，避免把整行敏感数据或数万条错误塞入响应。二进制接口契约与JSON任务状态接口分别说明，不对文件响应强套JSON包络。

**正例**：按授权范围每批读取并写出，空结果也有可读表头；超大量结果按单文件行数拆成多个 XLSX 并压缩为一个 ZIP；权限拒绝时不创建文件；中途写出失败标失败且结果不可下载。

**反例**：直接`list()`全表再注解导出；把所有结果写进一个无上限 Excel；为每个分片创建独立下载任务；敏感字段随Entity泄露；文件或ZIP还未finish就标成功；任务失败仍暴露半成品URL；分页过程中遗漏/重复却宣称全量一致。

## 五、工具与验证

先选定本次文件，再执行随包只读候选工具，不重复扫描全仓：

```powershell
./scripts/inspect-file-batch.ps1 -ProjectPath '<项目根>' -FilePath @('<Controller.java>', '<ImportService.java>') -OutputPath 'docs/临时验证物料/文件批处理/候选.json'
./scripts/select-json-summary.ps1 -InputPath '<候选.json>'
```

工具仅定位全量字节/集合读取、Excel注解和文件公开入口等线索，不生成新业务组件、不判定授权/事务/内容安全。命中后按本次任务读取真实调用链；0表示无候选的限定静态扫描完成，2表示有候选或未知，1表示输入/执行失败；均非业务合规结论。

按当前任务选择有意义的测试：超限拒绝、无权限和跨租户零副作用、伪扩展名/异常内容、元数据失败补偿、输入/输出中断释放；导入空集、失败行真实行号、批次边界、重复键、写入回滚计数；导出空结果、稳定分页、字段裁剪、公式文本、写出失败与结果权限。使用跟踪流/替身验证关闭和拒绝前不写入，数据库组件测试验证提交计数；不把这些替代真实文件服务、表格库和HTTP联调。

下载中心按已确认的任务所有权规则核验本人、他人、其他租户、过期和非成功任务；拒绝应发生在打开对象存储前。身份注入测试只证明服务端资源过滤，不证明生产认证链。错误响应核对实际公共异常处理器的HTTP状态、R失败字段和无附件头，不为使测试通过另写一套异常映射；发现公共重载或版本差异单独记录。

**脚本化范围**：当前工具提供事实盘点；固定DTO/Mapper骨架复用数据库脚本。授权策略、整单/部分成功、任务恢复和目标表格库仍是业务决策，不生成带假定权限或事务的“通用导入服务”。生成模式须基于已核实的同版公共接入模板提供。
