# 后端项目初始化

本流程用于新建或接管一个 AURA Java/Spring 后端项目。它负责后端工程的根入口、构建文件、后端源码与资源目录、项目文档入口和基础启动配置，不负责前端工程、页面、部署环境或业务功能实现。

## 适用边界

- 新建独立 Java/Spring 后端项目；
- 在既有前端或综合工程中新增后端子项目；
- 接管一个已有但缺少 AURA 后端入口、文档和构建检查的项目。

完整前后端工程、模块联邦工程或跨端工作区仍组合 `aura-base-project-engineering`；本流程不重复创建前端目录，也不虚构公司 BOM、SDK 坐标或版本。

## 初始化顺序

1. **确认真实基线**：确认项目根、Java/Spring 版本、父工程或 BOM、仓库分支、实际构建命令和已有模块；无法确认的版本保留缺口，不自行编造。
2. **建立最小工程入口**：创建实际需要的父 `pom.xml` 或 Gradle 构建文件、后端模块登记、`src/main/java`、`src/main/resources` 和启动入口；不创建未来可能使用的空 Controller、Service、Mapper、DTO 或能力目录。
3. **建立后端文档入口**：创建根 `README.md` 和根 `docs/README.md`；记录模块职责、构建命令、配置入口、启动方式和当前版本。模块文档就近放模块 `docs/`，不把接口、详细设计和部署说明混成一份。
4. **接入基础能力**：仅接入当前项目确实需要的统一响应、身份权限、数据访问、日志、异常和配置能力；依赖、配置和公开版本必须来自真实能力包或项目模板。
5. **建立启动与验证入口**：补充最小可用配置、健康/就绪入口和构建检查；敏感值只使用占位符或外部配置，不把真实凭据写入仓库。
6. **形成初始化交付**：运行 `check-backend-project-init.ps1`，再按项目实际执行构建和研发自测；分别记录工程结构、依赖解析、编译、启动和联调状态，未运行的内容不得写成通过。

## 初始化完成标准

| 检查项 | 完成要求 |
|---|---|
| 工程根与构建 | 能定位真实根入口和父工程/BOM；后端模块已登记 |
| 目录与职责 | 仅有当前职责所需的后端源码、资源和测试目录 |
| 文档 | 根 README、根 docs 入口和模块职责说明可查 |
| 配置与启动 | 配置入口、启动类和环境边界明确；无敏感值入库 |
| 能力接入 | 依赖、配置、调用与能力包公开版本可对应 |
| 验证 | 静态初始化检查通过；构建、启动、自测分别记录真实结果 |

初始化检查通过只表示结构和入口达到静态要求，不代表 Maven/Gradle 构建、服务启动、数据库连接或联调已经成功。
