# 网关与流量治理任务路由

本表仅负责选读；依赖、正反例和完成判断以[能力详细说明](../../../standards/05-能力包/01-通用工具类/07-网关与流量治理能力包/能力详细说明.md)为准。

| 研发任务 | 选读章节 | 重点核对 |
| --- | --- | --- |
| 新增、调整、删除或回滚动态路由 | 第 1、7 节 | 实际使用的路由实现、受控写入、删除完成顺序、路径匹配与回滚 |
| 开启网关灰度 | 第 3、7 节 | `gray.rule.enabled`、可信 `VERSION`、实例元数据、无匹配回退 |
| Feign 或非 Web 任务传递版本 | 第 4、7 节 | 上下文来源、Nacos 实例类型、下游请求头、实例选择、`finally` 清理 |
| 为 Servlet 接口或 Feign 调用配置保护 | 第 5、7 节 | Sentinel 规则、阻断与回退结果、恢复行为 |
| 为网关路由配置限流 | 第 6、7 节 | 限流过滤器、可信 IP/Key、阈值和拒绝结果 |
| 对外 API 自动收录到平台 | 仅读能力详细说明第 2 节 | `aura-common-core` 依赖、`aura.platform-api` 配置、`@PlatfomApi` 的 `code/version/name/requestPath`、`/openapi` 实际路径和启动上报结果 |

## 开发时

1. 先判断任务发生在网关、Servlet 接口还是 Feign 调用；不要把这三处的保护配置视为一项已自动启用的能力。
2. 路由变更先区分公共模块与目标网关实际使用的实现，确定服务发现名、匹配范围和受控写入入口；保存、删除和回滚均按目标网关的实际路由结果验证，不能把刷新消息或路由健康状态当作生效证明。
3. 灰度先确定可信版本来源、实例 `VERSION` 元数据和回退需求。现有选择器在指定版本无实例时会回退到普通实例，不能承诺严格隔离。
4. 非 Web Feign 调用使用版本上下文时，在 `finally` 清理；Web 请求头进入灰度前应由可信入口校验或重写。服务间灰度版本匹配分支依赖 Nacos 实例类型，非 Nacos 服务发现须先确认兼容性。
5. Sentinel 的 Servlet 阻断、Feign 扩展与网关 WebFlux 限流分别核对实际规则和返回。依赖或 `KeyResolver` 存在不等于阈值已生效。
6. 任务涉及平台 API 自动收录时，只读取能力详细说明第 2 节：确认 `net.fxft:aura-common-core`、`aura.platform-api` 配置、`@PlatfomApi` 四项元数据以及 `/openapi` 路径和启动上报证据；不要因此加载第 1、3～7 节。

## 边界

本模块不创建路由管理 API、不修改网关或公共模块内部实现，不把未经运行验证的限流、灰度、熔断或平台 API 自动收录写成已启用。需要严格版本隔离、外部灰度资格判断或项目特定回退时，先依据当前项目契约确定方案。
