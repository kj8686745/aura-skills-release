# 任务与调度任务路由

本表仅用于按任务选读；具体配置、代码示例、边界与完成判断以[能力详细说明](../../../standards/05-能力包/01-通用工具类/08-任务与调度能力包/能力详细说明.md)为准。

涉及周期执行时先读[定时任务与调度规范](../../../standards/01-基础编码规范/10-异步任务消息与外部系统集成规范/03-定时任务与调度.md)的命中规则及正反例；从项目设计的模块卡片、8.1 权限和8.2任务方案承接。已有项目调度约定直接复用，缺少影响实现的触发/窗口/范围/重试决定时集中确认，不自动把所有任务改成同一调度器。

开发先明确业务窗口和稳定业务键，再实现薄 Handler→Service→Repository/副作用→结果映射。区分系统服务身份与请求身份，参数不是授权；同窗口重复和多实例按实际业务选择幂等、原子认领或互斥，不固定上分布式锁。共享锁/租约使用时核对持有者、过期与旧执行者写回；部分失败、漏跑、超时、补跑和停用按设计落地，不捕获后伪报成功。业务自测与真实注册/触发分开记录。

默认选型按已确认边界直接采用：需统一启停、人工补跑、失败重试或多实例治理的业务任务优先现有 XXL-JOB；仅本进程状态维护且允许每实例运行可用 Scheduled。已有明确设计复用，不反复询问该默认政策；真正改变业务窗口、执行范围或恢复语义的缺失决定才集中确认。

## 开发时

1. 核对业务项目使用的 AURA 版本、`aura-common-job` 依赖、`DiscoveryClient` 和现有执行器启用方式；不同版本先对照实际源码，不照搬候选示例。
2. 新任务使用 Spring Bean 的无参 `@XxlJob` 方法，JobHandler 名与调度中心一致，通过 `XxlJobHelper.getJobParam()` 获取输入；业务处理下沉 Service。
3. 需要按租户执行、处理重复触发或跨系统副作用时，按基础编码规范 `BASE-07/08/10/11` 处理业务边界；不能把调度参数当成已授权租户，也不能把执行器配置当成业务幂等或跨系统事务。
4. Handler 正常返回前检查业务结果；Service 返回部分失败时，依据业务成功判据显式标记失败，不把调度成功当成批次全部成功。
5. 分别检查 Bean 创建、调度中心注册、一次真实触发和业务结果；未运行的环节明确写为未验证，不宣称任务已可用。

## 边界

项目选择 Spring `@Scheduled` 时，核对是否启用调度、时区、固定延迟/频率、实例数量和实际线程池/重叠行为；仅本进程维护可明确每实例运行。不要引入XXL依赖证明本地任务合规，不把 @Scheduled 当成共享数据任务的集群唯一保证。存量替代方案按设计及实际影响核对，不为纯局部改动强制全项目迁移。

消息消费、文件生成和普通接口仍由各自能力包处理。本模块不修改公共模块内部实现，不携带内部治理、评分或发布流程。项目缺少调度中心、无法确认启用入口或版本不一致时，应给出所缺条件和可验证动作，不编造框架 API。
