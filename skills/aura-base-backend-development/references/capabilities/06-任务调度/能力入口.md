# 任务与调度能力使用


先读[任务能力包入口](../../standards/05-能力包/01-通用工具类/08-任务与调度能力包/总入口.md)和[能力清单](../../standards/05-能力包/01-通用工具类/08-任务与调度能力包/能力清单与边界.md)确认任务边界，再在[研发任务导航](references/研发任务导航.md)中检索调度、任务或能力编号，选读详细说明。同版公开规范和当前项目实际依赖是能力事实源，不全文加载导航或能力正文，不能只凭本使用模块推断项目已启用调度。

## 任务路由与执行指南

确认任务命中本能力包后，先在[任务路由与执行指南](references/任务路由.md)中检索能力名称或编号，再读取对应能力条目、前置条件和验证要求。只打开当前任务需要的说明，不整包加载路由或能力正文。

## 边界

项目版本、能力入口、关键配置或运行结果无法从规范和项目确定时，列出缺口并停止推断。本使用模块不修改公共模块内部实现，不把未验证的能力写成已启用。


## 使用边界与输入


本模块按“执行器前置条件—任务处理器—业务 Service—重复与租户边界—调度结果—运行验证”组织。调度中心成功只代表触发链路成功，不代表业务批次全部完成。

普通同步接口、消息消费和文件生成仍由各自技能负责，避免任务技能越界承担业务实现。

接入执行器、开发定时任务或处理重试与租户边界时，提供项目配置和调度目标；也可显式调用 `$aura-base-backend-development`。

示例：`$aura-base-backend-development 判断订单统计任务能否接入现有 XXL-JOB 执行器，并说明缺少哪些运行条件。`

技能按任务读取能力资料；配置、注册和真实执行须分别验证，不能用代码编译代替调度成功。
