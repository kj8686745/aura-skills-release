# 数据与事务基础设施能力使用


先读[能力包入口](../../standards/05-能力包/01-通用工具类/05-数据与事务基础设施能力包/总入口.md)和[能力清单](../../standards/05-能力包/01-通用工具类/05-数据与事务基础设施能力包/能力清单与边界.md)，再在[研发任务导航](references/研发任务导航.md)中检索能力名称或编号，只读取命中的详细章节。同版公开规范与当前项目实际依赖是能力事实源，不全文加载导航或能力正文。

## 任务路由与执行指南

确认任务命中本能力包后，先在[任务路由与执行指南](references/任务路由.md)中检索能力名称或编号，再读取对应能力条目、前置条件和验证要求。只打开当前任务需要的说明，不整包加载路由或能力正文。

## 边界

项目版本、能力入口、关键配置或运行结果无法从规范和项目确定时，列出缺口并停止推断。本使用模块不修改公共模块内部实现，不把未验证的能力写成已启用。


## 使用边界与输入


本模块先区分普通数据访问与专项基础设施，再分别核对启用条件、配置、代理边界、唯一性和运行证据。它提供能力可接入性判断，不替代项目级数据模型、事务协议或公共模块改造。

动态数据源、分布式编号和跨服务事务各自按命中章节读取，避免把一个专项能力的前置条件误套到其他能力上。

需要接入动态数据源或 Snowflake 分布式编号，或核对跨服务事务模块是否已有可用契约时，说明当前依赖、配置和参与服务；也可显式调用 `$aura-base-backend-development`。

示例：`$aura-base-backend-development 核对当前服务能否使用动态数据源，并给出选择数据源时的真实配置和失败边界。`

普通单库 CRUD 和本地事务的共同规则使用基础编码规范，AURA 数据访问入口可用基础业务开发技能；本模块不把依赖存在解释为能力已运行成功。
