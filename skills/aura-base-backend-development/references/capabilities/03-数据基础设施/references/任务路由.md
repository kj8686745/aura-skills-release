# aura-base-backend-development 任务路由与执行指南

仅在当前任务命中本能力包时读取本文件。先确认项目版本、已启用模块和任务边界，再打开命中的能力条目；不要把整份能力包说明一次性加载。

## 开发时

1. 先判断是否仅需普通数据访问与本地事务；若是，共同规则回到基础编码规范，需要 AURA 数据访问入口时再查基础业务开发能力包，不增加本包依赖。
2. 动态数据源任务核对项目是否已启用、主数据源与配置表是否可用、目标名称是否已注册，再在可经 Spring 代理调用的 Service 边界选择数据源；不依据未经校验的请求值创建或切换连接。
3. 业务编号任务先确认唯一性、格式、节点编号分配和故障策略。Snowflake 示例只说明取号 API；若项目加载 `SequenceAutoConfiguration`，还须核对启动期间的序列表访问与建表行为。Redis/DB 构建器不能把未传递到取号链路的参数当成已生效配置。
4. 跨服务事务任务按基础规范划定参与方和一致性要求。本包只提供当前模块状态和缺口，不提供业务接入方案；没有匹配的项目级契约与回滚证据时，不生成声称可用的事务实现。
5. 分别报告已核对的源码事实、已编译的项目配置和已运行的结果；依赖存在不等于能力运行成功。

## 边界

本模块不修改公共模块内部实现，也不把内部治理或审查材料交给业务使用者。项目版本与候选规范不一致时，先核对当前源码，不照搬入口或推断兼容性。
