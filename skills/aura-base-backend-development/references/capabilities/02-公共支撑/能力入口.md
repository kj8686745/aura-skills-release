# 基础通用支撑能力包使用模块


能力事实与接入方式以链接的同版能力包正文为准；共同研发规则以基础编码规范正文为准。能力包编号只定位接入要点，不作为项目必须选用该能力的依据。

## 任务选择

先在[能力包入口](../../standards/05-能力包/01-通用工具类/03-基础通用支撑能力包/01-总入口.md)和[能力地图](../../standards/05-能力包/01-通用工具类/03-基础通用支撑能力包/02-能力清单与边界.md)确认任务确需本包，再在[研发任务导航](references/研发任务导航.md)中检索能力名称或编号，只读取命中的接入要点和示例。不要全文加载导航或能力包正文。数据库建模、Mapper、Service 分层及事务的共同要求以基础编码规范为准；选用 AURA 数据访问等入口时，再用 `aura-base-backend-development` 查接入组合。本使用模块只补充命中的公共能力用法。
## 任务路由与执行指南

先确认任务命中基础通用支撑能力，再读取[任务路由与执行指南](references/任务路由.md)中的对应接入要点、检查清单和示例。只打开命中的能力文档；数据库建模、Mapper、Service 分层及事务要求回到基础编码规范，公共包内部实现不在本使用模块范围。

## 执行边界

项目版本、能力入口、关键配置或失败行为无法从规范和项目确定时，列出缺口并停止推断。本使用模块不制定新规范、不决定能力发布状态，也不读取内部治理资料。


## 使用边界与输入


本模块按公共能力分流，先定位能力清单，再读取对应能力说明、配置、示例和边界。基础编码规范负责通用研发约束，能力文档负责框架已经提供什么以及业务如何接入，二者不混写。

文件存储、签名 URL 和可选 `/oss/*` 端点必须分别核对实际实现、权限、租户、元数据和失败补偿；能力依赖存在不等于项目运行成功。

业务需要统一响应、当前用户、权限、租户、缓存、日志、Feign 或文件存储等公共能力时，描述项目版本与具体业务场景；也可显式调用 `$aura-base-backend-development`。

示例：`$aura-base-backend-development 为当前设备详情接口选择已提供的用户上下文、租户和缓存能力，并说明接入条件。`

技能只选用已公开且项目实际具备的能力；接入要点和示例按任务读取随包能力文档，共同研发规则仍以基础编码规范为准。文件存储任务需同时说明实现类型、配置来源、业务文件关联和访问权限，不得把 `/oss/*` 端点或签名 URL 默认当作对外能力。
