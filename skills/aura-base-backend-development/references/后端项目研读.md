# 后端项目研读与接入摘要

## 适用场景

首次接入已有后端项目、接手陌生模块、开始改码前需要快速了解项目结构时使用。它是开发前置的项目理解工具，不是全项目规范审查，不替代详细设计，也不自动判断项目合规。

## 推荐顺序

1. 阅读项目根 `README`、`docs` 总入口和模块说明；
2. 确认 Maven/Gradle 构建入口、模块关系和启动方式；
3. 阅读 `SpringBootApplication`、配置入口和模块启动类；
4. 按 `Controller → Service → DAO/Mapper → 外部 Client` 研读实际调用链；
5. 对需要改动的模块，再读取对应规范、能力包、接口文档和技术详细设计。

## 摘要内容

研读摘要只包含：

- 项目和模块说明文件路径、标题和短摘要；
- 构建文件路径和类型；
- 启动类、Controller、Service、DAO/Mapper、配置类的路径与类名；
- 类级注释、`@description` 或现有模块说明的短文本；
- 未发现 README、启动类、构建入口或类级注释时的研读缺口；
- 推荐阅读顺序和未解析边界。

普通 Java 类没有框架注解时仍保留在 `codeEntries`，角色为 `other`。`javaClasses` 表示已识别的文件级类型摘要数；`annotatedJava` 保留旧口径，表示已分类为启动、接口、服务、数据访问或配置的数量，不是全部类数或注释覆盖数。

不输出完整源码、配置值、完整调用链、外部 SDK 内部实现或项目合规结论。研读模式只读，不会修改项目；需要真正补充项目内注释时，切换到注释增强模式，由 Agent 基于实际代码生成注释计划，再用脚本精确写回。

## 面向接手研发的交付

用户要求“了解项目做了什么、每个类做什么、快速接手”时，脚本画像只是定位线索，不能作为最终说明。Agent 还需读取目标调用链，在模块既有 `docs` 说明中整理：功能与边界 → 主要类职责及相对源码链接 → 关键流程与状态 → 变更入口和验证边界 → 阅读总结。模块入口链接项目总文档，项目总入口反向导航模块；已有主文档优先补全，不为每个类新建文件。

Git 提交主题单独注明基线，不直接转写为已交付能力；未提交试验功能与原版本功能分清。只读研读请求不因此改源码，明确补充注释时才同步写回；文档持久说明就近归入模块 `docs`，扫描 JSON 和执行报告归入项目约定的过程目录。正式接口、详细设计或能力包文档仍按各自模板，不用研读说明替代。

## 注释增强模式

注释增强不是把摘要复制回源码。先阅读目标类、方法和必要调用方：类说明职责与边界，方法说明输入、结果和副作用，行内注释解释分支原因、状态迁移、交叉维度或一致性限制，不逐行翻译代码。不能把“有注释”当作“解释充分”。JavaDoc 放在首个注解之前；普通实现任务顺带补充本次逻辑说明，不对整个项目强制扫描。

用户已明确要求补注释时，直接在指定范围实施和复核，不再要求逐条确认。少量改动可直接用补丁；批量插入时可生成项目相对路径、唯一 `anchor` 和注释正文组成的计划：

```json
{
  "items": [
    {
      "path": "module/src/main/java/example/DeviceService.java",
      "anchor": "    public DeviceStatistics statistics() {",
      "comment": "    /**\n     * 汇总设备总数和状态数量；只读查询，不改变设备状态。\n     */"
    }
  ]
}
```

先预览：

```powershell
./scripts/apply-backend-comment-plan.ps1 -ProjectPath '<项目根>' -PlanPath '<项目内注释计划.json>' -Json
```

复核预览后写回；已获用户授权的任务无需再次询问：

```powershell
./scripts/apply-backend-comment-plan.ps1 -ProjectPath '<项目根>' -PlanPath '<项目内注释计划.json>' -Apply -Json
```

计划放在 `<项目根>/docs/临时验证物料/后端项目注释增强/<模块>/`，默认结果写在计划同目录。脚本只接受 Java 源文件和纯注释文本，保留原换行；anchor 从完整代码行开始，JavaDoc 的 anchor 包含首个注解。已有注释跳过，位置不唯一或路径越界时报错。错误项不写入，其他成功项可能已写入，按结果逐项核对，不宣称整批原子提交。

验收必须查看实际源码 diff，确认说明符合代码、JavaDoc 位置正确且无业务代码变更；再次执行应跳过已有注释。研读脚本目前只采集类级摘要，不统计方法或分支注释，不能用其类注释计数验收注释增强。

## 执行命令

```powershell
./scripts/inspect-backend-onboarding.ps1 `
  -ProjectPath '<项目根>' `
  -ModulePath '<模块目录>' -Json
```

默认产物固定归档到：

```text
<项目根>/docs/临时验证物料/后端项目研读/<模块名>/
├─ 后端项目研读摘要.json
└─ 后端项目Git画像.md
```

也可以显式传入 `-OutputDirectory`，但目录必须位于项目根目录内。重复研读同一模块覆盖同名摘要，不新建无限过程文件。先读取摘要中的 `projectEntry`、`moduleDocumentation`、`buildEntries`、`git` 和 `codeEntries`，再按当前任务选择规范，不要把摘要 JSON 全文带入上下文。

项目位于外层 Git 仓库子目录时，`inheritedRepository=true` 表示分支和 HEAD 仅为所属仓库上下文；工作树只统计当前项目，提交与热点只取所选模块。没有模块提交记录时保持空列表，不用外层项目的提交代填。
