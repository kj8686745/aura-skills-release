# API 边界与网关路由

后端开发先确定接口边界，再选择内部接口或对外 OpenAPI 路由。两类接口共享 AURA 响应、分页、异常和服务端授权契约，但网关登记、认证方式、公开字段和交付物不同；不能因为响应结构统一就把两类入口混成同一流程。

## 共同要求

- 内部、服务间和对外 HTTP 均使用统一 `R<T>`、`CommonConstants.SUCCESS=200` 和公共分页对象；
- 服务端完成身份、租户、组织和数据权限校验，不能由前端或网关单独代替；
- 契约变化同步同一业务模块接口文档，记录 Controller 路径、网关最终路径、调用方和版本；
- 失败、超时、重复请求和外部调用结果按实际契约处理，不把下游原始响应码直接当作 AURA 响应码。

## 内部/服务间接口

- 路径、版本位置和网关改写沿项目既有内部契约，不能为了自动收录添加 `/openapi`；
- 不添加 `@PlatfomApi`，除非接口边界经确认后转为对外 OpenAPI；
- 核对内部认证、服务身份、租户上下文、调用方兼容和网关路由配置；
- 文档记录内部调用方、服务间认证、最终网关路径和失败处理，不填写对外 SDK/HMAC 收录项；
- 内部接口不因没有平台登记而判为缺陷。

## 对外 OpenAPI

- 实际公开访问路径必须以 `/openapi` 开头；
- Controller 方法使用 `@PlatfomApi`，填写 `code`、`version`、`name`、完整 `requestPath`；
- `requestPath` 与 Controller 实际映射逐字一致，路径变量正则同时记录源码转义形式和实际请求形式；
- 按网关能力说明接入自动收录配置，核对启动上报、平台目录或网关登记证据；
- 使用登记的 HMAC 客户端标识、签名版本、时间戳、nonce、防重放和签名契约；
- 对外 DTO 只暴露公开字段，禁止直接返回持久化实体、内部权限字段或租户内部标识；
- 对外 SDK、能力说明和模块接口文档必须同步版本、认证、错误、分页和兼容范围。

## 边界不明确时

只要无法确认接口是内部还是对外，先记录 `boundary=unresolved`，停止对 `/openapi`、`@PlatfomApi`、HMAC 和 SDK 收录作确定性结论；共同的响应、分页、异常和服务端授权规则仍可继续核对。不能仅凭 Controller 类名、模块名或是否经过网关猜测接口边界。
