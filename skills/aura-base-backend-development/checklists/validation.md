# 后端交付验证检查

- [ ] 已检查正常、参数错误、认证/权限拒绝和资源不存在路径。
- [ ] 对写操作已检查重复提交、事务失败、外部超时或异步受理边界（若适用）。
- [ ] 按 `AURA-BASE-SELF-002` 核对本次行为主张的实际断言：租户和初始状态检查写入值，重复操作确实执行多次并检查最终结果；只断言 `insert(any(...))` 或只执行一次，不能证明租户正确或幂等。Mock 仅支持替身边界内的结论。
- [ ] 涉及共享状态修改时，按 `AURA-BASE-BE-027` 沿“读取—判断—写入条件—影响行数/冲突结果”检查；按项目已有版本、状态条件或锁策略验证并发交错，不以事务注解或单次成功证明并发正确，不强制新增分布式锁。
- [ ] 涉及身份和租户时，按 `AURA-BASE-SEC-001/004/006` 核对认证上下文、用户与所选租户/资源的授权关系及读写范围；请求头和SQL过滤不是授权证明。复用项目已有安全链，链路未核实则标未验证，不臆造鉴权实现。
- [ ] 已运行目标项目可用的静态检查、构建和研发自测，并记录命令与结果。
- [ ] 按 `AURA-BASE-SELF-011/012` 核对测试实际发现、执行、通过及失败/中止情况和入口退出码；零测试、容器失败或全部中止不记为通过。重跑前使旧成功记录失效，依赖或编译提前失败时保留本次未完成状态。
- [ ] 接口文档、调用方、适配层和代码行为一致。
- [ ] 文件或表格任务已按命中场景核对超限/无权零副作用、输入流及临时产物清理、解析错误与原始行号、批次提交后的成功/失败计数、结果文件权限；未把小表格List当无界流式能力，未把半成品或仅受理标成功。
- [ ] 未验证项标记为“未验证”，未用静态搜索或编译通过代替运行证据。
- [ ] 实际变更均有对应的规则和验证：升级依赖核对最终解析与消费者兼容；改共享缓存、连接或线程时核对创建、使用、失效、关闭的并发交互与失败路径，不以线程安全容器代替复合操作验证。不涉及的环节跳过。
- [ ] 删除测试或更换依赖后，现行测试集合、历史试验、文档完成声明和交付链接已重新核对；明确哪次结果对应当前代码，而非累加旧测试数量。
