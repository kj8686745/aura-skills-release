# AURA 后端与接口规范审查

一次调用连续完成可执行的审查步骤，最后交付结果包，不逐项询问是否继续。版本见 `VERSION`，依据见[规范来源与验证](references/规范来源与验证.md)，使用方式见 [USAGE.md](USAGE.md)。

## 选择范围

- **后端项目审查**：按[后端审查执行路由](references/后端审查执行路由.md)覆盖全部适用规则域；其中接口规则选读下述专项，同一规则和发现不重复统计。
- **接口专项审查**：按[接口专项入口](references/专项/接口专项/审查入口.md)盘点指定接口、调用方和契约，不扩为全项目编码审查。
- 用户限定模块或要求抽查时遵守范围；未限定且请求项目审查时覆盖全项目。完整检查指定接口范围不代表完成项目级审查。

两种范围共用[完成门槛](references/后端审查完成门槛.md)和[六文件结果包模板](references/审查结果包模板.md)。不为每个接口创建一份报告，不另装接口审查技能。

## 能力包复用审查边界

后端业务项目的规范审查必须包含“基础能力是否复用”这一审查域，不能只检查业务代码是否符合基础编码规范。当前后端基础能力基线为：

- `AURA-CAP-COMMON-BUSINESS`：基础业务开发能力包，覆盖 Controller、Service、数据访问、本地事务、异常和统一返回的业务闭环；
- `AURA-CAP-BASE`：基础通用支撑能力包，覆盖统一响应、认证/当前用户、租户、基础实体、缓存、日志审计、服务调用和已公开的文件存储入口。

对上述基线，默认必须核对项目是否复用已公开入口，以及是否在业务代码中重新实现了同类能力。依赖存在不等于已经复用，必须沿着依赖、配置、调用入口和最终行为取证。确认在适用范围内重复实现时，按对应基础规范和能力接入要求判定偏差；只有项目类型不适用、能力契约未公开或存在可核验例外时，才记录为不适用、未证实或例外，不得凭目录名称直接放行。

物联中枢云、文件与实时、数据基础设施、任务调度、网关流量、数据安全等其他能力包属于按需能力。只有需求、路由、依赖、配置、接口或代码行为触发时才纳入审查；项目没有命中某个专项能力包本身不构成偏差。命中后优先核对公开能力入口和版本，再判断是否正确接入或是否重复建设，不能因为能力包存在就要求所有项目全部引入。

## 连续工作流

冻结仓库/分支/提交及未提交差异 → 建立审查单元目录和覆盖分母 → 全量盘点纳入范围 → 建立基础能力复用与专项能力触发账本 → 按规则域取证 → 追踪跨文件调用链与配置链并归并候选 → 逐规则判定 → 在授权与环境允许时构建/测试补证 → 写入六文件结果包 → 核对统计、来源、脱敏和未验证项。

能力账本至少记录能力包编号、复用级别（`基础必查/按需`）、触发依据、预期公开入口、实际依赖与调用、重复实现候选、证据编号和结论。基础能力未找到复用证据时不能直接判通过；专项能力未被触发时记录“不适用（未命中触发条件）”，不得为了凑数量引入审查项。

分支、环境、调用方或运行证据缺失时记录缺口并继续其余检查；目标项目无法定位或需要新增外部访问授权时才询问。未知状态不能猜成通过或偏差。构建有网络或数据副作用时先限定执行边界，失败不改业务代码或环境来制造成功。

规则状态统一为 `通过/偏差/未证实/不适用`，证据等级另列。每个规则必须引用适用单元、已检查单元和覆盖比；部分覆盖不得整体通过。正则命中仅为候选；没有命中也必须记录检查范围与方法。扫描提示不是完整规则清单，逐规则覆盖以实际规范矩阵与正文为准。

审查内外 API 时追踪原始响应、适配层、Controller 最终返回及真实路由。AURA 公共 `R<T>` 按 `CommonConstants.SUCCESS=200` 核对；内外分页按同一公共对象目标契约判断，不能把相同字段的私有 DTO 当作已统一。外部响应依据其已确认契约核查，不将外部协议值作为 AURA 标准。

报告区分审查执行状态与项目质量结论；每条证据记录观察事实、支持结论、不能支持的结论和局限；静态证据不证明线上权限、租户、事务或容量。敏感值在落盘前脱敏。审查不隐含代码整改、提交业务仓库、发布或生产验证；发现问题后仍完成结果包再移交。
