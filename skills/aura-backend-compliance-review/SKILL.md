# AURA 后端与接口规范审查

一次调用连续完成可执行审查并交付报告，不按模块反复等待确认。只读目标源码、锁文件和配置；补证不能隐含修改业务、访问生产或发布。版本见 `VERSION`，来源见[规范来源与验证](references/规范来源与验证.md)。

## 先选择任务

| 请求 | 执行范围 | 报告 |
|---|---|---|
| 审查本次修改、提交或文件清单 | 差异及受影响调用、公共契约和配置链，不默认扩为全项目 | 一份六章报告 |
| 审查整个后端项目 | 全部纳入资产与适用规则域 | 固定六文件包 |
| 接口专项 | 指定模块/接口及必要调用方；选读[接口入口](references/专项/接口专项/审查入口.md) | 有界局部用单报告；全量专项或明确要求结果包时用六文件 |

范围与格式分别记录。不明确的“审查项目”按全项目处理；缺 Git 基线时可按用户清单检查，但不能声称差异完整。项目无法定位或必须扩大授权时集中询问，其余证据缺口记录后继续。

## 连续执行

1. 固定仓库、分支/提交、工作树摘要、规范来源及输出位置。输出不计入被审资产。变更模式记录 base/head、增删改文件及实际可得差异；删除文件从基线取证，当前文件不存在不是读取失败。
2. 按[执行路由](references/后端审查执行路由.md)建立对象目录和规则范围。变更只选命中域；全项目先用规范矩阵盘点全部域，再分域读正文与正反例。前端专项不在本技能范围；未查域不能标通过。
3. 运行下述工具采集资产、接口与候选；沿真实类型、调用、配置链核实。工具不支持的映射或外部代码保持未知，不用检索零命中证明合规。
4. 必查当前范围涉及的基础业务与公共支撑是否复用。按执行路由的能力表只读命中章节，核对公开版本、实际依赖/配置/调用及重复实现候选。没有该功能不要求强装依赖；专项能力仅在需求、代码、依赖、路由或配置触发时追加。
5. 逐规则、逐单元记录 `通过/偏差/未证实/不适用`；候选判为确认偏差、排除或待补证。基础能力编号是能力身份，不替代正式规则 ID；未知能力契约不据此扣分。构建/测试只在授权和环境允许时补证，失败不改代码来制造通过。
6. 按[双模式模板](references/审查结果包模板.md)交付并运行报告自检；按[完成门槛](references/后端审查完成门槛.md)复核覆盖、统计、证据与未知边界。格式通过后仍人工复核严重性、误报、根因归并与关闭条件。

审查内外 API 均对照同一公共 `R<T>`、`CommonConstants.SUCCESS=200` 和公共分页目标契约；先核实真实框架类型和适配链，不新造类型或把外部 SDK 原始响应值当成 AURA 标准。对外 API 另核查 `/openapi`、`@PlatfomApi`、网关登记和实际收录证据；不向内部接口机械补注解。契约变更还须核对模块接口文档是否同步。

## 随包辅助工具

PowerShell 7；在技能目录执行，项目及模块路径换为实际范围。脚本不写报告、不改目标项目；默认摘要，`-Json` 返回逐项数据，按需筛选而非全文读入上下文。

```powershell
./scripts/inspect-backend-project.ps1 -ProjectPath '<项目根>' -ModulePath 'device' -Json
./scripts/check-backend-rules.ps1 -ProjectPath '<项目根>' -ModulePath 'device' -Json
./scripts/check-review-result.ps1 -Mode Change -ResultPath '<单报告.md>' -Json
# 全项目或全量专项六文件包使用 -Mode Project -ResultPath '<结果包目录>'
```

盘点/候选工具复用后端开发同源实现，完整携带依赖，不要求另装开发技能。它们仅处理指定模块；变更时可对所属模块采集上下文，但区分差异对象、关联对象和未审对象，不能把盘点到的文件全算已查。按需可直接调用 `inventory-api-contracts.ps1`，避免重复接口采集。详情与工具边界见执行路由。

退出 `0` 表示所请求静态处理未识别到问题，不代表项目合规；`1` 为执行/格式错误；`2` 为候选待复核或不完整。报告自检检查的是报告，不代替业务取证。敏感值落盘前脱敏；工具没有覆盖的规则仍须人工核对。
