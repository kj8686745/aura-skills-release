# 后端与接口规范审查使用说明

提供项目位置、范围和可得版本即可；技能一次执行到报告交付，不需要逐个模块发“下一步”。不指定版本时记录本地当前版本，不切分支或覆盖工作树。远程项目先按已有访问方式定位，不能将缺少权限猜成代码缺陷。

## 常见请求

> 使用 $aura-backend-compliance-review 审查当前项目相对指定基线的设备模块修改，包含工作树差异。只检查变更与受影响链路，交一份报告，不改代码。

> 使用 $aura-backend-compliance-review 对指定版本做完整后端规范审查，交六文件结果包，基础能力复用必须纳入，专项能力按触发场景检查。

> 使用 $aura-backend-compliance-review 只核对设备模块内外接口的响应、分页、OpenAPI 登记、权限及模块文档；一份报告列明调用方和未证实项，不扩大为全项目。

## 会得到什么

变更单报告按基线、结论、覆盖、发现与证据、候选、整改六章组织；全项目按同版模板交固定六文件包。全量接口专项也可用六文件包，但结论只覆盖接口范围。单报告不会链接不存在的六文件附件，不为单个接口拆报告。

报告明确纳入、已查、未查和排除对象；每个发现有规则 ID、证据、影响及关闭条件。缺运行材料保留未证实；合理例外保留依据；零发现不代表全部规则通过。基础能力只对当前范围涉及功能核对复用，不要求所有项目接入全部专项。

## 工具与边界

技能已包含盘点、接口采集、候选检索和报告检查脚本，PowerShell 7 执行。调用示例见 SKILL；`-ModulePath` 限定目录，默认 `.` 扫描项目，不能用默认值代替变更范围。候选工具输出不直接成为发现，报告脚本退出 0 也不代表证据真实或项目通过。

审查不包含代码整改、依赖安装、Git 提交、发布或真实环境验收。构建失败保留原始证据并继续其余核对，不修改项目或锁文件。无需另装接口审查、后端开发或内部构建技能。
