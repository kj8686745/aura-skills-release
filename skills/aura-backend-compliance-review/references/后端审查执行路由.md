# 后端审查执行路由

先按任务确定规则域，再从[随包基础编码规范矩阵](standards/01-基础编码规范/规范矩阵.md)定位稳定 ID、必要性和正文正反例。全项目逐一处理全部适用域；变更从改动及受影响链路选域，其余域列为未纳入，不计通过。矩阵中的前端专项不属于本技能范围。下表编号省略 `AURA-BASE-` 前缀，仅是检索提示，不是完整规则白名单；工程、架构、配置、安全、数据、日志、异步、运行资源、自测和交付域均按矩阵适用性处理，不能只查表内举例。接口专项从[接口入口](专项/接口专项/审查入口.md)执行。

| 审查域 | 优先规则 | 主要证据 | 结论边界 |
|---|---|---|---|
| 版本与工程结构 | BE-001、BE-002、BE-004、BE-005、BE-006、BE-042、BE-050 | `pom.xml`、模块目录、启动类、源码包、构建脚本、提交号 | 目录和依赖可做静态判断；兼容性仍需构建或人工确认 |

| 接口与边界 | API-001～API-026、BE-006、BE-007 | Controller、DTO、响应模型、路径、参数校验、异常映射、接口文档；命中对外 OpenAPI、`/openapi`、`@PlatfomApi` 或平台 API 配置时追加依赖、配置、网关登记和启动上报证据 | 只凭源码不能证明真实调用方兼容、线上权限或平台目录已收录 |

| 异常、日志与审计 | BE-029～BE-032、API-004、API-005 | `catch`、日志、异常处理器、审计事件、错误码 | 日志命中不能证明字段脱敏或完整链路 |
| 异步、消息与并发 | ASYNC-001～ASYNC-012、ASYNC-025、ASYNC-026、BE-024～BE-027 | `@Async`、消息监听、CompletableFuture、线程池、重试、幂等键、调度 | 代码结构不能替代消息投递、重复消费和故障恢复验证 |
| 配置与外部依赖 | BE-033～BE-041、BE-043～BE-047 | `application*`、配置绑定、依赖版本、Feign/SDK、环境变量 | 依赖存在不代表实际调用、超时和降级可用 |
| 自测与交付 | BE-048～BE-050 | `src/test`、测试报告、CI、镜像/部署脚本、变更记录 | 测试文件存在不等于测试执行通过；构建失败必须保留原始证据 |

## 标准审查阶段

接口响应码审查必须追踪返回值来源：AURA 公共 `R<T>` 的成功码按 `CommonConstants.SUCCESS=200` 核对；外部原始响应按已确认的被调用方契约检查，再追踪适配层与 Controller 最终返回，不根据历史样例推断外部协议。结合真实路由、暴露条件和调用方，与内外统一的 `R<T>` 和公共分页目标契约对照；存在偏差时记录实际影响和兼容要求，不将规范目标当作实现证据。

| 阶段 | 执行要求 | 产物 | 阶段性结论 |
|---|---|---|---|
| 版本与范围冻结 | Git 可用时固定 HEAD、base/head、工作树及未跟踪清单；用 `git diff --name-status <base> <head>` 与实际工作树差异核对增删改。摘要可能含敏感值，不落盘原始配置差异。无 Git 时记录文件版本/摘要与用户清单 | 版本与范围记录 | 无法证明差异完整时公开缺口，可完成给定清单核对；目标不可定位才阻断 |
| 纳入资产盘点 | 全项目盘点全部模块和适用资产；变更从清单沿引用及配置链补入必要对象。工具盘点结果先作为资产目录，不自动算作已检查 | 按类别去重的对象目录 | 同类别纳入=已检查+未检查；排除另列；抽样不得称项目审查完成 |
| 基础能力与专项能力盘点 | 按下表只选当前范围涉及功能，记录公开入口、版本及复用链；专项只对触发或触发性未知项建账 | 能力复用审查账本 | 未触发类别集中说明依据，不逐个罗列全部能力；没有该功能不要求强装依赖 |
| 规则域候选采集 | 按纳入范围运行随包工具和必要只读检索，记录版本、范围、过滤、时间和零命中；只保存脱敏后的必要结果 | 原始命中、唯一候选、证据索引 | 未被工具支持的规则继续语义核查，不将有限模式当完整扫描 |
| 归并与规则判定 | 同根因且触发和关闭条件相同才归并；逐单元取证后按唯一规则 ID 聚合：偏差优先，其次未证实，全部适用单元符合才通过，全部不适用才不适用 | 规则矩阵与发现 | 能力 ID 不充当规则 ID；部分单元通过不能代替整体通过 |
| 构建/测试补证 | 仅执行授权范围内、环境可得的相称验证；构建产物在约定位置或隔离副本，缺条件记录原因继续 | 命令、环境和实际结果 | 不自动联网安装、改锁文件或配置；无执行不写成功，也不强制无关模块构建 |
| 报告与复核 | 按已选形式输出单报告或六文件；运行随包报告检查并人工核对范围、真实性和归并 | 同版报告与未覆盖项 | 以完成门槛定义状态；脚本通过不代表项目合规 |

详细停止条件和完成状态见 [后端审查完成门槛](后端审查完成门槛.md)。

## 分批闭环与续接

先核对当前入口与随包规范的版本、适用框架和可读性。用户指定旧技能而其依据缺失或与当前契约冲突时，指出具体冲突；不得混用旧硬编码结论。需要更换明确指定的规则基线时集中确认，可确认的同源范围继续。

在单报告第三节或六文件 `03` 中维护批次队列，不增加过程文件。先按模块/入口与规则域划分静态批次，再单列构建、运行补证；每批只加载命中规则正文和正反例。执行循环：选可执行批次 → 读真实对象与必要调用/配置链 → 逐规则记录 U/E、观察和结论 → 更新矩阵、候选和剩余队列 → 直接取下一批。上下文续接读取基线、已完成摘要及下一批，不反复重读整套规范；基线变化只重查受影响项。

规则适用分母取真实作用范围，不以同域所有 Java 文件代替。例如 DTO 规则只映射相关 DTO 与使用入口，事务规则映射写入业务链；同规则不同结论或不同进度的单元拆行。矩阵逐行写 `执行进度=待执行/已执行/受阻`，另写四种规则状态及缺口。未查行关联盘点 E 和下一批，不虚构观察；已静态核实但缺运行结果可写“已执行＋未证实＋外部证据缺失”，说明已知与未知。单元全部适用静态规则完成才标已检查，候选引用、搜索命中和读过一次均不够。

抽取样本或受限清单中，某份文件不能提供证据，不等于整个业务没有满足该要求。对“缺少测试/文档/配置/复用”等否定性结论，先确认相关资产集合是否完整、是否存在明确交付承诺或能直接证明冲突的代码事实。全注释测试仅证明该文件不可执行；若未提供其他测试及交付声明，业务自测覆盖保持未证实，不将其计为已确认偏差或强制要求恢复这个特定文件。完整范围内确认缺失或明确虚假交付声明时，才依据对应正式规则判断；补证可以是其他有效测试或可重复步骤。报告格式通过不证明上述适用条件成立。

例如同一事务规则：`U-011 OrderService:create` 已检查出跨写入边界问题，关联具体 F/E；`U-012 RefundService:refund` 尚未读取，保留待执行并排入下一批，不能借前一个 F 把两者都算已查。没有扫描候选的规则仍按其检查方法取证。静态未完成不得用统一“缺运行环境”结束；只有实际中断、资料不可得或权限限制才留检查点，普通批次边界不等待“下一步”。

报告可以由脚本排版和汇总已有判定，不允许脚本以“无 F 即未证实”、域分组或固定名单自动填写结论。F 引用具体 U/E 和路径:符号；CH 写真实节点、前置、关键分支、期望/实际，不能只有“入口→业务→数据”或“遵循规则”。相同证据可复用，但各规则须有独立支持关系；重复套话提示需回到正文复核，不等于自动判违规。

基础能力按实际功能比较预期公开入口/版本与真实配置、调用和行为，不能以依赖或 import 单独证明复用。范围同时包含真实调用方源码时，静态比对路径、请求/响应字段、权限、分页和错误处理；缺联调环境只保留运行补证，不免除可读源码比对。多个项目的总入口总结共同根因、先后依赖和剩余工作，不只提供链接。

对统一响应核对真实 `R.code` 与 `CommonConstants.SUCCESS=200`，不得写成不存在的 `R.success=200` 字段；证据类型 S1～S4 不代替高/中/低置信度及其依据。

## 只读扫描示例

```powershell
rg -l "password:|secret:|token:|access[-_]?key:|private[-_]?key:|jdbc:" <项目> -g '*.yml' -g '*.yaml' -g '*.properties'
rg -n "Mapper|JdbcTemplate|Repository|\.select|\.insert|\.update|\.delete" <项目>/src/main -g '*Controller.java'
rg -n "@RequestBody List|List<@Valid|Map<String, Object>|CompletableFuture|@Async|@KafkaListener" <项目>/src/main -g '*.java'
rg -n "@PreAuthorize|SecurityContext|Tenant|Authorization|access_token" <项目>/src/main -g '*.java'
```

扫描根目录按实际模块展开，不能只扫描仓库根的 `src/main`。敏感配置先定位文件，再只记录键名和行号，证据落盘前脱敏。任何模式命中都只是候选：包括密码字段，也要区分真实字面凭据、占位符和环境变量引用，不能仅凭键名判定偏差。

基础能力复用可先用下列线索建立候选，再沿配置和调用链确认；线索不构成通过或偏差结论：

```powershell
rg -n "aura-common-service-starter|aura-common-data|SecurityUtils|TenantBroker|BaseEntity|CustomException|CommonConstants|R<|@HasPermission|@SysLog|@Audit|Feign" <项目> -g '*.java' -g '*.xml' -g '*.yml' -g '*.yaml' -g '*.properties' -g 'pom.xml' -g 'build.gradle*'
rg -n "ResponseEntity|自定义响应|自定义用户上下文|自定义租户上下文|自定义缓存工具|自定义审计|new .*Client|new .*Mapper" <项目>/src/main -g '*.java'
```

第一组用于确认基础能力入口是否存在及其组合位置，第二组用于发现可能绕过公共入口的重复实现候选。未命中不等于未复用，命中也不等于已违规；最终结论必须回到能力入口、规则正文和行为链证据。

## 全量扫描记录要求

- 每个扫描域记录扫描根目录、文件过滤条件、命令、执行时间、命中数量和原始输出位置。
- 统计口径必须能从 `rg --files`、构建模块或其他可复核命令重算；不能只填写估算值。
- 同一调用链或同一根因的多处命中合并为一个候选项，同时在证据索引中保留覆盖数量和代表性文件。
- 未扫描、无法读取或被排除的目录必须列出原因；不能用“未发现”代替“未扫描”。

## 审查单元与行为链深度要求

在逐规则判定前建立单元目录，作为覆盖分母。每个单元记录稳定 `unit_id`、类型（Controller、Service/UseCase、Mapper/Repository、Listener/Job、配置、测试或交付文件）、模块与入口、相对路径和符号、纳入原因、检查状态，以及未检查或排除原因。规则矩阵必须引用单元编号并给出覆盖比 `已检查/适用单元`；部分覆盖不得标为整体通过。

同时建立当前范围的能力复用账本。基础业务与公共支撑中对应功能必查；专项只为已触发或触发性未知项建账，其余类别集中写明未触发依据，不要求加载全部专项正文。账本包含：能力包编号、公开入口版本、触发依据、预期复用点、实际依赖/配置/调用、重复实现位置、正式规则 ID、E/F 编号、状态和未证实边界。能力事实说明提供“已有何能力”的依据，偏差判定仍回到正式编码规则。单看同名类、import 或依赖不能确认复用或重复建设。

在首次 `inspect-review-scope.ps1` 追加 `-IncludeCapabilityCandidates` 可获得同范围候选，避免再跑一轮全文搜索。`capabilityReuse.items` 中两类基础能力保留公开资料路径、依赖声明、配置位置、名称与调用线索及可能替代实现；全部保持 `not-evaluated`。`not-observed` 不是不适用，`signals-found` 不是已复用。先按命中功能读公开资料，再沿真实类型、注入、调用和失败分支确认；工具不能解析实例调用链或运行生效。配置只定位，Properties 识别受限键形态，YAML 只列文件；不输出配置键值或源码片段。将人工结论填入现有账本，不新增过程文件、不预造 U/E/F、不用候选数量替代规则覆盖。工具映射只覆盖登记的基础能力线索，专项或自定义入口仍须按需求补查，不从零命中推断无能力。

## 工具采集与复核

`inspect-review-scope.ps1` 固定当前项目/模块的纳入文件数量与路径摘要、排除目录、重解析点、构建声明和依赖坐标，并输出 SDK 使用候选；默认不返回完整文件名清单，需要逐文件资产目录时显式使用 `-IncludeFiles`。它只读取项目内声明和源码，不解析依赖树、缓存、JAR 或邻仓库。`inspect-backend-project.ps1` 提取指定模块的构建声明、类型角色、配置/文档/测试位置及直接接口映射；`check-backend-rules.ps1` 收集入口数据访问、线程创建、公共同名类型、响应/分页及 OpenAPI 线索。两者共用 `backend-common.ps1` 和 `inventory-api-contracts.ps1`，独立安装必须一并携带。盘点内部已经采集接口，无必要不再单独重复调用接口工具。

这些工具不提供完整 Java AST 或真实依赖解析：自定义组合注解、继承映射、Gradle DSL、外部公共契约、网关改写、DTO 全字段和运行生效需补证。候选数、Java 类型数和接口数不是规则覆盖数。工具默认排除 `.git`、构建缓存等，并跳过重解析点；被跳过对象在审查目录中保留解释。输出报告放项目外或在原始目录盘点时明确排除，避免把报告本身审进去。脚本发现 SDK 坐标或调用候选只用于建立项目内取证队列，不得把 SDK 内部文件加入纳入资产，也不得因 SDK 源码不可见而把本项目规则标成偏差。

同源工具在后端开发与本技能内分别携带，来源和 LF 摘要登记在 source.json；维护时比较共同实现，不能分别改成不同判定标准。报告检查使用与审查技能构建相同的 `check-review-result.ps1`，按所选格式调用；退出 2 的未解析项人工复核后记录，不通过删记录强行过检。

涉及契约、权限、租户、事务、缓存、异步、外部调用、重试或数据生命周期的候选，至少记录一条跨文件行为链。对 SDK、Starter、Feign Client 等外部依赖，链路在本项目的 `Client/Adapter` 调用出口停止；只核对本项目的依赖声明、配置、调用、适配和公开契约，不追入依赖内部实现：

```text
入口/触发器 → Controller/Consumer/Job → Service/UseCase
→ Mapper/Client/Adapter（项目内停止） → 配置/权限/事务/消息边界 → 响应或副作用
```

行为链至少包含 `chain_id`、触发前置、节点序列、成功/失败/权限/重试或事务分支、最终响应或副作用、期望行为、实际行为和未证实边界。接口专项还要列提供方、网关路由、调用方、适配层、原始响应和最终返回；正常、权限失败、超时或重复写入等负向场景无运行证据时必须记为未证实。外部 SDK 的内部线程、连接池、重试和编码实现不进入本项目统计；若需审查 SDK 本身，必须另行明确 SDK 范围、源码来源和结果包。

证据不只记录命令和位置，还要说明它支持什么。每个 `E` 至少记录观察事实、支持的规则或结论、不能支持的结论、路径/行号/提交、命令/环境/退出码、时间、脱敏方式和局限。静态命中不能支持线上权限、事务回滚、消息投递或容量结论；没有运行/联调环境时列出补证动作。
