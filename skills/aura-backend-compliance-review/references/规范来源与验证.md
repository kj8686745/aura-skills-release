# 规范来源与验证

技能版本以 `VERSION` 为准。逐文件来源、来源提交、工作树与随包 LF 摘要见 [source.json](source.json)；`sourceBinding=pending` 表示涉及未提交依据，不能当作已绑定正式提交。本版模板为 1.2.0，增加分批续接、执行进度与证据缺口区分；来源绑定、样本行为验证与发布状态分别记录，不互相替代。

本版支持变更单报告、全项目六文件包及按范围选择格式的接口专项；不携带前端专项正文。基础业务与公共支撑及按需专项的能力事实随包交付，执行只选当前任务命中章节。跨范围导航仅移除登记的链接目标并保留文字，不作为必读文件。使用统一接口契约，保留 SDK 原始响应与 AURA 响应之间的区别。

技能导航和扫描候选不作为规则事实源。`AURA-CAP-COMMON-BUSINESS` 与 `AURA-CAP-BASE` 中对应功能是必查复用基线，其他能力按需；能力编号不代替编码规则 ID，未公开契约不能推定违规。盘点与候选工具复用后端开发同源脚本，报告自检复用审查技能构建同源脚本，完整依赖随包携带；共同来源路径与摘要登记在 source.json，不能仅按文件名假定同源。脚本退出 0 不代表业务合规或审查充分。

历史项目报告不能代替本轮验证。验证结果与缺口在内部现有改造记录合并维护；行为状态见 source.json。隔离样本、目录、来源和链接检查与真实项目运行验收分开。当前没有执行提交、推送、发布或安装；发布资格沿用目录清单，源码版本变化不等于远端已经更新。
