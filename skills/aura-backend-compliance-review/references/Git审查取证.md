# Git 审查取证

按作者、按时间窗口或多分支审查时选读。先确认用户要求的是抽查、作者变更还是指定仓库全量。固定仓库身份、远端分支清单及完整目标 SHA，明确使用作者时间或提交者时间和带时区的左闭右开窗口。多分支按提交 SHA 去重。使用既有本地缓存时，先用已有远端清单及拉取结果确认对象、范围和时间。拉取失败、过期或缺 ref 的范围写成未完成。分支头的日期不能裁掉其历史，旧 Git 可遍历已固定目标的可达历史再按时间过滤。项目自带的服务器地址和认证仍从当前环境取得。

可用随包 Python 3.9+ 只读工具，结果保存在已有证据目录，只投影需要的计数、ref、SHA 或锚点字段。示例在技能根执行：

```text
python -B -X utf8 scripts/review-git-evidence.py --repo <仓库根> window --ref refs/remotes/origin/dev --ref refs/remotes/origin/main --start 2026-11-04T19:00:00+08:00 --end 2026-11-11T19:00:00+08:00 --date-field author
python -B -X utf8 scripts/review-git-evidence.py --repo <仓库根> anchor --commit <完整SHA> --path src/File.java --line 42 --snapshot-root <快照根> --attribute
```

`window`只读取明确传入的本地 refs 或 SHA，可复用本地已取得的完整历史。它不拉取远端，不发现遗漏分支，不将本地结果视为远端完整性证明。有效空窗口返回0和count=0，无法解析目标、浅历史或 Git 失败返回1。已失败的拉取即使本地还留旧 ref，也要记录并核对远端目标 SHA 后才可宣称完整。按作者时，可重复传入已确认的 --author-email（包括各历史别名），使用精确邮箱匹配，输出只记录筛选数量与提交。时间过滤、提交作者和具体行的引入归属分别核对。

`anchor`按固定提交核对文件和行号，可比对快照原始字节摘要。仅 CRLF 转 LF 后相同记为 crlf-lf-only，实质差异失败。建议在有多个同名仓库时用全局参数 `--expected-origin` 核对本地 origin（放在子命令前，使用无凭据的已知值）。`--attribute` 返回行归属线索，不能证明该提交引入根因。没有快照时只证明 Git 锚点，历史删除可从父版本定位。规则是否适用、规范来源是否已绑定、行证据是否足以支持结论仍分别复核。

明确要求按人员或仓库交付时，沿用四份报告和已有证据表。每个位置记录主发现、分组条目、仓库、被审 SHA、路径与行、引入 SHA（未知则待核）、归属依据。对照位置的差异与每个相关父版本。纯合并继承的代码归原提交，冲突解决新增内容才归合并提交。删除后恢复、改名和行移位沿父版本、相关补丁或行为查找，避免将历史代表行归给窗口内最后修改人。不同仓库或组的局部编号可以相同，全局以稳定主发现去重。两人共享一个根因可各有条目，合并统计仍为一个。

跨轮时在现有整改与复核章节保留旧报告/编号、当时及当前提交、行为触发、证据与当前状态。旧报告 D-001 与本轮 D-002 即使文件改名，若同一过滤分支仍在无匹配时返回全量，记持续。同文件的类型同步缺陷另记。缺少旧证据记关联待核。已修复须有旧问题的关闭证据，再次引入须另有修复后重新出现的版本与证据。
