# AURA（天玑）接口文档模板

> 按一个业务模块维护一份接口契约。先列模块内全部接口，再为每个接口复制“三”至“十一”的明细块；模块共同约定只写一次，有差异的接口在明细中说明。提供方和调用方共同维护，内容应能指导实现、接入和联调。

> 固定阅读锚点为：模块/接口基本信息、接口总览、职责与调用边界、统一认证与请求上下文、接口逐项契约、专项协议、联调与生命周期。实时事件、服务间调用和公开 OpenAPI 可以增加场景专属章节，但不得把一个接口拆成独立文件。

### 四、响应契约

所有 HTTP 业务接口统一使用 `R<T>{code,msg,data,ok?}` 响应外壳，其中 `ok` 是框架序列化出的只读兼容字段（如实际返回），调用方以 `code` 和业务错误码为准。调用边界只影响认证方式、数据范围和可公开字段，不改变响应外壳、分页字段或错误语义。HTTP 状态码不能替代响应体，错误响应必须另行填写状态、业务错误码、消息、请求标识和可重试性。

统一响应外壳字段（不得删除；`ok` 按实际序列化情况填写）：

| 字段 | 类型 | 必返 | 空值规则 | 业务含义 | 来源/转换 |
| --- | --- | --- | --- | --- | --- |
| `code` | integer | 是 | [成功/失败码规则] | AURA 业务结果码 | [框架或异常映射] |
| `msg` | string | 是 | [成功或失败消息规则] | 安全、可读的结果说明 | [框架或业务异常映射] |
| `data` | object/array/null | 是 | [本接口空值规则] | 本接口 DTO、分页或错误详情 | [业务模型转换] |
| `ok` | boolean | 否（框架兼容字段） | [实际返回时填写] | `code` 的只读成功标志 | [框架序列化] |

本接口 `data` 内业务字段：

| 字段 | 类型 | 必返 | 空值规则 | 业务含义 | 来源/转换 |
| --- | --- | --- | --- | --- | --- |
| [field] | [类型] | 是/否 | [规则] | [语义] | [来源] |

`data` 内模型示例（下方须再给出包含该模型的完整响应外壳）：

```json
{
  "[field]": "[value]"
}
```

本接口完整成功响应示例（将 `data` 替换为本接口真实模型）：

```json
{
  "code": 200,
  "msg": "success",
  "data": {},
  "ok": true
}
```

分页、排序或批量接口必须补充：`PageResult<T>` 的 `records`、`total`、`size`、`current`、`pages`，默认值、最大值、排序规则、数据范围和部分成功语义。不得把 ORM `Page/IPage` 直接作为接口返回类型。

分页接口字段表（适用时）：

| 字段 | 类型 | 必返 | 空值规则 | 业务含义 | 本接口约定 |
| --- | --- | --- | --- | --- | --- |
| `records` | array | 是 | 无数据时为 `[]` | 当前页公开 DTO | [填写记录模型] |
| `total` | integer | 是 | 无数据时为 `0` | 总记录数 | [填写统计口径] |
| `size` | integer | 是 | 保留实际生效值 | 每页数量 | [默认值/最大值] |
| `current` | integer | 是 | 保留实际生效值 | 当前页码 | [最小值/越界处理] |
| `pages` | integer | 是 | 无记录时为 `0` | 总页数 | [计算规则] |

接口边界只用于填写认证方式、数据范围和字段公开范围；不得把不同认证方式混写在同一行，但响应、分页和错误契约不随边界变化。
