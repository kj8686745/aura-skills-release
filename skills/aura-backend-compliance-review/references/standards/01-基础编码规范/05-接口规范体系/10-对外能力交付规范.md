# AURA（天玑）对外能力交付规范

**适用范围**：AURA 向业务应用、集成服务或第三方调用方提供平台能力时的说明、接口和 SDK 交付。
**不适用范围**：内部治理过程、能力包建设过程、源码审查记录和未公开的内部实现。

## 一、两类交付物的边界

AURA 对外能力交付包含“能力选择”和“接入使用”两类内容。每个能力包最多三份文档：`01-能力说明.md`呈现能力作用与场景，`02-接入与使用手册.md`归并操作规则、示例、API/SDK 与数据模型，`03-版本与兼容记录.md`集中版本变化和兼容范围。内容少时可以减少文件数，不能减少必要契约。

| 类型 | 解决的问题 | 主要读者 | 核心产物 |
| --- | --- | --- | --- |
| 能力说明 | AURA 有什么能力、什么时候使用、使用后得到什么 | 业务应用开发者、平台使用者 | 能力地图、场景、任务导航、结果和边界 |
| 接入与使用手册 | 平台能力如何操作，OpenAPI 或 SDK 如何引入、配置、调用和处理失败 | 平台使用者、API/SDK 调用方、集成开发者 | 使用规则及正反例、依赖、接口契约、数据模型、SDK 方法、完整示例与排错 |

能力说明回答“是否适合、能得到什么结果”；接入与使用手册回答“如何完成平台任务、如何通过接口或 SDK 接入”，包括控制台、配置或组件的具体操作。SDK 是能力对外交付的一种入口。两类内容通过稳定能力编号互相定位。

## 二、交付关系

一个能力包可以包含多个平台能力，也可以同时提供 HTTP OpenAPI 和 Java/其他语言 SDK。推荐关系如下：

```text
01-能力说明：能力地图、场景选择、任务导航与结果边界
02-接入与使用手册：操作规则、依赖、接口与数据模型、示例及排错
03-版本与兼容记录：能力包、服务、API、SDK、模型版本和变更影响
```

能力说明不得复制 API/SDK 全量字段；接入与使用手册不得重新定义能力包的业务边界。版本历史只在版本与兼容记录维护。三份内容通过稳定的能力编号、接口编号和章节链接关联。

## 三、统一要求

### AURA-BASE-API-027：先说明能力边界，再提供具体入口

**必要性**：必须

**正确写法**：先在能力地图说明“视频通道查询”，再链接 `/openapi/video/channel/queryPage`。

**错误写法**：只给一串 SDK 方法，不说明能解决什么问题。

**判断要点 / 验证方式**：能力说明与接入手册中的具体入口可以互相定位。

### AURA-BASE-API-028：能力说明与接入手册分工明确

**必要性**：必须

**正确写法**：能力说明写场景和结果；接入手册写操作规则、依赖、方法、请求响应、示例和模型。

**错误写法**：在能力说明中复制完整 SDK 参数表并另写一套错误语义。

**判断要点 / 验证方式**：抽查能力说明和手册是否出现重复且不一致的契约。

### AURA-BASE-API-029：集中记录 API/SDK 版本、依赖和发布顺序

**必要性**：必须

**正确写法**：在一份版本与兼容记录中集中列能力包、服务、API、SDK、模型和示例的准确版本、获取入口及升级影响；内部制品发布命令留在维护资料。

**错误写法**：只在代码片段中散落版本号。

**判断要点 / 验证方式**：版本表、构建文件和制品坐标一致。

### AURA-BASE-API-030：对外 HTTP 接口使用统一 OpenAPI 路径和登记契约

**必要性**：必须

**正确写法**：`/openapi/video/**` 与 `@PlatfomApi(code,version,name,requestPath)` 一致。

**错误写法**：使用内部路径或只写网关转发后的地址。

**判断要点 / 验证方式**：实际 URL、注解和网关目录三方一致。

### AURA-BASE-API-031：SDK 方法可追溯到具体 API 契约

**必要性**：必须

**正确写法**：`assets(...)` 明确对应方法、路径、请求 DTO 和响应模型。

**错误写法**：SDK 方法名与接口路径无法对应。

**判断要点 / 验证方式**：SDK 方法矩阵逐项可回查。

### AURA-BASE-API-032：按字段说明请求、响应、错误和异步结果

**必要性**：必须

**正确写法**：字段表列出类型、必填、默认、空值和业务含义，并给完整响应示例。

**错误写法**：只描述“返回成功/失败”。

**判断要点 / 验证方式**：逐接口契约和模型表完整。

### AURA-BASE-API-033：完整说明迁移、兼容和回滚

**必要性**：必须

**正确写法**：分页字段变更同时说明服务端、SDK 和调用方迁移。

**错误写法**：只升级 SDK，不说明服务端字段变化。

**判断要点 / 验证方式**：迁移表覆盖请求、响应、签名和调用方。

### AURA-BASE-API-034：不得把未验证结果写成已完成

**必要性**：必须

**正确写法**：明确“已核对源码，未执行 deploy”。

**错误写法**：文档写“已发布”但无制品或流水线证据。

**判断要点 / 验证方式**：发布说明区分静态核对、构建、发布和部署。

## 四、API/SDK 手册的最小内容

提供 API/SDK 的能力包，其接入与使用手册至少包含：依赖与引入、网关和认证、接口总览、逐接口请求/响应/错误契约、SDK 方法映射、共享数据模型、使用规则与正反例、典型流程、排错和限制。迁移、兼容及升级顺序集中写入版本与兼容记录并由手册链接。分页、文件流、事件推送、异步任务和批量写入按实际能力补充，不能用普通 CRUD 示例代替。

## 五、平台能力说明的最小内容

能力说明至少包含：能力定位、能力地图、适用与不适用场景、任务导航、结果和边界、与相邻能力的选择关系，以及到接入手册和版本记录的链接。接入前提、最小使用路径、失败处理和完整示例由手册承载。

## 六、状态边界

先展示能力目标和任务选择，再在手册提供首次成功路径及按模块查阅的参考。手册按“引入配置、首次调用、使用规则、模块接口与数据模型、完整示例、排错”组织；版本记录说明兼容与升级。不承诺固定几分钟完成，不让使用者先读所有字段才能开始。

表格用于能力比较、参数及版本查阅，不替代操作步骤。代码提供必要注释，JSON 保持合法，字段解释放相邻表格。快速示例与详细参考使用同一契约；没有实际 SDK 时不生成 SDK 章节。仅在对象关系或调用顺序不易理解时加图。

文档存在不等于能力已发布。能力、API、SDK 和示例分别记录自己的来源版本和状态；只有整体版本收录后，才可对外宣称属于该 AURA 版本。安装、任务触发和业务方实际使用属于使用方行为，不作为本规范文档的组成内容。
