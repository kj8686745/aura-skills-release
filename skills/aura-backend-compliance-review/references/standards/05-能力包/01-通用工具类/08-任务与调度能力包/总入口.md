# 任务与调度能力包

**能力包编号**：AURA-CAP-COMMON-JOB  
**所属能力域**：通用工具类  
**当前依据**：`aura-core-common` `dev@53bcd77` 的 `aura-common-job` 装配源码，父 POM/BOM 声明 XXL-JOB `3.4.2`；这是源码基线核对，执行器注册、调度中心兼容和实际触发仍需在目标项目验证

## 1. 能力定位

本能力包说明 AURA 提供的 XXL-JOB 执行器装配、调度中心地址发现和任务处理器接入方式，以及业务服务接入后能得到什么。租户上下文、业务批次状态、幂等和补偿由业务任务按基础编码规范实现，接入执行器不会自动提供这些保证。

## 2. 适用场景

周期执行先读[定时任务与调度规范](../../../01-基础编码规范/10-异步任务消息与外部系统集成规范/03-定时任务与调度.md)，再按实际选用的调度器接入。本包说明 XXL-JOB 能力，不默认所有本地周期维护都采用统一调度。

- 定时同步、清理和统计任务；
- 需要由统一调度中心触发的后台任务；
- 需要执行器注册、心跳和结果回调的服务；
- 需要自行记录业务批次状态、失败原因和重试次数的批处理。

不适用于普通同步接口、消息消费本身或大文件导出；后两者分别使用业务接口、消息总线和文件任务能力。

## 3. 接入后的能力链路

第一次开发可按[开发原理](./能力详细说明.md#9-开发原理从触发到业务完成)理解职责，再跟随[租户日报完整应用路径](./能力详细说明.md#10-实际应用租户日报生成)；实例内清理任务见[本地任务示例](./能力详细说明.md#13-本地任务怎样应用)。设计、配置、代码与验证保持在同一条业务链上。

```text
引入模块并导入配置
→ 创建执行器 Bean
→ 按显式地址或固定规则发现调度中心
→ 调度中心注册与触发已登记的 JobHandler
→ Handler 读取参数并调用业务 Service
→ 执行结果回传调度中心
```

业务批次状态、授权范围、重复触发结果、失败重试与补偿不由这条框架链路自动产生，按基础编码规范的任务与运行要求处理。执行器 Bean 已创建、注册成功、Handler 被触发和业务完成是不同结果。
