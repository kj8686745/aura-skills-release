# 基础通用支撑能力包

**能力包编号**：AURA-CAP-BASE  
**能力包版本**：0.1.0-draft  
**适用对象**：AURA 业务应用开发者、负责生成业务代码的 AI 编码助手  
**状态**：建设中  

## 1. 能力定位

基础通用支撑能力包为业务服务提供已经封装好的通用能力入口，覆盖统一 HTTP 响应、JSON、当前用户与认证上下文、租户上下文、缓存基础使用、基础实体、日志、审计、服务间调用基础和统一文件存储入口。幂等能力须在项目中确认切面实际生效后使用。

本能力包先回答“已有哪项公共能力、适合什么问题、使用后得到什么”，再提供接入方式和示例。共同研发规则以[基础编码规范矩阵](../../../01-基础编码规范/规范矩阵.md)定位的正文为准；本包的接入要点不作为第二套全局规则。

## 1.1 能力目标

业务开发者阅读本能力包后，应能完成以下工作：

- 根据业务问题选择正确的框架能力；
- 判断需要哪些依赖、配置和开发入口；
- 在 Controller、Service、数据访问和服务调用中正确组合能力；
- 处理认证、权限、租户、缓存、日志、审计和重复提交边界；
- 形成可以联调、维护和审查的完整业务实现。

本能力包的推广重点是让业务优先使用框架已有能力，减少重复造轮子和项目间不一致，而不是要求业务开发者了解公共包内部实现。

## 2. 命中条件

以下任务应优先加载本能力包：

- 新建或修改 AURA 后端业务接口；
- 需要获取当前用户、声明接口权限或处理内部调用；
- 需要统一返回体、JSON、租户上下文或 Redis 缓存；
- 需要增加操作日志、数据审计，或设计重复提交处理；
- 需要基于公共 Feign/OpenAPI 能力完成服务间调用。

以下任务暂不由本能力包承载：

- 文件/Excel、消息总线、实时推送、网关、规则引擎；
- 动态数据源、分布式事务、向量/检索、图数据库等专项接入。

按表中任务选择必要文档，先了解能力边界，再阅读接入要点和示例。阅读顺序如下：

```text
能力包索引
→ 本入口
→ 能力清单与边界（先了解框架能力）
→ 基础能力接入与使用要点（再学习如何使用）
→ 对应模块示例
→ 基础编码规范中被引用的规则
```

不得因为命中一个基础能力就加载所有专项能力包。
