# 基础业务开发能力包

**能力包编号**：AURA-CAP-COMMON-BUSINESS  
**所属能力域**：通用工具类  
**适用版本**：随 AURA 公司级框架版本发布

## 1. 能力定位

本能力包展示如何把 AURA 已提供的数据访问、基础实体、统一响应、业务异常及安全上下文入口，组合到一个后端业务功能中。Controller、Service、事务和自测是业务开发环节，不是本包另行发布的框架能力或第二套通用研发规则；这些环节的共同要求以[基础编码规范矩阵](../../../01-基础编码规范/规范矩阵.md)定位的正文为准。

本包回答“选用哪些现成入口、如何组合、接入后能得到什么结果”。

## 2. 能力组成

| 开发环节 | 选用的框架入口或实现方式 | 本包说明的接入结果 |
| --- | --- | --- |
| HTTP 入口 | `@HasPermission`、参数校验及统一 `R<T>` | 将已声明的权限与业务用例连接，按统一接口契约返回结果 |
| 业务处理与本地事务 | Spring Service、`@Transactional` | 在业务用例中组合数据库写入与回滚；不扩展到远程副作用 |
| 数据访问 | `aura-common-data`、`BaseEntity`、MyBatis-Plus `BaseMapper` | 按表结构选择实体与 Mapper，完成查询和写入 |
| 异常处理 | 公共 `CustomException` 与项目已启用的异常映射 | 将可识别的业务失败交由现有响应契约处理 |

## 3. 完整开发链路

```text
业务需求
→ 定义接口和输入输出
→ Controller 参数校验与权限入口
→ Service 编排业务规则
→ Service 划定本地事务
→ 按本能力包数据库章节完成读写
→ 处理异常和回滚
→ 按需接入日志、审计、幂等；使用缓存时在提交后处理失效
→ 按统一接口契约返回结果（所有 HTTP 接口使用 R<T>）
```

## 4. 与其他能力包的关系

- 数据库如何建模、查询和写入，由本能力包的数据库开发章节统一说明，不再拆成另一个基础能力包；
- JSON、鉴权、租户、缓存、日志、审计和重复提交处理，进入[基础通用支撑能力包](../03-基础通用支撑能力包/01-总入口.md)；
- 跨服务事务、分布式序列和动态数据源，进入[数据与事务基础设施能力包](../05-数据与事务基础设施能力包/总入口.md)；
- Controller 和 Service 的业务闭环仍由本能力包统一组织。

## 5. 接入结果如何核对

选用本包的数据库、响应或安全入口后，可沿实际业务调用核对：依赖与配置是否生效、Controller 是否调用业务用例、Mapper 读写是否符合该业务的数据范围、成功与失败是否按接口契约返回。事务回滚和所选横向能力只检查本次实际涉及的场景；研发自测与交付要求以[研发自测范围与验证层级](../../../01-基础编码规范/12-研发自测规范/01-范围与验证层级.md)、[证据、回归与交付结论](../../../01-基础编码规范/12-研发自测规范/03-证据回归与交付结论.md)、[交付物一致性与恢复](../../../01-基础编码规范/13-版本控制变更与交付规范/03-交付物一致性与恢复.md)及[交付说明与恢复验证](../../../01-基础编码规范/13-版本控制变更与交付规范/04-交付说明与恢复验证.md)为准，不由本包另设通用交付清单。

## 6. 详细内容入口

阅读时可按任务定位：能力地图见第 0.5 节，Controller/Service/事务见第 1～4 节，CRUD、主子表、分页和自测见第 8～14 节，数据库依赖、Entity、Mapper 与 SQL 见第 15～22 节，逐条使用规则见第 22.1 节，完整设备配置读写场景见第 23 节。具体依赖和公开入口应与项目使用的 AURA 版本一致。
