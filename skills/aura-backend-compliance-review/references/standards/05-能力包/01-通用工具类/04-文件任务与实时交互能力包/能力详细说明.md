# 文件任务与实时交互能力详细说明

**版本**：0.1.2-draft
**状态**：建设中  
**源码依据**：既有能力为 `aura-core-common` `dev@4a2a1f1`；第 6 节 Socket.IO 已对照 `aura-core-common` `dev@0f94cdc` 中的 `aura-common-socketio:1.0.5-RELEASE`；目标项目运行仍待验证

## 使用前确认

按实际任务引入 `net.fxft` 下对应的 `aura-common-oss`、`aura-common-excel`、`aura-common-sse`、`aura-common-websocket` 或 `aura-common-socketio` 模块；依赖版本由项目采用的 AURA 依赖管理确定，不应把模块全部引入。文件存储先确认 `FileTemplate` 实际注入的是本地还是对象存储实现。`aura-common-download` 当前不作为可直接照用的下载任务能力；不能为了使用本包其他入口而一并引入。文中的代码示例不能代替项目启动、权限和运行验证。

## 1. 文件存储组合说明

文件存储的公共依赖、配置、`FileTemplate` API、对象键、权限边界、正反例和完成判断统一见[基础通用支撑能力包文件存储说明](../03-基础通用支撑能力包/08-文件存储能力说明.md)。本能力包只补充它与 Excel、SSE、WebSocket、Socket.IO 或异步文件任务的组合关系，不再维护第二套文件存储契约。

组合接入时仍需确认：

1. 文件上传或生成任务的业务权限、租户和文件元数据；
2. 文件任务的状态、失败重试、结果访问和删除策略；
3. SSE/WebSocket/Socket.IO 通知的接收人、事件顺序、断线与重连语义；
4. 目标项目实际启用的模块和运行版本。

## 2. 下载任务模块与导出候选入口

### 能力作用

既有已绑定版本中的 `IExportExcelService` 实现整体被注释，不能作为可用入口。后续本地 `aura-core-common/dev` 工作树新增下表入口，并与 `aura-core-upms/dev` 的下载任务查询、归属和结果下载配套；当前未发布正式依赖版本。只在核实目标依赖实际包含这些签名时采用，不能将旧发布包视为自动支持。

| 业务需求 | 候选公开入口（包名net.fxft.aura.common.download.core） | 业务输入与结果 |
| --- | --- | --- |
| 自定义格式生成 | `new ExportJob(filename, contentType, writer)` | writer只接收OutputStream；返回一次生成作业 |
| 固定导出行模型 | `StreamingExcelExport.job(filename, Row.class, reader, config)` | reader为PageReader<T>，返回一个XLSX作业 |
| 动态列 | `DynamicStreamingExcelExport.job(filename, headers, reader, config)` | headers为List<String>，每行List<Object>按表头顺序；返回一个XLSX作业 |
| 超大量固定行模型 | `PartitionedStreamingExcelExport.job(filename, Row.class, reader, config)` | 多个XLSX依次写入一个ZIP；文件名使用.zip |
| 超大量动态列 | `PartitionedStreamingExcelExport.dynamicJob(filename, headers, reader, config)` | 与动态列相同的行值约束，交付一个ZIP作业 |

三类Excel生成工具使用FastExcel；导出模型使用`cn.idev.excel.annotation.ExcelProperty`，不要混用其他Excel库的同名注解。reader签名为`List<T> read(long offset, int limit)`；offset为此前已读取的源记录数，当前版本空页或短批次即结束，返回null或超出limit则失败。业务须冻结查询范围并使用稳定排序，选择合适的游标策略，不能在reader之前准备全量List。工具不先执行全量count。分页之后再过滤造成短页时，必须在业务查询层确认结束语义，不能直接把“过滤后不足limit”交给本版reader当末页。

单XLSX配置为`StreamingExcelExport.Config(batchSize, maxRows, sheetName)`；分片ZIP配置为`PartitionedStreamingExcelExport.Config(batchSize, maxRows, maxRowsPerFile, maxFiles, sheetName, entryPrefix)`。数值依据项目容量确定，不把默认值当作容量验收。ZIP内名称为前缀加连续序号；当前按行数拆分，不提供字节大小自动拆分或多工作表自动溢出。

### 导出模型与动态字段

使用独立导出DTO声明允许公开的字段，不直接输出持久化实体。长编号按文本生成，字段可读方式与本版FastExcel契约一致。下面是可读JavaBean行模型的最小写法，不代表任务业务模型也必须改为JavaBean：

```java
import cn.idev.excel.annotation.ExcelProperty;

public class TaskExportRow {
    @ExcelProperty(value = "任务编号", index = 0)
    private final String id;
    @ExcelProperty(value = "任务名称", index = 1)
    private final String title;

    public TaskExportRow(String id, String title) {
        this.id = id;
        this.title = title;
    }

    public String getId() { return id; }
    public String getTitle() { return title; }
}
```

当前固定行模型入口只接受具体JavaBean导出DTO：record、接口和抽象类型会提前拒绝，库实际识别的每个导出字段须具有公开getter；不通过修改业务对象去绕过公共约束。动态表头已在创建作业时复制为不可变集合，每批按相同字段顺序提供数据；不允许null行，空单元格可以为null。`List.of`不接受null值，允许空单元格的业务不能将其当作无条件行构造方式。

### 容量目标与当前候选实现的差距

通用要求遵循[文件输出规模规则](../../../01-基础编码规范/11-运行时并发与资源管理规范/04-文件批处理与性能边界.md#aura-base-runtime-019接口和任务输出必须限制数据规模)。能力使用不能只看类名或配置是否能创建，还应核对实际有效容量。

| 项目 | 使用/发布目标 | 当前候选事实及处理 |
| --- | --- | --- |
| 单工作表容量 | 依据格式总容量扣除实际表头、标题等占用，再受业务单文件上限约束 | 单文件Config已限制最多1,048,575条；写入前再按FastExcel实际表头行数检查，超出可用容量拒绝且不调用reader |
| ZIP中每份Excel | 每个文件独立满足可用数据行容量，且不遗漏/重复跨批次数据 | 分片上限同样先扣至少1行，再检查实际多行表头；批次跨分片不重新查询，已验证2/2/1连续分片 |
| 总量与分片数 | 独立限制总记录数、分片数、输出字节/磁盘和处理时间 | 当前只实现行数/分片数等部分边界，不表示字节、磁盘和耗时全部已受控 |
| 资源和空结果 | 全部分片和ZIP资源结束，空结果有可读表头、满片无空尾片 | ZIP使用明确关闭释放压缩资源，不关闭ExportJob持有的底层流；空表头、满片无空尾片及原失败不被收尾异常覆盖已通过隔离测试 |
| 行内容 | 表头、数据行数、字段值、顺序及敏感字段均正确 | 新增内容测试实际读取单文件、固定和动态ZIP的每个XLSX；权限及敏感字段仍由业务准备，不推广为任意模型都可用 |

上述状态仅描述本地候选源码，不表示既有发布依赖已经包含修正。业务项目不复制公共类自行修补；目标依赖尚不满足需求时记录版本缺口，选择已验证的有界方式或明确拒绝。当前没有标题空白行、自定义样式/处理器或多工作表的扩展参数，不能把表头扣减检查外推到未支持的布局；后续增加布局入口时须同时更新容量计算。

`@ExportMonitor`放在返回ExportJob的HTTP导出入口，切面处理同步/异步交付、执行租约和对象上传；业务不另建分片下载任务。旧void(HttpServletResponse, ...)写法只在请求线程生成，不能据此承诺超时提前返回。认证身份来自可信上下文；生成条件和字段范围由业务确定，下载中心按本人、当前租户、状态和有效期访问，不重新执行源业务查询。中断首版失败收口，用户重新发起，不自动续跑。

```java
// TaskExportRow、已冻结的snapshot与taskQueries属于业务类型。
@ExportMonitor("任务清单")
public ExportJob exportTasks(TaskQuery query) {
    var snapshot = taskQueries.freezeAuthorizedQuery(query);
    return PartitionedStreamingExcelExport.job("任务清单.zip", TaskExportRow.class,
            (offset, limit) -> taskQueries.readPage(snapshot, offset, limit),
            new PartitionedStreamingExcelExport.Config(1000, 2_000_000L, 100_000L, 20, "任务", "任务清单"));
}
```

**正例**：只加载一个批次，使用已验证的FastExcel行模型；逐份关闭XLSX后完成ZIP，下载中心交付一个任务；用解析器读取各分片核对真实数据内容。

**反例**：仅加注解但全表读入内存；复用已注释的旧服务；复制候选源码进业务项目充当正式依赖；只检查ZIP文件名或字节数就宣称数据完整和下载任务链已验收。

当前隔离样本证明了部分执行和文件生成行为，尚未证明正式依赖可解析、任意行模型序列化正确、超大行数容量、真实网关认证与对象存储链路。采用前仍需核对发布版本、表结构、配置及每份文件内容；缺少版本或证据时只报告缺口，不自行补造框架API或判定旧项目未复用候选能力。

### 配套接入顺序

1. 核对目标已发布公共版本及下载中心版本，确认download的候选入口已纳入；公共业务异常修正还需配套core与sentinel，不能仅换一个JAR。
2. 由维护方准备新任务表字段、结果元数据、执行字段和清理表；生成服务的download数据源与UPMS必须访问同一份任务数据，历史记录不回填、不自动归属。
3. 通过统一BOM引入`net.fxft:aura-common-download`，沿公共FileTemplate配置存储；生成端和下载端能访问任务实际resultBucket，不能只检查默认桶名称。
4. 业务在请求阶段固定过滤条件、可见字段与授权范围，返回声明类型为ExportJob的作业；后台只分页查询与写流，不捕获Servlet请求/响应，也不为每个Excel分片创建任务。
5. 调用方同时支持HTTP 200附件和HTTP 202任务结果，202时读取字符串taskId，随后查询当前用户任务；下载前核对本人/当前租户、SUCCESS和有效期，不重新筛选已生成文件内容。
6. 完成宿主自动配置、真实数据库、认证、对象存储和容量验证后启用维护扫描。cleanup-enabled与recovery-enabled默认false，关闭扫描不关闭导出或心跳，也不代表中断任务和过期对象会自动收口。

**接入正例**：一次导出创建一个任务并生成多个Excel的ZIP；查询和下载使用同一任务ID、同一存储位置；普通用户只能访问当前租户内自己创建的任务。

**接入反例**：只升级业务导出JAR而不升级UPMS模型和表；把本地联编使用的版本号当作已发布版本；生成端与UPMS分别连两份任务表；仅按HTTP 200判断下载成功；为调用候选API复制公共类进业务项目。

具体接入分为业务作业准备和平台环境配置。查询快照、领域行模型及读取服务由业务实现；任务服务、自动分流、存储上传、执行权与清理流程由公共组件承担。当前没有完整导入校验/确认/写入与失败行重试入口，不能因本节的导出闭环已经验证就宣称导入也已可用。

需要大文件导出时，按[文件批处理与性能边界](../../../01-基础编码规范/11-运行时并发与资源管理规范/04-文件批处理与性能边界.md)确定规模、内存和任务边界，按[身份上下文与权限边界](../../../01-基础编码规范/07-安全身份权限与敏感信息规范/01-身份上下文与权限边界.md)和[前端会话与文件访问](../../../01-基础编码规范/07-安全身份权限与敏感信息规范/03-前端会话与文件访问.md)处理提交与结果访问权限。目标项目若已有完整且验证过的文件任务实现，可按该项目的版本契约接入；不能仅引用本模块并宣称下载中心可用。

## 3. Excel 导入导出

### 能力作用

提供 Excel 请求解析、响应导出、字段转换、校验和多 Sheet 处理能力。

### 开发步骤

1. 定义导入 DTO 和导出 VO，不直接使用持久化实体；
2. 声明列名、类型、必填和错误信息；
3. 导入时逐行校验，并明确失败行的反馈方式；
4. 大文件导入使用任务或分批处理；
5. 导出时限制查询范围和字段，敏感字段必须脱敏；
6. 记录导入、导出操作日志。

### 正确方向

```java
@PostMapping("/import")
public R<ImportResult> importDevices(
        @RequestExcel List<DeviceImportRow> rows, BindingResult bindingResult) {
    // 默认监听器将有效行和错误分别保存；返回的rows不代表原文件全部行。
    // 下列适配器是业务类型，按本版BindingResult target/ErrorMessage契约实现。
    var failures = importErrorAdapter.from(bindingResult);
    if (!failures.isEmpty()) {
        // 本例采用整单拒绝：任何写入前通过项目统一错误契约反馈失败行。
        throw importErrorAdapter.toBusinessException(failures);
    }
    return R.ok(deviceImportService.importRows(rows));
}
```

`@RequestExcel` 修饰 `List<导入行DTO>` 参数，而不是方法；上传字段默认名为 `file`。`ImportResult`、错误适配器和业务 Service 是项目业务类型，需由项目定义，不是框架新增入口。上例是有界小表格的整单拒绝流程片段；采用部分成功时必须把解析错误和有效行共同纳入结果，不得只统计rows。导出时 `@ResponseExcel` 修饰返回 `List<导出行VO>` 的方法，不能直接把持久化实体交给响应处理器。

`aura-core-common dev@e311702` 的 `RequestExcelArgumentResolver` 将监听器错误列表作为 `BindingResult` 的target，默认监听器返回的List仅含有效行；不能仅检查`hasErrors()`就认定文件无错。该默认监听器还累积有效行和错误，不能充当无界文件的分批写入器。其行号来自逐次invoke计数，使用多行表头、空行策略或自定义监听器时，须核对解析上下文与真实行号，不把过滤后的List索引作为原文件行号。

### 错误方向

```java
public void importData(List<DeviceEntity> rows) {
    deviceMapper.batchInsert(rows);
}
```

直接将上传内容绑定到实体并批量入库，缺少字段校验、权限和失败行处理。

### 完成判断

- 导入 DTO 与实体分离；
- 失败行和错误原因可追踪；
- 导入具备重复提交和事务边界设计；
- 导出字段符合权限和敏感数据要求。

## 4. SSE 能力

### 能力作用

SSE 适用于服务端向前端单向发送进度、通知或流式结果。它不适合需要客户端频繁反向发送消息的双向会话。

### 开发步骤

1. 定义连接身份、租户和权限；
2. 使用当前模块的 SSE 端点建立连接，并核对项目实际暴露路径；
3. 为每类事件定义事件名和数据结构；
4. 处理断开、超时、重连和多实例分发；
5. 关闭连接时清理持有器和订阅关系。

### 正确方向

```java
// 业务侧已确认接收人及其租户、事件访问权限后发送。
boolean sent = SseEmitterMessageSender.send(recipientUserId, eventPayload);
// false 表示当前发送入口没有成功投递，不能据此宣称用户已收到。
```

当前 `SseEmitterEndpoint` 在 `/sse/info` 建立连接并按用户 ID 登记；发送器提供定向发送和广播。这个入口没有替业务完成事件级租户隔离，广播也不适合发送用户私有数据。多实例时须核对所用分发器及断线后的投递语义。

### 错误方向

```java
SseEmitterMessageSender.broadcast(privateProgressPayload);
```

把某个用户的导出进度广播给所有连接，会越过接收人和租户边界。

### 完成判断

- 未授权用户不能订阅他人事件；
- 事件数据不会跨租户发送；
- 断开和重连不会遗留连接；
- 业务方知道事件顺序、重复和丢失语义。

## 5. WebSocket 能力

### 能力作用

WebSocket 适用于需要保持会话并进行双向实时通信的场景，例如协同状态、实时控制和双向消息。

### 开发步骤

1. 明确握手认证、会话身份和允许来源；
2. 定义消息类型、版本和错误格式；
3. 按消息类型实现 `JsonMessageHandler<T>`，让 `type()`、`getMessageClass()` 与实际消息一致；
4. 明确心跳、断线重连、顺序和重复消息处理；
5. 多实例部署时定义消息分发和会话路由；
6. 关闭会话时清理服务端持有状态。

当前模块默认连接路径是 `/ws/info`，并提供 `WebSocketMessageSender.send(sessionKey, message)` 和 `JsonMessageHandler<T>`。默认允许来源较宽，项目接入时应限制到实际前端来源；握手拦截器存在不等于每类业务消息都已完成鉴权。

### 正确方向

业务消息处理器实现 `JsonMessageHandler<T>` 后，先按当前会话身份核对消息类型和业务资源权限，再调用业务 Service；回复消息可使用 `WebSocketMessageSender.send(session, responseMessage)`，定向发送前应确认目标会话属于预期接收人。

### 错误方向

```java
session.sendMessage(new TextMessage(request.getParameter("message")));
```

直接转发客户端内容，缺少消息类型校验、权限校验和敏感数据处理。

### 完成判断

- 握手和每类消息都有权限边界；
- 消息格式、版本和失败语义明确；
- 断线、重连和会话清理经过设计；
- 多实例下不会把消息发送给错误会话。

## 6. Socket.IO 认证连接与租户广播

### 能力作用与边界

`aura-common-socketio` 与第 5 节的 `aura-common-websocket` 是不同模块。它提供 Socket.IO 协议连接认证、连接管理和按租户广播，适用于浏览器使用 Socket.IO 4.x 客户端接收同租户的业务通知。嵌入式模式复用业务服务 HTTP 端口，独立 Netty 端口是兼容选项；前端必须使用 `socket.io-client`，原生 `new WebSocket(...)` 不能替代。公共包不定义业务事件名、消息 DTO、按用户定向、离线消息、补发接口或 Redis 跨实例分发。

本节的模块版本、配置、认证和广播方法对应 `aura-core-common dev@0f94cdc` 源码。目标应用接入前须以实际依赖版本复核这些入口；物联中枢告警事件、旧配置前缀和测试接口不是通用公共契约。

### 依赖与配置

接入资料对应 Java 21+、Spring Boot 4 的 Servlet 应用；项目运行版本不满足时先核对兼容性，不套用本节配置。目标项目的 BOM 若已管理版本，应沿用 BOM；接入资料所对应的模块版本为 `1.0.5-RELEASE`：

```xml
<dependency>
    <groupId>net.fxft</groupId>
    <artifactId>aura-common-socketio</artifactId>
    <version>${aura.version}</version>
</dependency>
```

示例使用业务服务路径 `/api/service`，Socket.IO 传输路径 `/socket.io`，业务 namespace `/notifications`。启用前应用须提供可注入的 `OpaqueTokenIntrospector`，认证结果为包含非空 `id`、`tenantId` 的 `AuraUser`；模块不负责签发 Token。

```yaml
server:
  servlet:
    context-path: /api/service
aura:
  socketio:
    enabled: true
    context: /socket.io
    namespace: /notifications
    legacy-netty-enabled: false
```

接入资料列出的 `aura.socketio` 默认值：`enabled=false`、`context=/socket.io`、`namespace=/`、`legacy-netty-enabled=false`。只有启用独立 Netty 监听器才使用 `host`（默认 `0.0.0.0`）和 `port`（默认 `9092`）；嵌入式模式无需开放该端口。安全链与网关应让实际握手路径进入模块认证，不能因为放行握手而放行业务 HTTP 接口。客户端传入原始访问令牌 `auth.accessToken`，不附加 `Bearer `；租户 ID 只能来自服务端认证结果，不信任客户端自报。

若沿用 AURA 现有 `security.oauth2.client.ignore-urls` 配置，须把相对于 Servlet context-path 的 `/socket.io/**` 合并到原有忽略列表，并核对网关对外的 `/api/service/socket.io` 映射与 WebSocket Upgrade。安全链的实际匹配规则若使用完整 URI，则按真实请求路径配置；不可直接覆盖原忽略列表或开放整个 `/api/service/**`。反向代理读取超时还应大于服务端实际心跳间隔与超时之和。

### 后端发送与前端连接正例

业务保存成功后由服务端核对目标租户，再向**当前实例**同租户的嵌入式连接广播。事件名和数据结构由业务模块定义，以下仅为示例：

```java
import net.fxft.aura.common.socketio.SocketIoBroadcaster;
import org.springframework.stereotype.Service;
import java.util.Map;
import java.util.UUID;

@Service
public class NotificationPushService {
    private final SocketIoBroadcaster broadcaster;

    public NotificationPushService(SocketIoBroadcaster broadcaster) {
        this.broadcaster = broadcaster;
    }

    public boolean push(Long trustedTenantId, String businessId) {
        // trustedTenantId 来自认证上下文或已校验的业务记录，不取请求参数。
        Map<String, Object> message = Map.of(
                "messageId", UUID.randomUUID().toString(),
                "businessId", businessId
        );
        // 返回 true 只表示至少一次本地发送调用未抛异常，不是客户端 ACK。
        return broadcaster.broadcastEmbedded(trustedTenantId, "notification.message", message);
    }
}
```

```javascript
import { io } from 'socket.io-client'

export function connectNotifications({ serviceOrigin, getAccessToken, onNotification, refreshMissedNotificationsByHttp }) {
  const socket = io(`${serviceOrigin}/notifications`, {
    path: '/api/service/socket.io', // 对外传输路径，不包含 namespace
    addTrailingSlash: false,
    transports: ['websocket'],     // 当前嵌入式实现不提供 polling 端点
    autoConnect: false,
    auth: (callback) => callback({ accessToken: getAccessToken() })
  })
  socket.on('notification.message', onNotification)
  socket.on('connect', refreshMissedNotificationsByHttp)
  socket.connect()
  return () => {
    socket.off('notification.message', onNotification)
    socket.off('connect', refreshMissedNotificationsByHttp)
    socket.disconnect()
  }
}
```

前端示例采用 `socket.io-client:4.8.1` 接口写法，不代表已完成目标项目联调；业务应用仍须按实际依赖和服务端协议版本核对。`path` 是带应用或网关前缀的传输地址，`/notifications` 是 namespace，二者不能拼成同一个路径。退出登录、切换用户或租户时断开旧连接；重连后通过业务 HTTP 查询补齐断线期间消息，并按消息 ID 去重。组件销毁时移除监听器并断开不再使用的连接。

### 反例与交付判断

```javascript
new WebSocket(`${serviceOrigin}/api/service/socket.io/notifications`)
```

原生 WebSocket 不会完成 Socket.IO 握手，且把 namespace 错拼到传输路径。另一个错误是向嵌入式连接调用 `broadcast(...)`：接入资料将其归于独立 Netty 连接；嵌入式连接须调用 `broadcastEmbedded(...)`。两种连接集合不会自动互转，使用两种传输时应分别发送，不能用短路 `||` 漏掉第二种。

公共连接注册表位于当前进程；多实例下必须由业务把事件分发至持有连接的各实例后分别本地广播。公共包不保证用户私有消息的定向权限、离线补发、严格顺序或客户端业务处理完成。交付时至少验证：有效/无效 Token、跨租户隔离、正确事件实际到达、断线后 HTTP 补齐；多实例使用时再验证跨实例分发。握手 `101` 或广播返回 `true` 都不能代替这些结果。
