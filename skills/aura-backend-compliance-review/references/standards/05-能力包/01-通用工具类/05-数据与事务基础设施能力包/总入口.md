# 数据与事务基础设施能力包

**能力包编号**：AURA-CAP-COMMON-DATA-INFRA  
**版本**：0.1.0-draft  
**所属能力域**：通用工具类  
**状态**：建设中；能力可用范围以本包清单为准  
**当前源码依据**：`aura-core-common` `dev@4a2a1f1`；业务项目须核对实际依赖版本

## 1. 能力定位

本能力包说明业务服务如何接入已写明用法的动态数据源与 Snowflake 分布式编号，并说明跨服务事务模块当前尚未形成公开接入契约的边界。存在模块或构建器不等于业务项目已经具备可接入能力。

它适用于已经明确存在多数据源或分布式编号需求的业务；遇到跨服务一致性问题时，本包只帮助识别当前事务模块的接入缺口，不作为普通业务服务的默认依赖。

## 2. 能力范围

| 能力 | 当前公共模块 | 解决的问题 |
| --- | --- | --- |
| 动态数据源 | `aura-common-datasource` | 在已配置、已验证的数据源之间选择访问目标 |
| Snowflake 分布式编号 | `aura-common-sequence` | 在明确节点编号和运行依赖后生成业务编号 |

`aura-common-sequence` 中的 Redis/DB 区间构建器和 `aura-common-seata` 中的分布式事务实现线索，列在[能力清单的非接入项](./能力清单与边界.md#1-当前不作为可直接接入能力的实现线索)中；当前不提供可直接照用的业务接入示例。

## 3. 选择原则

```text
单数据源本地事务 → 使用普通数据访问和本地事务
多个数据源切换 → 动态数据源
需要分布式业务编号 → 核对 Snowflake 入口和节点编号
跨服务写入且必须保持一致 → 按基础规范设计参与方与一致性机制；当前事务模块不能直接作为接入方案
```

不要因为项目使用微服务、Redis 或 Feign，就自动启用动态数据源或分布式事务。

## 4. 使用前必须明确

- 数据源切换的触发条件、默认数据源和恢复方式；
- 编号的业务名称、唯一性、排序要求和失败处理；
- 选用动态数据源或 Snowflake 时，目标项目的启用入口、运行依赖和失败结果。

## 5. 使用入口

先在[能力清单与边界](能力清单与边界.md)确认当前接入范围，再按[能力详细说明](能力详细说明.md)核对依赖、示例与项目验证结果。单数据源 CRUD 和本地事务的共同规则由基础编码规范规定；需要 AURA 数据访问入口时再查基础业务开发能力包，不需要引入本包。
