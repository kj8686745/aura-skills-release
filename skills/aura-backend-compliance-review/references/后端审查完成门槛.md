# 审查完成门槛

后端项目和接口专项共用本门槛，范围始终以用户任务为准。项目全量不等于接口专项全量；限定范围之外列为未覆盖，不随意标为不适用。

| 环节 | 必须留下的证据 |
|---|---|
| 基线 | 项目版本、未提交差异、规范来源、纳入和排除范围 |
| 盘点与扫描 | 纳入范围内的模块/文件/接口数量、扫描方法、过滤条件和零命中结果 |
| 候选判定 | 每个候选确认偏差、排除或待补证；归并仍可定位原始命中 |
| 规则判定 | 每个纳入规则均为通过、偏差、未证实或不适用，附依据及证据级别 |
| 构建与运行补证 | 实际命令、环境、结果；未执行或失败的原因与影响 |
| 结果包 | 按[统一模板](审查结果包模板.md)完成六文件，发现可追溯到规范与证据 |
| 最终复核 | 规则/发现/候选统计闭合、路径可复核、敏感信息脱敏、缺口如实保留 |

执行状态只采用模板中的 `阻断/部分完成/抽查完成/静态审查完成/发布准入审查完成`。部分代表性判定不能称静态审查完成；未知运行行为可保留未证实，但不得留下没有检查说明的规则空白。

静态审查完成表示指定范围的逐规则检查与候选判定已记录，不表示全部规则通过，更不表示运行、联调或发布验收通过。发布准入审查完成必须有对应准入标准与实际证据，不因文件齐全自动升级。

规则状态与证据级别分开；通过项写清实际检查对象，多模块只查部分不能代其余通过。每个候选都有判定状态即可闭合，不需要用猜测消除待补证。只有扫描结果而无逐规则矩阵时交付部分完成结果包，说明剩余工作。
